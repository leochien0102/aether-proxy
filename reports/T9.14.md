- `aether-proxy/src/lib/schema.uc`：新增 docs/05 十行涉及的 11 个 UCI 选项，声明类型、范围、枚举与传输/安全层归属；未设置的扩展不物化到快照。
- `aether-proxy/src/lib/config.uc`：JSON 对象检查（解析失败显式转为校验失败）、Mux/Vision 冲突检查；支持可选扩展省略未设置值。
- `aether-proxy/src/lib/render/outbound.uc`：按 docs/05 的 Xray 键名渲染，保留 false/0/-1 的语义；Mux 关闭时不输出 Mux 与调优项，TFO/MPTCP 都关闭时不输出 sockopt。
- `aether-proxy/src/lib/uri.uc`：区分 gRPC 与 XHTTP 的 mode，解析 extra/ech/pqv；非法 extra 返回 invalid_value。
- `aether-proxy/src/lib/node.uc`、`aether-proxy/src/lib/sub.uc`：补齐两处字段表，保证 parse/import 一致、订阅覆盖写入及缺失删除；gRPC bool 的 UCI 字符串与快照布尔值按含义比较，避免未变订阅反复计为更新和触发重载；不修改身份算法。
- `tests/unit/node_fields.uc`：独立构造完整期望出站对象，覆盖逐键渲染、省略、范围/枚举、导入/订阅字段表和身份稳定性。
- `tests/unit/uri.uc`：新增分享链接和失败原因案例；既有 `tests/node/parse.py` 自动取该语料，检查真实 CLI parse/import/已提交 UCI 的逐项一致性。
- `tests/sub/run.sh`、`tests/sub/fixtures/grpc-multi.txt`：新增真实 staging/commit 路径的扩展删除与 ID 保留测试，以及 gRPC+ECH 首次写入、重复更新字节不变/updated=0 测试。
- 新增 `tests/fixtures/t14-node-fields-grpc/{aetherproxy,context.json,expected/xray.json}` 和 `tests/fixtures/t14-node-fields-xhttp/{aetherproxy,context.json,expected/xray.json}`。

新夹具拆成两份，因为现有渲染器只渲染当前节点：这样 gRPC+TLS（multiMode/ECH/Mux/TFO）和 XHTTP+REALITY（extra/pqv/MPTCP）都真正进入 expected 并接受 Xray 检查，而非只把第二节点写进不使用的配置段。ECH 用 Xray 的 `tls ech --serverName cover.example` 生成；PQV 是 `mldsa65 -i AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA` 的公开 Verify 值，夹具不含私钥。

## TODO(design) 与设计边界

本卡新增的三个 TODO 均在代码旁说明理由：

1. `schema.uc`：docs/05 只指定 ECH/PQV 为字符串，没有定义其编码与本地校验规则；保持不透明字符串，不臆造格式约束。真实夹具使用有效生成值，启用时仍由已有 Xray 验证链路检查。
2. `schema.uc`：docs/05 没说明与当前 transport/security 不匹配的字段是否应使配置无效；沿用既有节点字段策略，保留并做类型/范围检查，只在对应传输/安全层渲染，避免切换传输时丢失可编辑配置。
3. `uri.uc`：docs/05 仅定义 gRPC mode=multi/gun，未定义其他值；未知 mode 保守地跳过并返回 invalid_value，避免静默猜测；有 `grpc unknown mode skipped with reason` 测试。未携带 mode 时不生成选项（Xray 缺省 false），gun 生成 UCI `0`。

原文件已有的其他 TODO(design) 不属于本卡，未修改。无设计文档改动。
