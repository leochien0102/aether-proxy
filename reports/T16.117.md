## 最终语义

本节替代早期「两空自动免认证」及 clear 下拉设计：

- 新增两个协议共享的 `main.proxy_auth_enabled`，干净配置默认关闭。只接受显式 `0` / `1`，无效或空值不能当作关闭。
- 认证开启时共享用户名、密码均必填，即使两个监听均关闭也一样。清空字段不关闭认证；空对/残缺对不能保存。
- 认证关闭时可保存空对或保留完整凭据；渲染绝不带 accounts，SOCKS 使用 noauth。单填仍拒绝。
- 缺少新字段的历史配置，只要共享或旧组存在任一凭据就保守推断认证开启；完整旧组可继续使用，残缺/冲突必须修复，不能升级后静默开放。有效保存显式写入迁移结果，关闭必须保存 `0`。
- fresh 缺省关闭时新填完整凭据，也必须存显式 `0`，否则下次会被历史推断误开认证。
- 整体「清空凭据」按钮为 `type=button`，只清表单和旧来源选择，不保存、不切换认证。关闭认证并成功保存清空结果时删除共享及全部旧凭据。关闭认证但未主动清空，可保留旧冲突组，显式 `0` 压住旧配置。
- 清空后又选择旧来源，以最后选择的完整旧组为准。取消、原生 Reset 或验证失败不改持久凭据。
- 监听默认双关，绑定/端口/TCP-only/路由/现有防火墙边界不变。关闭认证意味着任何可达端口的客户端均可使用代理。

## 最后一轮确定阻断：原生 Reset 遗留清空状态

DSH 反馈真实 SDK 场景：旧冲突 → Clear → 失败 Save → Reset → 认证 off → Save，旧字段被误删。

本轮只读检查实际本地 SDK 源码：

`/workspace/openwrt/openwrt-actions/build/rockchip/feeds/luci/modules/luci-base/htdocs/luci-static/resources/form.js`

其中 `Map.reset()` 直接返回 `this.renderContents()`，并不调用 `load()`；`Map.save()` 成功后才调用 `load()`。原先只在 load 清除 `credentialsCleared` 漏掉真正的原生 Reset 路径。

修复：同时包装 map 的 `reset` 和 `load`，在委托原方法前清除表单局部 `credentialsCleared`；不改全局 LuCI、不替代原生保存/复位流程。`tests/luci/form-defaults-harness.js` 增加与 SDK 一致的 reset→renderContents double，新增专门回归：清空后失败、原生 reset 不经过 load、认证仍开时恢复冲突错误，再关闭认证保存只写 `proxy_auth_enabled=0`，所有旧凭据必须保留。真实 SDK 最后场景的旧字段保留断言保持原样。
