# T16.114 DNS 层级切换失败后恢复原服务

## 范围与根因

- 工作树：`/workspace/openwrt/aether-proxy-wt/T16.114`。
- 分支：`fix/t16.114-dns-tier-rollback`；实际基线/任务卡提交：`b6d66f8dc37cd14ecbf5c3bad3c3d6af0a55975e`（卡正文的 a15c84ea 是前一提交）。
- 根因：`action_set_tier()` 发布候选配置并停止旧 DNS 后，候选启动、readiness 或 dnsmasq 通知失败直接返回。monitor 不提交新 tier，却没有补偿已经发生的文件及进程变化。
- 仅修改 `aether-proxy/src/lib/monitor.uc`、`tests/monitor/` 和本报告；未修改通用 HUP 回滚、DNS Question 回显、nft、版本、CI 或设备配置。

## 实现

1. 覆盖前读取实际 `current/chinadns.conf` 的完整字节，读取失败不发布、不停止原进程；不重新推导旧配置。
2. 发布后的候选启动、owned UDP/TCP readiness、首次 dnsmasq HUP 任一步失败，都在现有 busy/操作锁内停止候选（同时取消其崩溃重启），恢复保存的旧字节，使用本次操作捕获的原引擎路径启动恢复代。
3. 恢复代复用 `published_dns()` 验证正式 UDP/TCP 监听属于该代进程；只有正向已尝试通知 dnsmasq 时才在恢复 ready 后再次 HUP。原始错误始终返回，不发切层成功事件；恢复失败以 `rollback_dns:` 拼接第二段错误，不递归重试或二次取锁。
4. 正向 stop/start、正向 readiness、恢复 stop/start、恢复 readiness 和通知完成后的边界检查停止请求；TERM 优先结束动作，不再启动下一代、不发切层成功通知，由原完成路径释放 busy/锁。

## 同一隔离反例：基线失败，修后通过

```sh

python3 tests/monitor/tier-dns-rollback.py --monitor-source /tmp/T16.114-baseline-monitor.uc exit
python3 tests/monitor/tier-dns-rollback.py exit
```

第一条测试预期 RC=1：失败候选退出后，状态仍为 T1，`byte_identical: false`，真实 loopback 新 DNS 查询得到 `[Errno 111] Connection refused`。旧配置额外含注释哨兵，断言逐字一致，而非重新渲染等价内容。

修后同一 `exit` 用例 RC=0：`byte_identical: true`，候选退出且模拟 `/proc/<candidate>` 已移除，只出现候选及一次恢复代；恢复代对不同名称/ID 的新 UDP、TCP 查询均返回旧配置答案 `192.0.2.11`。候选配置答案为 `192.0.2.22`，并在 HUP 失败路径及成功重试中实际验证，避免只凭 PID、端口可连、状态标签或缺少成功事件判定恢复。

证据层次：这里是 **Python DNS stub 进程 + 实际 loopback UDP/TCP socket/DNS 报文**；管理动作和 readiness 的进程拥有权使用既有 fixture 的模拟 `/proc`。响应器在被管理 DNS 子进程内部，不是独立旁路服务；不声称验证过真实 chinadns-ng 引擎。正式端口为 loopback `127.0.0.1:31053`，测试串行运行。

## 覆盖与结果

- 候选立即退出：旧字节、真实 UDP/TCP 新查询、候选消失、原错误；随后再次切层成功，返回候选答案且仅一条成功事件。
- 候选 readiness 超时：同上；未进入正向 HUP 时恢复不额外 HUP。
- 首次 HUP 失败：严格顺序 `candidate ready → HUP failed → candidate exit → restored ready → HUP ok`，服务及字节恢复，原错误返回。
- 两次 HUP 均失败：旧服务仍回答新 UDP/TCP 查询，原 HUP 和恢复 HUP 两段错误可见，不宣称成功。
- 恢复自身 readiness 超时：原候选退出错误与 `rollback_dns: ... required sockets not ready` 同时保留，旧字节仍恢复，无成功事件。
- 旧配置缺失：无发布、无子进程停止/拉起、无 HUP，原进程继续回答新 UDP/TCP 查询。
- TERM：候选 readiness 和恢复 readiness 均用文件屏障保持未就绪，再投递 TERM；停止后无新增 DNS 代、无 HUP/成功事件、无误报动作错误，状态 stopped、锁释放。
- 复用既有正常切层、TCP-only/impostor readiness、T3 回试 T2 成功/失败策略测试。
