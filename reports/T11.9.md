## SDK 实验（隔离目录，不改共享 SDK/固件树）

OpenWrt 24.10.8 官方 SDK：`/tmp/T11.9-sdk/x86_64`、`/tmp/T11.9-sdk/aarch64`。
x86 SDK 从已有 SDK 复制；ARM SDK 从官方 armsr/armv8 下载，并以官方 sha256sums 校验通过（SDK SHA256 `5f430f5b30c9ea6dc472710356c139abf916b7ebd5de14e108e9cc204f40a2a4`）。两个 SDK 的 aetherproxy feed 均指向本 worktree。

1. 双架构 `make package/chinadns-ng/compile V=s` 成功（x86 先 clean）。
2. x86 再 clean chinadns-ng，单独 `make package/aether-proxy/compile V=s` 成功；日志先进入 aether-xray、chinadns-ng，再进入 aether-proxy，应用 ipk 生成。未手工预编译 chinadns-ng 来代替依赖测试。
3. 关闭 CONFIG_ALL/ALL_NONSHARED/ALL_KMODS，将应用设为 y、两个独立二进制依赖显式取消，再执行 `make defconfig`：三个配置均自动为 y；生成的 tmp/.config-package.in 包含 select PACKAGE_chinadns-ng，tmp/.packageinfo 的应用 Depends 包含 +chinadns-ng。
4. 包检查命令：
   ```sh
   python3 tests/release/check_chinadns_packages.py \
     /tmp/T11.9-sdk/aarch64/bin/packages/aarch64_generic/aetherproxy/chinadns-ng_*.ipk \
     /tmp/T11.9-sdk/x86_64/bin/packages/x86_64/aetherproxy/chinadns-ng_*.ipk
   ```
   两包元数据均为 chinadns-ng / 2025.08.09-r1，仅一个可执行数据文件 usr/bin/chinadns-ng；ELF64 little-endian，ARM machine=183、x86 machine=62；二进制 SHA256 分别为 `42ddd494200ec6d88b35902927688d316bc23e06e6c08d9e01eb2412196ab845`、`842ea4e9816efd91d39bc76ead5c4a42e79011757e37c521b4270b675cfcb30c`。x86 执行 -V 确认 2025.08.09；ARM 未执行（主机为 x86）。

本地 SDK 实构建为 ipk；apk 资产选择由离线 Release workflow 测试覆盖，本任务未实构建 apk。
