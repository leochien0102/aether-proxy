## 实现

修改 `aether-proxy/files/aether-proxy-rawlog.sh`：

1. 将一次性 logread/awk 管道改为持续采集循环。logread 正常 EOF 或非零退出导致 awk 结束后，collector 不再 `exit 1`；awk 自身退出也会触发回收及重建。
2. 每轮结束先终止、wait 回收旧 logread/awk，再删除 FIFO。新会话重新创建 0600 FIFO，不遗留旧 reader，也不重叠启动采集对。
3. 对短会话退出按 1、2、3、4、5、5… 秒退避，正常 EOF 同样退避，避免空输出重连形成忙循环。会话持续至少 30 秒后将退避重置为 1 秒。
4. sleep 使用后台子进程加 wait；TERM/INT 可中断采集等待或退避，退出码为 0。EXIT 清理会终止并 wait 回收 sleep、logread、awk，删除 FIFO。
5. 每次重连重新读取当前 raw.log 的字节数及行数。保留既有追加、整行过滤、超长记录丢弃及轮转逻辑，不截断既有记录。

保持边界：生产仍写 `/var/run/aether-proxy` 的 tmpfs；raw.log、raw.log.1 和 FIFO 为 0600；每段最多 1 MiB / 2000 行，只保留当前段及一个旧段。仍仅调用 `logread -f -e aether-proxy` 获取新增记录，不清空、不修改 logd，不添加 flash 写入或 UCI 配置写入。

## 场景对照

扩展 `tests/daemon/raw-log.py`：

| 场景 | 宿主机结果 |
|---|---|
| fake logread 正常输出后 exit 0 | collector 保持存活并重连；后续 SERVICE_STARTED / PROXY_HEALTHY 记录均写入，文件继续增长 |
| fake logread 连续 exit 5 | 实测相邻调用间隔符合 1、2、3、4、5、5 秒；无忙循环 |
| 非零退出后恢复 | 不重启 collector 即可继续写入后续健康事件 |
| awk 被终止，logread 仍在 follow | 旧 reader/awk 均被回收，随后重新采集 |
| TERM 发生在 5 秒退避期间 | 2 秒内正常退出，sleep 被回收，FIFO 不残留 |
| TERM 发生在采集期间 | 原有采集清理断言保持通过 |
| INT 发生在重连后的采集期间 | 2 秒内正常退出，reader/awk 均回收，FIFO 不残留 |
| supervisor 下 reader 短暂失败 | collector 本身不崩溃、不产生 CHILD_CRASHED；正常停止后 pid 文件与 reader 均消失 |
| 权限及轮转 | FIFO 0600；raw.log/raw.log.1 0600、单段 1 MiB / 2000 行上限、精确字节边界、超长整行拒收、计数及 CLI 隔离均通过 |

测试中的 SERVICE_STARTED / PROXY_HEALTHY 是 fake logread 输入，不是真机服务事件。既有 supervise raw-log 专项预期从“reader 失败导致一次 CHILD_CRASHED”改为“reader 失败由 collector 内部处理，不产生 CHILD_CRASHED”。

获得连接后应在不 bump、不写 flash 的前提下，用 tmpfs 中的候选脚本及可恢复的运行时切换方式验证：

1. 重启服务，确认 collector pid 存活，raw.log/FIFO 为 0600，目录位于 tmpfs。
2. 在多个观察窗口记录 raw.log/raw.log.1 的字节数及行数，核对 logread 中实际出现的后续服务启动、恢复健康等事件也持续进入 raw.log，而非仅启动瞬间的一批。
3. 检查 collector 不存在 CHILD_CRASHED 后停更；可在可控窗口终止 logread/awk，验证自动重连后仍收到新增记录。
4. 停止服务，确认 collector、logread、awk、退避 sleep 和 FIFO 均清理，再恢复运行时环境。

SERVICE_STARTED / PROXY_HEALTHY 是状态事件，不应为了让文件增长而合成周期事件；验收应以真实发生的新日志是否持续被采集为准。重连期间不回填历史，依然遵守新增记录采集语义，因此退避窗口可能漏收记录，本卡不提供无损日志交付保证。
