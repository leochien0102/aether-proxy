## 实现与回滚语义

在 `aether-proxy/src/lib/monitor.uc` 中改造 `update_node_ip` 与 `restart_child`：

1. **操作锁复用（不二次取锁）**：`monitor.tick()` 已持有全局 `C.LOCK_FILE` 与 `daemon.busy`，`update_node_ip` 全程不再次调用 `sys.lock()`，所有出口经 `finish()` → `finish_tick()` 统一释放 `C.LOCK_FILE` 与 `daemon.busy`。
2. **先暂存与校验，后发布**：
   - 修改 `current/` 前先读取当前活动 `current/aether-proxy.nft` 与 `current/xray.json` 原字节。
   - 在 `run_dir/staging` 写入候选 `aether-proxy.nft` 与 `xray.json`，先执行 `nft -c -f` 与 `xray run -test` 校验；校验或暂存写入失败直接清理 `staging/`，不触碰 `current/`、内核 nft 或 Xray 进程。
3. **按实际改变的资源精确回滚**：
   - 发布阶段先写 `current/aether-proxy.nft` 再写 `current/xray.json`：若第二份写入失败，仅还原已改写的 `current/aether-proxy.nft`，不重载 nft 也不重启 Xray。
   - `apply.nft_load` 加载失败：`nft -f` 在内核原子生效，仅还原两份 `current/` 文件，不重载 nft 也不重启 Xray；`sets.save` 保持不删。
   - `apply.nft_load` 成功后重启 Xray 并等待 `xray_ready.published` 就绪；若子进程启动失败（`child.pid() == null || child.error() != null`）或就绪失败（非 `TERM` 取消），依次还原 `current/` 两份文件、重载旧 `aether-proxy.nft`、重启旧 `xray.json` 并等待 `xray_ready.published` 就绪。
   - 仅当新 Xray 就绪且未收到停止信号时，才删除待恢复 `sets.save`、更新 `machine.node_ip` / `daemon.state.node_ip` / LKG 并发出一次 `NODE_IP_CHANGED`。
4. **回滚失败单独可见**：回滚任一步失败均单独记录 `START_FAILED`（`step: monitor:rollback_current` / `monitor:rollback_nft` / `monitor:rollback_xray`），并将原错与回滚错拼接后传回 `monitor:actions`，不发布 `NODE_IP_CHANGED`、不更新运行态 IP 与 LKG、不假称已恢复。
5. **在途 `SIGTERM` 停止优先**：
   - `restart_child()` 在旧子进程停止回调中先检查 `daemon.ctx.stopping_requested`，已请求停止则不再拉起新子进程。
   - `update_node_ip` 在发布前、重启前、重启回调、就绪等待后及回滚入口/回调均检查 `daemon.ctx.stopping_requested`，在途收到 `TERM` 不复活退出中的子进程，正常调用 `finish(null)` 释放 `busy` 与 `C.LOCK_FILE` 并交由 `shutdown()` 完成停止。

## 注入点与前后证据

测试脚本 `tests/monitor/node-ip-rollback.py` 使用真实 `aether-proxy daemon`、`monitor.uc`、`xray_ready.uc` 与隔离临时 sysroot，在临时副本包装 `nft`（记录每次 `nft -f` 实际加载字节到 `loaded-nft.conf`）和 `xray`（记录每次启动实际读取配置到 `xray-active-config.json`），并对 `sys.write_atomic` 提供一次性路径故障注入；绝不触碰宿主网络或真机。

| 场景 | 注入点 | 实际改变资源 | 期望恢复范围 |
| --- | --- | --- | --- |
| `positive-control` | 无（正控） | 两份 `current/`、nft、Xray、state、LKG | 仅一次 `NODE_IP_CHANGED`，零 `BUSY`/`START_FAILED` |
| `stage-second-fail` | `staging/xray.json` `write_atomic` 失败 | 仅 `staging/aether-proxy.nft` | 清理 `staging/`，零 nft 加载与 Xray 重启 |
| `write-second-fail` | `current/xray.json` `write_atomic` 失败 | 仅 `current/aether-proxy.nft` | 还原 `current/aether-proxy.nft`，零 nft 加载与 Xray 重启 |
| `xray-test-fail` | `xray run -test` 返回非零 | 仅 `staging/` | 清理 `staging/`，`current/`/nft/Xray 未改动 |
| `nft-load-fail` | `nft -f` 一次失败 | 两份 `current/` | 仅还原两份 `current/`，零额外 nft 重载与 Xray 重启 |
| `xray-crash-fail` | 新 Xray 启动后立即退出 | 两份 `current/`、内核 nft、Xray 进程 | 还原两份 `current/` + 重载旧 nft + 重启旧 Xray 就绪 |
| `xray-ready-fail` | 新 Xray 缺少引用 DNS 端口 `31082` | 两份 `current/`、内核 nft、Xray 进程 | 还原两份 `current/` + 重载旧 nft + 重启旧 Xray 就绪 |
| `rollback-nft-fail` | 新 Xray 立即退出 + 回滚 `nft -f` 失败 | 两份 `current/`、内核 nft、Xray 进程 | 单独报 `monitor:rollback_nft` 且 `monitor:actions` 同时保留原错与回滚错，不切 IP/LKG |
| `rollback-xray-fail` | 新 Xray 立即退出 + 回滚 Xray 缺 `31082` | 两份 `current/`、内核 nft、Xray 进程 | 单独报 `monitor:rollback_xray` 且 `monitor:actions` 同时保留原错与回滚错，不切 IP/LKG |
| `term-during-stop` | 旧 Xray 停止屏障内向 daemon 发 `SIGTERM` | 旧 Xray 正在退出 | 不拉起新 Xray（启动次数不变），`state=stopped`，释放锁 |
| `term-during-ready` | 新 Xray 等就绪期间向 daemon 发 `SIGTERM` | 新 Xray 等待中 | 不触发回滚复活旧 Xray，`state=stopped`，释放锁 |
