## 1. 调用链、回调发布边界与根因修复

### 真实 monitor 动作调用链与发布边界
- `monitor.tick(daemon)` 获取全局操作锁（`C.LOCK_FILE`）并置 `daemon.busy = true`，观测并经 `next()` 产出 `transition` 后，调用 `run_actions(daemon, transition.state, transition.actions, 0, error => finish_tick(...))`。
- `run_actions()` 顺序执行每个动作，遇到 `set_tier:<tier>` 时经 `run_action()` 调用 `action_set_tier(daemon, tier, done)`；若任意动作返回非空 `error` 或 `daemon.ctx.stopping_requested` 为真，立即中止后续动作并进入 `finish_tick()`。
- **发布边界（`finish_tick()`）**：
  - 仅在 `!daemon.ctx.stopping_requested && error == null` 时提交 `daemon.machine = machine`、写出 `transition.events`（含 `DNS_TIER_CHANGED`）、调用 `persist_state()` 更新 `state.json`，并在包含 `set_tier:T2` 时调度一次性 `daemon.immediate` 立即重采样。
  - 当 `error != null`（且未停止）时走现有动作失败路径：`log_failure(daemon, 'actions', error)` 记录 `START_FAILED (monitor:actions)`，保留 `set_tier:<tier>: <reason>`，不提交新 `dns_tier`、不发 `DNS_TIER_CHANGED`、不调度 `daemon.immediate`。
  - 当 `daemon.ctx.stopping_requested` 为真时，不更新 `daemon.machine`、不发 `DNS_TIER_CHANGED`、不覆写停止态 `state.json`，释放锁与 `busy` 后调用 `uloop.end()` 唤醒生命周期主循环。

### 根因与修复
- **修复前**：`action_set_tier()` 在 `restart_child()` 拿到新 DNS 子进程 PID 后即直接调用 `apply.dnsmasq_hup(daemon.ctx)` 并回调 `done(null)`，在子进程尚未完成 `exec` 或尚未绑定目标 UDP/TCP 监听套接字时就通知 `dnsmasq` 刷新缓存并宣告切换成功。
- **修复后**：在 `aether-proxy/src/lib/monitor.uc` 的 `action_set_tier()` 中，于 `restart_child()` 成功后复用 T16.91 的 `xray_ready.published_dns(daemon.ctx, daemon.children.dns)`：
  - 每次从当前已发布 `current/chinadns.conf` 读取 `bind-addr`/`bind-port`，在 5 秒有界超时内校验本代子进程身份（`/proc/<pid>/stat`）、FD 归属（`/proc/<pid>/fd` inode）以及目标 UDP（非连接态 `07`）与 TCP（`LISTEN` `0A`）双传输监听。
  - 仅在 `!daemon.ctx.stopping_requested && ready.ok` 时执行单次 `apply.dnsmasq_hup(daemon.ctx)` 并回调成功。
  - 若等待期间 `daemon.ctx.stopping_requested` 置位（`SIGTERM` 取消），直接 `done(null)` 退出：不 HUP、不重启第二个子进程、不把取消当成已就绪、不产生误报错误事件。
  - 若 `!ready.ok`（子进程早退、超时或配置异常），直接 `done(ready.detail)` 进入现有动作失败路径，不 HUP、不误报成功并保留完整原因。

### 普通 tier 切换与 T3 回试 T2 策略区分
- **普通 tier 切换**（如 `T1 -> T2`、`T2 -> T1`、`T2 -> T3`）：单次 `set_tier:<tier>` 等待本代 `published_dns` 就绪后恰一次 HUP 并提交目标 tier。
- **T3 定期回试 T2（`periodic_retry`）**：先执行 `set_tier:T2`（等待本代 UDP/TCP 监听就绪后再 HUP 并提交 `T2` 与 `t2_retry_pending=true`），随后 `finish_tick()` 经 `daemon.immediate` 触发立即 DNS 探测；**并非每次回试必回落**——若立即探测成功（`dns_ok === true`），清除 `t2_retry_pending` 并**保持在 T2**；仅在立即探测失败（`dns_ok === false`）且 `allow_china_fallback == true` 时才回落 `T2 -> T3`（`reason=t2_retry_failed`），且该次回落同样先等新代就绪再 HUP。
