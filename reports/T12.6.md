# T12.6 B25 概览页热力图 UI

## 结论

B25 概览页热力图已按 docs/b25-heatmap.md §7 与 docs/10「B25：概览页使用热力图」落地：
概览页「流量与连接」之后、「组件版本」之前渲染「使用热力图」卡片。`load()` 读 UCI
`stats.heatmap_enabled`（缺省/空/非 `'1'` 均关），**关闭时完全不渲染、不发
`stats_history` 请求**；开启时只在 `fetchRefresh` 末尾经 `ap.call('stats_history')`
读取（TTL 10 分钟 + 跨本地日期立即重读）。7 列（周一…周日）× 至多 13 行、按本地日期
对齐周，只画已有日期不补零；颜色按 `log1p(tx+rx)` 归一化分 5 档；健康度用内边框/角标/
透明度表达，`observed=0` 中性灰不画成故障；tooltip 四行纯文本（title 属性，不注入
HTML）；窄屏水平滚动；i18n 全部进 po。历史读取失败不阻塞其他卡片、保留最后成功数据、
控制台每次失败连击只 warn 一次。无外部图表库、无后端/usage/API/采样改动、版本未动、
未 push。

## 实现

- `model/overview.js`（纯函数，无请求、无 DOM）：
  - `heatmap_enabled(value)`：仅 `'1'` 为开（docs/05 口径）。
  - `heatmap_today(ms)`：unix 毫秒 → 本地日历 `YYYY-MM-DD`。
  - `heatmap_view(reply, today)`：应答 → 卡片视图模型。`ok:false`/无应答 →
    `{state:'error', text}`（「读取使用历史失败（%s）」）；`enabled !== true` →
    `{state:'off'}`（整卡隐藏）；`days` 空/全部无效 → `{state:'empty', text:'暂无数据'}`；
    否则 `{state:'ok', weeks}`。条目校验：`YYYY-MM-DD` 真实日历日期（拒绝
    `2026-02-30`）、缺字段/负数收 0、`healthy` 收口到 `observed`、**未来日期丢弃**、
    重复日期取后一条。网格：周一起始行覆盖数据实际跨越的周（历史短则行少）、最多
    13 行、更早条目丢弃；无条目日期为 `null` 格（不补零）。
  - 颜色档位：`v = log1p(tx+rx)`，`max` 取显示天里的最大值；`max>0 && v>0` 时
    `level = min(4, 1 + floor(v/max·4))`，否则 0——0 流量恒为最浅档，单日数据即
    第 5 档。
  - 健康档：`observed==0` → `none`（中性）；`healthy>=observed` → `ok`；`healthy>0`
    → `warn`；`healthy==0` → `bad`。
  - tooltip：日期 / 代理流量（`byte_text` 自动单位 1024 进位 B→TB，KB 起一位小数）/
    健康占比（`round(100·healthy/observed)%`，`observed=0` 显示「–」）/ 观测时长
    （秒/分钟/小时/天进位，复用已有「%s 小时」条目）。
- `view/overview.js`：
  - `load()` 增加 `heatmap: uci.get('aetherproxy','stats','heatmap_enabled')`；
    `render()` 存为 `heatmapCfg` 并初始化热力图状态，先渲染「读取中…」占位
    （先出页面后填数据）。
  - `fetchRefresh` 链尾 `.then(() => this.loadHeatmap())`：排在 status/stats/events
    之后，慢或失败的历史读取不延迟其他卡片；`loadHeatmap` 有 TTL 门（`heatmapTtl` =
    10 分钟）+ 本地日期变化强制重读 + 单飞守卫（`heatmapRequest`）。关闭时
    `loadHeatmap` 只同步清卡片、绝不发请求。
  - `updateHeatmap()` 只写自己的区域：关闭/`off` 应答清空整卡（已空则不写 DOM，
    不破坏「每次迟到回复只写自己区域」的既有测试门）；成功网格 + 失败时叠加一行
    警告色错误文字；首次读取失败只显示错误。`console.warn` 仅在失败连击开始时一次。
  - `heatmapGrid(weeks)`：7 个星期表头 + 每周 7 格；有数据格
    `ap-heat-cell ap-heat-l<0..4> ap-heat-<ok|warn|bad|none>` + `title`（纯文本）；
    空格 `ap-heat-blank` 无 title。外层 `ap-heat-scroll`（`overflow-x:auto`）+
    固定 7 列 1.6em 网格，窄屏水平滚动。
  - CSS 以 `<style>` 元素随视图返回（`HEATMAP_CSS`）：绿色 rgba 五档在深浅主题下
    都成立，健康色走主题变量（`--warning-color`/`--error-color-high` 等）；
    不新增静态资源 URL，避免旧脚本配新 CSS 的缓存组合（T10.12 同因）。
  - `refreshConfig` 的 unchanged 比较加入 `heatmapCfg`；开关变化立即重置状态并
    `loadHeatmap()`（关→清卡，开→立刻重读）；`readSwitchConfig` 同步读取该字段。
- `common.js`：METHODS 表加入 `stats_history: ['days']`（`ap.call` 白名单；docs/10
  规定页面不得自行 `rpc.declare`）。这是消费 T12.5 API 的必要前端声明——T12.5 只加了
  插件与 ACL，本卡补齐后同时修复了 `static.test.js`「ACL 与前端方法一致」自 T12.5
  起的既有失败（任务卡允许改动清单未列 common.js，属为满足卡内「`ap.call('stats_history')`」
  要求的最小前端改动，理由记入 docs/10 第 7 条）。
- `po/zh_Hans/aether-proxy.po`：新增 16 条（使用热力图、周一…周日、暂无数据、
  读取使用历史失败（%s）、代理流量 %s、健康占比 %s、观测时长 %s、%s 秒/分钟/天；
  「%s 小时」已存在复用）。
- `tests/luci/static.test.js`：PLUGIN_METHODS 补 `stats_history: ['days']`。
- `docs/10-cli-luci.md`：新增「B25：概览页使用热力图」小节（开关与调用、失败/空态、
  网格、颜色与健康度、tooltip、内联样式与窄屏、common.js 方法表）。

## 决定与理由

- **网格行数跟随数据跨越的周数（而非固定 13 行）**：任务卡写「最多 13 行」且
  「历史不足 90 天只画已有日期」——新装 3 天数据画 12 行空白周不是「只画已有日期」；
  取数据最早/最新条目所在周之间的行，超过 13 周截掉更早的。
- **读取节奏 TTL 10 分钟 + 跨天立即**：历史按天粒度变化，不进 5 秒轮询（docs/10
  明确 stats_history 不参与轮询）；10 分钟一次对当天的 observed/healthy 累计仍有
  可见的刷新，跨天检测保证新日期格及时出现。不传 `days`，用后端默认 90。
- **`enabled:false` 应答隐藏整卡**：后端读的是已应用配置，与页面 UCI 快照可能不同
  （高级页改开关未应用时页面 UCI 已是 `'1'`）；以后端为准比显示「暂无数据」诚实，
  且 UCI 再次变化时（refreshConfig）会立即重新评估。
- **健康档不用平滑阈值**：`healthy==observed` 才算 ok、部分不健康一律 warn 边框、
  全不健康 bad+角标——任何一次不健康时段都如实标记，避免 0.98/0.99 这类拍脑袋
  阈值；视觉上是细内边框，不干扰流量主色。
- **CSS 内联在视图里**而非独立 .css：卡片允许「可选新增静态资源」，但独立 CSS 文件
  经 `L.resource` 引入没有 LuCI 的 `?v=` 版本参数，正是 T10.12 要对抗的升级后旧缓存
  问题；随视图脚本走版本参数则不可能出现脚本/CSS 新旧错配。
- **错误不弹全局横幅、warn 只记一次**：失败每 10 分钟自动重试，全局通知会反复打扰
  （「失败显示简短错误…不刷日志」）；横幅只留给 status 这类主链路失败。
- **允许清单外的 common.js 一行声明**：见实现节；不改后端、不改 API 语义、ACL 不动。
