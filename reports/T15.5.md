### 关键实现边界

- 需求来自实际发布的 `chinadns.conf` 与 `xray.json`，没有读取 UCI 或重新选择 tier。TPROXY 始终保留；只加入 DNS 实际引用的端口和协议，普通远程/私有端点不受本门管理。
- child PID 固定；stat 的 starttime 在首个可验证采样固定，之后身份丢失/变化立即失败。初次 proc 不可读只算 not-ready，不据此报 ready。每次成功前均核对同一个 child PID/starttime、该网络命名空间的表和其 FD inode；不跟随 respawn。
- TCP 必须 LISTEN，UDP 必须绑定；IPv6 `::1` 不冒充 IPv4。IPv6 通配 TCP 额外做同预算内、无 payload、仅 loopback 的非阻塞 IPv4 连接，且排除其他监听 inode 替它响应；UDP 不以未经证实的 IPv6 通配绑定通过 IPv4 要求。
- 每次 wait 共享 5 秒单调 deadline，派发真实信号；每轮、成功前及超时尾部检查停止意图。没有外网或 DNS 请求，没有上游应答门槛。
- 保留 DNS → dnsmasq → 原 resolve_node → Xray 的顺序、degraded 无 Xray 分支、tier/LKG/fail_open/T15.1 语义；不创建 bootstrap child，不接 B1，不宣称 B3 或真机 SERVFAIL 窗口已经修复。

## 测试证据边界与既有夹具修改原因

### 真实 socket 与 proc fixture 严格区分

1. `run.py` 的 W1–W6/W10 主体：真实 TCP/UDP loopback bind、真实 PID/starttime/FD inode、真实 `/proc/PID/net`、真正发送 SIGTERM；实际判断始终由新 ucode 模块完成。没有真实 Xray 进程，也不依赖 DNS 上游应答。IPv6 dual-stack 是真实内核 listener 行为回归，不冒称 Xray 真机验收。
2. 同一脚本后半段明确标注 `proc fixture`：稳定构造非 LISTEN TCP 状态、不可读 FD、坏行、starttime 重用。PID、socket 表、FD 全部在同一个 ctx.root 下，绝不借用宿主表补齐。
3. `lifecycle.py`：真实 daemon/reload/monitor/supervise 动作与真实停止信号，但 socket 与归属为 **合成 proc fixture**。只在模块副本里加速 IP 刷新调度、注入一次 state 写失败，不替换 readiness、renderer、tier 或 rollback。W7–W9 不是实际 Xray socket 测试。

### 逐项既有夹具修订

- **`tests/stubs/daemon-bin/xray`**：旧 stub 只在全局 tcp6 写一条 inode=0 的 TPROXY 行，无法证明本次 child 归属。现从实际配置生成每个 tunnel 的协议、端口、地址，结合本次 PID/stat 和合成 FD inode，放在该 child 的 proc/net 中；旧全局 tcp6 行仅继续供原周期 health 测试使用。默认行为模拟 Xray 自身会创建的 inbounds，不代表 DNS 已能应答。`xray-dns-delay` 先发布 TPROXY 再延迟 DNS，`xray-dns-missing-port` 永不发布指定 DNS socket；新场景真实经过等待和失败，未用 ready marker 掩盖它们。
- **`tests/daemon/stop-state.py`**：旧断言要求停止后整份 calls.log 一字不变，隐含“必须继续等到 listener 超时才开始 shutdown”。新门取消后可立即清理，所以允许既有 shutdown 命令，仍逐项阻止 scheduled/curl/Xray/DNS 新启动，且保留所有 stopping 字段与最终 stopped 断言。长窗口继续检查不会出现迟到成功回写。
- **`tests/bootstrap-dns/suite.py`（Q11）**：B1 当时冻结 daemon/reload/monitor 整文件，B2 任务必需修改这些文件。现在比较三个文件中原 `apply.resolve_node(...)` 调用行及参数完全不变，并拒绝 explicit resolver/bootstrap 的接入；dns_test 仍逐字节冻结。原 resolve_node 内容比较依然保留。另一个原有边界假设只适用于 B1 合并前 main：合并后 main 已含 explicit helper，旧截取把 helper 算入 old 函数；两侧现在同样在 B1 注释边界截止，保留旧 main 的 fallback 截点。`git diff main -- apply.uc` 为空，是本次发现的夹具假失败而非改 B1 实现。
- 其他 daemon/reload/monitor/schedule 夹具未修改，直接在增强后的共享组件 stub 上通过；不更新任何 golden。
