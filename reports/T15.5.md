### 关键实现边界

- 需求来自实际发布的 `chinadns.conf` 与 `xray.json`，没有读取 UCI 或重新选择 tier。TPROXY 始终保留；只加入 DNS 实际引用的端口和协议，普通远程/私有端点不受本门管理。
- child PID 固定；stat 的 starttime 在首个可验证采样固定，之后身份丢失/变化立即失败。初次 proc 不可读只算 not-ready，不据此报 ready。每次成功前均核对同一个 child PID/starttime、该网络命名空间的表和其 FD inode；不跟随 respawn。
- TCP 必须 LISTEN，UDP 必须绑定；IPv6 `::1` 不冒充 IPv4。IPv6 通配 TCP 额外做同预算内、无 payload、仅 loopback 的非阻塞 IPv4 连接，且排除其他监听 inode 替它响应；UDP 不以未经证实的 IPv6 通配绑定通过 IPv4 要求。
- 每次 wait 共享 5 秒单调 deadline，派发真实信号；每轮、成功前及超时尾部检查停止意图。没有外网或 DNS 请求，没有上游应答门槛。
- 保留 DNS → dnsmasq → 原 resolve_node → Xray 的顺序、degraded 无 Xray 分支、tier/LKG/fail_open/T15.1 语义；不创建 bootstrap child，不接 B1，不宣称 B3 或真机 SERVFAIL 窗口已经修复。

### 本轮逐项既有集成夹具调整原因

| 夹具文件 | 本轮调整原因 |
|---|---|
| `tests/daemon/run.sh` | 每个 daemon sys-root 显式有自己的 ELF metadata，旧延迟/缺失监听场景原样保留。 |
| `tests/daemon/start-stop.py` | 生命周期 fixture 需要自己的 ABI 来源，含 reload/清理和故障场景。 |
| `tests/daemon/stop-state.py` | 补 metadata；另将保留字段比较的基准采样移至 busy 阶段已被 hold、紧邻 TERM 前。首轮重跑发现原读法可能取到启动后的首次 monitor sample 之前的状态；仍逐字段严格相等，不放宽写屏障。 |
| `tests/daemon/version-gate.py` | 共用 fixture 的正常启动也需 metadata，连同引用此 fixture 的 config-recovery/missing-events 测试一起覆盖。 |
