## 原因与实现依据

先执行 `node --test tests/luci/form-defaults.test.js` 的复现用例，当时尚未实现共用模块：

```text
✔ T10.54 reproduction: SDK Flag saves both untouched DNS defaults
1 passed, 0 failed
```

替身以 SDK 24.10.8 的 `FlagValue.formvalue/parse` 行为编写：未改动时读到显示的 `0`/`1`；parse 不比较 cfgvalue。两个选项均为 `rmempty=false`，原实现因此依次调用：

```text
set aetherproxy dns direct_dns_enabled 0
set aetherproxy dns allow_china_fallback 1
```

SDK `AbstractValue.parse` 对列表则比较原始 cfgvalue 与默认列表显示值，原项缺失时也会写入；可选空 Value 还会调用 remove。共用模块先比较生效值/显示值，但无效输入与必填空列表仍交还 SDK；真正发生修改时才使用原 write/remove。

额外保留的既有行为：

- `ucisection` 覆盖由原 SDK writer/remover 处理，避免高级页写错段。
- 不活动的传输/安全层字段按 docs/05 保留；`host.udp`、`node.mux` 只有与直连/Vision 冲突且确实存着启用值时才沿 SDK 路径删除。显式禁用默认值不因此删除。
- 可信 DNS 裸 IP 与 `tcp://IP` 的等价比较不改变原存储；UDP 仍与 TCP 区分。
- MAC 的 scalar 与单元素列表等价，避免未命名规则在不改保存时误补名称；改了设备的编辑框仍调用原命名逻辑。
- placeholder 的后端默认值与显示输入分开；缺省时输入当前生效默认值也无写入。UA 和 VMess method 的 fallback 分别按当前版本/协议求值。

- SDK LuCI 源码仅只读参考；Xray 使用 `/workspace/openwrt/ci-spike/tools` 的现有缓存，没有下载和改写其他仓库。
- 没有 git push；所有提交在本卡分支，提交消息无 AI 署名尾注。
