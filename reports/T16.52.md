## 实现

- `.github/workflows/release-component.yml`：`merge-multiple: false`，调用唯一生产入口
  `python3 tools/release/collect_component.py --artifacts artifacts --output assets --component "$COMPONENT" --version "$VERSION"`；
  收集成功后再运行 `sha256sum --check SHA256SUMS`。原有 `gh release view "$tag"` 拒绝覆盖守卫保留。
- `tools/release/collect_component.py`：严格核四个 artifact 名字；每槽恰一件包，索引文件可存在，额外包保守拒绝。
  包必须为 artifact 根目录的普通文件，读取真实元数据再核 `(component, version, arch)` 与格式。
  IPK 读取 OpenWrt tar 外壳、`debian-binary`、`control.tar.gz/control`；APK 读取 v3 ADB 包 schema，
  支持当前生产者的 `ADBd` raw-deflate 与未压缩 `ADB.`，检查 block、object、blob 类型/边界。
- APK 字段与结构已对照 apk-tools 3.0.5 官方源码 commit
  `b5a31c0d865342ad80be10d68f1bb3d3ad9b0866` 的 `src/adb.h`、`src/adb.c`、`src/apk_adb.h`：
  `PKG_PKGINFO=1`，`PI_NAME=1`、`PI_VERSION=2`、`PI_ARCH=5`，blob 类型 8/9/10，对象类型 14。
  本次仅下载这三个小型源码文件至 `/tmp/t1652-*` 只读核对；未下载 SDK 或构建工具链。
- 同名 APK 保存在不同输入目录；输出附架构一次，已有正确后缀不再附加。IPK 保留既有命名；
  全部身份、输出碰撞及规范名通过后才建立同父目录隐藏 staging，写四包、生成 manifest，逐件重读哈希，最后原子 rename 为 `assets/`。
  输入失败不产生 `assets/`；暂存失败会清理 staging；已有输出目录直接拒绝且不修改它，工作流非零即停止，不执行发布步骤。

## 红灯与负例

所有下列负例由生产 CLI 返回 1，在任何上传/创建 Release 之前失败；除已有目录拒绝覆盖用例保留原文件外，均断言 `assets/` 不存在且无隐藏 staging 遗留。

| 用例 | 注入 / 期望 | 实际 |
|---|---|---|
| 缺槽 | 删 24.10.8/x86_64 artifact；期望四槽 | artifact slots 不匹配，exit 1 |
| 槽内缺包 | 删上述槽 IPK；期望一件 | got 0，exit 1 |
| 同槽重复 | 增加另一 IPK；期望一件 | got 2，exit 1 |
| 错组件 | 文件名仍 xray，包内改 chinadns-ng；IPK/APK 各测 | expected metadata / actual 不同，exit 1 |
| 错版本 | 包内改 99.0-r1；IPK/APK 各测 | expected metadata / actual 不同，exit 1 |
| 错架构 | x86_64 槽包内改 aarch64_generic；IPK/APK 各测 | expected metadata / actual 不同，exit 1 |
| 错格式/槽 | IPK 槽扩展名改 APK；另将真实 IPK bytes 放入 APK 文件 | wrong format / expected APK v3，exit 1 |
| 输出碰撞 | ARM IPK 包内身份正确，却与 x86 IPK 输入同名 | output name collision，exit 1 |
| 重复架构后缀 | APK 带 `_x86_64_x86_64` | invalid output name，exit 1 |
| 额外槽 | 增加 25.12.5/all artifact | artifact slots 不匹配，exit 1 |
| 损坏包 | 非包字节；APK 越界 root offset / 截断 deflate | 解析失败，exit 1 |
| 覆盖输出 | 已有 assets/sentinel | exit 1，旧字节与目录内容不变 |

正例另测 APK 已有后缀只出现一次、未压缩 ADB，以及既有 DNS/ChinaDNS-NG 两组件（版本是测试输入，不修改 Makefile）。
工作流契约测试确认实际调用受测入口、显式保留目录、校验 manifest、收集在创建 Release 前且旧 Release 守卫仍存在。

旧版失败证据由 `test_old_merged_layout_red` 实际运行旧 shell 循环：4 件输入在 merge=true 后变成 3 个文件
（两个同名 APK 仅余 1 个），旧循环枚举 `packages-*` 子目录得到 `0`，`[ "$count" -gt 0 ]` exit 1。
这同时证明修目录布局还不足以消除覆盖风险；四槽与输出名必须一起验证。

## 未验证边界与禁止操作

未跑在线 SDK 四架构构建、GitHub artifact 服务、真实 `gh release create`、设备安装或通道操作；仅离线输入证明上传前收集门禁。

解析器不是完整包管理器：不验证 APK 签名、安装脚本、payload 可执行性/依赖；不支持 APK v2 或未知压缩方式（失败关闭），
也不从目录名推导本不存在于包内的 SDK 字段。SDK 归属由现有上传契约决定，格式及包内架构另行交叉核对。
本入口以 GitHub 单 runner、独占输出路径运行；不承诺两个进程并发争用同一输出路径时的 no-clobber（exists 与 POSIX rename 间存在竞态）。
已有 Release 的禁止覆盖由保留的 gh 守卫负责。blob16/blob32 和扩展 ADB 块已按源码实现边界检查，但本次 fixture/缓存没有单独覆盖这些分支。
SHA256SUMS 证明最终发布副本与已收集字节一致，不是上游来源签名。
