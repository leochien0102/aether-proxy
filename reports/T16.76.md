## 根因分析与最小修复

旧版 `aether-proxy/src/lib/update.uc` 的 `package_update()` 在 `package_update_selected()` 已执行并返回后，再次检查 `if (budget_left() <= 0) result = incomplete();`。
当更新在准入时预算充足（如剩余 300s >= 180s），并在已准入的安装/校验/回滚事务期间跨过 `chain_deadline` 后，外层返回路径会丢弃 `package_update_selected()` 返回的真实结果并覆写为 `BRIDGE_INCOMPLETE`：

- 已完成的安装成功被改报为失败（`BRIDGE_INCOMPLETE`），否认已提交事务；
- 已完成的安装/校验失败被改报为 `BRIDGE_INCOMPLETE`，丢失原 `code`、`detail` 与 `rolled_back` 等回滚信息。

最小修复（`aether-proxy/src/lib/update.uc`）：

- 移除 `package_update()` 在 `package_update_selected()` 返回后的 `if (budget_left() <= 0) result = incomplete();` 覆写，直接保留已返回的结果并在退出前清空 `chain_deadline = null`；
- 保留 `package_update()` 入口的 `if (budget_left() <= 0)` 拒绝逻辑（并在早退前清空 `chain_deadline = null`），以及 `install_target()`、`install_with_rollback()`、`prerequisite_prepare()`、`update_companion()`、`continue_chain()` 既有的 180 秒准入门禁与回滚/刷新语义。

## 回归测试设计

`tests/update/walker-outcome.uc` 复用 `tests/update/walker-postdownload.uc` 的受控单调时钟与实际生产源码加载方式，直接提取并执行 `aether-proxy/src/lib/update.uc` 的 `budget_left`、`budget_ready`、`group_failure`、`incomplete`、`install_with_rollback`、`package_update_selected` 与 `package_update` 完整外层返回路径，在 `opkg` 与 `apk` 两条路径上覆盖 3 类边界（无长 `sleep`、无真实安装、无外网/设备）：

1. `success-after-expiry`：入口剩余 300s（`clock=100`, `deadline=400`），在已准入的 `install_package()` 内时钟推进至 `401`（`budget_left=-1 <= 0`），安装与校验成功并执行 `write_updates()`。断言返回 `ok=true, exit=0, code=null`、版本号与 `rolled_back=false` 完整，记录 `UPDATE_INSTALLED` 且无 `BRIDGE_INCOMPLETE` 事件。
2. `failure-after-expiry`：同一时间边界（入口 300s、安装中跨过 `deadline`），`verify_package()` 失败触发回滚与 `activate_rollback()` 并执行 `write_updates()`。断言保留 `ok=false, exit=1, code='UPDATE_VERIFY_FAILED'`、`detail='verification failed; rolled back to 1.8.0-r1'` 与 `value.rolled_back=true`，记录 `UPDATE_VERIFY_FAILED`/`UPDATE_ROLLED_BACK` 且不改报 `BRIDGE_INCOMPLETE`。
3. `expired-entry`：入口时钟已过期（`clock=401`, `deadline=400`）。断言立即返回 `BRIDGE_INCOMPLETE`，且 `fetch_manifest`、`download_asset`、`install_package`、`write_updates` 调用次数均为 0、本机库存无变化、无 `UPDATE_STARTED` 事件。
