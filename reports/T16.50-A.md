# T16.50-A｜同时关闭服务与热力图的停服路径

## 范围与根因

- 工作树：`/workspace/openwrt/aether-proxy-wt/T16.50-A`
- 分支：`fix/m3-stop`
- 原 reload 在处理 `main.enabled=false` 前，无条件对热力图关闭执行 drain；持续锁竞争使 reload 提前失败，无法到达 `changed.stop`，daemon 仍然运行。
- 原生命周期 drain 对所有失败重试 40 次，导致解析错误及非竞争取锁错误也空等约两秒。

## 修改

- `aether-proxy/src/lib/reload.uc`：仅目标服务仍启用时，热力图停用前 drain 失败才拒绝 reload。同时关闭服务及热力图走既有 `changed.stop → monitor.stop_usage()`；旧启用 usage owner 保留至最终 checkpoint/recovery，不跳过落盘。
- `aether-proxy/src/lib/sys.uc`：保持 `lock()` 返回接口，新增 `lock_contended()`。每次取锁先复位；仅实际 `flock('xn')` 的 EAGAIN 错误置 true；mkdir/open 等失败均为 false。固定版本 ucode 的 fs API 只暴露 strerror 字符串，因此在最低层精确识别 Linux 的 `Resource temporarily unavailable`，不根据泛化的 op 或路径推断。
- `aether-proxy/src/lib/usage.uc`：取锁失败附带结构化 `retryable`，供 daemon 及 CLI 消费，错误文本及 `op` 保持不变。
- `aether-proxy/src/lib/monitor.uc`：仅 `retryable === true` 执行最多 40 个 50ms 事件循环片段；解析、写入及其他取锁错误立即返回，停服仍尝试恢复文件。
- `tests/daemon/usage-lifecycle.py`：扩展至 11 场景，仅私有生产模块副本观测 flush 次数及采样输入，不代调生命周期或手工 flush。

关键生命周期断言：

1. **单次 HUP 同时关闭两项配置**：真实 daemon；独立 quota writer 在真实 sidecar flock 内暂停；持续持锁直至 daemon 实际退出。进程退出 0 且最终状态 stopped，不依赖第二次 HUP 或 TERM。
2. **完整待写日表**：恢复文件 schema=1、mode=0600，无 quota 快照、无临时残留；`2026-11-18=(tx=200,rx=60,observed=2,healthy=2)`，`2026-11-19=(7,3,1,1)`。停服事件暴露恢复路径。
3. **重启合并**：daemon 退出后才释放 quota writer；重新启用并启动，精确保留最新 quota `{bytes:123000000000,set_at:177}` 及上述两日数据；成功恢复后移除 pending。
4. **恢复文件也写失败**：真实创建 `usage-pending.json.tmp.<pid>` 目录制造 exclusive-create 失败；同样单次 HUP 同时关闭配置，进程非零退出，明确记录 `FS_FAILED op=usage_recovery`，不伪称恢复成功，原账本不变。
5. **仅关闭热力图失败**：保持原断言并显式确认失败后旧启用 snapshot 继续采样；释放锁后的后续 HUP 能成功停用。
6. **非瞬时失败**：真实损坏 JSON，以及 sidecar 为目录引发 EISDIR（避免 root 环境下 chmod 无效）；各自仅一次生命周期 flush，不进入两秒循环，仍保存完整 pending。最终运行各约 0.114 秒；其他 teardown 开销不属于锁等待预算。
7. 原 TERM 短锁自动重试、持锁恢复、停用短锁原次 HUP 自动完成、跨日 checkpoint 与无脏数据不重写均继续通过。
