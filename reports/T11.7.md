## 实现

1. `push.tags: ['v*']` 与无额外输入的 `workflow_dispatch`；普通分支 push / PR 不触发。
   手动运行选择已有 tag/ref，不再输入 version；分支 ref 在第一步明确拒绝。
   版本只取 `github.ref_name` 去掉首个 `v`，如 `v0.6.2-r1` → `0.6.2-r1`。
   tag 必须是安全版本名，防止 notes 路径/参数注入。
2. 读取公开 channel-stable 的 `manifest.json`，仅当
   `packages['aether-proxy'].current.version` 精确匹配版本时继续。
   默认每 60 秒轮询，以 Bash `SECONDS` 计算 5400 秒等待预算；单次请求超时受剩余预算约束。
   job 总超时 105 分钟，为后续下载与上传保留时间。超时输出最后失败原因。
3. 从匹配的 manifest 快照选择 aether-proxy、luci-app-aether-proxy、
   luci-i18n-aether-proxy-* 的全部架构 ipk/apk；aether-xray 仅
   aarch64_generic / x86_64 的 ipk/apk。不选 previous、其他包、data、manifest 或 signature。
   必需包/架构/格式缺失则失败，不静默上传不完整集合。
4. URL 只允许安全的裸相对文件名；拒绝绝对路径、目录、`..`、URL、查询串、
   百分号编码、反斜杠、换行等。要求扩展名和包名前缀匹配，sha256 必须为 64 位十六进制。
   下载后逐个校验 sha256；所有文件校验通过之后才操作 Release。
5. 仅使用 `${{ github.token }}`（仓库 GITHUB_TOKEN），`contents: write`，没有 PAT / 跨仓库 secret。
   `gh release view` 查询；不存在则 `gh release create --verify-tag`，存在则复用；
   上传使用 `gh release upload --clobber`。同 ref concurrency 串行，重复运行可覆盖同名资产。
6. 新建 Release 时优先 `docs/releases/<version>.md`；否则生成通用说明，包含
   先 aether-xray 后应用/LuCI/i18n、ipk/apk 不混用、ARM64 / x86_64 映射及 all/noarch 说明。
   已存在的 Release 不改 notes。
7. 错误分别标明 manifest 未出现（含无效 manifest）、版本不匹配、下载失败、hash 不符、
   Release 创建失败、Release 上传失败；所有 Bash run 块均以 `set -euo pipefail` 开头。

workflow 本身只使用 ubuntu runner 的 Python 标准库、curl、sha256sum、gh。

覆盖：

- YAML 解析、触发器、权限、无 version 输入、60 秒/5400 秒常量、无 secret 引用。
- 对全部 4 个 run 块执行 `bash -n`，检查严格模式。

- fake manifest：先未出现、再旧版本、最后匹配；断言中间等待两次。
- 未出现超时、版本不匹配超时、无效 JSON 结构分类。

- 下载失败、hash 不符不调用 gh；创建失败不上传；上传失败有独立错误。
- 自定义 notes / 通用 notes；执行两次只创建一次、上传两次且保持同一资产集合。

所有测试在临时目录运行，`gh` / `curl` / `sleep` 全由 fake 可执行文件替代；

没有实际等待 90 分钟；生产等待常量与 Bash deadline 控制已做静态检查。
未执行真实 GitHub Actions / 下载 / Release 发布，这是本任务明确的安全边界。
