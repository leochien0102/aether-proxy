### 测试实现与变异验证

- PATH 集成测试只链接 `sh`、`mktemp`、`sleep`、`rm`、`cat`、`curl`、`sha256sum`、`sed` 和宿主机 usign 到隔离目录，直接调用宿主机 ucode 二进制；不把宿主机 `/bin`、`/usr/bin` 或仓库公共替身目录加入被测 PATH，不会误用真实包管理器。
- 每个包管理器包装替身先记录 `$0` 和参数，再执行仓库已有替身。相对和空 PATH 项可区分「显式绝对路径调用」与「重新使用裸命令名」，不仅检查查找成功。
- PATH 完全为空/未设置的默认路径测试读取实际 `package_manager()` 函数体，使用 `loadstring()` 和假的 fs 调用该私有函数；假 fs 仅允许 `/bin/opkg`，检查先探测 `/usr/sbin/apk` 并最终找到 `/bin/opkg`。这样不要求宿主机安装 opkg、不改宿主机目录，也不为测试新增生产导出。其余 PATH 场景都调用真实 `update check`/`update package`。
- 临时把 `installed_version()` 和 `install_package()` 改回原来的裸命令名/重拼 `--bin-dir` 路径调用方式，执行更新测试，预期退出码 1，实际 `153 passed, 3 failed`；相对 PATH、空 PATH 项及安装绝对路径断言均失败。随后恢复实现，重新执行两项卡上测试，得到上表的全通过结果；变异未提交。
