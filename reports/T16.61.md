## SDK 默认 `postinst` 与本包钩子对照

对照本地 OpenWrt/LuCI SDK 中的 `/workspace/openwrt/openwrt-actions/shared/feeds/luci/luci.mk`（第 239-248 行）：

```makefile
ifndef Package/$(PKG_NAME)/postinst
define Package/$(PKG_NAME)/postinst
[ -n "$${IPKG_INSTROOT}" ] || { \
	rm -f /tmp/luci-indexcache.*
	rm -rf /tmp/luci-modulecache/
	/etc/init.d/rpcd reload 2>/dev/null
	exit 0
}
endef
endif
```

同时核对 `/workspace/openwrt/openwrt-actions/lede-src/include/package-ipkg.mk`（第 164、254-260 行）：

- `$(eval $(call BuildIPKGVariable,$(1),postinst,-pkg,1))` 会将自定义 `Package/$(PKG_NAME)/postinst` 写入 `CONTROL/postinst-pkg`；
- 打包框架另外独立生成 `CONTROL/postinst` 入口调用 `default_postinst $0 $@`，由 `default_postinst` 在内部执行 `postinst-pkg`。因此自定义钩子不得重复调用 `default_postinst`（不重开已撤回的 H9）。

对照结论：

| 项目 | `luci.mk` 默认 `postinst` | 基线 `73c85241` 本包 `postinst` | 本卡修复后 `postinst` |
| --- | --- | --- | --- |
| 离线构建保护 | `[ -n "$${IPKG_INSTROOT}" ] \|\| { ... }` | `[ -n "$${IPKG_INSTROOT}" ] && exit 0` | 保留 |
| 菜单索引缓存清理 | `rm -f /tmp/luci-indexcache.*` | 缺失（被 `ifndef` 屏蔽） | 补回 `rm -f /tmp/luci-indexcache.*` |
| 模块缓存清理 | `rm -rf /tmp/luci-modulecache/` | 缺失（被 `ifndef` 屏蔽） | 补回 `rm -rf /tmp/luci-modulecache/` |
| `rpcd` 刷新 | `/etc/init.d/rpcd reload 2>/dev/null` | `[ -x /etc/init.d/rpcd ]` 后 `reload`，失败打印 `rc=$$?` 到 stderr 且退出 0 | 保留原逻辑（无 `restart`，无 `2>/dev/null` 或 `\|\| true`） |
| `postrm` | 未定义 | 仅在线 `rpcd reload` | 不改动（不扩展到卸载） |

### 修复后 `Package/luci-app-aether-proxy/postinst` 全文

```sh
#!/bin/sh
[ -n "$${IPKG_INSTROOT}" ] && exit 0
rm -f /tmp/luci-indexcache.*
rm -rf /tmp/luci-modulecache/
if [ -x /etc/init.d/rpcd ]; then
	/etc/init.d/rpcd reload || echo "luci-app-aether-proxy: rpcd reload failed (rc=$$?)" >&2
fi
exit 0
```

- 缓存不存在时，`rm -f /tmp/luci-indexcache.*`（POSIX `sh` 下未匹配通配保持字面量，`rm -f` 静默返回 0）与 `rm -rf /tmp/luci-modulecache/` 均返回 0 且无 stderr 输出。
- 仅清理 LuCI 框架指定的两项缓存，不触碰 `/tmp/luci-indexcache`（无后缀）或其他无关文件/目录。
- `IPKG_INSTROOT` 非空时在首行直接 `exit 0`，不碰宿主缓存也不调用 `rpcd`。

## 隔离测试与同用例旧红新绿证据

`tests/rpcd/run.sh` 是仓库既有包钩子测试位置（原 T16.11 在此提取 `postinst`/`postrm` 并用 stub 验证）。本卡将其路径隔离扩展为独立临时根 `$T/root-$hook`：

- 先将 `/tmp/` 替换为 `$hook_root/tmp/`，再将 `/etc/init.d/rpcd` 替换为 `$hook_root/etc/init.d/rpcd`；
- 静态断言替换 `$hook_root` 后的脚本文本不含任何残留宿主 `/tmp/` 或 `/etc/` 路径，保证测试绝不在宿主真实 `/tmp` 或 `/etc` 上执行清理；
- `rpcd` stub 改为追加写入 `>>"$T/reload.log"`，并用 `wc -l` 精确校验调用次数（在线场景为 `1` 次，离线场景为 `0` 次）；
- 支持 `AETHER_PROXY_TEST_LUCI_MAKEFILE` 环境变量，便于用同一套用例直接复跑基线 `73c85241` 的 `Makefile`。

## 未验证边界

1. **源码钩子测试不等同于真实 ipk/apk 打包及真机验收**：本卡在宿主机隔离临时根中提取并执行 `Makefile` 中的 `postinst` 钩子，离线对照了 OpenWrt 24.10 对应的 `luci.mk` 与 `package-ipkg.mk`（`postinst-pkg` 机制），未在本地运行 OpenWrt 24.10.8 (`ipk`) 或 25.12.5 (`apk`) SDK 实际打包解包核验最终产物中的脚本，也未在真机上执行 `opkg`/`apk` 升级并验证真实 LuCI Web 菜单刷新。
2. **浏览器端缓存与真机 rpcd SIGHUP**：本卡只修复服务端 `/tmp/luci-indexcache.*` 与 `/tmp/luci-modulecache/` 清理，不涉及浏览器端缓存策略，也未在真机验证 `rpcd reload` 的运行期行为。
3. **`tests/luci/run.sh` 基线既有失败**：`tests/luci/logs-r17.test.js` 的 `T10.60 scenario 4` 在基线即因缺少 `instance_lock` 中文翻译失败，本卡受范围与白名单限制未做顺手修复，需由对应后端/UI 卡处理。
