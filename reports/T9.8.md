## 宿主机两种重载的 steps

以下为最终完整串行测试一轮的实际 TRACE，单位毫秒。Xray/nft/DNS 均为隔离替身，不代表真机耗时；真机由协调者下次窗口测。

A = `n_00000000000000000000000000000001`，B = `n_00000000000000000000000000000002`。

| 字段 / 步骤 | 只改模式 gfw → bypass_cn | 切换节点 A → B |
|---|---:|---:|
| from_node → to_node | A → A | A → B |
| actions | nft_replace, restart_chinadns | nft_replace, restart_xray |
| elapsed_ms | 343 | 407 |
| steps.config_render | 91 | 103 |
| steps.resolve_node | 0 | 17 |
| steps.validate | 31 | 38 |
| steps.sets_export_render | 34 | 34 |
| steps.actions | 41 | 33 |

对应 JSON：

```json
{"from_node":"n_00000000000000000000000000000001","to_node":"n_00000000000000000000000000000001","actions":["nft_replace","restart_chinadns"],"elapsed_ms":343,"steps":{"config_render":91,"resolve_node":0,"validate":31,"sets_export_render":34,"actions":41}}
{"from_node":"n_00000000000000000000000000000001","to_node":"n_00000000000000000000000000000002","actions":["nft_replace","restart_xray"],"elapsed_ms":407,"steps":{"config_render":103,"resolve_node":17,"validate":38,"sets_export_render":34,"actions":33}}
```

`config_render` 包含读配置、必要的解析后重渲染、staging 写入和初始哈希；`resolve_node` 只统计解析；`validate` 汇总两轮校验（包括首轮前置检查）；`sets_export_render` 是导出动态集合与带集合重渲染/写 nft；`actions` 包含发布、执行、写 state 与清理 previous。elapsed 从 HUP 回调起，另包含等待 monitor、读取 current 哈希、旧产物读取、第二次哈希和规划等开销，**不保证等于五项之和**。

额外计时回归：B → A 时在 daemon 读取 current 哈希处人为等待 1 秒，事件 `elapsed_ms=1409`，steps 为 `config_render=103, resolve_node=22, validate=36, sets_export_render=32, actions=32`。断言总耗时减 steps 之和至少 900ms；如果起点错误地放到 reload.run 内，这条断言会失败。此人为延迟不用于上面的普通重载数据。

## 偏差与待定

1. **新增 TODO(design) 一处**：`aether-proxy/src/lib/reload.uc` 第二轮 `validate_nft()` 调用旁。T9.8 场景 2 写“只改模式 nft -c 一次”，但模式确实改变 nft，docs/04 和要求 2、3 明确要求首轮 nft 校验以及导出集合后再校验。实现遵循设计正文：模式/节点切换均做 **两次产物 nft 校验 + 一次前置 kernel-feature 探针**；无变化做一次产物校验 + 一次探针。场景 3 的“两次”也按产物校验计，不包括探针。未跳过原前置检查，也未为了次数修改共享 check 模块。协调者需要统一卡片测试口径；本报告不把场景 2 的字面次数伪报为完成。
2. docs/09 尚没有 RELOAD_APPLIED 目录行：按任务卡及 docs/04 的明确约定，由协调者合并时补。本卡不改 docs；新增独立的 docs/04 字段契约测试，不削弱 docs/09 的已有闸门。
3. 节点解析失败已有 apply 的 NODE_RESOLVE_FAILED，reload 保留 `START_FAILED(step=reload:resolve_node)`，没有重复记录 NODE_RESOLVE_FAILED；执行动作/回滚失败保留原 primitive 和 `reload:` 前缀事件。成功事件仅在事务成功后记录。
4. 未新增其他 TODO(design)。daemon 原有的启动清理顺序、停止锁策略和调度器 timer 分配失败三处 TODO 未改动，不在本卡范围。
5. 未在 OpenWrt/H28K 上测真实数据面、真实切换耗时和页面交互；宿主机隔离替身覆盖流程，中文渲染由 LuCI 模型测试覆盖。真机窗口由协调者负责。
