## 场景对照

脚本均为 `spikes/S15.3/probe.py`（由统一入口调用）；证据为normal/restored.jsonl。
表中断言写aether版本的原文，除E6注明外chinadns有完全相同的后缀、实际前缀为`chinadns-ng`。
每行均有双引擎scenario分类，不省略不支持项。

| 卡上的场景（编号与原话） | 测试脚本函数 | 断言名（原文） | 如何证明/会杀死什么缺陷 |
|---|---|---|---|
| E1 无列表、无集合的最小私有配置 | basic/resolve | `aether-dns E1 minimal node IPv4 from explicit private endpoint` | 真实child完整最小配置返回指定上游`.11`；只看listening或依赖列表/nft而不能解析会失败 |
| E2 正式链路缺失 | basic | `aether-dns E2 formal stand-in closed`；`aether-dns E2 node IPv4 from explicit private endpoint` | 本卡正式替身确实关闭，显式私有端点仍取得IP；接错正式端点的变异精确失败；caller系统resolver被禁止 |
| E3 boot上游选择 | basic/rendered | `aether-dns E3 renderer boot selection False`；`aether-dns E3 renderer boot selection True`；`aether-dns E3 only selected target receives` | 真实renderer展开wan，开关0/1的目标与UDP/TCP实际收包对应；固定公共DNS或选错列表会失败 |
| E4 UDP/TCP、端口和host语法 | basic | `aether-dns E4 actual transport and literal target`；`chinadns-ng E4 non-TLS host@IP rejects without stripping host` | 裸scheme/显式UDP/TCP/#port实查；两引擎host语义不同，不能静默删host；无#port仅启动接受，默认53网络行为未测 |
| E5 多上游竞争 | competition | `aether-dns E5 udp node IPv4 from explicit private endpoint`；`aether-dns E5 tcp node IPv4 from explicit private endpoint`；`aether-dns E5 one caller query creates two concurrent exchanges` | 两种顺序均快上游`.55`胜出，一问各收一次；按列表串行或只发首项会答错/计数失败 |
| E6 TLS能力边界 | tls_contract | `aether-dns E6 TLS must reject startup`；`aether-dns E6 explicit TLS diagnostic`；`chinadns-ng E6 TLS handshake and DNS query, no UDP fallback`；`chinadns-ng E6 host preserved as TLS SNI` | aether场景UNSUPPORTED，明确拒绝两种TLS配置；回退TLS1.3握手/查询和SNI通过，不能偷换UDP/TCP |
| E7 私有端口冲突及重试 | conflict | `aether-dns E7 readiness requires owned child and expected source`；`aether-dns E7 collision explicitly exits nonzero`；`aether-dns E7 retry candidate 2 of at most 10 node IPv4 from explicit private endpoint` | 占位者双协议监听不会被当成本child；失败wait后第二候选真实成功；错误接受占位者时精确变异失败 |
| E8 所有权、成功/失败/取消清理 | lifecycle/Child.close | `aether-dns E8 actual unanswered query times out`；`aether-dns E8 real SIGTERM bounded cancellation cleanup`；`aether-dns E8 stopping one does not stop other`；`aether-dns E8 external preset preserved`；`aether-dns child reaped`；`aether-dns owned temporary files removed` | 成功/启动失败/无应答/真实信号取消都收口；PID消失、UDP/TCP可重绑、本代文件消失；误清其他实例或外部文件会失败 |
| E9 child被SIGKILL后的残留 | lifecycle | `aether-dns E9 reject same-name other instance PID/config`；`aether-dns E9 SIGKILL leaves owned config`；`aether-dns E9 same-name other instance remains responsive` | 身份核对后只杀本child，真实wait返回-9，本代残留文件被清；误杀同名另一实例将无法应答 |
| E10 不接管正式DNS | basic/main/audit | `aether-dns E10 authorities receive node only, never ordinary gfw`；`aether-dns E10 handoff/intent bytes unchanged`；`E10 fixture unchanged even on failure` | 全部caller qname只有节点；fixture逐字节未变，端点/命令受约束；接入普通域名或动handoff会失败，不宣称域名ACL |

正常最小配置、成功和每种失败的完整child日志由`wait.log`保留；`socket_reusable`记录回收后双协议重绑成功。
端口占用实验只有两次尝试，建议生产分配器最多10个候选并共享deadline，不把实验写成已实现生产端口池。

## 偏差与待定

- 没有生产代码修改或TODO(design)代码占位。本卡提供契约建议，不自行冻结新产品行为。
- 初稿后复核发现authority清理顺序使慢UDP回复可能碰到已关闭transport；已改为先取消/gather全部任务再关UDP，
  保留任务结果并传播意外异常，suite额外要求正常/恢复stderr为空。完整重跑通过，原始最终证据已更新；不涉及引擎能力改动。
- aether-dns TLS：UNSUPPORTED，不转UDP/TCP；回退非TLS host@IP：UNSUPPORTED子项，真实拒绝。
- 裸IP无#port只验证启动接受；实际UDP/TCP都用动态#port，禁止探针访问宿主真实53。
- TLS默认853、证书校验、TC/CNAME追问/坏报文完整resolver未覆盖；探针只有最简A/IN，不能复制成生产查询器。
- 私有端口不接handoff不是域名访问控制，不能宣称其他本机进程不能访问。没有在bootstrap发送普通gfw请求。
- Python audit不覆盖引擎syscall；没有全量抓包/系统调用沙箱；通过literal配置与受控收包证明成功路径。
- SIGKILL实测为父进程wait收口；生产孤儿/崩溃残留需supervise负责，不能由非父进程假称wait成功。
- 本次未触发必须依赖nft/正式DNS/系统resolver或改变boot/tier/LKG/T15.1才能工作的停点。
- 未做H28K/真实procd/生产readiness与编排验收；后续查询器/readiness/编排三卡边界见设计文档。
