## 触发、顺序与时间线

- 默认关闭。仅当全局打开且当前节点未退出时，在 monitor tick 内复用 `node_reachable`，以 3 秒超时探测 `state.node_ip` 与当前节点端口。TCP 成功清零并重新武装；换节点或生效 IP 也清零。TCP 不等同于代理 HTTP 健康，也不借用 T16.12/14 的域名候选 IP 探测。
- `0 → 1 → 2 → 3` 次当前 IP 连续失败，若不在保护期则锁存本轮一次尝试；相同故障即使超过冷却也不复试。保护期内可以累计失败，期满仍失败才尝试。若本轮前置刷新已经替换 IP，不以旧 IP 的失败触发切换。
- 按已应用 UCI 的节点段顺序遍历；跳过当前、显式 `0` 与 30 分钟内试过的节点。每个候选走原解析器（含既有 LKG 兜底），解析成功再 3 秒 TCP 探测。第一个可达进入现有事务，不再试后面的候选；若预检或事务失败，保留原节点并记 WARN。
- 例：`12:00` 第 3 次失败，候选 A 拒绝、B 可达且 reload 成功，则 `12:10` 前不自动切，A、B 各从自己的尝试时刻算到约 `12:30` 才可再次成为候选。若全部失败，同样冷却 10 分钟，且必须先出现新的故障才有下一次尝试。若 `12:06` 手动成功 reload 到不同节点，则保护至少延长至 `12:16`，以成功 reload 记录与当前 `state.node_id` 一致为准。原节点自行恢复不触发回切。
- 运行时变更复用 render、Xray 预检、nft 以及 child restart/rollback。传入已探测的 IP，避免 reload 再解析出另一个未探测 IP。成功发布 `state.node_id`，没有 UCI 写入路径；重启仍从 UCI 读取用户选择。
