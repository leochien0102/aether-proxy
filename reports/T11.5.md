## 单独构建结论：本次 SDK 会自动带出核心

验证环境：OpenWrt **24.10.8 x86/64 SDK** 的隔离副本 `sdk-x86`，两个包注册为 `package/aether-proxy` 与 `package/aether-xray`，均解析为 `CONFIG_PACKAGE_*=m`（SDK 的 `CONFIG_ALL=y`）。未修改 SDK feeds 源码。

1. 首次执行 `make package/aether-proxy/compile V=s`，退出 0，实际先编译并打包核心，再生成应用 ipk。
2. 最终隔离构建目录变更后，先 `make package/aether-xray/clean V=s` 并删除核心 ipk，再只执行 `make package/aether-proxy/compile V=s`，退出 0，重新生成核心与应用 ipk；不是拿旧 ipk 当作依赖构建成功。
3. SDK 的 `tmp/.packagedeps` 实际包含：
   ```make
   $(curdir)/aether-proxy/compile += $(curdir)/aether-xray/compile ...
   ```
4. 同时分别执行双架构的 `make package/aether-xray/compile V=s`，均成功独立生成核心包。

**结论**：在本次已注册两个包、已生成正确元数据与包选择的 24.10.8 SDK 中，应用单独 compile 会自动构建核心。不能据此承诺所有未注册/未刷新元数据的构建树都能如此；文档仍提供明确构建两个包的命令：

```sh
make package/aether-xray/compile package/aether-proxy/compile
```

实际主构建树仍链接旧 channel 包，本任务未切换其链接，也未在该树上运行 compile；它当前的元数据不能代表迁入后的依赖关系。

- `sdk-arm`：官方 `openwrt-sdk-24.10.8-armsr-armv8_gcc-13.3.0_musl.Linux-x86_64.tar.zst`，校验官方 sha256sums 中的 SHA256 `5f430f5b30c9ea6dc472710356c139abf916b7ebd5de14e108e9cc204f40a2a4` 后解包，`make defconfig` 后架构为 aarch64_generic。
