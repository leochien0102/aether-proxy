## 根因与修复方案

### 根因（H7）

1. 原 `view/aether-proxy/overview.js` 的「应用」按钮无条件执行 `uci.set('aetherproxy', 'main', 'port_scope', ...)` 与 `uci.save()`，仅把 `port_scope` 写入 LuCI 会话暂存（`/tmp/.uci`），并未提交到 `/etc/config/aetherproxy`。
2. 当节点或模式同时变化时，前端随后调用 `node_use` / `mode_use`，后端 `cmd/node.uc` 以绝对路径加载已提交配置（刻意屏蔽会话 delta），只提交 `node`/`mode` 并触发一次 `init reload`；daemon 读到的仍是旧 `port_scope`，新范围丢失，同时在会话草稿中残留未提交项。
3. 当仅修改 `port_scope` 时，前端走 `ui.changes.apply(true)`，会把同一 LuCI 会话中所有无关草稿（含本包其他选项及其他包草稿）一并提交并清空，且不经过受限切换事务的预检与失败回滚。

### 修复实现

1. **CLI 受限切换事务扩展（`aether-proxy/src/lib/cmd/node.uc`、`aether-proxy/src/aether-proxy`）**：
   - `node use <id> [--mode <mode>] [--port-scope <all|common|common_extra>]` 与 `mode use <mode> [--port-scope <all|common|common_extra>]` 共用 `use_selection` / `selection_locked`。
   - 入参先校验枚举白名单与重复/缺失参数（非法返回 `USAGE`、退出码 `2`，不写 UCI、不重载）；再在隔离暂存包中仅追加实际变化的 `node`/`mode`/`port_scope` 变更（未改字段不额外写入；`port_scope` 原值未设置时按 schema 默认 `'all'` 判重），经 `sub.load_committed_config`（含 `common_extra` 下的 `extra_ports` 校验）及 `preflight_selection` 校验后原子发布，运行态下仅触发一次 `init reload`；未启用/停止态不启动也不重载。
   - 保持旧调用完全兼容：不传 `--port-scope` 时 JSON 返回字段与原有契约逐键一致；传入 `--port-scope` 时附加 `port_scope` 与 `previous_port_scope`（原值未设置返回 `'all'`），失败（含 `init reload` 非零）时保留 `committed` 与 `previous_port_scope` 供调用方回滚。
2. **rpcd 与前端声明（`aetherproxy.uc`、`common.js`）**：
   - `node_use` / `mode_use` 新增可选字符串参数 `port_scope`，在 rpcd 层按 schema 白名单校验后透传 `--port-scope`，不新增 ubus 方法，不放宽 ACL。
3. **概览页模型与视图（`model/overview.js`、`view/aether-proxy/overview.js`、`po/zh_Hans/aether-proxy.po`）**：
   - `model.switch_request` 支持 6 参（向后兼容旧 4 参），按实际变化组合分派单次 `node_use` 或 `mode_use` 请求（仅改范围复用 `node_use({ id, port_scope })`），未变化字段不传入请求参数；三项均未变化时禁用「应用」按钮。
   - `overview.js`「应用」按钮直接走 `handleNode(nodes.value, modes.value, this.portScopeSelect.value)`，彻底移除 `uci.set`/`uci.save`/`ui.changes.apply(true)`；`load`/`refreshConfig`/`readSwitchConfig` 同步追踪 `currentPortScope` 并保留未应用的下拉编辑；`rollbackSwitch` 在回滚前校验 `node`/`mode`/`port_scope` 三项归属，按返回旧值恢复并等待回滚重载结果，回滚失败时明确停在 `rollback-failed` 并保留持久横幅。
