### 「▲」浮层的时机与不再出现的确认

- SDK `validation.js` 在校验失败后设置输入框的 `data-tooltip`、`data-tooltip-style`，接着派发 `validation-failure`，原因在 `event.detail.message` 中。
- SDK `ui.js` 全局捕获 `focus`、`mouseover` 并调用 `showTooltip`；因此聚焦或鼠标悬停在带属性的输入框上，会出现 `▲ 原因`（视口底部可能换为 `▼`）。失焦或移出时调用 `hideTooltip`。
- 保存本身不是 `showTooltip` 的专用触发器；它通过 `checkDepends()` / 校验重建上述属性，之后的聚焦或悬停会让浮层出现，已显示的浮层也可能留在页面上。
- 本卡在冒泡失败事件中仅对两种添加框移除这两个属性，显示事件原文红字，并传 `{ target: input }` 给 SDK 的 `ui.hideTooltip()` 收起已有浮层。成功事件清除红字并恢复原边框。
- 场景测试从“已有浮层正在显示”开始，模拟 keyup、blur、保存校验，断言浮层收起、两个属性均不存在；再模拟聚焦和悬停，确认不会重新显示。SDK 诊断实际执行原版 Validator 和 tooltip 方法，复核同一事件顺序。其他字段仍能显示 `▲`。
- 只有被拒的 `+` / 回车及被拦的保存使用原来的 300ms 抖动；纯校验事件不抖动。成功测试直接改 `value` 后发 keyup（不发 input），确保确实由 `validation-success` 清除反馈，而非误靠输入监听器清理。
