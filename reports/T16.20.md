# T16.20 连接就绪判定修复

分支 `feat/t16.20-connect-ready`，基线 `77275ca`。

## 改动前后

`socket.poll()` 返回的是参与轮询的 fd 列表，而不是只包含就绪 fd 的列表。静默丢包时仍有一项，但 `revents` 为 0；此时 `SO_ERROR` 为 0 不能证明握手已经完成。旧实现凭 `length(polled) > 0` 继续读 `SO_ERROR`，误判为可达。

现将判定收在 `aether-proxy/src/lib/monitor.uc` 的 `connect_poll_ready(polled, sock)`，由节点探测与 daemon 共用；`net.uc` 不变。先用 `polled?.[0]?.[1] ?? 0` 取掩码，仅在非零时读取 `SO_ERROR`。没有就绪事件（包括 `poll()` 返回 `null`）均不可达。`connect()` 立即成功仍直接返回，不经 `poll()`。

| `revents` | `SO_ERROR` | 修复前 | 修复后 |
|---:|---:|---|---|
| 4 | 0 | `true` | `true` |
| 28 | 111 | `false` | `false` |
| 0 | 0（新实现不读取） | `true` | `false` |
| `polled == null` | 不读取 | `false` | `false` |

### `daemon.uc` 影响

开机网络检查的 `connect_target()` 使用同一判定。静默超时不再让该目标提前通过；它与其他失败目标一样，由上层在原总截止时间内继续检查或等待。即时成功、立即失败、poll 返回 `null`、有事件时的 `SO_ERROR` 判定和 socket 关闭均保持原行为。单 fd 的 poll 成功返回时总有一项，旧循环原本就会在首轮退出，移除数组长度分支不会改变轮询时长。每目标超时、总预算、重试机制和 monitor 的 3 秒探测超时、失败阈值、冷却均未改。

`tests/daemon/stop-state.py` 的异步停止场景需要节点刷新真的进入 Xray 重启；原夹具使用 TEST-NET 地址，在本机曾靠 TCP 超时误判走到重启。现仅让这些场景在启动后将刷新应答指向本机的临时监听端口，保留原有启动地址与停止断言。

无事件、schema、UI、`node-probe.log` 字段、LuCI、po、版本、Makefile 或 `docs/09` 变动。

## 场景对照

| 场景 | 验证方式 |
|---|---|
| 四组 poll / `SO_ERROR` 输入 | `tests/unit/connect_ready.uc` 直接调用共享函数，核对返回值；仅非零 `revents` 读取一次 `SO_ERROR`。 |
| `connect()` 立即成功 | 同一单测通过假 socket 调用 `node_reachable()`，检查直接成功、关闭 socket、不调用 poll 或读取错误。 |
| 探测目标静默超时 | `tests/monitor/driver.uc` 在 `failover-success` 的首轮观测注入 `EINPROGRESS` 和单项 `revents=0`，检查不读 `SO_ERROR`、关闭 socket，且失败计数到 1。后两轮用真实 loopback 拒绝；两轮不切换，第三轮切到可达候选并发出 `NODE_FAILOVER`。不使用真实防火墙。 |
| 既有 failover 回归 | monitor 套件保留 `failover-success`、`failover-off`、`failover-opt-out`、`failover-all-dead`、`failover-rollback` 的原有断言。 |
| daemon 开机网络检查 | 跑 daemon 套件；新的就绪判定由共享 helper 的单测覆盖。 |

真机静默丢包回归留给设计负责人：预期约 90 秒内累计 3 次失败，发出 `NODE_FAILOVER` 并切到下一可达节点；本次未操作路由器。
