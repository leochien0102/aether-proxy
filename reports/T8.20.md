# T8.20 完成报告

## 根因分析（修改实现前记录）

已在未修改实现的分支上扩展 `tests/daemon/run.sh`，令 Xray 替身每次启动延迟 1 秒再发布 tcp6 的 TPROXY 监听记录，按既有 T8.12b 场景依次切换节点和节点 IP。

实测旧实现：

```text
FAIL  probe reload: node change probes within 5 seconds
FAIL  probe reload: node change adds exactly one probe: expected '2', got '1'
FAIL  delayed reload: node change leaves no missing-listener count: expected '0', got '1'
TRACE delayed node reload: xray_down_count=1
FAIL  probe reload: IP change probes within 5 seconds
FAIL  probe reload: IP change adds exactly one probe: expected '2', got '1'
FAIL  delayed reload: IP change leaves no missing-listener count: expected '0', got '2'
FAIL  delayed reload: planned restarts never emit XRAY_DOWN_FAILOPEN
TRACE delayed IP reload: xray_down_count=2 state=failsafe
daemon: 126 passed, 7 failed
```

计数时间线：

1. 启动后为 running/T1，`xray_down_count=0`。
2. 第一次 SIGHUP 换节点：`reload.execute_action(restart_xray)` 仅等待旧进程退出，`start_child()` 仅用 PID 非空判成功，没有等待新端口就绪。`daemon.run_monitor()` 在 reload 返回后立即 `tick()`；`monitor.observe()` 读到尚未监听，`next()` 把 0 加到 1，不发 curl。
3. 替身在 1 秒后监听，但监听恢复本身不会清计数；只有下一轮 **观察到**监听才能清零。两次 reload 之间即使端口正常，没有观察就仍为 1。
4. 第二次 SIGHUP 变更节点 IP：再主动重启并立即观察尚未监听的新进程，该轮把 1 加到 2，触发 `XRAY_DOWN_FAILOPEN` 和 failsafe。因此并非新进程已经崩溃，而是跨主动重启累积了不具备就绪语义的采样。

另一个同源入口是 reload 的 `wait_stopped()` 内部调用 `uloop.run()`：周期/立即定时器可以在重载进行中重入 monitor，而当前 handler 未标记 busy。仅清计数或增加宽限时间均不能保证「新路由已应用后立即检测」。

B10 的真机原始日志不在仓库，不能断言 12:41:50 那一轮的前一轮具体来源；上述是本地确定性复现的逐轮证据，解释了同样的误报机制。

拟修复依据：沿用启动流程已有的 5 秒 TPROXY 就绪检查、双栈监听判定和 reload 失败回滚语义，让主动重启在监听就绪后才算完成；重载期间串行化 monitor。保持真实故障的连续 2 轮规则，不引入计数豁免、额外宽限期或新的阈值，不需要修改设计。如实现验证发现需要新规则则停止。

## 改动

- `aether-proxy/src/lib/monitor.uc`：共用现有 5 秒 TPROXY 就绪等待；十分钟节点 IP 刷新主动重启 Xray 时也等待监听，保持该动作持有 busy/锁。
- `aether-proxy/src/lib/daemon.uc`：启动复用同一等待函数（原有超时、轮询和停止信号处理不变）；reload 执行期间设置 busy，避免内部 `uloop.run()` 重入 monitor。
- `aether-proxy/src/lib/reload.uc`：Xray 正向重启和回滚重启均等待端口就绪，不再把 fork 成功当作路由已生效；未就绪通过原有失败/回滚路径处理。
- `tests/daemon/run.sh`：本地生成延迟 1 秒监听的 Xray 包装替身；强化既有 T8.12b 节点/节点 IP 切换用例，新增真实子进程退出的两轮故障放行与周期检测跨 reload 边界测试。
- `tests/monitor/driver.uc`：既有 failsafe 用例从计数 0 起真实执行两轮；新增节点 IP 刷新等待延迟监听的用例。
- `tests/monitor/run.sh`：为节点 IP 刷新提供仅在该测试启用的延迟替身，运行新增用例。
- `reports/T8.20.md`：根因、场景映射、变异验证及命令完整输出。

没有修改 `docs/`、共享基础设施、共享替身或 golden 期望文件。修改既有测试的原因：T8.12b 原用例用立即监听替身，不能发现 fork 与就绪的区别；monitor 原用例从人为设定计数 1 开始，不能独立证明第一轮的容忍行为。现有断言全部保留，前者使用更严格的替身，后者增加第一轮断言。
