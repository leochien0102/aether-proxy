## 1. 根因与修复摘要

1. **正向与回滚 `restart_chinadns` 过早返回并 HUP dnsmasq**：
   - 修复前，`reload.uc` 的 `start_child()` 对 `key == 'dns'` 仅检查 `child.pid() == null` 即返回成功，随后 `execute_action()` 与 `rollback_actions()` 立即执行 `apply.dnsmasq_hup(daemon.ctx)`，在目标 DNS 子进程尚未绑定监听套接字（甚至尚未完成 exec）时就向 `dnsmasq` 发送 `SIGHUP` 并宣告 `RELOAD_APPLIED`。
   - 修复后，在 `aether-proxy/src/lib/xray_ready.uc` 新增：
     - `dns_requirements(chinadns_text)`：从 `chinadns.conf` 解析并校验 `bind-addr` 与 `bind-port`（拒绝缺失、重复或非法地址/端口），生成 `[udp, tcp]` 双传输就绪要求。
     - `published_dns(ctx, child, on_signal)`：每次调用重新读取 `current/chinadns.conf`（正向读已发布配置，回滚读已恢复配置），复用现有 `xray_ready.wait(..., { label: 'formal DNS' })` 的有界等待（5s）、`uloop` 取消机制（`ctx.stopping_requested` / `SIGTERM`）、目标进程 generation（`/proc/<pid>/stat` starttime）、FD 归属（`/proc/<pid>/fd` inode）以及实际传输（UDP 非连接态 `07` + TCP `LISTEN` `0A`）判据。
   - 在 `aether-proxy/src/lib/reload.uc` 的 `start_child()` 中，当 `key == 'dns'` 时调用 `xray_ready.published_dns(daemon.ctx, child)`，未就绪直接返回 `ready.detail`，阻止正向/回滚过早 HUP `dnsmasq`。
2. **回滚 DNS 失败不可见**：
   - 修复前，`rollback_actions()` 的 `restart_chinadns` 分支仅记录 `log_failure(daemon, 'rollback_chinadns', err)`，未将错误追加到 `errors`，导致返回的 `reload` 失败详情与 `state.json` 的 `last_reload.error` 丢失回滚失败原因。
   - 修复后，与 `rollback_xray` 一致，在 `err != null` 时记录 `log_failure(daemon, 'rollback_chinadns', err)` 且 `push(errors, "rollback_chinadns: ${err}")`，并跳过 `apply.dnsmasq_hup(daemon.ctx)`，使 `START_FAILED (reload:rollback_chinadns)`、`START_FAILED (reload:actions)` 与 `last_reload.error` 均保留可定位原因。

## 4. 返工追加提交：`SIGTERM` 取消 DNS 等待不得再启动回滚 DNS

### 问题与修复
- 在 `b41fc480` 上，当正向 `restart_chinadns` 正在等待 DNS 监听就绪期间收到真实 `SIGTERM`（`daemon.ctx.stopping_requested == true`）时，虽然 `published_dns` 立即取消返回，但 `apply_plan` 进入 `rollback_actions` 后仍对 `restart_chinadns` 调用了 `start_child`，导致在停止流程中又多 fork 了第二次旧 DNS 子进程。
- 追加修复（仅改动 `aether-proxy/src/lib/reload.uc`）：
  - `execute_action('restart_chinadns')` 在 `wait_stopped(daemon.children.dns)` 后若 `daemon.ctx.stopping_requested` 为真，直接返回 `{ ok: false, detail: 'formal DNS readiness cancelled' }`，不再启动新 DNS 子进程。
  - `rollback_actions` 的 `restart_chinadns` 在 `restore_current` 恢复旧文件并 `wait_stopped(daemon.children.dns)` 停止已中断的正向子进程后，若 `daemon.ctx.stopping_requested` 为真则 `continue`，不再启动旧 DNS 子进程，也不向 `dnsmasq` 发送 `HUP`；非取消失败（`stopping_requested == false`）仍完整执行旧 DNS 重启、就绪验证与 HUP。
