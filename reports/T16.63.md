## 真实 LuCI SDK 渲染语义与验证边界

### 实际 SDK `E()` / `dom.append()` 语义依据

在 OpenWrt `luci-base` 的 `luci.js` 中，`E(tag, attr, children)` 调用 `dom.create()` → `dom.append(node, children)`（OpenWrt 24.10.8 `luci.js:1311-1335, 1504-1543`，25.12.5 同构）：

- **数组子项（`Array.isArray(children)`）**：逐项处理，对 DOM 节点调用 `appendChild(child)`，对其他任意值调用 `appendChild(document.createTextNode('' + child))`。文本节点永不经过 HTML 解析器，`<`、`>`、`&` 原样显示。
- **标量字符串（非数组、非函数、非 DOM 节点、非 `null`/`undefined`）**：执行 `node.innerHTML = '' + children`，交由浏览器 HTML 解析器解析，导致含 `<...>` 的错误文案生成真实 DOM 元素、含 `&` 的片段触发实体解码。

沿更新页状态行及同源值核对结果：

| 渲染点 | 数据来源 | 修前路径 | 修后路径 |
| --- | --- | --- | --- |
| 状态行错误 `<span>` | `vm.error`（`status.code` / `status.detail`） | 裸字符串 → `innerHTML`（漏洞） | `[ vm.error ]` → `#text` |
| 状态行通道链接 `<a>` | `vm.url`（`updates_available.url`） | 仅判 `!== '–'`，文本裸传 | 平台 `new URL()` + `http:`/`https:` 白名单；文本 `[ text ]` |
| 状态行检查时间 | `vm.checked` | 数组子项 → `#text` | 保持 `#text` |
| 状态行 `this.summary` | `model.job_result()` / 异常消息 | `textContent` | 保持 `textContent` |
| 状态行 `this.progress` | `ap.job_progress()` | `textContent` | 保持 `textContent` |
| 表格 `<td>` / 按钮 / 运行中组件 `<p>` | `vm.rows` / `model.components()` | 数组子项 → `#text` | 保持 `#text` |
