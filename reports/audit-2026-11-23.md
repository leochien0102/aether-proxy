## 2. Critical（阻断级 / 线上高危）

### C1. `aether-dns` 无界并发任务与 64 KiB 缓冲分配（FD 耗尽 & 路由器 OOM DoS）
- **位置**：`aether-dns/src/server.rs:147-218`、`aether-dns/src/server.rs:253-256`、`aether-dns/src/upstream.rs:16-38`
- **问题**：
  - 每个 UDP 包和 TCP 连接都无上限地向 `JoinSet` 派生任务；TCP 连接直接按客户端 2 字节长度头分配 `vec![0; len]`（最高 64 KiB）并最多持有 5 秒。
  - `upstream::exchange` 每次上游请求分配 64 KiB `Vec` 并新建独立 `UdpSocket`/`TcpStream`。在 `bypass_cn`（`RouteTag::None`）下单个查询并发 4 个上游（4 FD + 256 KiB）；上游卡顿 5 秒时，250 qps 即可消耗 ~5000 FD（远超 OpenWrt 默认 1024 `ulimit -n`）与 ~320 MiB 内存。
- **建议**：使用 `tokio::sync::Semaphore` 限制 UDP/TCP 并发数；TCP 请求长度限制在 `12..=4096` 字节；UDP 接收缓冲改为 4096 字节或使用有界缓冲池。

### C2. `release-component.yml` 使用 `merge-multiple: true` 导致组件发版必然失败且覆盖 `.apk`
- **位置**：[`.github/workflows/release-component.yml:57-81`](../.github/workflows/release-component.yml#L57-L81)
- **问题**：`actions/download-artifact@v4` 设置了 `merge-multiple: true`，导致所有架构产物平铺到 `artifacts/`，不再保留 `packages-<arch>` 子目录，且 `aarch64_generic` 与 `x86_64` 的同名 `.apk` 互相覆盖；随后的 `for dir in artifacts/packages-*` 匹配 0 个目录，发版必然失败。
- **建议**：改为 `merge-multiple: false`（与 [`.github/workflows/release-assets.yml:79`](../.github/workflows/release-assets.yml#L79) 一致），并强制校验 4 件资产齐全且版本匹配。

## 3. High（高危缺陷 / 生产可靠性风险）

### 3.1 `aether-proxy` 核心运行时与数据面

#### H1. 重复启动 `daemon` 在获取 `LOCK_FILE` 之前覆写 `state.json` 和 `daemon.pid`
- **位置**：[`aether-proxy/src/lib/daemon.uc:1251-1265`](../aether-proxy/src/lib/daemon.uc#L1251-L1265)（锁在 [`daemon.uc:472`](../aether-proxy/src/lib/daemon.uc#L472) 才获取）
- **问题**：若已有 daemon 运行，第二个 `aether-proxy daemon` 会先将 `state.json` 覆写为 `starting`、将 `daemon.pid` 覆写为自身 PID，随后抢锁失败退出（exit 3），留下指向已退出进程的 `daemon.pid`（破坏 `cleanup --wait` 存活判断）。
- **建议**：在写入 `state.json` 与 `daemon.pid` 之前先获取 `C.LOCK_FILE` 或校验 `daemon_alive()`。

#### H2. `aether-proxy-logfilter.awk` 丢弃路径每行 fork `/bin/sh`（进程风暴）且非原子写 `.logstats`
- **位置**：[`aether-proxy/files/aether-proxy-logfilter.awk:17-19, 42-53, 202-205`](../aether-proxy/files/aether-proxy-logfilter.awk#L17-L53)
- **问题**：放行日志每 5s/50 行才更新一次统计，但**被限流丢弃的每一行**都会调用 `write_stats()`，每次通过管道 fork+exec `/bin/sh` 并 `close()`。日志洪峰时（如带唯一 IP/端口的报错绕过相邻去重）会打满路由器 CPU；且 `> "$1"` 非原子写可能导致读取方看到空/残缺 JSON。
- **建议**：丢弃路径同样按时间/计数节流 `write_stats()`（仅在 `summary()`、`END` 及节流窗口写盘），并在 `stats_writer` 中改为写临时文件后 `mv -f`。

#### H3. 单值 `signal` 导致 `SIGHUP`（reload）/ `SIGUSR2`（xray 重启）在 `SIGUSR1` 待处理时被静默丢弃
- **位置**：[`aether-proxy/src/lib/daemon.uc:1278-1293`](../aether-proxy/src/lib/daemon.uc#L1278-L1293)
- **问题**：`signal` 为单标量，只要 `signal != null`，后续非 `stop` 信号直接丢弃。WAN `ifup` 时 [`aether-proxy/files/aether-proxy.hotplug`](../aether-proxy/files/aether-proxy.hotplug) 会同时发 `SIGUSR1` 并触发 `dns sync-wan`（发 `SIGHUP`），极易丢掉 reload。
- **建议**：改为布尔集合/位掩码（`pending.stop` / `reload` / `xray_restart` / `tick`），按优先级依次消费。

#### H4. `monitor.uc:update_node_ip()` 在校验前直接覆写运行中的 `current/` 且无回滚
- **位置**：[`aether-proxy/src/lib/monitor.uc:363-411`](../aether-proxy/src/lib/monitor.uc#L363-L411)
- **问题**：在 `xray run -test`、`load_nft` 和 `xray` 重启成功之前就用 `write_atomic` 覆盖了 `current/aether-proxy.nft` 和 `current/xray.json`。若任一步骤失败，`current/`、nft 集合与运行态将永久失步且无回滚。
- **建议**：改为在 staging 目录校验，或直接复用 `daemon.reload` 路径以获得完整校验与回滚保证。

### 3.2 `aether-proxy` 更新链路、LuCI 与打包/CI

#### H5. `apk` 环境下升级 `aether-proxy >= 1.0.0` 必报 `PREREQ_MANUAL_REQUIRED`
- **位置**：[`aether-proxy/src/lib/update.uc:220-224, 1046-1055, 1095-1116`](../aether-proxy/src/lib/update.uc#L220-L224)
- **问题**：`installed_metadata()` 在 `apk` 分支始终返回 `provides: []`，导致 `prerequisite_satisfied()` 无法识别已安装的 `dns-engine`（即使 `aether-dns >= 1.0.0` 已是最新版本）。后续进入 `prerequisite_prepare()` 时因 `aether-dns` 不在 `previous` 版本而直接失败。
- **建议**：在 `apk` 分支解析 `/lib/apk/db/installed` 的 `p:` 字段或调用 `apk info -P <name>` 填充 `provides`。

#### H6. 清单包含 `compatibility` 时提前返回 `UPDATE_UP_TO_DATE`，跳过伴生包更新
- **位置**：[`aether-proxy/src/lib/update.uc:1276-1286`](../aether-proxy/src/lib/update.uc#L1276-L1286)
- **问题**：当 `aether-proxy` 本体已在终态版本（`plan.active == false`）时直接返回 `UPDATE_UP_TO_DATE`，未继续执行 `update_together()` / `install_with_rollback()`，导致 `luci-app-aether-proxy` 或中文翻译包的待更新/重试被静默跳过。
- **建议**：移除 `if (!plan.active)` 的提前返回，仅在 `plan.active` 为真时走桥接升级逻辑。

#### H7. 概览页「应用」按钮无条件暂存 `port_scope`，且与节点/模式同时切换时 `port_scope` 不会生效
- **位置**：[`luci-app-aether-proxy/htdocs/luci-static/resources/view/aether-proxy/overview.js:1165-1182`](../luci-app-aether-proxy/htdocs/luci-static/resources/view/aether-proxy/overview.js#L1165-L1182)
- **问题**：
  1. `uci.save()` 只写入 `/tmp/.uci` 暂存区，而 `handleNode()` 调用的 `cmd/node.uc` 按绝对路径读取 `/etc/config/aetherproxy`（刻意忽略 `/tmp/.uci`），因此同时修改 `port_scope` 和节点/模式时，`port_scope` 根本不会被提交生效。
  2. 即使未修改 `port_scope`，每次切换节点都会在 LuCI 顶部留下「未保存的更改」角标。
- **建议**：仅在 `port_scope` 实际变化时调用 `uci.set`/`uci.save`，并与节点/模式切换正确联动提交（加防连点与错误处理）。

#### H8. `aether-proxy-usage.keep` 缺少前导 `/`，`sysupgrade` 保留 `usage.json` 存在失效风险
- **位置**：[`aether-proxy/files/aether-proxy-usage.keep:1`](../aether-proxy/files/aether-proxy-usage.keep#L1)（对比 [`aether-proxy/files/aether-proxy.keep:2-3`](../aether-proxy/files/aether-proxy.keep#L2-L3)）
- **问题**：文件内容为相对路径 `etc/aether-proxy/usage.json`。OpenWrt `sysupgrade` 将 `/lib/upgrade/keep.d/*` 传给 `find` 时不保证工作目录在 `/`，从 `/root` 执行 `sysupgrade` 时会匹配失败，导致 `1.2.2-r10` 刚落地的刷机保留热力图账本失效。
- **建议**：改为 `/etc/aether-proxy/usage.json`（或合并进 `aether-proxy.keep`）。

#### H9. 自定义 `Package/aether-proxy/postinst` 覆盖了 OpenWrt `default_postinst`
- **位置**：[`aether-proxy/Makefile:52-56, 74-79`](../aether-proxy/Makefile#L74-L79)
- **问题**：直接定义 `postinst` 会替代 OpenWrt 自动生成的 `default_postinst`，导致在线安装（`opkg install`/`apk add`）时既不执行 `/etc/uci-defaults/99-aether-proxy`，也不自动 `enable` `/etc/init.d/aether-proxy`。
- **建议**：改用 `Package/aether-proxy/postinst-pkg` 挂载 `fw4 reload`（或显式调用 `default_postinst`）。

#### H10. `changed-components.sh` 漏掉 `luci-app-aether-proxy`/`aether-proxy`，单包改动推送会触发 smoke 失败或误跳过
- **位置**：[`tools/ci/changed-components.sh:17-24`](../tools/ci/changed-components.sh#L17-L24)、[`.github/workflows/build.yml:8-26`](../.github/workflows/build.yml#L8-L26)
- **问题**：`smoke.sh` 要求 5 个包齐全，但 `add_smoke_companions` 只补了 `aether-xray`/`chinadns-ng`/`aether-dns`。仅改 `aether-proxy/*` 会漏编 `luci-app-aether-proxy` 导致 smoke 报错；仅改 `luci-app-aether-proxy/*` 会漏编 `aether-proxy` 跳过 smoke。同时 `build.yml` `paths` 漏掉了 `tools/ci/**`。
- **建议**：将 `aether-proxy` 与 `luci-app-aether-proxy` 加入 `add_smoke_companions()`，并在 `build.yml` `paths` 补充 `tools/ci/**`。

### 3.3 `aether-dns` 核心与集成契约

#### H11. 单线程 Tokio 运行时中执行同步阻塞 Netlink I/O（且缓存命中也触发）
- **位置**：`aether-dns/src/main.rs:34`、`aether-dns/src/nftset.rs:139-289`、`aether-dns/src/server.rs:344-392`
- **问题**：`current_thread` 运行时上通过 `std::sync::Mutex` + 同步 `libc::sendto/recv`（1s 超时）操作 netlink；每次缓存命中还会再次调用 `write_reply()` 阻塞整个事件循环。
- **建议**：将 netlink 写入下沉到专用后台线程（有界 `mpsc` 通道，附带近期已写 IP 去重），`is_china` 走 `spawn_blocking` 或专用线程。

#### H12. 上游响应校验缺失 QNAME/QTYPE/QCLASS + 可预测递增 TxID
- **位置**：`aether-dns/src/upstream.rs:62-67`、`aether-dns/src/server.rs:149-211`
- **问题**：`valid_reply` 只比对 2 字节 ID、QR 位和 `QDCOUNT == 1`，不校验 Question 段；上游 ID 从 0 顺序递增（违反 RFC 5452），易受乱序/伪造 UDP 应答污染缓存及 nftset。
- **建议**：使用加密随机 16 位 TxID，并在 `valid_reply` 中严格校验响应 Question 段（大小写不敏感 QNAME + 精确 QTYPE/QCLASS）。

#### H13. 快速 `SERVFAIL`/`REFUSED` 抢先赢得上游竞速，取消健康上游
- **位置**：`aether-dns/src/upstream.rs:62-67`、`aether-dns/src/upstream_group.rs:38-39`
- **问题**：`valid_reply` 接受任意 RCODE，`upstream_group::exchange` 取最先返回的 `Ok` 并丢弃其余上游。若某个上游故障并在 1ms 内返回 `SERVFAIL`/`REFUSED`，它会持续压死 20ms 返回正常结果的健康上游。
- **建议**：对错误 RCODE（`SERVFAIL`/`REFUSED`/`FORMERR`/`NOTIMP`）暂存为兜底结果，继续等待其他上游的 `NOERROR`/`NXDOMAIN`。

#### H14. 域名分流、应答缓存、判定缓存全部大小写敏感（RFC 1035 违规 / 分流绕过）
- **位置**：`aether-dns/src/server.rs:40-41`、`aether-dns/src/lists.rs:48-100`、`aether-dns/src/cache.rs:182-185`
- **问题**：未做 ASCII 小写归一化。大写或混合大小写查询（如 `Google.Com` 或 DNS 0x20 随机化）会漏匹配 `gfwlist`/`chnlist`/`uproxy`/`udirect`/`boot`，落入 `default_tag` 导致分流绕过，同时造成缓存分裂。
- **建议**：路由查表与缓存键统一 ASCII 小写化（返回给客户端的报文保留原始查询大小写）。

#### H15. 集成契约冲突：`aether-proxy` 允许并渲染 `tls://` 上游，但 `aether-dns` 启动时直接拒绝
- **位置**：[`aether-proxy/src/lib/config.uc:43-50`](../aether-proxy/src/lib/config.uc#L43-L50)、[`aether-proxy/src/lib/render/chinadns.uc:72-110`](../aether-proxy/src/lib/render/chinadns.uc#L72-L110)、`aether-dns/src/config.rs:200-209`
- **问题**：`aether-proxy` 校验放行 `tls://` 并写入 `chinadns.conf`，但 `aether-dns` 在 `validate_startup()` 中硬编码拒绝 `tls://`（`Err("tls:// P0-conditional 未实现")`），导致预检通过后启动失败。
- **建议**：要么在 `aether-dns` 实现 DoT，要么在 `aether-proxy` 选择 `aether-dns` 引擎时前置拦截 `tls://` 并给出明确提示。

## 5. Low（低危 / 工程卫生与文档漂移）
