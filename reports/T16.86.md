# T16.86 · 分享链接导入：拒绝节点字符串字段中的控制字符（M13 第二部分）

## 范围与基线

- 工作树：`/workspace/openwrt/aether-proxy-wt/T16.86`
- 分支：`fix/t16.86-import-controls`
- 基线：`598031e5`（`main`）
- 修改文件：
  - `aether-proxy/src/lib/uri.uc`：
    - 新增基于 `ord()` 逐字节扫描的 `has_control_chars()`、`value_has_control_chars()` 与 `node_has_control_chars()`（不依赖在 `NUL` 处截断的 POSIX 正则，且 UTF-8 多字节序列均 `>= 0x80`，不会误伤中文/emoji 或普通空格 `0x20`）。
    - 在公共入口 `parse_line()` 先只裁剪首尾普通空格 `trim(line ?? '', ' ')` 再校验原始字节，拒绝包含 ASCII C0（`0x00`–`0x1f`）或 DEL（`0x7f`）的输入（不把尾部 `\r`/`\n`/`\t` 静默删掉后接受）。
    - 在 `url_decode()` 逐字节检查原始字节与百分号解码结果，拒绝任何 `< 0x20` 或 `== 0x7f` 字节。
    - 在 `decode_base64()` 先拒绝包含 `\x00` 的输入，避免 `replace()` / `match()` / `b64dec()` 在 `NUL` 处静默截断；在 `parse_vmess()` 拒绝解码后 JSON 中含原始 `\x00` 与含控制字符的 `port`，在 `split_userpass()`、`parse_ss()` 旧式整体 Base64 及 `parse_new_protocol()`（SOCKS/HTTP）Base64 userinfo 解码后立即拒绝控制字符，避免 `lc()` 在 `NUL` 处截断 `method`。
    - 在所有协议共用的统一出口 `finish_node()` 中、`validation_skip()` 之前执行 `node_has_control_chars(node)`，确保任何字符串字段及字符串数组元素（如 `alpn`、`local_address`）都不含 ASCII C0 或 DEL。
    - 在 `parse_body()`、`decode_subscription()` 与 `is_clash_yaml()` 中改用 `NUL` 安全的 `split(text, '\n')` + `strip_trailing_cr()` 替代 `replace(..., /\r\n/g, '\n')`，保留订阅按 LF/CRLF 分行及合法整包 Base64 换行，同时确保单行中的原始 `NUL` 不会把整份订阅后续合法节点静默截断。
  - `docs/06-nodes-subscription.md`：在「URI 格式」补充公共边界拒绝 ASCII C0/DEL 控制字符、拒绝而非删字符或 NUL 截断、保留 UTF-8/普通空格/订阅 LF&CRLF/合法整包 Base64 换行的契约说明。
  - `tests/unit/uri.uc`：新增 43 组 T16.86 单元测试（其中 37 组单行用例亦被 `tests/node/parse.py` 自动复用于 `node parse` / `node import` 对齐校验），覆盖 `%00`、编码 CR/LF、DEL、C0、VMess JSON 转义、Base64 userinfo 控制字节、中文/普通空格、美观缩进 VMess JSON、CRLF 混合订阅、折行 Base64 订阅及全坏订阅。
  - `tests/unit/uri_controls.uc`：新增 4 组直接调用 `uri.parse_line()` 的字节级测试，覆盖无法经 POSIX `argv` 传递的原始 `NUL` 字节（label、scheme、VMess Base64 尾部）与首尾普通空格裁剪。
  - `tests/node/run.sh`：新增真实 CLI `node parse` / `node import`（JSON 与人类输出）验收断言，验证坏链接均以退出码 2、`CONFIG_INVALID` / `malformed` 拒绝，UCI 文件逐字节不变、stderr 为空、输出不回显凭据，并验证合法中文+空格标签正常写入 UCI。
  - `tests/sub/run.sh`：新增真实 `sub update` 集成断言，验证 CRLF 混合订阅与折行 Base64 混合订阅跳过坏条目并正确发布相邻合法中文+空格节点、不泄露凭据，全坏控制字符订阅以 `SUB_NO_VALID_NODES` 失败且 UCI 逐字节不变、不触发 `init reload`。
  - `reports/T16.86.md`：本任务验收报告。

## 基线字节级对照（旧实现缺陷 vs 修后行为）

在基线 `598031e5` 上用项目固定的 `tests/host/ucode` 直接执行 `uri.parse_line()` / `uri.parse_body()` 及 `uci.cursor` 复现，证实旧实现存在以下错误接受与静默截断：

| 用例（输入字节特征） | 基线 `598031e5` 行为 | 修后行为 |
| --- | --- | --- |
| `vless://<uuid>@edge.example%00.evil:443?security=tls#good%00evil` | **错误接受**：返回 `address="edge.example\u0000.evil"`（`validate_node` 的 POSIX 正则在 `NUL` 处停止而放行）、`label="good\u0000evil"`；落地 `libuci` 时静默截断为 `edge.example` 与 `good` | `{ "skip": "malformed" }` |
| `ss://aes-128-gcm%00evil:pw@ss.example:8388#ok` | **静默截断成另一合法值**：`url_decode` 解出 `aes-128-gcm\x00evil` 后被 `lc()` 截断为 `method="aes-128-gcm"` 并返回合法节点 | `{ "skip": "malformed" }` |
| `vmess://<valid_b64>\x00GARBAGE` | **静默截断成另一合法值**：`decode_base64` 内 `replace(/[[:space:]]/g, '')` 在 `NUL` 处截断，丢弃 `\x00GARBAGE` 并返回合法 VMess 节点 | `{ "skip": "malformed" }` |
| `vless\x00evil://<uuid>@edge.example:443?security=tls#ok` | **静默截断成另一合法值**：`lc(scheme)` 截断为 `vless` 并返回合法节点 | `{ "skip": "malformed" }` |
| `vless://<uuid>@edge.example:443?type=ws&security=tls&path=%2Fws%0d%0aX-Injected:1#ok` | **错误接受**：`path` 含 `0x0d 0x0a`（`2f77730d0a...`） | `{ "skip": "malformed" }` |
| `vless://<uuid>@edge.example:443?security=tls#del%7ftag` | **错误接受**：`label` 含 `0x7f`（`64656c7f746167`） | `{ "skip": "malformed" }` |
| `vmess://` JSON 含 `"ps":"ok\u0000evil"` / `"ok\nevil"` / `"ok\u007fevil"` / `"add":"vm.example.com\u0000.evil"` | **错误接受**：JSON 解码出的 C0/DEL 控制字节直接进入节点字段 | `{ "skip": "malformed" }` |
| `parse_body("vless://...@bad.example:443?security=tls#bad\x00tail\r\nvless://...@good.example:443?security=tls#good")` | **静默截断整份订阅**：`replace(/\r\n/g, '\n')` 在 `NUL` 处截断，把坏行截成 `label="bad"` 接受，并把第二行合法节点直接丢弃 | 跳过第 1 行（`skipped.malformed = 1`），正常返回第 2 行合法节点 |
