## 先测试：两处缺陷的红灯

| 基线场景 | 实测 |
|---|---|
| `tests/daemon/raw-log-burst.py`，宿主机 sh/awk | 40 条启动行全部按序入盘，后续两条每秒输出也可见；不等 EOF。 |
| 同一夹具，`RAW_LOG_BUSYBOX=1`，BusyBox 1.37.0 ash/awk | 红：每次重试只留下 `burst 00`，其余 39 条和后续 tick 都没进入 `raw.log`。 |
| daemon 夹具：`logread -f` 延迟 650 ms 才接收实时日志 | 红：xray 没等新会话就绪；模拟 DNS 启动串未落盘。 |
| `tests/cli/log-stats.py`，每秒一条新消息，不退出过滤器 | 红：6.02 秒后 `ACCEPTED` 仍是 `1`，`DROPPED` 为 `0`。 |

BusyBox awk 的 `fflush()` 执行刷新但不设置返回值。旧收集器用 `fflush("raw.log") != 0` 判断错误，能在成功落盘第一行后误退出 awk。宿主机 BusyBox 重现了这一行模式；另外用延迟订阅夹具独立复现了启动窗口。OpenWrt `logread -p` 在 `log.read` 订阅之前写 PID，不能作为就绪信号。

## 修复与复现

- `aether-proxy/files/aether-proxy-rawlog.sh` 单独调用 `fflush()`，不判断 BusyBox 未定义的返回值。用本次跟随会话读到的 syslog 探针（或真实应用实时行）确认已挂上，再写 `raw-log.ready`。探针不写入 `raw.log`；重试和退出清理标记。
- `aether-proxy/src/lib/daemon.uc` 启动收集器前清旧标记，首次启动 xray/DNS 前最多等 2 秒；若无回执则发一条 warn、继续启动。模拟延迟订阅的 18 条 DNS 启动行（7 条 `dnl_init` + 11 条 `on_start`）完整按序入盘，xray 在新握手之后启动；静默跟随场景超时告警一次且服务仍运行。无需回放；保持 `logread -f` 只读新行，不在重连时重复写历史。超时放行和日后断线期间的行不回补。
- `aether-proxy/files/aether-proxy-logfilter.awk` 保留会话起点、首条和 EOF 快照；后续每次放行时检查距上次写入 5 秒或新增 50 条，任一达到即写。丢弃计数变化及摘要仍立即写，写失败本会话自禁用。限流阈值、轮转和 CLI 输出不变。`docs/09-logging.md` 记录上述行为。

```sh
python3 tests/daemon/raw-log-burst.py
RAW_LOG_BUSYBOX=1 python3 tests/daemon/raw-log-burst.py  # 需 BusyBox 在 PATH
python3 tests/cli/log-stats.py
```

```text
PASS raw.log (host sh + awk): 40/40 ordered burst lines + two 1s ticks, live after 2.05s
PASS raw.log (BusyBox ash + awk): 40/40 ordered burst lines + two 1s ticks, live after 2.03s
T16.37 live log stats (5.02s, before EOF): 'xray\t1\t0\t-\t-\t20\t120' -> 'xray\t6\t0\t-\t-\t20\t120'
PASS stats refresh after 50 accepted rows, 5 seconds, and every drop (before EOF)
```

`log stats` 两次均读活跃会话，`ACCEPTED 1 → 6`，`DROPPED 0 → 0`。`LOG_STATS_AWK='busybox awk' python3 tests/cli/log-stats.py` 同样通过，实测 5.03 秒。

## 维护者三步命令（x86 / chinadns-ng，待执行）

1. 切到只含本次两个试用 ipk 的目录，安装后重启设备，等 `aether-proxy` 服务启动：
   ```sh
   opkg --force-reinstall install ./aether-proxy_*_x86_64.ipk ./luci-app-aether-proxy_*_all.ipk
   reboot
   ```
2. 重新登录后检查原始启动串：
   ```sh
   raw=/var/run/aether-proxy/raw.log
   grep -c dnl_init "$raw"
   grep -c on_start "$raw"
   grep -E 'dnl_init|on_start' "$raw"
   ```
   预期 `dnl_init > 0`，并看到完整、按序的 `on_start` 启动串，不再只剩 `local listen addr`。
3. 在子进程仍运行、且有新日志的情况下读两次：
   ```sh
   aether-proxy log stats
   sleep 10
   aether-proxy log stats
   ```
   预期 `chinadns-ng` 的 `ACCEPTED` 明显大于 `1`，并随新的放行日志继续增长。若间隔内没有新日志，计数无需变化。
