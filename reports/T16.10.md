## 验收
1. DOM 顺序：`h2(日志)` → `toolbar(div)` → tabs 行 → eventPanel → rawPanel。toolbar 内为按钮行（清空日志、截断到上次启动）→ toolbarError。切 tab 仅切换两个 panel.hidden 并刷新数据，不替换 toolbar 或错误区。
2. rawPanel 内为来源/行数与刷新行 → rawContent；没有清空/截断按钮，也没有操作错误区。原始日志读取失败仍按原契约在 rawContent 内显示，不与工具栏操作错误混用。
3. 两个按钮均 `cbi-button-remove`；使用既有 `ap.confirm({destructive:true})`，由公共模块的 ui.showModal 实现。进入确认即同时禁用两个按钮，取消不发 RPC，失败与成功刷新结束均恢复。
4. 调用序列（`tests/luci/logs.test.js` 中使用实际 view 与可控 RPC）：
   - 取消：confirm(false) → 无 RPC；清空与截断均覆盖。
   - 确认成功：confirm(true) → log_clear({}) 或 log_truncate({})，各恰一次 → events({})（events tab）或 log({source:'dns',lines:1000})（raw tab）。
   - 失败：确认 → 对应动作返回 FS_FAILED / NOT_RUNNING / TIMEOUT → 工具栏内单个错误 p；保留内容，不调用刷新、不弹通知；重试先清除旧错误。
   - 在截断在途期间切到 raw：log_truncate({}) → 切 tab 的 log({source:'all',lines:200}) → 动作成功时读取最新控件 log({source:'xray',lines:500})；工具栏始终同一节点。
5. 旧的 events/raw 请求即使晚于操作成功后的刷新返回，也不能重新显示已删除记录。成功时清除 lastEvents 缓存，避免后续失败回退到操作前的事件数据。
6. 新增/更新 i18n：
   - `Truncate to last startup` → 截断到上次启动。
   - `Only logs (events and raw logs) since the most recent service startup will be kept. Earlier records will be deleted. This cannot be undone.` → 只保留最近一次服务启动之后的日志（事件与原始日志），更早的记录会被删除且不可撤销。
   - `Unable to clear logs:` → 无法清空日志：。
   - `Unable to truncate logs:` → 无法截断日志：。
   - `Unable to modify logs.` → 无法修改日志。（替代旧 `Unable to clear logs.` 兜底。）
   - 两个按钮均通过 po；`Clear logs` 是复用条目，没有重复增加。
7. `git diff --check` 通过；无后端、rpcd、ACL、common/model、采集脚本、其他页面、版本、docs 或共享测试设施改动。
8. 真机验证未做：按卡由设计负责人在合并后构建安装，确认两按钮在事件页与原始日志页均可用。本卡没有操作设备或 VM。
