## 场景对照

以下断言均来自 `tests/job/run.sh`；事件断言调用 `tests/job/assert-event.uc`，严格比较字段集合，不只搜索日志中的某个字符串。

| 卡上的场景（按卡上的编号与原话） | 测试脚本 | 断言名（PASS 行的原文） | 这条断言如何证明该场景 |
|---|---|---|---|
| 1）子命令输出 `{"ok":false,"code":"USAGE","detail":"unknown subscription 's_x'"}` 退出 2 → 恰好一条 `CMD_FAILED`，含 `code: USAGE` 与该 `detail` | `tests/job/run.sh` | `usage CMD_FAILED matches exactly` | 独立日志必须只有一条 `CMD_FAILED`；核对完整命令、rc=2、空 stderr、USAGE、原始原因及 error 等级。缺详情、多记一条或字段值不对都会失败。 |
| 2）输出不是 JSON → 只有 `cmd`、`rc`、`stderr` | 同上 | `non-json CMD_FAILED matches exactly` | 替身输出 `not JSON`、退出 2，stderr 有两行；断言仅有三个基础字段，stderr 为第一行。旧代码同时记录 sys.run 和解析失败两条事件，会因数量不是 1 失败。 |
| 3）成功的作业不记 | 同上 | `success CMD_FAILED matches exactly` | 成功子命令故意也带 code/detail；等到作业为 ok 后断言整个独立日志中没有 `CMD_FAILED`。误以 code 存在就记失败会被检出。 |
| 4）原有全部测试照旧通过 | `tests/host/ucode tests/run.uc`、全部 `tests/*/run.sh` | `277 passed, 0 failed, 0 skipped`；各套件汇总见上表 | 串行执行所有 16 个套件且退出码全 0，涵盖原有 job 互斥、脱离调用者、损坏文件、JOB_LOST、清理及参数转发等断言。 |

### 额外边界与兼容性

| 检查点 | PASS 行的原文 | 证明 |
|---|---|---|
| 原始作业结果保持不变 | `usage job keeps child exit`；`usage job keeps original detail in result`；`usage job keeps terminal detail null`；`usage job keeps error code` | 作业 exit=2、error=USAGE、result.detail 原样保存，终态 detail 仍 null，不把事件摘要写回作业。 |
| 非 JSON 作业结果保持不变 | `non-JSON job keeps raw stdout detail`；`non-JSON job keeps null result` | 作业 detail 仍为原始 stdout，result 仍 null。 |
| stderr/detail 首行与 200 字符上限 | `truncated CMD_FAILED matches exactly`；`first-line CMD_FAILED matches exactly` | 220 字符和多行输入核对截断后的完整事件；短多行输入额外证明首行规则不只是长度裁剪。 |
| 截断不影响作业文件 | `event truncation leaves result detail untouched`；`event truncation leaves job error untouched` | result.detail 保留空白和后续行，error 保留完整的 220 字符字符串。 |
| code 同样有上限 | `truncated-code CMD_FAILED matches exactly` | 220 字符 code 的事件值恰为前 200 字符。 |
| 无 detail / 无 code | `missing-detail CMD_FAILED matches exactly`；`missing-code CMD_FAILED matches exactly` | 前者只附带 code，后者不附带 detail；不生成不存在的原因或码。 |
| 错误字段不是字符串 | `malformed-code CMD_FAILED matches exactly`；`malformed-detail CMD_FAILED matches exactly` | 对象类型的 code 不附带扩展字段；对象类型的 detail 不字符串化，合法 code 保留。对应 TODO(design) 的保守处理。 |
| JSON 数组、非零退出 | `non-object CMD_FAILED matches exactly` | 非对象结果不附带 code/detail，仍恰好一条基础事件。 |
| 退出 0、stdout 非对象 | `invalid-zero CMD_FAILED matches exactly` | 保留原有失败状态及解析诊断，只记一条事件；不会因为关闭 sys.run 自动日志而漏记此旧路径。 |
