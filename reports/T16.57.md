## 触发顺序与根因分析

### 真实调用链

1. daemon 运行于 `run_monitor()` 主循环（`aether-proxy/src/lib/daemon.uc`），初始 Xray 实例（PID `P1`）存活。
2. daemon 收到 `SIGUSR2`：信号回调设置 `signal = 'xray_restart'` 并 `uloop.end()`；主循环置 `monitor_daemon.busy = true`，调用 `restart_xray(ctx, children, monitor_daemon.state, done)`。
3. `restart_xray()` 调用 `children.xray.stop(start_again)`：向旧 Xray（`P1`）发送 `SIGTERM`，挂上 `done_cb = start_again` 与 `SUPERVISE_TERM_GRACE_MS`（1000 ms）强制结束定时器后返回，主循环重新进入 `uloop.run()`。
4. 旧 Xray（`P1`）进入退出流程但尚未退出时，daemon 收到 `SIGTERM`：信号回调执行 `write_stopping(ctx)`（置 `ctx.stopping_requested = true` 并通过 `state.hold_stopping()` 原子发布 `state.json` 为 `stopping`），设置 `signal = 'stop'` 并 `uloop.end()`。
5. `run_monitor()` 跳出主循环，在停机清理前等待 `while (monitor_daemon?.busy) uloop.run(C.DAEMON_POLL_MS)`。
6. 旧 Xray（`P1`）退出，`supervise.on_exit` 触发 `finish_stop(P1)` → `start_again()`。

### 根因（两处交错缺陷）

1. **停机后仍拉起新 Xray**：旧版 `restart_xray()` 的入口及 `start_again()` 回调未检查 `ctx.stopping_requested`。旧 Xray 退出后，`start_again()` 无条件创建新 supervisor 并调用 `children.xray.start()` 启动新 Xray（`P2`）；随后 `xray_ready.published()` 因 `ctx.stopping_requested` 返回 `cancelled`，又使 `done(ready.detail)` 通过 `event_failure(ctx, 'sigusr2', ...)` 误报 `CMD_FAILED (stop:sigusr2)`。即使最终 `shutdown()` 会杀掉 `P2` 使终态进程数为 0，中途已错误拉起第二个 Xray 实例。
2. **嵌套 `uloop.run(1)` 消费 `uloop.end()` 导致停机挂起**：当 `SIGTERM` 落入 `start_again()` 内部的 `xray_ready.published()` 时，`xray_ready` 中的 `cancelled()` 调用嵌套 `uloop.run(1)` 消费了信号回调的 `uloop.end()`；`done` 回调返回到外层 `uloop.run()` 时未补调用 `uloop.end()`，外层事件循环会一直挂起而不进入 `shutdown()`（在测试开发阶段实测触发 10s 超时）。

### 修复方案

- `aether-proxy/src/lib/daemon.uc`：
  - `restart_xray()` 入口、`start_again()` 启动新实例前、以及 `xray_ready.published()` 返回后均检查 `ctx.stopping_requested`；若已请求停机，不再启动新 Xray、不再查询版本或写状态，直接调用 `done(null)` 释放 `monitor_daemon.busy`。
  - `xray_ready.published()` 因停机取消返回 `{ ok: false, cancelled: true }` 时，向 `done` 传 `null` 而非失败文本，避免误报 `CMD_FAILED (stop:sigusr2)`。
  - `run_monitor()` 中 `restart_xray` 的 `done` 回调在 `ctx.stopping_requested` 为真时调用 `uloop.end()`，确保外层事件循环立即退出并进入正常 `shutdown()`。

## 三个时点的隔离夹具与握手设计

`tests/daemon/stop-during-xray-restart.py` 使用独立临时目录、`--sys-root`/`--bin-dir` 隔离 stub、未修改的真实 `aether-proxy daemon` 信号入口（`SIGUSR2` / `SIGTERM`），通过受控 Xray stub 的 `xray-launches.log` 与文件屏障精确控制并观测三个时点（全部远小于 `SUPERVISE_TERM_GRACE_MS = 1000ms`）：

- **T1（旧实例开始退出）**：发送 `SIGUSR2` 后，旧 Xray（`old_pid`）在 `TERM` trap 中原子写入 `xray-exiting`（含自身 PID）并等待 `hold-xray-exit` 释放；测试校验 `xray-exiting == old_pid`。
- **T2（daemon 已接受停机）**：观察到 T1 后向 daemon 发送 `SIGTERM`，等待 `state.json` 变为 `stopping`（证明真实信号处理器已执行 `write_stopping(ctx)`），并在此时断言 `hold-xray-exit` 仍存在、`old_pid` 仍存活且尚未记录 `exited`。
- **T3（允许旧实例退出）**：删除 `hold-xray-exit` 放行旧 Xray，随后断言 `old_pid` 正常记录 `exited`（非 1s `SIGKILL` 超时击杀）。

## 旧红新绿与对照证据

### 旧红（基线 `e94cc51b`，未修 `daemon.uc`）

执行 `python3 tests/daemon/stop-during-xray-restart.py`（退出码 `1`）：

```text
PASS  T16.57 core: initial single xray started
PASS  T16.57 core: initial xray pid alive
PASS  T16.57 core: T1 old xray started exiting
PASS  T16.57 core: T2 daemon accepted stop while old xray still held alive
PASS  T16.57 core: T3 old xray exited via barrier (not SIGKILLed)
FAIL  T16.57 core: no new xray started after stop accepted: starts=[258, 396] xray_run_calls=2 sigusr2_failures=1
```

可见旧实例 `PID 258` 按 T1→T2→T3 退出后，旧版 daemon 仍在停机过程中启动了第二个 Xray `PID 396`（`xray_run_calls=2`）并产生 1 条 `CMD_FAILED (stop:sigusr2)`。

### 新绿（修复后）

执行 `python3 tests/daemon/stop-during-xray-restart.py`（退出码 `0`）：

```text
PASS  T16.57 core: initial single xray started
PASS  T16.57 core: initial xray pid alive
PASS  T16.57 core: T1 old xray started exiting
PASS  T16.57 core: T2 daemon accepted stop while old xray still held alive
PASS  T16.57 core: T3 old xray exited via barrier (not SIGKILLed)
PASS  T16.57 core: no new xray started after stop accepted
PASS  T16.57 core: no spurious stop:sigusr2 CMD_FAILED
PASS  T16.57 core: daemon exited cleanly in stopped state with no leftovers
PASS  T16.57 positive: restarted once with new pid and stayed running
PASS  T16.57 positive: clean stop after restart
PASS  T16.57 normal-stop: clean exit with single xray start and no leftovers
```

- **核心场景**：仅启动 1 次 Xray（`starts == [old_pid]`，`xray run -c` 调用 1 次），无 `stop:sigusr2` 的 `CMD_FAILED`，daemon 以退出码 `0` 正常退出，`state.json == stopped`，记录 `SERVICE_STOPPED`。
- **正对照（未取消重启）**：同一夹具与同一屏障下仅发 `SIGUSR2`，不发 `SIGTERM`；旧 Xray 退出后正常启动且仅启动 1 次新 Xray（`new_pid != old_pid`），`xray version` 刷新完成且 daemon 保持 `running`，随后普通停机退出码 `0`、`state == stopped`。
- **普通停机对照**：不发 `SIGUSR2` 直接 `SIGTERM`，退出码 `0`、`state == stopped`、仅 1 次 Xray 启动、无错误事件。
- **无泄漏与有界退出**：所有等待均有界（2s/5s/10s），daemon 在独立会话中启动；`finally` 必然解除屏障、终止并回收进程组及所有记录过的子进程 PID；退出后 `old_pid`、`new_pid`、`chinadns-ng` 均不存活，`daemon.pid` / `xray.pid` / `chinadns-ng.pid` 均已清理。
