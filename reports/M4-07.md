## W7 变异

命令：

```bash
export PYTHONDONTWRITEBYTECODE=1
python3 tests/update/mutate-walker.py
```

实际输出：

```text
PASS  M4-07 W7 mutation handoff: exit=1; FAIL  M4-07 W1 inventory, handoff, events and result
PASS  M4-07 W7 mutation cap: exit=1; FAIL  M4-07 W7-cap inventory, handoff, events and result
PASS  M4-07 W7 mutation progress: exit=1; FAIL  M4-07 W7-progress inventory, handoff, events and result
```

1. **handoff**：把成功中间步的 `continue_chain(...)` 改成直接 `return result`。W1 只能安装 0.7.0，无法得到 target 库存与引擎，opkg/apk W1 都红。
2. **cap**：去掉安装前及 handoff 前的剩余步数门禁，保留 `bridge_plan()` 不变。首份合法链有两步；在第一个 handoff 重签一份加入 0.8.0 的合法链，原实现最多装到 0.8.0 后拒绝第三步；变异后越过最初两步预算而装到 1.0.0，两格式 W7-cap 都红。这证明防循环上限独立于链本身的排序校验，不能用渠道不断扩链延长作业。
3. **progress**：去掉新 CLI 入口对实际已装版本相对前驱必须严格前进的判断。handoff 包装器把库存重置为 0.6.3，模拟再次进入同一个链前驱的循环。原实现在任何重复安装前返回 `BRIDGE_UNAVAILABLE`；变异后开始重装，精确调用数和事件数断言失败，两格式 W7-progress 都红；步数门禁仍使变异测试有界退出。

变异结束后恢复实现，再运行全部五组验收测试得到本报告的全绿结果。没有把变异实现提交到分支。
