### 既有断言的路径适配（逐项说明）

1. `valid: staging path` 改为 `valid: staging path is check.<pid>`：PID 动态生成，断言完整 run-dir 前缀与数字 PID；另对四个 `files` 字段逐一断言为该路径下的产物名。
2. 四条 `render <name>: identical to staged <file>` 保持原断言名与逐字节 `cmp`，比较对象改为 nft 校验器执行时复制的真实 check 产物。不能继续读取命令结束后的 staging，因为该目录现在必须已删除。
3. `valid: only staging created in run dir` 改为 `valid: run dir is empty after check`，另增加两种成功路径的无 `check.*`、无 daemon staging 断言；`boot.txt not written` 保留。
4. `data dir overrides baseline: chnlist from data dir` 与 `data dir overrides baseline: apple from baseline` 保持原名和路径内容检查，读取校验器抓取的 `chinadns.conf`；仍测试实际 check 产物，而非仅用 render 结果替代。
5. 原有完整 precheck 回归仍执行；校验器初始化提前复用，以支持命令结束前抓取产物。该处旧注释同步更正，不再声称之前所有 check 都跳过 precheck。

### 代码风格与边界

- 模块头注释注明 docs/10 与 docs/04；不显然的所有权、集中清理及并发创建父目录的理由已写在代码旁。
- 新增函数职责单一，均不足百行；跟随原文件 tab 缩进，新增代码行不超过 120 列（tab 按 4 列）。
- 私有目录用 `mkdir` 独占创建且权限为 `0700`；若同名旧目录/链接已存在，保守失败，不复用、不删除不属于本次调用的目录。
- 两个 check 可能同时创建共享 run-dir；`mkdir_p` 失败后仅在确认目标已是目录时继续，避免父目录创建竞争被误报为失败。
- 未顺手修复任务范围外的旧行为；原有配置错误、PRECHECK_FAILED、RENDER_INVALID 的 JSON 和退出码由原场景继续验证。
