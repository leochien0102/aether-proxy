## 根因与改动说明

### 根因

`aether-proxy/files/aether-proxy.init` 的 `restart()` 在启用态（`enabled=1`）发布私有意图文件时，直接在当前 shell 中执行 `umask 077` 且未隔离作用域：

```sh
intent_tmp="$_AETHER_PROXY_RESTART_INTENT.$$"
umask 077
if ! printf 'restart\n' > "$intent_tmp" || ! mv -f "$intent_tmp" "$_AETHER_PROXY_RESTART_INTENT"; then
```

这导致无论发布成功还是失败，当前 shell 的 `umask` 都被永久改写为 `0077`，外溢到随后的 `stop`、`start` 以及返回后的调用方 shell。

### 改动

1. **`aether-proxy/files/aether-proxy.init`**：
   - 将 `umask 077` 及临时文件写入/原子 `mv -f` 发布收拢到子 shell：
     ```sh
     intent_tmp="$_AETHER_PROXY_RESTART_INTENT.$$"
     if ! (umask 077 && printf 'restart\n' > "$intent_tmp" && mv -f "$intent_tmp" "$_AETHER_PROXY_RESTART_INTENT"); then
         logger -t aether-proxy "cannot write $_AETHER_PROXY_RESTART_INTENT"
         rm -f "$intent_tmp" || logger -t aether-proxy "cannot remove $intent_tmp"
         return 1
     fi
     ```
   - `intent_tmp` 在子 shell 外以当前 shell 的 `$$` 生成，子 shell 仅在创建与发布意图文件期间将 `umask` 设为 `077`，不硬编码恢复值（如 `022`），无论成功或失败退出，父 shell 的原始 `umask` 均完全不受影响。
   - 完整保留既有语义：临时文件→`mv -f` 原子发布、先发布再 `stop`、失败时记录日志并 `rm -f "$intent_tmp"` 且返回 `1`（不继续 `stop`/`start`）、`TERM` 信号屏蔽与恢复以及禁用态路径。
2. **`tests/stubs/procd/run.sh`**：
   - 新增 17 条 T16.66 断言，在临时目录和同一测试 shell 内直接调用真实 `restart()`（`stop`/`start` 沿用 stub）：
     - **成功路径（非默认原始 `umask 0027`）**：验证 `restart` 返回 `0`、`stop` 入口处意图文件已可见、权限 `0600`、内容严格为 `restart\n`、无残留临时文件，且 `stop`、`start` 及 `restart` 返回后的调用方均观测到原始 `0027`。
     - **rename 失败路径（非默认原始 `umask 0027`）**：通过 `mv` stub 构造无破坏性 rename 失败，验证临时文件在 rename 前确以 `0600` 创建、`restart` 返回 `1`、`stop`/`start` 均未调用、临时文件被清理且未发布意图文件、调用方 `umask` 仍为 `0027`。
     - **写入失败路径（非默认原始 `umask 0007`）**：在临时目录预置同名目录 `$AETHER_PROXY_RUN_DIR/restart-intent.$$` 构造无破坏性重定向写入失败（在 root 与非 root 下均稳定触发），验证 `restart` 返回 `1`、`stop`/`start` 未调用、未发布意图文件、调用方 `umask` 仍为 `0007`。
