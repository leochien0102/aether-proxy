### 第 4 条：先复现与根因
阅读指定 SDK 的 `form.js` 后，先修改测试替身、加入编辑框保存回归，尚未修改视图时执行：

```sh
node --test --test-name-pattern='T10.42 scenario 4' tests/luci/access-page.test.js
```

输出为 1 项失败：`T10.42 scenario 4: modal saves recalculate no-effect marks from new widgets, not the old Map root`，断言 `'' !== '0.6'`（预期淡显但未淡显）。这在原实现上复现了 `proxy → follow` 保存后无标记。

根因不是 UCI 没有写入：SDK 的 `handleModalSave()` 保存子 Map 后，对父 Map 执行 `load()`、`reset()`。父 Map 的 `renderContents()` 先构造各 section 的新节点，再替换 `map.root` 的内容；`formvalue()` 经 `getUIElement()` / `map.findElement()` 搜索当前 root。因此原先在 GridSection.renderContents 中运行 updateRows，虽然处理的是新行，却读到旧表格里的策略或游戏模式，压过已经更新的 UCI 值。原替身直接读输入对象，没有模拟这种替换时序，掩盖了缺陷。

修复只把重画时的计算移到 Map.renderContents 返回的 Promise 完成后：新控件已经装入 root，再计算标记与排序。原有 inline onchange 仍立即读取未保存输入，不重新渲染，不改 UCI 段顺序。回归测试同时覆盖两种未列出策略下的标记增加 / 取消，以及游戏模式开关；直接撤去此修复会重新出现上述失败。
