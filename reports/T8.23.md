## 验收

### 1. 修复前复现与修复后耗时

先补新增测试、尚未修改 sys.uc 时，执行：

```sh
tests/host/ucode -e 'import * as test from "./tests/unit/sys_run.uc"; for (let c in test.cases) if (c.kind == "inherited") print(c.name, ": ", test.run(c), "\n");'
```

结果：true 用例因耗时约 10 秒而 FAIL；sleep 30 用例约 2 秒、返回 124 且 timed_out=true，原本即可通过。这说明本次问题主要是命令提前完成后无法取消计时器，而非长命令必然无法被 KILL。

另用 `git show main:aether-proxy/src/lib/sys.uc > tests/unit/sys-baseline.uc` 提取未修改模块，父 shell `trap '' TERM` 后 exec 宿主机 ucode，逐项调用原始模块并用 `clock(true)` 计时（纳秒差使用浮点除法）；临时模块运行完即删除。实测原始输出：

```text
baseline [ "true" ]: 10.009s, code 0, timed_out false
baseline [ "sleep", "30" ]: 2.013s, code 124, timed_out true
```

修复后完整单元测试的一次实测：

```text
INFO  inherited ignored TERM: true returns within 2s without timer residue: 0.007s, code 0, timed_out false
INFO  inherited ignored TERM: timeout returns 124 within 3s without timer residue: 2.014s, code 124, timed_out true
262 passed, 0 failed, 0 skipped
```

两个新增用例都从 `sh -c 'trap "" TERM; exec "$@"'` 启动独立解释器，避免污染测试运行器自身的信号处置；返回后对比 sleep 1/10/30 的 PID，新增残留即失败。TERM 顺序测试使用捕获 TERM 写文件并立即退出的命令，确认命令确实先收到 TERM，且 grace sleep 被回收。

补强 stdout/stderr 必须为空的断言时，另捕获到一次取消竞态：宿主机 shell 的内部 kill 诊断在文字之后附带空行。现一并过滤内部 helper 的空行；命令自己的 stderr（包括相同诊断文字和前后空行）仍完整保留。额外对继承 TERM、TERM 顺序和诊断保留用例连续运行10轮，输出 `PASS  sys_run cancellation stress: 10 rounds`，之后完整单元测试仍为262项全过。

### 2. restart 超时与回滚生效

命令：`bash tests/update/run.sh`。

结果：`update: 357 passed, 0 failed`。

- 用生产 `restart_service` 函数体与 sys.run 替身验证常量和传入 timeout 均为 90，不需要真的等待 90 秒；安装检查和回滚调用同一个函数。
- aether-proxy 更新前 running/starting/degraded：检查失败后重装旧版，额外 restart 一次；stopped/error/缺 state/failsafe：不额外 restart。
- xray-core 更新前 running：检查及回滚各一次 SIGUSR2；starting/degraded：回滚一次；stopped：零次。每个请求都深比较 name、整数 signal=12、无 instance。
- `--previous` 检查失败后安装 current，并执行对应激活动作；核对两次安装的资产版本、回滚的 --force-downgrade 和最终已装版本。
- 回滚后 restart 返回 7 / ubus 返回 9，均有回滚事件之后的 CMD_FAILED，最终仍 exit 1、UPDATE_VERIFY_FAILED、rolled_back=true。
- 两个 LuCI 包的失败回滚均不执行 restart 或 ubus。
- 每个矩阵用例核对 UPDATE_VERIFY_FAILED → UPDATE_ROLLED_BACK，且没有 UPDATE_INSTALLED；后续既有 updates.json 刷新可能另记 UPDATE_AVAILABLE，不将其误判为回滚验证。
