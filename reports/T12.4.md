# T12.4 B25 usage.json 持久化

## 结论

B25 每日使用数据已按 docs/b25-heatmap.md §3/§5 落盘：`/etc/aether-proxy/usage.json`，
schema 1，0600，`sys.write_atomic` 原子重写；写入时机为跨天切日后与 daemon 干净停止，
v1 无定时 checkpoint；保留最近 90 个本地日期，不写未来/负时间；损坏/权限错误按空历史
处理且只 warn 一次、不删原文件；关闭开关零采样零写盘。未做 history API、未做 UI、
未改配置默认，版本未动、未 push。

顺带修掉一个 T12.3 遗留 bug：ucode 的 `localtime()` 返回的 `mon` 本就是 1–12（1-based，
`wday`/`yday` 同理），`local_date()` 里的 `tm.mon + 1` 把所有日期标签整体后移了一个月
（宿主构建 2026-11-01 返回 `mon: 11`，实测 `usage.json` 写出 `2026-12-01`）。T12.3 的
单元测试因输入（`timelocal({mon: 9})`）与输出同错而自洽，未暴露；本卡的 daemon 集成
测试用 Python `date.today()` 对表才暴露。修复后 T12.3 测试常量改用 `mon: 10` 表示十月。

## 实现

- `aether-proxy/src/lib/usage.uc`：在纯聚合之上新增持久化三函数（I/O 仅限读
  `usage.json` 与经 `sys.write_atomic` 写入，docs/12 规则 1 已补注）：
  - `load(path) → { days, error, op }`：缺失文件＝空历史无错误；损坏/权限错误＝空历史
    + `op: 'read'|'parse'` 错误详情，由调用方 warn 一次；条目校验（键须 `YYYY-MM-DD`、
    四字段须非负数值），非法条目丢弃，保留条目的未知字段原样带回（§3「未知字段保留」），
    `healthy > observed` 收口回 `observed`。
  - `collect(state, previous) → days|null`：合并持久化基线 + 本次运行的完成日 + 当日
    （当日为空也写一条，§3「当前日也写一条」）；晚于存活日的日期（时钟前跳后回拨）
    直接丢弃不重写；按本地日期字符串排序裁剪到 `C.USAGE_DAYS_KEEP`（90，含当日）。
  - `write(path, days, now)`：`{schema: 1, updated_at, days}` 单文档，`%.J` 序列化，
    先 `sys.mkdir_p` 父目录再 `sys.write_atomic`（临时文件 0600 + rename，读方与掉电
    均只见完整文件）；返回值即写入校验（短写/close 失败会被 write_atomic 拦下并放弃
    rename），失败携带原因且原文件不动。
- `aether-proxy/src/lib/monitor.uc`：
  - `flush_usage(daemon)`（导出）：开关 `!== true` 直接返回（不加载、不创建、不写）；
    首次调用才 `usage.load` 并缓存到 `daemon.usage_days`，读失败以
    `warn FS_FAILED{op,path,detail}` 记录且进程内只记一次（`daemon.usage_warned`）；
    `collect` 为 null（从未采样）则不写；写失败 `warn FS_FAILED{op:'write'}` 后返回，
    内存数据保留，下次跨天或停止重试；成功后缓存已写地图，成功本身不记事件。
  - `sample_usage`：记录采样前存活日，`usage.sample` 跨天结束后立即 flush（ucode 不做
    声明提升，`flush_usage` 定义在其调用方之前，沿用本文件 `tick` 的既注约定）。
    时钟回退保持存活日不产生日变化，不触发 flush。
  - `create_daemon` 初始化 `usage_days: null`、`usage_warned: false`。
- `aether-proxy/src/lib/daemon.uc`：run_monitor 的两个干净停止点（reload 请求停止、
  信号停止）在 `shutdown()` 前各加一次 `monitor.flush_usage(monitor_daemon)`，位于
  busy 等待之后，最后一轮 tick 的样本包含在内。启动回滚/外层失败路径的
  `shutdown(normal_stop=false)` 不 flush（monitor 从未运行，无数据可落）。
- `aether-proxy/src/lib/const.uc`：`USAGE_FILE = '/etc/aether-proxy/usage.json'`。
- `docs/12-ucode.md`：规则 1 的 I/O 许可清单补入 `usage.uc`（任务卡把持久化函数定在
  该文件；写路径仍只能经 `sys.write_atomic`，规则 3 不变）。

## 决定与理由

- **懒加载而非启动读取**：首次 flush（≤24 小时后的跨天或停止）才读文件。设计 §3 的
  「按空历史启动」对 T12.4 无可观测差异（历史读取入口属 T12.5），换来关闭路径与
  测试环境的零 I/O，且损坏警告自然收敛为进程内一次。
- **同日合并语义为「本次运行赢」**：重启后的部分当日覆盖文件里的旧当日，而非相加。
  计数器跨重启连续时相加看似更优，但 observed/healthy 的秒数会重叠、时钟回退/清零
  组合下无一致语义；与设计「重启丢当天数据属预期」一致。落盘文件里的完成日同理
  （完成日只会被本运行更完整的数据覆盖）。本卡边界，T12.5 读取时即此口径。
- **写失败逐次记 warn 而非一次**：flush 频率 ≤ 每天一次 + 停止一次，逐次记录不会刷屏，
  且持续故障（如目录被占）每次可见；读失败（损坏/权限）按要求只 warn 一次。
- **`sys.write_atomic` 返回值即「校验写入成功」**（要求 2 的最低档）：临时文件 write+
  close 均校验后才 rename，短写/ENOSPC 不会污染原文件；未做读回（每日一次的写入
  再读回 10–20 KB 收益有限）。
- **flash 预算**：90 天约 10–20 KB，每天 1–2 次原子重写（跨天 + 可选停止），远低于
  设计 §5 的寿命预算；未实现 6 小时 checkpoint（v1 明确不做）。
- **隐私**：文件内容只有日期与 tx/rx/observed/healthy 四个数字，无域名/节点/目的地。

## 测试

新增：

- `tests/unit/usage.uc` +13 例（合计 33）：缺失/损坏/非对象/`days` 非表 → 空历史口径
  与损坏文件不删除；未知字段保留、healthy 收口、非法条目（负值/缺字段/非日期键/非对象）
  丢弃；0600 + 文档内容 + 无 `.tmp.*` 残留；目录占位写失败 → 报错 → 解除后重试成功；
  collect 合并/覆盖同日/丢弃未来日/无存活日返回 null/96 个日期裁剪到 90（首尾对位）。
- `tests/monitor/driver.uc` 三个场景（22 项断言），`tests/monitor/run.sh` 接线
  （`heatmap-persist`/`heatmap-corrupt` 用 `heatmap-conf`，`heatmap-persist-off` 用关闭夹具）：
  - persist：真实 tick 跨天（假时钟驱动采样器到昨天正午，tick 的真实墙钟完成切日）→
    原子重写、schema/updated_at、昨日累计值落盘、种子历史存活、当日零条目、恰好 3 个
    日期、0600、无残留、成功静默；目标位换成目录 → 失败不删除目标、恰一次 warn →
    解除后重试成功且再次静默、无残留。
  - corrupt：损坏文件恰一次 warn、被 flush 覆盖为合法文档、缓存空历史不再 warn、
    空历史上继续累计。

  恰一次 `warn FS_FAILED`、停止时覆盖为合法文档；目录占位：干净退出 0、目标仍是目录、
