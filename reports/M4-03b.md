### T13 三次变异与恢复

命令：`python3 tests/update/mutate-prerequisite.py`。

1. 将 `return run_ok && pkg_ok;` 改成 `return run_ok;`。输出：`PASS  M4-03b T13 pkg_ok: exit 1; FAIL  M4-03b T3 prerequisite transaction`。旧 chinadns 被错误跳过，完整安装序列不符。
2. 将 `if (prior == null || prior.version != installed.version)` 改为只检查 prior 存在。输出：`PASS  M4-03b T13 exact_recovery: exit 1; FAIL  M4-03b T7 prerequisite transaction`。日期版被错误自动替换，不再是零安装的人工迁移拒绝。
3. 将 `prerequisite_prepare` 暂换为成功占位事务，把真实调用移到 `package_update_selected` 之后。输出：`PASS  M4-03b T13 engine_order: exit 1; FAIL  M4-03b T10 prerequisite transaction`。桥接 backend 先于 DNS，顺序断言失败。

恢复：脚本先保存原文件 bytes，每轮执行后 `write_bytes(original)` 并比较字节相同；外层 finally 再恢复，异常也不会留下变异。每轮额外输出 `PASS  M4-03b T13 <name>: original bytes restored`。恢复后正常更新套件再次 `938 passed, 0 failed`。

## 偏差与待定

- 新增 TODO(design)：冻结 action 集合没有 failed/not_started。前置下载、校验等发生在任何安装之前的错误，沿用原失败 code/exit，并用 manual_required（不能声称 installed/rolled_back）表示前置未完成；报告保留该命名歧义。事务实际执行后成功撤销才标 rolled_back；撤销失败保留 installed，并在 detail 明确 engine rollback failed。
- apk 只可靠读取版本、Provides 为空；25.x 真实包管理器行为未验证，不用版本代替 Provides。签名 current/previous 提供可校验资产时可保守安装；缺少精确恢复来源时拒绝。
- provider 读取使用 aether-dns 和已知旧 chinadns-ng 的包元数据；不猜测其它第三方包的能力，无法确定则走保守前置/人工路径。
- 本卡旧代码顺手修正：未安装 backend（version=null）也能执行安装，而不是被 version_newer(null) 的检查逻辑跳过；本卡修改的是组安装条件，不改变发现接口“未安装不标 newer”的契约。其余原回滚策略不重构。
- 服务状态测试使用现有 init/state stub，证明事务调用顺序及可恢复库存，不声称是真机 DNS 或包安装测试；没有真机/root/容器操作。
- 保留 update.uc 原有的包管理器超时及 Xray 状态策略 TODO；本卡没有扩展其语义。
