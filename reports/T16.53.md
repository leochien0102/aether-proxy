## B. 反例（同一原始命令块）

三个临时目录分别注入给 `CHANNEL_WORKTREE`；均运行完整 `contract-run.sh`，不是仅单独运行某个 test 命令。通过 `bash -x` 跟踪核对没有出现 `+ python3 `，证明未进入任何测试。

| 输入 | 检查结果 | 退出码 | 进入测试 |
| --- | --- | --- | --- |
| 不存在的 `absent` | `test -d` 失败 | 1 | 否 |
| 固定 SHA 副本删除目标 workflow | HEAD 正确，`test -f` 失败 | 1 | 否 |
| 有目标 workflow 的独立 fixture 仓 | HEAD `e2cfc6d45dba26dde310a5de075ae5f15eabf4e9` 不匹配 | 1 | 否 |

复现负例（接上面的 TMP）：

```bash
git clone --quiet --no-hardlinks "$TMP/channel" "$TMP/no-workflow"
rm "$TMP/no-workflow/.github/workflows/publish-channel.yml"
mkdir "$TMP/wrong-sha"
git -C "$TMP/wrong-sha" init -q
mkdir -p "$TMP/wrong-sha/.github/workflows"
printf 'name: wrong revision fixture\n' > "$TMP/wrong-sha/.github/workflows/publish-channel.yml"
git -C "$TMP/wrong-sha" add .
git -C "$TMP/wrong-sha" -c user.name=Fixture -c user.email=fixture@example.invalid \
  commit -qm fixture
for case in absent no-workflow wrong-sha; do
  rc=0
  CHANNEL_WORKTREE="$TMP/$case" bash -x -e -o pipefail "$TMP/contract-run.sh" \
    > "$TMP/$case.log" 2>&1 || rc=$?
  test "$rc" -ne 0 || exit 1
  if grep -q '^+ python3 ' "$TMP/$case.log"; then exit 1; fi
  printf '%s: exit %s; no test command entered\n' "$case" "$rc"
done
```

实测负例日志：`missing-directory.log`、`missing-workflow.log`、`wrong-sha.log`，位于上述证据目录。所有删除/fixture 提交仅发生于临时副本，未动真实配对仓。
