固定上限选为 **`UPDATE_DATA_MAX_BYTES = 8 * 1024 * 1024`（8,388,608 字节 / 8 MiB）**：

1. **增长余量充足**：最大单项 `chnlist.txt` 当前约 1.33 MiB，8 MiB 提供约 6× 单项增长余量（超过当前全部 5 项明文总和的 5.4×），与现有 `const.uc` 中 `UPDATE_MANIFEST_MAX = 1 MiB`、`UPDATE_SPACE_RESERVE = 1 MiB`、`CUSTOM_MAX_BYTES = 64 KiB` 量级一致。
2. **契合路由器内存与 tmpfs 约束**：`update_data_item()` 随后会对通过大小与哈希校验的明文执行 `fs.readfile()`、`line_count()`、`data_parser()` 及临时暂存写盘；8 MiB 将单次更新的 tmpfs 峰值与 ucode 解析内存严格限制在低内存 OpenWrt 设备可承受范围内，防止高压缩比文本耗尽 `/tmp` 或触发 OOM。

## 实现设计与资源界限

修改位置：`aether-proxy/src/lib/const.uc`、`aether-proxy/src/lib/update.uc`（`GUNZIP_BOUNDED_SCRIPT`、`decompress_data_file()`、`update_data_item()`）。

1. **解压过程中流式限长**：
   - 创建权限 `0600` 的私有 FIFO（`data-<name>.plain.fifo`），并行启动 `gunzip -c <src> > <fifo>` 与 `head -c $((max_bytes + 1)) < <fifo> > <dst>`；
   - `gunzip` 的 stdout 不再进入 `sys.run` 的 stdout 捕获文件（`sys.run` 仅收到空输出或 15 字节的 `LIMIT_EXCEEDED\n` 标记）；
   - `head -c` 最多读取并写入 **`max_bytes + 1`（8,388,609）字节** 即关闭 FIFO 并退出，从而准确区分「恰好上限」与「超出一字节」。
2. **超限、失败与超时立即中止并回收资源**：
   - 当落盘字节数 `> max_bytes` 时，立即向 `gunzip` 发送 `TERM` / `KILL` 并 `wait` 回收子进程，删除 FIFO、辅助日志与明文临时文件，返回 `decompressed size exceeds 8388608 bytes`；超限路径下 `update.uc` **0 字节** 读入 ucode 内存。
   - 当 `gunzip` 因无效/损坏 gzip 非零退出时，删除明文临时文件并透传 `gunzip exited <code>: <stderr>`。
   - 当 `sys.run` 超时（`C.UPDATE_COMMAND_TIMEOUT_SECS = 35s`）向脚本发送 `TERM` 时，脚本 `trap` 立即中断 `wait`、终止并回收 `head` 与 `gunzip`，清理全部临时文件；`update.uc` 返回后再次兜底清理 `data-<name>.txt.gz`、`data-<name>.plain`、`data-<name>.plain.fifo`、`data-<name>.plain.err`。
3. **保留全部原有下游校验与原子发布**：
   - 流式解压成功且 `fs.stat(plain_path).size <= C.UPDATE_DATA_MAX_BYTES` 后，先直接对 `plain_path` 执行 `file_sha256()` 比对 `item.content_sha256`（哈希不匹配直接删临时文件返回，不读入内存）；
   - 再读取明文并删除 `plain_path`，依次执行原有 `line_count()`（≥ 清单 `lines` 的 90%）、`data_parser()`（逐行域名/CIDR 语法校验）以及 `.tmp` 写盘、`mv` 原子替换和 `.sha256` 写入（失败回滚原规则）。

### 资源上界汇总

| 资源 | 界限 |
| --- | --- |
| 管道内核缓冲 | 单个 FIFO 缓冲（Linux 默认 ≤ 64 KiB） |
| `/tmp/aether-proxy-dl` 解压临时文件 | 至多 `UPDATE_DATA_MAX_BYTES + 1`（8,388,609 字节），超限/失败/读完后立即删除 |
| `sys.run` stdout 捕获 | ≤ 15 字节（仅 `LIMIT_EXCEEDED\n` 或空） |
| ucode 堆内存（超限或哈希不匹配路径） | 0 字节明文读入 |
| ucode 堆内存（通过限长与哈希校验后） | 至多 `UPDATE_DATA_MAX_BYTES`（8,388,608 字节） |
| 解压子进程与超时 | 受 `C.UPDATE_COMMAND_TIMEOUT_SECS`（35s）约束，超限/失败/超时立即 `TERM`/`KILL` + `wait` 回收 |

## 真实入口测试覆盖（`tests/update/rule-size.sh`）

所有用例均通过真实 CLI 入口 `aether-proxy update data --json`（在独立 `setsid -w` 会话与外层 `timeout -k 5` 保护下运行，使用本地回环 HTTP 通道、真实 `usign` 签名、真实 `gzip` 压缩与真实 `gunzip` 解压，仅用无害注释行与合法 CIDR 夹具，不联网、不碰设备、不需宿主特权）；进程残留检查统一通过 `ps -e -o pid=,sid=,comm=` 枚举该独立会话的全部存活进程（不再局限于当前终端会话或猜测进程名）：

0. **残留检查阳性对照**：在独立 `setsid` 会话中启动无害 `sleep 60`（非 `gunzip`/`head` 进程名），存活期间断言 `rs_session_pids` 必能检出该 PID；终止并回收后断言该会话残留进程数为 `0`。
1. **正常 gzip 更新**：退出码 `0`，`updated` 包含 `chnroute4`，触发 `reload`，无临时文件与会话子进程残留。
2. **恰好上限（8,388,608 字节）**：退出码 `0`，`updated` 包含 `chnroute4`，落盘字节数精确等于 `8388608`，`.sha256` 与落盘内容一致，触发 `reload`，无临时文件与会话子进程残留。
3. **恰好上限 + 错误 `content_sha256`**：退出码 `1`，`failed.chnroute4 == "decompressed content sha256 mismatch"`，旧规则与旧 `.sha256` 逐字节不变，未触发 `reload`，无临时文件与会话子进程残留。
4. **超限一字节（8,388,609 字节，清单压缩/明文哈希与行数均合法）**：退出码 `1`，`failed.chnroute4 == "decompressed size exceeds 8388608 bytes"`，记录 `UPDATE_VERIFY_FAILED` 事件，旧规则与旧 `.sha256` 逐字节不变，未触发 `reload`，无临时文件与会话子进程残留。
5. **多倍超限无害重复文本（32 MiB 注释+合法 CIDR，压缩后约 35 KiB）**：流式提前中止，退出码 `1`，`failed.chnroute4 == "decompressed size exceeds 8388608 bytes"`，旧规则与旧 `.sha256` 逐字节不变，未触发 `reload`，无临时文件与会话子进程残留。
6. **无效 gzip（非 gzip 字节流，压缩校验字段与清单一致以直达解压路径）**：退出码 `1`，`failed.chnroute4` 报 `gunzip exited ...`，不发布，旧规则与旧 `.sha256` 逐字节不变，未触发 `reload`，无临时文件与会话子进程残留。
7. **确定性超时（真实 `update data` 入口 + 生产 35s 超时路径）**：通过仅作用于本用例的临时 `PATH` 无害 `gunzip` 替身记录自身 PID 后 `exec sleep 120` 阻塞，外层设 `timeout -k 5 55` 保护（不代杀，完全交由生产 `C.UPDATE_COMMAND_TIMEOUT_SECS = 35` 超时处理）；断言外层未超时、CLI 退出码 `1`、`failed.chnroute4 == "gunzip timed out after 35s"`、记录 `UPDATE_VERIFY_FAILED`、旧规则与旧 `.sha256` 逐字节不变、未触发 `reload`、无临时文件残留、记录的 `gunzip` PID 已终止回收且独立会话内残留进程数为 `0`（所有断言完成后再执行兜底清理，防止失败时污染宿主）。
