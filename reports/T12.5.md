# T12.5 B25 stats history / rpcd API

## 结论

B25 历史查询已按 docs/b25-heatmap.md §6 落地：CLI `aether-proxy stats history
[--days N] [--json] [--sys-root DIR] [--run-dir DIR]` 与 rpcd `stats_history`
（参数 `{days?: number}`，ACL 归 read）。成功返回
`{ok:true, enabled:true, days:[{date,tx,rx,observed,healthy}...], updated_at}`；
关闭返回恰好 `{ok:true, enabled:false, days:[]}` 且**不打开 usage 文件**；文件
缺失/损坏返回 `days:[]`、`updated_at:null`，仍 `ok:true`（rpcd 不会因此失败）。
`days` 取 1–90（缺省 90），只返回最近 N 个有数据日期、按日期升序。只读：不改
文件、不触发 monitor/采样、不进入 5 秒轮询、不记事件。未做 UI，未改采样/持久化
语义，版本未动、未 push。

## 实现

- `aether-proxy/src/lib/usage.uc`：`load(path)` 扩展返回 `updated_at`（T12.5 允许
  范围内的只读字段）——文档解析成功时取墙钟 `updated_at`（非负数值，复用现有
  `numeric()` 校验），否则（缺失/损坏/`days` 非表/字段非法）为 `null`。条目校验
  （`YYYY-MM-DD` 键、四非负数值、healthy 收口、未知字段保留）原样复用，
  `op/error` 语义与 monitor 的消费不受影响。
- `aether-proxy/src/lib/cmd/stats.uc`：
  - `--days` 由 `lift_days()` 在共享参数解析前摘出（`pipeline.parse_args` 无此
    数值选项），随后的 history 分支校验 `^[0-9]+$` 且 1–90；重复 `--days`、缺值
    均 `USAGE`（退出码 2）。无参数 `stats` 的参数面、错误文案、输出逐字节保持
    原状（`--days` 出现在非 history 形式下报 `--days is only valid with stats
    history`）。
  - `history` 分支先用 `config.load` 读 `stats.heatmap_enabled`（confdir 取
    `--confdir`，否则 `--sys-root` 前缀 + `/etc/config`，同 `probe url`）：关闭
    直接返回 disabled 应答，不触碰文件；配置无效 → `CONFIG_INVALID`（退出码 2，
    与 `status` 同口径）。
  - 开启时 `usage.load(root + C.USAGE_FILE)`，`history_entries()` 把日期升序排
    序、取最近 N 个，只输出 `date/tx/rx/observed/healthy` 五个字段（load 保留的
    私有未知字段不跨 API）。人读输出与 `stats` 一致（JSON 原文）。
  - 全程无 `log.event`：历史查询是只读请求，失败不刷 logd（与 `stats` 的
    「independent nulls, never events」同则）。
- `aether-proxy/src/aether-proxy`：`--help` 命令表加 `stats history` 一行
  （分派无需改：`stats` 模块内部按 `positional[0]` 分流，同 `probe`）。
- `luci-app-aether-proxy/root/usr/share/rpcd/ucode/aetherproxy.uc`：新增
  `stats_history`（read 家族、普通 10 秒预算）：`days` 缺省不传；给出时必须为
  1–90 的整数（`type == 'int'`），否则 `USAGE` 不执行；映射为
  `stats history [--days N]` 转发，CLI JSON 原样返回——包括关闭与空历史应答，
  rpcd 不重塑、不因损坏文件失败。
- `luci-app-aether-proxy/root/usr/share/rpcd/acl.d/luci-app-aether-proxy.json`：
  `stats_history` 加入 read.ubus.aetherproxy。
- `docs/10-cli-luci.md`：Dashboard 部分新增 `stats history` 小节（应答契约、
  开关前置、1–90、升序、缺失/损坏口径、rpcd 方法与参数）；`docs/05-config.md`
  的 `heatmap_enabled` 行补历史查询入口与关闭语义。

## 决定与理由

- **损坏/不可读与缺失同形（空历史 + `updated_at:null`，`ok:true`）**：任务卡允许
  「明确错误码」或空历史，取空历史——与 docs/b25-heatmap.md §5/§8「损坏按空历史、
  不阻塞」一致，也避免只读查询把磁盘细节（EACCES/EISDIR）当业务错误暴露；与
  缺失同形还让前端只需处理一种空态。warn 归 monitor（进程内一次），history 不记
  事件。
- **关闭应答不含 `updated_at`**：b25-heatmap §2/§6 与任务卡三处均写
  `{ok:true, enabled:false, days:[]}`，按文档逐字实现（JS 侧 `updated_at` 为
  undefined，无消费问题）。
- **无效配置 → `CONFIG_INVALID`**：history 必须读配置判断开关，与同为轮询读的
  `status`/`probe url` 同口径；rpcd 原样转发该 JSON，不会崩。
- **history 不接受 `--bin-dir`**：参数面按「影响行为才接受」收紧（卡片签名为
  `--days/--json/--sys-root/--run-dir`），`--confdir`/`--sys-root` 是读配置与
  usage 路径所必需（docs/10 仅供测试的选项）；`--run-dir` 按卡片签名接受不使用。
- **升序返回、只导出五字段**：热力图（T12.6）按周网格消费，升序省一次翻转；
  条目白名单让 `usage.json` 里的未知字段止步于文件层。
- **`usage.load` 而非新读取函数**：条目校验/收口/未知字段语义单一来源，monitor
  与 history 永远同一口径（任务卡要求 1）。

## 偏差与待定

- 「损坏 → 空历史」与「缺失」在 API 上不可区分（见决定 1）；如后续需要区分，
  可在应答加可选 `degraded` 字段，属契约扩展而非破坏。
- 配置无效时 history 返回 `CONFIG_INVALID` 属本卡定的口径（任务卡未覆盖此象限），
  已写入 docs/10；如 T12.6 希望配置坏时热力图仍渲染空态，需改口径并同步文档。
- rpcd 侧 `days` 的 1–90 上界取 `C.USAGE_DAYS_KEEP`，与 CLI 共享常量；若将来
  保留窗口改长度，两端同步。
- 热力图 UI（T12.6）、真机 H28K 验收按拆分归后续卡；本卡未动 UI、monitor、
  daemon、采样与持久化逻辑。未 bump 版本；未 push。
