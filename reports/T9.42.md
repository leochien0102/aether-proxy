### B. 新增边界用例（修前本来就通过）

- `unit/uri[24]`（JSON 数组）、`[25]`（空 payload）、`[26]`（JSON 字符串）在修前就是 `malformed`，它们锁的是「对象判断」，
  不是异常保护；报告不再把它们算作「修前必失败」。
- `T9.42 name checks leave no temporary file`、`T9.42 uppercase hex sha256 is accepted`、`T9.42 int size 0 …`
  等是正向/边界回归，修前也成立。
- 上一版的 `T9.42 asset name with a separator is rejected` 在 `main` 上也能通过（无 `sub/` 目录时下载本来就会失败），
  它不是有效复现；本轮已改成按错误 `detail` 区分「名字校验拒绝」与「下载/校验失败」。

### C. 因新 API/契约在旧代码上不存在而失败

- 把本轮的 `T9.42/R2` 契约用例与 main 原 loader 组合运行：只有一条失败并停在第一项
  （`the callback receives the node being built`）。复核的对照结果是 `7 passed / 3 failed`，其中包含字段/API 不存在；
  这些是契约差异，不作为「生产渲染危险」的证据。
- 与之相对，生产 sink 的复现依据是 A 类最后两行（main 生产代码 + 修正 loader + 页面测试的真实断言失败）。

### D. 修正测试替身后暴露的旧断言（测试建模更新）

- `tests/luci/loader.test.js` 旧 T10.18 断言 `E('p','<img src=x>')` 的 `textContent` 是原文、`childNodes[0]` 是 `#text`——
  正是 D-F3 指出的错误建模；改为「标量 = `innerHTML` 写入、数组 = 文本节点」。
- `tests/luci/progressive-lists.test.js` 的 `T10.34 scenario 1/4`、`T10.28 scenario 2` 读 `textvalue()` 文本的断言、
  `T10.25 scenarios 2/3` 的订阅提示改读 `innerHTML`（静态 `<br>`），以及 `overview`/`rules`/`common` 中读
  `children[0] === '字符串'` 的断言，都因「数组项成为文本节点」而需要改读 `textContent`/文本节点。
- 这些改动保留原业务期望，只是把断言对上新替身；没有删期望来掩盖失败。

### R2 补齐 G3 契约与防回退断言

**实现**：重写 `tests/luci/loader.js` 的 `element()`/`appendChildren()`/`contentChildren()`：

- 函数子项以**目标节点**为参数，返回值递归追加；
- 真正的稀疏数组按索引展开（空位成为文本 `undefined`），`null`/`undefined` 数组项成为 `null`/`undefined` 文本，
  而标量 `null`/缺省不产生写入；
- 文本节点/元素/fragment 识别为 DOM 节点并保持身份（不再走 `[object Object]` 的 HTML 写入）；
- `innerHTML` 之后追加内容保留先前内容并保持顺序，`append()` 返回 `lastChild`/子节点/`null` 与 SDK 一致；
- `innerHTML` 是 `[LegacyNullToEmptyString] DOMString`（`null`→`''`，`undefined`→`"undefined"`）；`textContent` 是 **nullable**
  `DOMString?`（`null` 与 `undefined` 都按 WebIDL 转成 IDL null → 空串 → 清空子节点，不创建文本节点）；
- `DocumentFragment` 插入时把子节点移入父节点并清空自身（`appendChild` 仍返回 fragment）；
- 每次 innerHTML 写入追加到全局写入日志，`htmlWriteMark()`/`htmlWritesSince()` 能看到后来被清空/移除的写入。
