### S7：两次反向变异

1. **显示映射变异**：仅将 `model/conflicts.js` 的 `component_name()` 返回表达式替换为 `return String(name);`，不改调用点、不改测试。运行 `node --test tests/luci/logs-r17.test.js`，退出 1，50 pass / 3 fail：
   - `M4-02b2 S5: new and historical component events have identical Chinese text` 失败：新旧事件显示原始 id，文本不再相同。
   - `M4-02b2 S5: component prechecks stay missing and unknown ids pass through` 失败：期望 DNS 引擎却得到 dns/旧 id。
   - `M4-02b2 S6: new and historical notices share Chinese text and package guidance` 失败：两条通知不再等价。
   恢复：变异脚本在 `finally` 中逐字写回内存保存的原文件。
2. **发射点变异**：在 `daemon.uc`、`cmd/check.uc`、`cmd/status.uc` 中将本卡新增的 `name == C.CHINADNS_COMPONENT ? C.DNS_COMPONENT : name` 都替换为 `name`，包含 precheck item/detail 的 component 局部变量；内部查找本来就是旧名，故各出口回到 chinadns-ng。分别运行：
   - `python3 tests/daemon/missing-events.py`：退出 1，41 passed / 15 failed。单独 DNS 缺失的关键失败行为：`FAIL  T9.47 default missing=chinadns-ng start exact missing error events`、`FAIL  T9.47 default missing=chinadns-ng aggregate precheck preserved`（S1），`FAIL  T9.47 default missing=chinadns-ng check exact warnings`（S3），`FAIL  T9.47 default missing=chinadns-ng status exact notices`（S4，两次轮询）；同时缺失及显式路径场景也变红。
   - `python3 tests/daemon/version-gate.py`：退出 1，93 passed / 1 failed：`FAIL  T9.44 start chinadns-ng banner 2025.08.08: exact error event policy`（S2）。
   - `python3 tests/daemon/version-gate.py --check-only`：退出 1，79 passed / 1 failed：`FAIL  T9.44 check chinadns-ng banner 2025.08.08: exact warning policy`（S3）。
   - `bash tests/status/run.sh`：退出 1，202 passed / 2 failed：`FAIL  s2: component is dns`、`FAIL  s2b: component is dns`（S4）。
   恢复：同一变异脚本在 `finally` 中将三个文件逐字还原；之后完整重跑验收表的七个必需套件及额外 check-only 命令，全部恢复绿色。
