# T9.32 停止中状态、早期状态带 DNS 级别、停止后保留配置触发器

分支 `m9/stop-state`。

## 改动

- `aether-proxy/src/lib/daemon.uc`
  - 新增 `write_stopping()`，在 `shutdown(..., normal_stop=true)` 开头调用：读当前 `state.json`，保留其余字段，`state: stopping`、`since: time()`，写失败只记 `FS_FAILED`（不走 `write_state`，避免记 `START_FAILED`）后继续；最后照旧写 `stopped`。所有「正常停止」路径（运行中 SIGTERM、启动中途 SIGTERM、等网络时 SIGTERM、错误退避中 SIGTERM）都经 `shutdown(true)`，因此启动中途收到 SIGTERM 同样先写 `stopping`。启动回滚（`normal_stop=false`）不写。
  - 早期 `starting` 状态加 `dns_tier`：UCI 原值 `dns.direct_dns_enabled == '1'` -> `T2`，否则 `T1`。
- `aether-proxy/src/lib/const.uc`：`STOPPED_BY_USER_FILE = 'stopped-by-user'`（init 是 sh，自己写同名）。
- `aether-proxy/files/aether-proxy.init`
  - `stop_service()`：写 `/var/run/aether-proxy/stopped-by-user`（init stop、restart、enabled=0 的内部 stop 都会走到）。
  - `start_service()` 开头清标记（start、restart 的后半、reload 拉起都经过）。
  - `reload_service`：`enabled=0` -> 在运行才 `stop`，然后清标记；`enabled=1` 且没在运行 -> 有标记直接返回，否则 `start`；在运行 -> HUP 不变。
  - `service_stopped`：清理之后（无论清理成败）`procd_open_service` + `service_triggers` + `procd_close_service` 重新登记不带实例的服务，返回值仍是清理的返回值。
- 读 `state.json` 的其他命令（`status`、`probe now/url`、`dns`、`node`、`sub`、`custom`、`update`）都是白名单判断「在运行」，`stopping` 自然落在「不在运行」，**未改动**。`status` 原样回显状态。

## 偏差与待定

- **TODO(design)**（init 注释里同样标了）：重新登记依赖 rc.common procd 模式在 `stop` 里先 `stop_service`、再删除服务、最后调用 `service_stopped` 这一顺序；宿主机只能用替身验证。H28K 上需看：`/etc/init.d/aether-proxy stop` 后 `ubus call service list '{"name":"aether-proxy"}'` 有服务、无 instance、有 triggers；`enabled` 关再开并应用后服务启动；`stop` 后改配置不启动。另外手动标记写在 `stop_service`（而不是覆盖 `stop`），因为 rc.common 的 `stop` 不便覆盖。
- `cleanup` 命令（`lib/daemon.uc` 的 cleanup 路径，卡片只允许改早期状态和停止流程开头）未写 `stopping`：04 说 cleanup 是「同样的步骤」，但它只在 daemon 已死或 `service_stopped` 兜底时运行，页面看到的 `stopping` 由 daemon 自己负责；如需 cleanup 也写，是另一处改动。
- `lib/update.uc` 对 `stopping` 落到既有的 TODO(design) 分支（返回 false），未改（不在允许范围）；只影响停止过程中恰好做 xray 更新校验的极窄情形。
- 前端（`overview.js` 等）把 `stopping` 当作不活跃、按钮规则与「正在停止」文案不在本卡范围。
- 等网络（`--boot`）时 `wait_network` 重写的 `starting` 原来固定写 `dns_tier: 'T2'`，会把早期状态的 T1 盖掉；一并改成按配置取 T1/T2（同属早期状态写入，测试 `network wait publishes starting and keeps the T1 dns_tier`）。
