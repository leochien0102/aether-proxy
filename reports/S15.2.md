## 偏差与待定

- 无生产修复、真机验收或部署结论。真实的是本机报文和监听/取消顺序；B 使用 Python 隔离中继代替真实 DNS 引擎。真实 chinadns 最小配置、TLS/host@ 及多上游并发未实测，列为建议 B0 的先行契约验证。
- P3 的 fail_open、P7 的 fragment/intent 为模型，不替代真实 daemon/nft/procd 回归；P4 使用纯 renderer 注入 WAN 上游映射，不实测 ubus。没有改变级别、缓存优先级或 T15.1 边界。
- 探针 response 只处理可控 A 回答，不是通用 DNS 解析器。生产 CNAME/压缩/恶意包/TC/TLS/多上游的合约和新增测试在设计文档明确列出，不把 dns_test boolean 当 IPv4。
- P5 实验以实际 DNS 往返证明端点可用；生产门禁建议检查实际引用 socket，不以真实外网回答作为启动前置条件。监听不代表代理健康，健康仍归 monitor。
- 默认 T1 的 GFW 查询不送 bootstrap/系统；现有用户主动开启 T2 或已有 T3 降级策略的直连语义不由本卡改变。首次 start 接管前与显式 stop 后不在 T15.1 连续性承诺范围。
- 任务卡停点未触发：受控环境能证明真实 socket/报文顺序；推荐不要求改变 DNS 级别、LKG 优先级、boot 配置语义或 restart 保护边界。真实组件的后续契约若不满足必须停止，不自行扩范围。
- 待负责人决定：B 私有端口/最小配置、TC 是否 TCP 重试、socket 归属校验、reload/monitor 是否仅复用新 gate。建议 B0–B3 及设备窗口分别拆卡。
- `scenarios()` 超过百行，因为按 P1–P7 集中编排顺序实验，共享同一组隔离 socket 并由统一 finally 清理；协议、资源管理、取消验证已分离，不是生产状态机。
- 新增代码中无 TODO(design)；未决均在设计文档明列，不暗中实现。
