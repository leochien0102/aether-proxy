# T12.3 B25 采样与内存聚合

## 结论

monitor 内的代理计数器采样与按天内存聚合已落地：开关开启时每轮 tick 采样一次
`proxy_tx/proxy_rx` 并累计 `tx/rx/observed/healthy`；关闭时零采样（连 nft 计数器查询
都不执行）。当日数据只在内存，重启丢失属预期；不写 `usage.json`、不做 history API、
不做 UI、不改配置默认，版本未动。

- `aether-proxy/src/lib/usage.uc`（新增，纯聚合）：无 I/O、无时钟访问。输入当前
  tx/rx、墙钟 `now`、单调钟 `elapsed`、上限 `cap`、服务状态、`proxy_ok`；
  输出/累计当日 `tx/rx/observed/healthy`，跨天时把完成日移入内存 `days` 表。
  规则逐条对应 docs/b25-heatmap.md §4：
  - **首次基线不计量**：`day == null` 的首个样本只记录 `last_tx/last_rx` 基线，
    字节与秒数均不计（即使 elapsed/计数器可读）。
  - **计数器变小按清零**：`current < previous` 视为表重建，`delta = current`；
    tx/rx 独立判定。基线从未可读时，首个可读样本按 `delta = current` 起算。
  - **elapsed 上限**：`min(max(elapsed, 0), cap)`，monitor 传入
    `interval_ms × 2`（`C.USAGE_ELAPSED_FACTOR`），休眠/跳轮不会一次性灌入大量秒数。
  - **跨本地日期切日**：本地日期（`localtime` → `YYYY-MM-DD`）与存活日不同时，先把
    旧日连同自上次样本的待计增量写入 `days`，再从当前计数器起新日；中间日不回填 0。
  - **时钟回退不写负数**：新日期早于存活日时保留当前日继续累计（不重开旧条目）；
    elapsed 为负一律按 0 计；`now` 非法（非数值/负数）整样本忽略。
  - **observed/healthy 口径**：`observed` 仅在服务处于 `running/degraded/failsafe` 且
    本轮读到计数器时增加；`healthy` 仅在 `running && proxy_ok === true` 时增加，
    每轮后 `healthy ≤ observed` 收口。计数器读不到只跳过本轮字节（保留基线，
    下次可读样本接续序列），不记事件。
  - **内存窗口**：`days` 保留最近 89 个完成日（+当日共 90，`C.USAGE_DAYS_KEEP`），
    滚动裁剪；T12.4 落盘时口径一致。
- `aether-proxy/src/lib/counters.uc`（新增）+ `cmd/stats.uc` 重构：T8.12a 的
  `nft -j list counters` 读取（argv、超时、解析、失败语义逐行保留）抽成共享
  `counters.proxy_counters(ctx)`；`stats` 命令改调共享函数，输出不变
  （`tests/stats` 全绿即证）。monitor 采样复用同一实现。
- `aether-proxy/src/lib/monitor.uc`：`create_daemon` 初始化 `usage`/`usage_mono_ms`；
  tick 在停止检查之后、`next()` 之前调用 `sample_usage(daemon, obs)`——
  第一行即 `snapshot?.stats?.heatmap_enabled !== true` 直接返回，关闭路径不构造
  nft 命令；elapsed 在发起 nft 读取**之前**用单调钟量好，读取耗时计入下一轮。
  `cap` 取 `interval_ms(daemon.machine) / 1000 × 2`；服务状态用本窗口实际所处的
  `machine.state`（转换前），健康判定用本轮 `obs.proxy_ok`。
- `aether-proxy/src/lib/const.uc`：新增 `USAGE_ELAPSED_FACTOR = 2`、
  `USAGE_DAYS_KEEP = 90`。
- 不记录域名/节点/目的地：usage 状态只有日期与四个数字。

## 决定与理由

- **共享读取放新文件 `counters.uc` 而非 usage.uc**：任务卡要求 usage.uc 保持纯聚合
  （测试要注入假计数器/假时钟），而 `stats` 命令与 monitor 是仅有的两个消费者；
  `counters.uc` 只依赖 `const`+`sys`，两层都能干净 import，避免 cmd→monitor 的层级
  倒挂。任务卡允许清单的「必要时抽成共享函数」即指此类调整。
- **回退日保留存活日而非重开旧条目**：设计 §8「时钟回退保留旧条目」。重开旧日会在
  `days` 里产生第二次写入/合并歧义；继续在存活日累计保证任何时刻 `day` 唯一、
  字节单调不减、秒数永不为负。日期追上后按正常切日处理。
- **内存裁剪提前到 T12.3**：设计把「裁剪在落盘时做」写在 T12.4，但长驻 daemon 的
  `days` 无界增长没有必要；在切日时按同一 90 日窗口裁剪，T12.4 落盘口径自动一致。
- **关闭判定用 `!== true`**：T12.2 的快照字段是严格 bool（`off_unless_one` 归一化），
  `!== true` 使缺失/异常快照都落在关闭侧，与「关闭路径零采样」的验收一致。
- **集成测试只验证采样入口**（任务卡原文）：假时钟的逐日账目全部下沉到单元测试；
  monitor 集成只断言「关→零 nft 计数器查询、聚合为空」「开→每 tick 恰一次采样、
  基线/增量/坏读/接续」。

## 测试

- `tests/unit/usage.uc`（新增，20 例）：假时钟用 `timelocal` 构造（与宿主时区无关，
  取正午避开 DST），假 nft 用纯数字——首次基线、首样本不计、同日增量、tx/rx 独立
  清零、坏读跳字节保基线、坏读后接续、基线从未可读、elapsed 上限、负 elapsed、
  `starting` 不计 observed、degraded/failsafe 计 observed 不计 healthy、
  `proxy_ok=false/null` 不计 healthy、坏读轮 healthy 不越界、跨日结转（含待计增量）、
  跨日坏读、多日跳跃不回填、时钟回退保留存活日且零秒、非法 `now` 整样本忽略、
  89 完成日滚动裁剪。
- `tests/monitor/driver.uc` 新增 `heatmap-off`/`heatmap-on` 场景（12 项断言）：
  关闭时两次 tick 均无 `list counters` 调用且聚合为空；开启时每 tick 恰一次采样、
  首样本仅基线、增量累计（2500/2000）、degraded 轮 healthy 恒 0、坏读跳字节保基线、
  下次可读接续序列。
- `tests/monitor/run.sh`：新增 `heatmap-conf`（sample 夹具 + `stats.heatmap_enabled '1'`）
  并跑两个新场景；`tests/stubs/daemon-bin/nft` 增加 `-j list counters` 分支——
  仅当 `$SYSROOT/nft-counters.json` 存在才输出计数器，否则空输出成功退出，
  其余测试路径行为不变。
- `tests/stats/test.py` 未改：其独立 nft stub 继续钉住共享函数的 argv、超时与全部
  失败形态（fail/空表/缺计数器/非 JSON/非数组），保证重构后 `stats` 输出逐字节不变。

## 偏差与待定

- 任务卡允许清单未列 `tests/stubs/daemon-bin/nft` 与 `tests/monitor/run.sh` 的
  conf 准备段：monitor 集成验证「开启时采样」需要 nft stub 能应答计数器查询、
  需要一个开启开关的 conf，均属测试基建的直接组成部分；stub 分支默认路径
  （文件不存在 → 空输出）对既有场景是惰性的。
- 当日数据仅在 `daemon.usage` 内存对象中，本卡无任何读取入口（API 属 T12.5）；
  观测手段即单元/集成测试的断言。
- 真机 H28K 验收（`usage.json`/API/UI）按拆分归 T12.4–T12.6，本卡未覆盖。
- 未 bump 版本；未 push。
