## 停点证据

### 基线源码边界

`aether-proxy/src/lib/supervise.uc`：

1. `start_child()` 用 `uloop.process()` 创建 child 后才取得 PID、调用 `sys.write_atomic(pidfile, ...)`（约 95–109 行）。
2. PID 文件写入失败时发送 TERM，再由父进程的 uloop timer 在 1000 ms 后升级 KILL。
3. 此时若父进程被 SIGKILL，父进程的升级 timer 不再执行。
4. `kill_stale()` 依赖可读的 PID 文件和命令行子串；它不是本卡要求的“所属独占目录＋完整配置 argv＋可执行文件＋PID 生命周期”身份校验器。不能将它直接用作新 private child 的安全残留清理器。
5. 正式 child 的现有退避不能用来冒充短命 bootstrap 的无 respawn 生命周期；`raw_log` 也不是新生产方案的替代选项。

### 实际进程实验

在本卡 `tests/` 下用 `tempfile.mkdtemp(prefix='.t15.6-lifecycle-')` 建实验目录，结束后删除。未修改 tracked 文件。

实验调用实际的宿主 ucode 和生产 `aetherproxy.supervise`，不是 Python 生命周期状态机：

```ucode
import * as uloop from 'uloop';
import * as supervise from 'aetherproxy.supervise';
uloop.init();
let child = supervise.create({
    name: 'aether-bootstrap-dns',
    argv: [ '/bin/sleep', '60' ],
    run_dir: ARGV[0],
    backoff: [ 5 ],
    raw_log: true
});
child.start();
uloop.run();
```

运行方式：`tests/host/ucode -e <上述程序> -- <实验目录>`。

控制器为 Python，仅负责构造故障、实际信号、proc 观察和实验收尾：

1. 先将 `<实验目录>/aether-bootstrap-dns.pid` 建成目录，使原子 PID 发布的 rename 失败。
2. 用 `subprocess.Popen(..., preexec_fn=...)` 启动上述 ucode；preexec_fn 设 `SIGTERM=SIG_IGN`。这是人为故障注入，不宣称真实 DNS 引擎平时忽略 TERM。
3. 从 `/proc/<父PID>/task/<父PID>/children` 查直属 child，要求 cmdline **精确等于** `/bin/sleep\0` + `60\0`；保存 stat starttime。
4. 观察后等待 30 ms，对 ucode 父进程实际发送 SIGKILL，并 `wait()` 直属父进程。
5. 等待 1.15 秒，核对原 child starttime 相同且状态不是 Z/X。该时刻已超过原监督器 TERM grace。
6. finally 中再次核对 starttime 后仅 SIGKILL 本实验 child。没有广泛 pkill、同名扫描杀进程或修改宿主服务。

## 安全资源协议设计（本轮仅设计，待负责人确认）

### 0. 结论、假设与尚未闭合项

本轮没有写生产实现、测试实现或修改 docs。以下步骤和实验均为**待实现/待执行**，不能以状态表或流程描述代替竞态证据。

建议先验证候选 P：**无额外 helper 的受监督 gate shell；父确认并原子发布完整身份后才允许同 PID exec 引擎**。它针对“引擎已执行、身份尚不可恢复”窗口提出关闭办法，但目前**不宣称整个资源协议已经可实施并满足 C6/C8**。

两项必须先解决的验证/机制门槛：

- **G1：gate 的有界、无二次 fork 等待。** 下述原型依赖实际 `/bin/sh` 的 FIFO 双向打开及带超时的 builtin `read`。不能按 OpenWrt 版本推断支持，也不能偷偷改用 bash、timeout、轮询 sleep 或 Python 作为生产依赖。需在已有目标 shell 上验证；宿主 `/bin/sh` 与设备 shell 不等价。前置能力失败时禁止创建 bootstrap，不用 LKG 掩盖能力错误。
- **G2：孤儿信号的原子目标绑定。** `stat/starttime/exe/argv` 检查后再执行数字 PID `kill` 存在检查—使用竞态。重复检查只能缩窗，不能证明绝不误杀。当前已检查的 ucode 2025.07.18 接口没有找到可直接绑定该生命周期的 pidfd signaling API。**本设计不建议降低身份检查，也不把数字 PID kill 伪装成原子安全操作。** 若要求在目标恰好退出并被立即复用时也绝不误杀，则孤儿 TERM/KILL 部分仍未闭合；在找到原卡允许的机制以前，只能拒绝不安全信号、保留证据并返回清理失败，不能声称已完成安全收口。

G2 不涉及改 B2：B2 的身份观察可决定“不报 ready”，而发送信号会作用于另一个进程；不能从 B2 的观察正确性推导数字 PID kill 的原子正确性。

本轮只读核对了本 worktree 的最低版本源码：`tests/host/src/ucode/lib/uloop.c:990–1051` 在 C 内部 fork 后直接 execvpe，父侧才构造 uloop handle；没有脚本可插入的 pre-exec 回调。其 `process_fns` 只有 `pid/delete`，delete 文档明确不终止进程；`task.kill` 是数字 PID 的 `kill(..., SIGTERM)`。检查现有 fs/socket/core 导出未找到 pidfd API。这是当前接口证据，不是对所有 Linux 可用机制的不可能性证明，也不授权修改共享 host 源码。

环境与威胁边界：

- 原生 Linux/OpenWrt，同一 PID/mount namespace；独占代目录为 0700、普通文件 0600，由本服务持有；不将同权限恶意篡改者当成隔离可抵御的攻击者。但意外损坏、同名其他实例、二进制替换与 PID 重用仍须 fail closed。
- boot ID 区分设备启动；starttime 取 `/proc/<pid>/stat` 第 22 字段，按右侧 comm 括号结束定位，保存原始整数，不用墙钟或 PID 文件 mtime 代替。starttime 不是密码学随机标识，也不宣称单独可以消除 PID 重用竞态。
- “有界”是同一单调 deadline 下不无限轮询/派生；不能保证 SIGSTOP、不可中断内核等待、无调度机会的进程在墙钟 N 秒内一定消失。到界仍不能证明退出就明确失败，保留身份，不继续成功路径。
- 拟议预算：最多 10 个候选、begin 的握手/授权/owned ready 共用原 5000 ms 绝对 deadline；gate 无授权等待上限 5 秒，不以重试续期。每次 end 的独立清理上限拟为 7000 ms（含未登记 gate 的正常超时等待，或已登记 child 的 TERM 1000 ms→KILL 后回调/核验等待；不得串行重置总上限）。候选回收耗时也消耗 begin 的原 deadline，因此 begin 最坏只允许原 5 秒加最后一次清理尾部 7 秒，不是每个候选重新获得 5 秒。7 秒是本次待确认的内部清理预算建议，不新增用户选项，不改正式 child grace。
- 任意元数据都不是单独的杀进程许可；必须与实际进程交叉验证。身份不可确定时不广泛扫描后杀同名进程。

### 1. 候选比较

| 候选 | 身份发布与执行 | 评价 |
|---|---|---|
| A：直接 fork/exec DNS，父稍后写 PID | 引擎可以先于任何可恢复身份运行 | 否决；正是前次风险的起点 |
| B：child 登记 → 父确认 → 授权 exec | child 先写 shell 自身身份，父校验后写确认及授权 | 概念可行，但不能假设 ucode 有原地 exec；若用 shell 再 fork ucode 登记 helper，会新增 helper 的 fork 前后/未登记/孤儿/退出回收窗口。未经相同层级论证不能采用 |
| P：父确认受阻 gate → 发布身份 → 授权同 PID exec | 父已有 uloop child PID；实际观察 gate shell 后登记身份。shell 只用 builtin 等待授权、关闭控制 FD、exec 引擎 | 建议先验证，少一个 helper/reader 生命周期；仍受 G1/G2 约束，不是完成结论 |

不采用 `raw_log` 代替无 respawn。不采用“子进程自己知道 PID，所以天然可恢复”的推论。不加入一个在 daemon 死后持续监督引擎的常驻管家来改变原卡模型。

### 2. fork 前的每代记录与所有权

代目录逻辑布局：`run_dir/bootstrap/<generation>/`。`generation` 是原子创建、不可复用的随机代标识；不能用固定名或只用 PID。任何目录/记录准备失败时不 fork。

| 对象 | fork 前内容/权限 | 谁拥有、何时可删除 |
|---|---|---|
| 代目录 | 原子 mkdir 0700，校验实际目录、属主与无 symlink；父容器仅用于枚举代，不递归清空 | 本代；只定向删除登记项，未知文件保留并报错 |
| `plan.json` | 格式版本、generation/nonce、boot ID、父 PID/starttime、父实际 exe dev/inode 及完整 argv、代目录 dev/inode、配置路径/哈希、选定引擎路径及 resolved exe dev/inode、**完整引擎 argv 数组**、完整 gate argv/解释器 exe 身份、端点、创建单调时刻/共享 5 秒 deadline、owned 文件清单 | 父 fork 前通过 `sys.write_atomic` 写入、回读；cleanup 可读；最后删除 |
| `bootstrap.conf` | 同一冻结 snapshot 的 boot_upstreams 完整列表，最小私有配置；0600，内容哈希与 plan 对应 | 本代；引擎退出前不得删/替换；不是正式 current |
| `grant.fifo` | mkfifo 0600；父在 fork 前以 RDWR+CLOEXEC 打开，记录 inode；无授权字节 | 本代 IPC；不是正式日志 FIFO，不是 handoff；两端退出/关闭后才 unlink |
| `identity.json` | fork 前**不存在**；不得预写虚假 PID/starttime | 父在实际观察 gate shell 后原子写入；授权前回读核对 |
| `authorized.json` | fork 前**不存在** | 父完成身份确认后、写任何授权字节前原子写；它表示“可能已经获准 exec”，不表示引擎已启动 |
| `.pid`（若兼容 supervise 需要） | fork 前不存在；不能用它作为唯一身份来源 | 写失败也不得授权；由本代 supervise 清理，不影响正式 DNS pid |

plan 必须在任何 `uloop.process` 前完整落盘；创建后 handle 立即登记 `ctx.bootstrap_handles`，其 owned 清单与创建进度逐项记录。没有完整 plan 就没有启动许可。记录发布失败需清理已知 owned 项，不能靠扫描同名进程弥补。

普通文件仍用 `sys.write_atomic`，临时文件名/权限/归属也纳入定向清理。控制 FIFO 是**流式 IPC**，不能用 rename 写 FIFO；需明确的有界 fs stream 写/flush/close处理。这是 `supervise` 内部授权 API 的一部分，不是第二种普通文件写入接口；负责人若不认可此 IPC 用法，P 仍不可进入实现。

目录所有权不由文件名证明。cleanup 必须拒绝 symlink、越出代目录的路径、非法 schema、同名不同 inode 项和不认识的外置文件。损坏时保留证据，不执行 `rm -rf run_dir`，也不把“路径看起来在 run_dir 下”当成完整身份。

### 3. 协议状态表

状态由**已提交的记录＋实时进程观察**推导；内存 `state` 或一份可撕裂的覆盖式状态 JSON 不得成为唯一依据。

| 状态 | 已持有资源/所有者 | 引擎能否执行 | 父正常动作 | 父在该阶段 SIGKILL 后的处理依据 |
|---|---|---|---|---|
| S0 准备中 | 父创建目录/配置/plan/IPC；无 child | 否 | plan 回读完整后才能推进 | 没有授权；只处理可证明的 owned 文件。不完整记录不据此杀进程；如所有权也不清楚则隔离报错 |
| S1 plan 已提交、fork 未确认 | plan、FIFO、父内存 handle；child 可能尚未 fork，也可能仍在 fork→exec shell 间隙 | 否；唯一 fork 目标是 gate，不是 DNS | 等待 gate PID/实际 exe/完整 argv 可验证，受共享 deadline 约束 | 不能凭 prepared 状态谎称“肯定没 fork”。未登记 pre-exec child 甚至可能暂时仍显示父的 exe/argv；不得杀疑似 daemon。gate 最终无授权超时退出；无法证明其已退出时保留 plan 并报错 |
| S2 gate 已观察，身份尚未提交 | uloop 直属 gate PID；父有实时身份，磁盘仍无完整 identity | 否 | 写 identity，含 PID/starttime、gate/engine 两种允许形态和 plan 哈希，回读；任何失败走 stop，不授权 | 无持久身份不可按 PID 文件杀；可以只读定位完整 nonce gate 的候选作核验/等待，不能给扫描结果自动生成杀进程许可；超时/不确定保留证据 |
| S3 identity 已提交，未授权 | 记录固定 gate PID/starttime；无授权字节 | 否 | 派发停止意图、复核 gate 与 identity，写 authorized | cleanup 有完整 gate 身份；取消/拒绝授权。可等待 gate 自行超时；安全 signal 仍须满足目标绑定条件 |
| S4 authorized 已提交，授权发送结果不明 | 完整 plan/identity/authorized；父可能尚未发送，也可能已经发送 | **按可能执行处理** | 在共享 deadline 内仅一次发送完整 nonce 行；失败也不得回退成 S3 | 父死后不能根据“没有 started 标志”断言引擎没执行；cleanup 接受同一 PID/starttime 的 gate 或精确 engine argv/exe，等待或安全终止 |
| S5 gate 已读授权、exec 过渡 | 同 PID/starttime；控制 FD 应关闭；shell 或引擎形态可能切换 | 可以 | 不依赖 accepted/started 文件；固定本次 PID，验证 exec 身份再检查 owned UDP/TCP | 与 S4 同样处理；跨 exec 读取不一致时重采样/失败，不把混合采样凑成身份 |
| S6 引擎执行/就绪/解析 | supervise 直属引擎；代文件；本端点 socket；无 respawn | 已执行；只能 B1 节点解析 | B1 成功/失败/取消均进入 end；child 退出不重派生 | cleanup 使用 identity 固定生命周期、完整配置 argv、实际 exe、代目录；socket 仅是辅助证据，不是身份替代 |
| S7 收尾中 | 身份/授权记录一直保留，禁止再授权；可能仍有活 child | 不再授权；已获授权者仍按可能执行处理 | TERM→独立有界 KILL→直属真实退出回调；关闭 IPC/timer；未证实退出不得删身份 | 后续 cleanup 重复相同收口；不能因为存在 stopping 标记就删记录或跳过存活核验 |
| S8 已停止、文件回收 | 直属回调已到；或孤儿已证实不再执行/不再是旧身份；本代 FD 已关闭 | 否 | 仅删除 owned 文件；plan/identity 最后删除，最后 rmdir | 删除中途死后按 remaining manifest 幂等继续；未知项不删。非父进程不声称 wait 孤儿 |

状态 S1/S2 的谨慎退路不是“任务已收口”：如果无法证明未登记 child 已退出，cleanup 返回失败、保留代与错误，不启动下一代来掩盖它。没有授权只保证不会启动 DNS，不保证未登记 gate 已即时消失。这一 liveness 缺口必须在后续实验中证明可安全处理，否则仍是停点。

### 4. gate 与授权的精确含义

P 不需要“child 写身份”helper。gate 的逻辑仅允许以下 builtin 操作，不能调用循环 sleep、登记子进程或后台 awk：

1. 先用 builtin `cd` 进入固定本代目录，再打开本代 FIFO 为 RDWR，避免父已死时阻塞在只读 open。父确认与残留核验还必须通过 `/proc/<pid>/cwd` 的实际目录 dev/inode 证明所属代；只看配置路径不够。
2. 以有界 builtin read 等待一行 token；超时、EOF、短/错 token、打开失败均直接非零退出。
3. 核对**完整** token；关闭控制 FD，然后用 shell `exec` 原地执行预先固定的引擎与 `-C <本代配置>`。不 fork DNS，不自动重试。

这是行为规格，不是已验证 shell 程序。`read -t` 是否覆盖整行、RDWR FIFO 和 CLOEXEC 语义均须实测；不能在不支持的 shell 上悄悄换无界 read。

父授权顺序：

- 固定 `uloop.process` 返回 PID；实际观察 gate shell 的 starttime/exe/完整 argv/代目录一致；仅有 proc.pid 不够。
- 原子发布并回读 identity；`.pid` 等任何必需记录失败均不授权。
- 派发/核对停止意图与原 5 秒 deadline；记录 `authorized.json`，其中包含 identity/plan 的完整对应关系。
- 再核对停止意图与 deadline，仅在仍允许时向 FIFO 发送一次完整随机 token 行。将发送开始后的任何错误都视为“授权可能已交付”，不擦掉 authorized。
- 父获得身份前 token 不入 FIFO；任意晚到的 gate 不能靠“文件存在”放行。FIFO 存在不是授权，PID 文件存在也不是授权。
- token 写入需单消息有界、禁止多 writer/重复复用、处理 write/flush/close 失败。拟固定为 64 个 hex 字符加换行，远小于 Linux PIPE_BUF；FIFO 是新建空队列，只允许父一次写入，父自身 RDWR 保证有 reader。不能通过循环写入填满队列。已查最低版本 fs.open 没有 O_NONBLOCK 模式标志，**不虚构 `r+ne` 一类可用接口**；单次小消息的 write/flush 有界性仍属 G1 待验证。不能把部分写入当成功；即使父误报发送失败，完整身份已先提交，所以不重新制造无身份引擎窗口。

**关键不变量**：任何可使 gate 执行引擎的 token，在其第一个字节可能被交付前，完整 identity 和 authorized 已经原子发布并回读。父死在任意写边界只能导致“没有 exec”或“可能 exec，但有完整恢复身份”；不得出现第三类。需用实际时序阻塞实验验证实现满足它。

authorized 是保守承诺，不是可撤回的互斥锁：一旦 token 可能被消费，删除授权文件也阻止不了已经获准的 exec。因此 end/cleanup 不能以删 grant 替代停止该生命周期。父死在最后一次存活检查后，已获准 gate 仍可能 exec；不承诺它会自动感知父死亡。

取消语义也不能过度声称：父观察取消后不再派生或发送新授权；取消前已提交的授权可能与取消并发被消费，必须按既有 child 收尾，禁止后续 Xray/正式 DNS/handoff/成功探针。这个方案没有额外 helper/reader fork；若实现引入这些派生就必须重新分析，不能藏在“日志”或“登记”里。

### 5. cleanup、PID 重用、元数据损坏及 TERM 无效

cleanup/下次 start 通过同一入口执行，仍服从现有全局锁与 daemon 活跃性检查；不改 init。只有原 daemon 已死/明确授权交接，才能收口其代，不能清理并行仍活的另一实例。

校验必须至少包含：plan schema/boot ID/代目录 dev+inode+属主以及进程实际 cwd 归属；配置路径与哈希；identity 与 plan/authorized 的对应关系；PID/starttime；实际 exe 对象及完整 NUL 分隔 argv；只接受明确登记的 gate 或 engine 形态。PID 表示哪个进程、exe 表示执行什么、argv 表示使用哪个配置、目录/nonce 表示属于哪一代，不能互相替代。二进制在记录后被替换导致身份不匹配时停止并隔离，不借 B2 socket ready 绕过 exe 校验。

| 故障 | 处理 | 不允许的处理 |
|---|---|---|
| plan/config/FIFO 准备失败 | fork 数为零；定向清理已知 owned 项；错误返回 | 创建 child 后再补身份 |
| `.pid` 或 identity 写失败 | 不发布 authorized、不发 token；直属句柄走 stop/真实回调；父已死则依无授权规则保留/等待 | 仅凭 LKG 继续启动并遗留 gate |
| authorized 写/回读失败 | 不发送 token；已有身份继续留存至退出确认 | 吞错后 exec |
| token 发送中父死亡/写失败 | 按可能已授权收尾；不再次发送；完整身份必须仍在 | 把“没有收到 ACK”当成没有 exec |
| identity/authorized 后来丢失、截断或不一致 | 不凭残缺记录杀；保留剩余文件、报错并阻止继续成功启动 | 从同名进程猜回 PID；删证据后声称已清理 |
| PID 已不存在或 starttime/boot ID 不符 | 不向该 PID 发任何信号；旧生命周期不再执行不等于杀了新 PID | 只因 PID 相同就 TERM/KILL |
| 同名进程/同引擎另一个配置/另一个代 | 完整 argv、路径、nonce、exe/lifecycle 区分；无匹配就不发信号、不删其文件 | substring 命中、占位 socket 或同进程名即认领 |
| 原 child 忽略 TERM | 原监督器存活时用独立 TERM grace→KILL→真实回调；KILL 或回调仍未证实退出则保留身份返回失败 | 只返回 stop 已发送；timer cancel 后删除 PID/身份 |
| 父已死，原引擎忽略 TERM | **必须先解决 G2 才能交付安全 KILL**；目前保守设计只允许非信号隔离/失败，不声称完整回收 | 借“多次读 starttime”宣称原子安全；广泛 pkill |
| gate 未登记且被 SIGSTOP/迟迟无调度 | 不允许引擎执行；不能保证其自动定时退出；保留记录并显式失败 | 通过等待 N 秒假装进程一定不存在 |

直属 child 与孤儿必须分开：父仍持有未 reaped 的直属 child 时，退出后 zombie 使 PID 在回收前不能重用，这是可能用于安全 signal 的前提；但需审计 uloop 的实际 reaping 点与所有嵌套 event-loop 派发，证明 kill 期间不会先 reap 后误用旧 PID。不能仅根据 JS 句柄非 null 就假定 PID 被内核保留。孤儿没有这个前提。

对孤儿，若 identity 与实际进程仍一致，只是可识别，不等于可原子发信号。若 old identity 已消失，可报告“不再执行/不再属于旧身份”，不得报告本进程 wait/reap 成功。socket 已关闭也不能单独证明进程退出。

### 6. 每个故障窗口的可重复实验与判定（均待执行）

实验 harness 只能负责外部 barrier、故障注入与观测；必须运行真实拟实现的 ucode/supervise/gate。测试 hook 不参与生产授权决策，不能让测试 hook 替实现修复竞态。每个 barrier 要保存真实 PID/starttime/argv/exe、文件字节、单调时间线；父 SIGKILL 后先保留现场，再用真实 cleanup/下次 start 收口。

| ID/注入点 | 可重复方法 | 必须命中的判定 |
|---|---|---|
| F0 目录/plan/config/FIFO 准备逐项失败 | 在各 syscall/API seam 注入错误；实际目录/权限/rename 故障交叉验证 | `prepare_failure_has_zero_forks_and_zero_grants`；owned 外预置文件逐字节不变 |
| F1 plan 完成、uloop.process 前父死 | 在 pre-fork barrier SIGKILL；确认无 child 曾创建 | `prepared_without_fork_has_no_engine_or_authority`；只删除 owned 项；intent/handoff 不变 |
| F2 fork 后、父未取得/持久化 PID | 在 uloop 返回/登记 seam 阻塞父；实际 SIGKILL；观察 gate 最终启动但收不到 token | `unregistered_child_never_executes_engine`；不得把没有 PID 文件判成无人；清理不能证明退出时明确失败并留 plan |
| F2b fork→exec shell 的内核调度间隙 | 用户态 after-fork barrier不能精确证明此 C 内部窗口；在不改共享 host 源码前提下用重复 SIGKILL stress，记录覆盖不足 | 静态不变量是唯一 exec 目标为 gate、无 token 不进引擎；stress 未命中不能记“该窗口实测 PASS”。精确暂停此窗口的机制待确认，不加 ptrace/gdb 依赖或改共享 host |
| F3 gate 已观察、identity 写入中 | 注入 atomic write/rename/回读失败与 `.pid` 失败；父分别存活/被 SIGKILL | `identity_failure_never_grants_exec`；存活父真实退出回调到达；无 timer/FD 增长 |
| F4 identity 已提交、authorized 前 | 实际 SIGKILL；另测此刻 SIGTERM | `confirmed_but_ungranted_gate_does_not_exec`；停止优先，不发生后续服务 fork |
| F5 authorized rename 前后、token 前 | 每个边界 SIGKILL；记录有无 authorized，不人为补写 | `possible_authority_always_has_complete_identity`；cleanup 不依赖 started ACK；未送 token 时不得误认为已 ready |
| F6 token write/flush/close 逐个失败或父死 | 流 IPC seam 注入短写/失败；真实完整写与断行写对照；观测真实 gate | `delivered_or_uncertain_grant_keeps_identity`；短/错 token 不 exec；不重复授权 |
| F7 gate 已消费 token、exec 前父死 | token 消费点 test-only builtin barrier，不能后台派生 helper；取消 barrier 后观察 | `exec_after_parent_death_is_still_identifiable`；同 PID/starttime、精确 engine argv；明确允许此时启动而依靠 cleanup，不声称自动即时终止 |
| F8 exec 前后混合采样 | 控制引擎延迟启动，重复读取 shell→engine 过渡；同名他实例持续运行 | `mixed_exec_samples_never_authorize_cleanup_signal`；不误认另一实例 |
| F9 引擎 owned ready/UDP/TCP/CNAME 查询期间父死 | 两个真实引擎＋B1，受控 UDP/TCP authority；各 barrier 实际 SIGKILL | 原 identity 可追溯；只有节点名/CNAME；后续 cleanup 先证实停止再删文件；这才可计 C8/C12 证据 |
| F10 TERM 被忽略；KILL 前/后父再死 | 实际忽略 TERM fixture；正常父与孤儿分别执行，记录真实回调/非父观察 | `ignored_term_never_erases_live_identity`；直属真实 wait；孤儿 G2 未解决不得记完整 PASS |
| F11 PID 重用/身份记录伪装 | 真实无关同名实例；另用 proc fixture 精确变更 starttime/exe/argv/配置/boot ID；信号 API spy 记录目标 | `mismatched_identity_receives_zero_signals`；真实另实例继续答复。fixture 不冒称真实内核 PID 复用 |
| F11b 最后核验→signal 的 TOCTOU | 在最终核验后、发信号前 seam 改变目标身份，验证方案是否有生命周期绑定；若只有 kill(pid)，这一反例仍成立 | 未提供原子绑定时必须标为未解决；不能用最终多读一次把失败挪到下一个 seam。实际内核 PID 复用不在当前宿主确定可重复的覆盖内，不改 pid_max/namespace/权限来造假 |
| F12 收尾每一次 unlink/rmdir 前后父死 | engine 已真实退出；文件删除 seam 逐项注入；放入外部预置文件及另一代 | `partial_cleanup_is_idempotent_and_generation_local`；identity 最后删；未知文件不删且不报完整成功 |
| F13 grant 超时/取消/缺失及 FD 继承 | 实际目标 shell：RDWR open、整行超时、CLOEXEC；反复成功/失败/TERM，检查 FD 与子孙进程 | `gate_has_no_helper_or_reader_forks`、`gate_controls_close_before_engine_exec`；不借宿主 bash 替目标 shell证明 |

F2b/F11b 的覆盖局限是显式未决项，不把纯模型或无法控制的时序写成已解决。前次实际 supervisor SIGKILL 实验仅证明旧方案风险，不能作为上述新协议成功证据。

后续反向验证至少应破坏：identity 前发送 token；把 FIFO 存在当许可；把 token 发送失败当未授权并删 identity；去掉完整 argv/starttime/exe 核验；停止后再授权；只按超时推定未登记 child 已消失。每项必须命中表中精确断言，恢复后重跑。

### 8. 自动保证与后续 cleanup 的界线

| 情形 | 自动可期待的保证（仍待实测） | 依赖后续 cleanup 的部分 |
|---|---|---|
| 无授权、gate 得到正常调度 | builtin 超时后自行退出；永不 exec 引擎；无 helper/reader | 剩余 owned 文件；父死后不能代替 init 触发 cleanup |
| 无授权，但 SIGSTOP/D-state/长期无调度 | 只保证没有有效授权，不保证墙钟即时退出 | 保留证据/失败；未证明退出不能宣称安全资源全收口 |
| 已授权、父 SIGKILL | 只有“任何获准引擎已有完整恢复身份”；不保证引擎感知父死或自己退出 | cleanup/下次启动终止/核验、owned 文件回收；G2 未闭合则不能完成这项 |
| 正常父存活的 end | 取消授权与 respawn，直属回收路径 TERM/KILL/uloop 回调 | end 报错/父再次死后的幂等续清；不能先擦身份 |
| 孤儿已不执行 | 可据实际生命周期消失判断旧实例不再执行 | 文件回收；不能声称非父 wait |

不增加自动定时清理服务、不改 init；如果用户从不再触发 cleanup/启动，已授权引擎可能持续存活，不能宣称 SIGKILL 自动立即回收。
