# T16.118 计时器收尾状态误报为握手失败

## 问题

2026-11-27 10:40（x86）与 11:09（H28K 复现）出现成对事件：

```
CMD_FAILED   {cmd:"rm -rf /var/run/aether-proxy/applied/<hash>", rc:-1,
              stderr:"timer exited early (status 1)"}
START_FAILED {step:"render", detail:"cannot publish …: generation cleanup failed"}
START_RETRY  {attempt:1, in_secs:30}
```

`rm -rf` 本身是成功的（同内容目录实测 0.00 s），`rc=-1` 与 `status 1` 都是
`aether-proxy/src/lib/sys.uc` 的命令包装器合成的：计时器子 shell 的最后一条
`kill -KILL "$runner"` 打在一个已被 `wait` 回收的 PID 上，`kill` 返回 1，
这个状态成了计时器的退出码，包装器把它当成结束帧的参数报成握手失败，
于是 publish 中止，靠 30 秒 `START_RETRY` 才起来。

触发条件经真机重演确定为「改写配置后的第一次重启」：卸载 `chinadns-ng` → 装回
`aether-dns` 不重启时 0 条事件，直接重启 7 秒成功；只有「配置文件被改动」的那次重启
会走到上述告警。

## 修改

1. `aether-proxy/src/lib/sys.uc`：`D` 分支在 runner 已完成（`runner_done=1`）时不再把
   计时器的非 0 状态当成握手失败——runner 的真实退出码已经通过 `R` 帧到达，
   收尾 kill 的状态只是记账。
2. `aether-proxy/src/lib/pipeline.uc`：`remove_generation()` 在目标不存在时直接成功，
   并在 `rm` 返回非 0 时以「目录是否真的消失」为准——publish 只需要旧代目录不在了。

保留的语义：真超时仍是 `124/timed_out`；命令本身非 0 仍返回它的码；握手帧真损坏
（缺 `P`/`T`/`S`/`G`、帧不可解析）仍是 `-1`。

## 测试

- `tests/unit/sys_run_timer_handshake.uc` 新增
  `timer kill status never becomes a handshake failure`：命令忽略 TERM 并在宽限期后成功退出，
  断言不再出现 `-1` 与 `timer exited early`，且 stdout 完整。
- 全量单测：`1798 passed, 0 failed`（基线 1797 + 新增 1）。
- `tests/reload/run.sh`：`289 passed, 0 failed`。

## 真机验证

构建 1.3.1-r4 试用包后在 H28K 上做 10 次「改一项配置 → 重启」，统计
`timer exited early` / `generation cleanup failed` 的出现次数，并在结束时把配置、
服务与账本恢复原状。
