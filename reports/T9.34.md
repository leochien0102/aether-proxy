- 除本报告外，变更只在任务卡允许的 lib 文件、`tests/unit/`、`tests/status/`、`tests/daemon/`、`tests/stubs/`。未修改 09 事件目录、`log.uc` 等级表、LuCI、已有夹具或共享 runner。

## 检测与隔离约束

- 正常一次运行扫描：`nft list tables` 一次、`nft list chains inet fw4` 一次、`killall -0 clash` / `killall -0 mihomo` 各一次。表查询失败立即返回；链查询失败忽略输出，视为没有链。同插件多个迹象只返回一次。
- 名字严格取自 04：`inet ss_spec` / `ip ss_spec_mangle` → `ssr-plus`，`inet passwall` / `inet passwall2`，fw4 的 `homeproxy_` / `openclash` 链前缀，`inet nikki`，以及相应进程。没有扩展 dae 等未核实插件，也不再匹配任意 `passwall*` 表。
- 对未运行插件，只有 init 存在且 boot/configured 任一为真才产生一项 `{code: 'CONFLICT_ENABLED', args: {plugin, boot, configured}}`，两个布尔值均为 JSON bool。对方 UCI 包缺失或无法解析视为未配置。
- `CONFLICT_ENABLED` 仅是 notice；既不调用事件记录，也不依赖事件等级表。测试用已有事件文件哨兵验证不写事件；配置和 state 字节也保持不变。
- 新测试不创建 `uci.cursor`，直接在独有临时 confdir 写入 UCI 文本，避免默认 savedir；没有新引入 `uci.cursor(confdir)` 或写 `/tmp/.uci` 的测试。现有单元 harness 的 cursor 未改。定向测试前后和最终串行全量结束后 `/tmp/.uci` 均不存在；未清理或触碰宿主机的 UCI savedir。
- 所有新增冲突场景的 nft、killall、init `enabled` 均来自 `tests/stubs/`；按 argv 分开注入 tables/chains/进程响应，init 替身只读取私有 `.boot` 标记。`--confdir`、`--sys-root`、`--bin-dir` 均指向独有临时目录，不依赖宿主机插件、nft 或实际 clash/mihomo 进程。

## 原有断言逐条说明

1. `tests/unit/apply.uc` 的 `run_misc()`，原始期望数组 `[ 'clash', 'mihomo', 'passwall2', 'ss_spec' ]` 改为 `[ 'clash', 'mihomo', 'passwall2', 'ssr-plus' ]`。这是原测试里唯一把 `ss_spec` 作为返回冲突名的断言；输入仍保持真实的 `table inet ss_spec`，并未把 nft 表名错误改成插件名。
2. `tests/daemon/run.sh` 原第 6 场景仍注入 `table inet ss_spec`，原来的 error/precheck/无 nft 加载/无 dnsmasq 重启/等待重试/可停止断言全部保留；原来没有 `missing` 身份断言，本次补上 `conflict:ssr-plus`，不是删除或弱化旧断言。
3. 原测试并无字面量 `conflict:ss_spec` 的预期串；上述第 1 条是等价的旧名字数组断言。新增用例统一要求 `conflict:ssr-plus`，不改 nft 输入、历史文档中的事故描述或其他无关名字。
