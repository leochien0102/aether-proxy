# T16.49 默认保配置备份包含热力图账本

## 范围与根因

- 工作树：`/workspace/openwrt/aether-proxy-wt/T16.49`；分支 `feat/t16.49-usage-backup`；基线 `9f9658842ceb78ff1a51bfab6176b8e03401b2d7`。
- OpenWrt 默认 `build_list_of_backup_config_files()` 调用 `list_static_conffiles()`，后者直接将 keep.d 内容作为 `find` 参数。旧条目 `etc/aether-proxy/usage.json` 相对于调用 cwd 解析，在 `/root` 下丢失账本；归档阶段的 `tar -C /` 无法挽回枚举阶段漏掉的文件。
- `aether-proxy/files/aether-proxy-usage.keep` 改为唯一一行 `/etc/aether-proxy/usage.json`。安装位置仍为 `/lib/upgrade/keep.d/aether-proxy`，包不携带账本。
- `tests/ci/smoke-host.py` 同步精确字节断言；新增独立归档夹具 `tests/ci/usage-backup.py`。
- 不修改 sysupgrade、运行时、Makefile、workflow 或版本。没有刷机、固件镜像输入、真实设备访问、维护者构建树写入、push 或 main 合并。SDK 和验收产物仅写入本工作树 `.cache/T16.49/`。

## 归档验收设计与来源

夹具下载并校验 SHA-256 后原样使用 OpenWrt **v24.10.8** 的：

```text
https://raw.githubusercontent.com/openwrt/openwrt/v24.10.8/package/base-files/files/sbin/sysupgrade
https://raw.githubusercontent.com/openwrt/openwrt/v24.10.8/package/base-files/files/lib/functions.sh
https://raw.githubusercontent.com/openwrt/openwrt/v24.10.8/package/base-files/files/lib/functions/system.sh
https://raw.githubusercontent.com/openwrt/openwrt/v24.10.8/package/base-files/files/lib/upgrade/common.sh
https://raw.githubusercontent.com/openwrt/openwrt/v24.10.8/package/base-files/files/lib/upgrade/tar.sh
```

`jshn.sh` 取自该 OpenWrt 版本 `package/libs/libubox/Makefile` 指定的 libubox 提交 `49056d178f42da98048a5d4c23f83a6f6bc6dd80`（`sh/jshn.sh`）。所有预期哈希在夹具 `SOURCES` 中，运行时逐文件打印；`sysupgrade` 为 `227db731326313bd43553645523874f308a381f8593e20a03081f9cdfb1fca18`。

隔离方式：无特权 user/mount namespace + `chroot`；官方同版本 x86_64 rootfs 的 BusyBox 与 musl/libgcc 提供 ash/find/tar/gzip 等实际工具（只提取这三个二进制文件并建立 applet/loader 链接，不提取发行版 keep.d）。官方 rootfs SHA-256 为 `6c94190246a54088e3984fc0c4cbbb518972abb2b10a28e30a0c41554eea8b9d`。只从真实 IPK 的 `data.tar.gz` 读取指定 keep.d 常规文件，不把包整体安装到 rootfs，不执行包服务脚本。rootfs 中仅这一份 keep 清单；opkg status 为空；`/etc/sysupgrade.conf` 仅列 `/etc/config/backup-sentinel` 这个无关文件，不列账本或其父目录（保证旧路径反例有非空归档，而非只触发 tar 空输入报错）；不启用 `-c/-o/-k/-u/-n`，没有其它清单兜底。

每次实际命令形态：

```sh
unshare --user --map-root-user --mount chroot "$ROOTFS" \
  /bin/sh -c 'cd "$1" && exec /bin/sh /sbin/sysupgrade -b "$2"' \
  usage-backup /     /tmp/slash.tgz
unshare --user --map-root-user --mount chroot "$ROOTFS" \
  /bin/sh -c 'cd "$1" && exec /bin/sh /sbin/sysupgrade -b "$2"' \
  usage-backup /root /tmp/root.tgz
```

只切到被测试的 cwd，不先切 `/`；不改上游脚本，不硬编码 tar 输入。稀疏 rootfs 的 `/proc/mounts` 为空（无 ramdisk root），`/dev/null`、`/dev/zero` 是普通文件替身，后者仅供上游 tar header helper 读取零字节；无宿主设备绑定。空 init.d glob 的告警保留在各日志，不影响 `-b` 的归档输出。上游生成的 `etc/uci-defaults/10_disable_services` 也保留，不干预归档。

恢复检查读取实际 `.tgz` 的成员，要求 `etc/aether-proxy/usage.json` 恰好出现一次，提取后与原始已知账本 **bytes 严格相等**，另输出字节数与 SHA-256，且验证原件未改变。旧相对清单反例仅改变隔离 rootfs 中实际提取条目的开头 `/`：`/` 对照成功；`/root` 执行同一个恢复断言必须抛出 AssertionError（账本缺失），测试捕获这个预期红灯，若意外通过则整个夹具失败。

## 复跑与结果

### 实际 SDK 构建

独立下载官方 SDK，按官方 sha256sums 校验：

```text
openwrt-sdk-24.10.8-x86-64_gcc-13.3.0_musl.Linux-x86_64.tar.zst
SHA256 ac4a0405d2eea821b06f93c14ba13ffa90ad0457648903df7dde02570027ab21
```

构建复跑命令（仅本树缓存目录；不依赖维护者树）：

```sh
cd /workspace/openwrt/aether-proxy-wt/T16.49
CACHE="$PWD/.cache/T16.49"
mkdir -p "$CACHE/tmp"
export TMPDIR="$CACHE/tmp"
ARCHIVE=openwrt-sdk-24.10.8-x86-64_gcc-13.3.0_musl.Linux-x86_64.tar.zst
BASE=https://downloads.openwrt.org/releases/24.10.8/targets/x86/64
(cd "$CACHE" && curl -fLO "$BASE/$ARCHIVE" && curl -fL "$BASE/sha256sums" -o sdk-sha256sums &&
 grep -F "$ARCHIVE" sdk-sha256sums > sdk-sha256.check && sha256sum -c sdk-sha256.check)
tar --zstd -xf "$CACHE/$ARCHIVE" -C "$CACHE"
SDK="$CACHE/${ARCHIVE%.tar.zst}"
mkdir -p "$SDK/package/aether-proxy"
rsync -a --delete aether-proxy/ "$SDK/package/aether-proxy/"
printf '%s\n' CONFIG_ALL_NONSHARED=n CONFIG_ALL_KMODS=n CONFIG_ALL=n \
 CONFIG_SIGNED_PACKAGES=n CONFIG_PACKAGE_aether-proxy=m > "$SDK/.config"
make -C "$SDK" defconfig V=s
make -C "$SDK/package/aether-proxy" TOPDIR="$SDK" compile V=s -j2
diff -qr aether-proxy "$SDK/package/aether-proxy"
```

本次最初尝试顶层 `make package/aether-proxy/compile` 会递归处理内核依赖包，停止本次构建进程后改用上述 SDK 原生单包目标成功；没有伪造包，也没有修改任何 Makefile。完整本地脚本 `.cache/T16.49/build-commands.sh` 已收敛为成功命令，成功日志 `build-single-package.log`，源码副本 `diff -qr` 一致。
