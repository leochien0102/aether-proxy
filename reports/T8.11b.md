## 偏差与待定

- **同步了 main（T8.10 日志页、T8.11a 启用开关）**：本卡开工时 main 在 `7e4781f`，期间 T8.10/T8.11a 合并进 main，并新增了 `tests/luci/static.test.js` 的「po 不得有重复 msgid」检查。本卡的 po 追加与 main 的日志页都写了 `Error`/`Warning`/`Notice` 三条，直接合并会产生重复 msgid。因此把 main 合并进本卡分支（merge commit），并去掉本卡重复的三条（保留 main 的，译文相同）；`tests/luci/run.sh` 的「po has no duplicate msgid」随之通过。除此之外本卡没有改 main 带来的任何文件。
- **四个 tab 跨三个 UCI 段（`main`/`probe`/`dns`）**：10「高级页」要求四个标签，其中「开机与检测」同时含 `main` 与 `probe` 字段、「组件与 DNS 实例」同时含 `main` 与 `dns` 字段。LuCI 的 `s.tab`/`taboption` 只能挂在单个 section 上，而每个选项的读写段由所属 section 决定。实现改为**一个 `NamedSection('main')` 承载四个 tab**，属于 `probe`/`dns` 的选项设置 LuCI 的按选项覆盖属性 `ucisection`（`form.js` 的 `load`/`write`/`remove`/`depends` 都优先用它），从而既能凑齐四个 tab，又能把值写进正确的段。已在 24.10.8 与 25.12.5 两份 luci-base 的 `form.js` 中确认 `ucisection` 存在且语义一致。
- **`DeviceSelect` 的 ACL**：按卡上的要求没有自行改 ACL。`tools.widgets.DeviceSelect` 经 `network.getDevices()`/`getNetworks()` 走 `luci-rpc.getNetworkDevices`、`getWirelessDevices`、`getBoardJSON`、`network.interface.dump` 与 `network`/`wireless` UCI；这些都在 `luci-base` 自带的 `acl.d/luci-base.json` read 里（`luci-rpc` 四项 + `network.interface dump` + UCI `network`），而 `luci-base` 是任何 LuCI 页面的依赖，所以本包不必再显式授予。若真机验收发现只装了本 app 的 ACL 而受限，再在 `luci-app-aether-proxy.json` 的 read 里补这几项。
- **长 msgid 的单行长度**：「3a」要求单行 ≤ 120 列，但 `tests/luci/static.test.js` 用 `/_\('([^']*)'\)/g` 从源码抽取 msgid，把字符串拆成多段拼接会让抽取到的 msgid 与运行时的完整 msgid 不一致、po 检查失败（现有 `model/overview.js` 等也有同样的长行）。因此 `advanced.js` 里 5 条较长的说明文字保持单行（最长 197 列）。用户可见的说明文字本身很短，只有英文 msgid 较长。
- **本页没有 `depends`**：10「高级页」没有规定字段间依赖（如 `boot_check_targets` 依赖 `boot_wait_timeout > 0`），所以未添加；`static.test.js` 的 `depends` 检查因此是空真。若设计希望加，需要先在 10 里写明。
