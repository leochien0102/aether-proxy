## 验收

### 1. 本地功能

- 默认 bypass_cn/global：连续三次失败后，nft 默认链变为 GFW，chinadns 使用 GFW 名单和原有 T3 上游，状态和事件一致；没有重启 Xray，也没有写 UCI。
- 连续两次成功后还原规则；从未健康的启动则第一次成功即恢复；进入和退出各只记录一次正确等级、参数的事件。
- 设备 bypass_cn、proxy、direct 的实际 UCI 场景通过；独立 global 设备策略存在设计矛盾，仅能用原始渲染快照验证，不能声称有效 UCI 场景全过（见场景表和待定项）。
- 降级期间切换节点、切换默认模式继续带覆盖，关闭开关取消；即使降级产物逐字节相同，也更新 `status.mode` 而不修改降级开始时间。
- 锁冲突跳过后续补做；哈希失败、nft 应用失败均不提前发布降级状态或事件；下轮成功后补做。恢复时锁冲突同样保留覆盖，解锁后恢复。
- 停止与 cleanup 清除两个字段；没有目标、禁用开关时不做规则动作、不记录模式事件。
- `nft -c` 真机校验未执行：本环境没有 OpenWrt/H28K 的内核与授权，不使用 sudo/容器；提供新增 nft 黄金夹具供复核者在 H28K 验证。宿主机集成测试中的 nft 是替身，不冒充真实内核校验。

## 偏差与待定

1. **设计矛盾：设备 `global` 与 `proxy`。** 02 和本卡同时要求「global 设备覆盖降级」与「强制代理 proxy 不变」，但 05/schema 只允许 follow/direct/bypass_cn/gfw/proxy，页面的设备「全局」本来就是 proxy。未新增持久化枚举、未改变 proxy；渲染器能处理明确提供的原始 global 快照并有单测，但用户不能通过当前有效 UCI 表达此独立策略。`TODO(design)` 位于 `render/nft.uc`，须由设计负责人明确两种语义如何区分；不把这项端到端场景写成已完成。
2. **默认值快照兼容。** 本卡只许新增 fixtures，且要求旧黄金样本逐字节不变；直接物化 `degrade_gfw: true` 会改变四个既有 snapshot/echo expected。保守使用 schema `default: null, omit_unset: true`，未设置时保留缺省键，monitor/reload 以 `!= false` 实现默认开启；显式 0/1 则归一为 bool。这不改变实际默认功能，但与 12「未设置字段填默认」的一般规范有偏差，`TODO(design)` 位于 `schema.uc`。没有修改那四个旧 expected，请复审决定是否后续统一物化默认值。
3. **允许文件清单遗漏 pipeline。** 实际 `pipeline.render()` 会重建 runtime 对象，只保留 node_ip/dns_tier/restored；只改卡列出的文件会导致覆盖无法到达渲染器。额外改 `aether-proxy/src/lib/pipeline.uc` 一行透传，不引入新设计；真实 daemon 测试会在缺少这行时失败（状态声称降级但链体未变，初次集成验证已捕获）。其余没有改动清单外产品文件。
4. 顺手理顺的既有路径仅限本卡相关：live hash 取值共用（读失败保守拒绝应用，不再用旧哈希猜测）；无动作重载也更新 mode 等元数据（降级时切模式经常文本相同）。分别有 `failed live hash...`、`mode switch with byte-identical...` 回归断言。三处 daemon 旧等待条件因新增字段而误匹配，修复后原 267 条断言通过；不是删除或放宽失败断言。
5. `monitor.next`、`reload.run`、daemon 生命周期主函数是既有长状态机，本卡只在明确阶段接线，未为凑百行重构无关流程；新独立辅助函数保持短小。
6. 本卡新增 TODO(design) 仅上面两处；没有解决或改写其他卡遗留的 TODO。事件目录/前端文案保持原样，按卡要求等待前端卡。
