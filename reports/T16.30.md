# T16.30 — 三个发版入口

## 操作顺序

| 入口 | 先后顺序 |
|---|---|
| `tools/release/rc.sh <version> [--dry-run]` | 同 commit 门禁 → RC tag → GitHub prerelease → 验证后以 `publish_target=rc` 写持久签名通道 → 打印 URL 和 24 格 SHA-256。不写 stable。 |
| `tools/release/promote-rc.sh <rc-tag> [--dry-run]` | 验证已发布 RC → 同 commit 的正式 tag → `release-assets` direct 从门禁组 18 件并发布 → 核对正式 Release 的 commit 和对应 RC 包 SHA-256 → **通过后**以正式 tag、`publish_target=stable` 写通道 → 清空 RC 通道。 |
| `tools/release/release.sh <version> [--dry-run]` | 同 commit 门禁 → 正式 tag → `release-assets` direct → 以正式 tag、`publish_target=stable` 写通道并清空残留 RC → 打印 `current/previous` 和 24 格 SHA-256 对照。 |

按 `6b7985c` 顺序定案：**两条正式发版路径都先有正式 Release，后写 stable**。RC Promote 的比对失败会停止，不派发 stable，已存在的 RC 通道保留。

新发版只取该 commit 的门禁字节。历史上复用过其他 commit 已发布包的 RC 可以做只读预演，但不能用于新 promote。同版本同名包的字节与已发布版本冲突时停止，不覆盖旧资产；正式包中的 noarch 两个架构共用同一件。正式 Release 的 18 件资产不增加：清单写入 release notes 的机器可读注释，以便验证 commit、哈希及 GitHub 文件名归一化前的包版本。
