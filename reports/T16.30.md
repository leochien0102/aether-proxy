# T16.30 — 三个发版入口

## 操作顺序

| 入口 | 先后顺序 |
|---|---|
| `tools/release/rc.sh <version> [--dry-run]` | 同 commit 的门禁 → RC tag → 独立 GitHub prerelease。到此为止，不写通道。 |
| `tools/release/promote-rc.sh <rc-tag> [--dry-run]` | 验证已发布 RC → 通道 promote（暂存签名 `channel-rc`，更新 `channel-stable`，清空 `channel-rc`）→ 同 commit 的正式 tag → 由匹配的通道包建正式 Release → 核对 RC/Release SHA-256。**通道先于 Release**。 |
| `tools/release/release.sh <version> [--dry-run]` | 同 commit 的门禁 → 正式 tag → 从四份门禁产物组 18 个正式包并建 Release → 正式 Release promote → 打印 `current/previous` 和 24 个架构/格式格子的 SHA-256。**Release 先于通道**。 |

新发版只取该 commit 的门禁字节。历史上复用过其他 commit 已发布包的 RC 可以做只读预演，但不能用于新 promote。同版本同名包的字节与已发布版本冲突时停止，不覆盖旧资产；正式包中的 noarch 两个架构共用同一件。正式 Release 的 18 件资产不增加：清单写入 release notes 的机器可读注释，以便验证 commit、哈希及 GitHub 文件名归一化前的包版本。
