### 六格预期命令（未在本地运行容器）

每格先检出代码并下载对应 artifact 到 `smoke-packages`，然后运行：


arm64 两个 OpenWrt 格和一个 ImmortalWrt 格再运行固定版 qemu action。以下函数展开即 workflow 的 Docker 命令；六次调用表示六个独立 CI 作业，不是本地执行记录：

```sh
run_case() {
    docker run --rm --platform "$1" \
        --cap-drop ALL --security-opt no-new-privileges \
        --volume "$PWD:/repo:ro" \
        --volume "$PWD/smoke-packages:/packages:ro" \
        --entrypoint /bin/sh "$2" -c \
        '/bin/ash -n /repo/tests/ci/smoke.sh && exec /bin/ash /repo/tests/ci/smoke.sh /packages /repo'
}
# packages-24.10.8，ipk
run_case linux/amd64 openwrt/rootfs:x86-64-24.10.8
run_case linux/arm64 openwrt/rootfs:armsr-armv8-24.10.8
# packages-25.12.5，apk
run_case linux/amd64 openwrt/rootfs:x86-64-25.12.5
run_case linux/arm64 openwrt/rootfs:armsr-armv8-25.12.5
# packages-24.10.8，ipk
run_case linux/amd64 immortalwrt/rootfs:x86-64-openwrt-24.10.6
run_case linux/arm64 immortalwrt/rootfs:armsr-armv8-openwrt-24.10.6
```

四个 ipk 格在容器内执行：

```sh
opkg --offline-root / update
opkg --offline-root / install "$AP_IPK" "$LUCI_IPK" "$ZH_IPK"
# 版本、文件、check、render/cmp、ucode 加载检查
opkg --offline-root / remove luci-i18n-aether-proxy-zh-cn luci-app-aether-proxy aether-proxy
```

两个 apk 格在容器内执行：

```sh
apk --root / --no-scripts update
apk --root / --no-scripts add --allow-untrusted "$AP_APK" "$LUCI_APK" "$ZH_APK"
# 版本、文件、check、render/cmp、ucode 加载检查
apk --root / --no-scripts del luci-i18n-aether-proxy-zh-cn luci-app-aether-proxy aether-proxy
```

`AP_*` / `LUCI_*` / `ZH_*` 是脚本从 `/packages` 找到的对应本地文件，必须每包恰好一份。所有格使用源解析依赖，未设置 `--force-depends`、`--nodeps` 等绕过参数。`--offline-root /` / `--no-scripts` 用于抑制维护脚本，避免本包 postinst/postrm 的 `fw4 reload` 以及依赖钩子调用服务；不是绕过依赖。另丢弃全部容器 capabilities，不启动 init/procd，不运行 nft。
