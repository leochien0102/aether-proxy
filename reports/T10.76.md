# T10.76 — 节点拖动操作列优化（0.5.0）

## 范围与实现

- 分支：`t10.76/drag-polish`，基于 `release/0.5.0`；未使用 start-task.sh，未修改发布分支，不 push。
- `luci-app-aether-proxy/htdocs/luci-static/resources/view/aether-proxy/nodes.js`：操作列改为 **☰ / 检测 / 编辑 / 删除**；当前节点行没有删除。
- 接收 `renderRowActions(section_id, more_label, trEl)`，把行对象传给父类；按 `drag-handle` class 提取父类原手柄并前置，不创建新的拖放实现。
- 保留 Probe/Edit/Delete 按钮对象及事件处理器、父类返回的 td、按钮 nowrap 与 flex 布局。
- 桌面整行拖影来自额外的 `dragstart` 监听中调用 `dataTransfer.setDragImage(trEl, clientX - rect.left, clientY - rect.top)`；不替换父类 `handleDragStart`。
- 本地 SDK `form.js` 的父类支持第三个行参数，但其渲染调用仍省略该参数。因此在 dragstart 时，对缺省的 trEl 用 `tdEl.closest('.tr')` 取得已挂载行；测试覆盖传参和缺参两条路径。
- 触摸端仍完全使用 LuCI 内置 touchend 排序，无桌面式拖影；没有添加自定义触摸拖影或排序事件。
- 拖动排序仍由父类 `map.data.move` 暂存，Save & Apply 后持久化；未改后端、rpcd、UCI 格式、概览模型或其他页面。

## 先复现，再修复

先只修改 `tests/luci/progressive-lists.test.js` 的 formDouble、手柄前置期望与行/拖影断言，以及 `tests/luci/nodes.test.js` 的静态断言，再在旧实现运行定向测试：**121 passed / 5 failed**。

失败项：三种父类按钮排列的顺序断言、trEl 转发断言，以及包含三参数签名和 setDragImage 的静态检查。随后才修改实现。

## 真机验收边界

自动测试验证的是行对象、监听保留、拖影 API 及相对坐标，不代替浏览器的实际拖影绘制。**真机仍需盯一次桌面拖动视觉**：确认拖影为整行、指针锚点正确，并确认保存应用后顺序保留。触摸端没有桌面拖影，需确认内置触摸排序仍正常。本次未进行真机视觉验收。
