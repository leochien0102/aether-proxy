### 1. 依据与 nft 语法证据

本 worktree 的 `docs/tasks/m9.md` 末尾仍是原始 T9.45，没有用户提及的「T9.45 修订（2026-10-30）」节（完整读到文件末尾，并以 `rg` 确认）。按用户本轮明确给出的五项修订要求执行，不改 docs，也不合并/rebase 其他分支。

只读使用 SDK 中已有的 `dl/nftables-1.1.6.tar.xz`，将其中两个文件解到本卡被忽略的证据目录供阅读；没有把第三方实现复制到产品代码或提交文件。源码证据：

- `nftables-1.1.6/src/scanner.l:132`：quotedstring 模式匹配两个双引号之间所有非双引号字符，没有反斜线转义双引号的分支。
- `scanner.l:907–910`：仅删掉尾引号并复制引号内部文本，返回 `QUOTED_STRING`；没有 unescape 步骤。
- `src/datatype.c:540–548`：`string_type_parse()` 把 `sym->identifier` 的原始字节交给 `constant_expr_alloc()`，没有 C-style 解码。

所以：双引号不能在该 nft quoted string 内表示；`"br-\lan"` 是一个反斜线，`"br-\\lan"` 是两个；`"br-\x09lan"` 虽可通过词法，但表示字面 `\x09`，**不是 tab 编码**。按修订授权，双引号和 C0/DEL 拒绝，其余字符不新增白名单。初版关于 hex 支持待验证的 `TODO(design)` 已删除，不再留一个已被源码证实错误的逃逸机制待定项。

SDK 二进制运行方式：

```sh
SDK=/workspace/openwrt/sdk-spike/sdk-25.12.5/staging_dir/target-x86_64_musl/root-x86
"$SDK/lib/ld-musl-x86_64.so.1" \
  --library-path "$SDK/lib:$SDK/usr/lib" \
  "$SDK/usr/sbin/nft" -c -f <file>
```

此 SDK 的 libnftables/libmnl/libnftnl/libjansson 在 `usr/lib`，所以除 `lib` 外还需加上 `usr/lib`；仅给 `lib` 会报缺库，未把此类失败算作语法检查结果。`--version` 实际输出：`nftables v1.1.6 (Commodore Bullmoose #7)`。
