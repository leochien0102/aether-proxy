## 验收

### 编码、配置和输出兼容性

- `quote_string()` 只做 nft 双引号字符串边界编码；反斜线先变为 `\\`，双引号再变为 `\"`。两个 guard 共用同一编码后的列表，函数不做存在性查询、外部命令或运行态读取。
- 长度 1/15 接受、0/16 报 `main.lan_ifaces:invalid_value`；UTF-8 的 15/16 字节对照确保不是按字符数判断。缺键/null 分别回退到 `br-lan`，空字符串（标量与列表元素）分别拒绝；`[]` 是 `too_few`，不是默认值。
- 对照 `git ls-tree -r --name-only main tests/fixtures` 列出的每一份既有 nft golden，将工作区文件字节与 `git show main:<path>` 比较：`PASS existing nft golden bytes unchanged: 13/13`。没有运行 `--update`，没有重写既有断言或期望文件。
- 计数链使用一个独立、完整的字节期望，保留 `proxy_tx/proxy_rx` 声明、output/input 挂钩与两条 node_ip4 计数规则。所有既有 nft golden 也保留了主机策略、挂钩与固定注释。

### 真实 nft 仅语法检查：环境不可用

尝试的命令与结果（**未加载任何规则、未在设备上创建接口或表**）：

```text

exit=127
$ nft -c -f tests/fixtures/t945-quoted-ifaces/expected/aether-proxy.nft

```

第一份最小 probe 的规则为 `iifname "br-\x09lan" counter`，用于验证 tab 的十六进制转义。宿主机没有 nft（也没有在 `/usr/sbin/nft`、`/sbin/nft`、`/usr/bin/nft` 找到），因此 **没有得到 nft 接受或拒绝 `\xNN` 的证据**。不能把退出 127 说成语法拒绝，更不能声称真实 nft 检查通过。

本卡按「设计未覆盖时采取最保守行为」暂时收窄配置契约：所有 0x00–0x1f、0x7f 均在 config 层报 `invalid_value`，不猜测 hex escape 支持、不输出原始控制字节；包括 tab 的全部 33 个值分别测试。双引号和反斜线仍然接受且编码，不增加其他字符白名单。是否可放宽控制字节须补真实 nft 解码验证后决定，代码已标 `TODO(design)`。这是尚未完成的环境验证项，而不是已证实 nft 不支持。

没有运行会调用 sudo/modprobe 的 `tests/ci/nft.sh`，也未运行依赖真实 nft 创建集合的 chinadns-ng CI 验证；遵守不使用 sudo、不安装系统软件包、不运行容器的限制。新增 golden 可由具备权限及 nft 的后续 CI 进行真实检查。
