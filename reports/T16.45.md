# T16.45 同一日内重启后今日流量不再归零

开启热力图时，`create_daemon()` 只在启动时读取一次 `usage.json`，将本地今日的有效条目作为内存累计基线。缺文件或无有效今日条目时静默从零起算；读取或解析失败记一次 `FS_FAILED`（`op=read`），后续仍可采样。首次可读的 nft 计数只建立基线，不作为增量；之后只加新流量。SIGHUP 不重新播种，`stats history` 仍用完整的实时值覆盖磁盘今日值，跨天或正常停止仍沿原路径落盘。

异常退出（如 `SIGKILL`）后只能恢复最后一次落盘的累计，尚未落盘的流量仍会丢失。不改磁盘结构、配置、额度或 LuCI。

## 修复前 / 修复后

在基线 `4260e28f` 的隔离副本与修复工作树上运行同一个 monitor 场景。两侧均预置本地 `2026-11-21` 的 2 GB（`tx=200000000`、`rx=1800000000`、`observed=1800`、`healthy=1500`），创建新 daemon，再让 nft 计数增长 `2500` / `4000` 字节。取第二次采样的 `state.json`；将该快照与**初始**磁盘文件放入独立 sysroot，由对应版本的真实 `stats history --json --days 1` 读取。最后从 monitor 场景取模拟跨天后的实际落盘文件。以下输出省略了时间戳及无关字段。

```

```
