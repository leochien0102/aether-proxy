## 根因与涉及的实际入口

### 涉及的实际入口追踪

| 入口 | 文件与函数 | 作用 |
| --- | --- | --- |
| 候选引擎解析 | `aether-proxy/src/lib/cmd/check.uc` `find_component()` + `aether-proxy/src/lib/component_id.uc` `engine()` | 按当前候选配置的 `main.chinadns_bin` 或默认发现顺序解析本次将启用的 DNS 二进制路径及引擎名（`aether-dns` / `chinadns-ng` / `null`） |
| 实际下发给 DNS 引擎的上游 | `aether-proxy/src/lib/render/chinadns.uc` `render()` / `boot_upstreams()` + `aether-proxy/src/lib/bootstrap.uc` `render()` | `dns.china_dns` 始终下发给 DNS 引擎（`china-dns`、`udirect`、T3 及关闭直连时的 `boot`）；`dns.direct_dns` 仅在 `dns.direct_dns_enabled == true` 时下发（T2、`boot` 及 `bootstrap.conf`）；`dns.trust_dns` 由 Xray 消费且 schema 本身禁止 `tls://` |
| 配置检查 | `aether-proxy/src/lib/cmd/check.uc` `check_staged()` → `precheck()` | 发现候选组件后立即执行 `dns_upstream_issues(snapshot, path)`，不兼容时返回 `PRECHECK_FAILED`（退出码 `1`，`errors` 带 `item` 与 `detail`） |
| 冷启动 | `aether-proxy/src/lib/daemon.uc` `start_sequence()` 第 3 步 `check.precheck()` 与第 5 步 `validate_render()` | 在 `wait_network`、清理残留、发布 `current/`、启动 `bootstrap`/`xray`/`dns` 或接管 nft/route/dnsmasq 之前以 `PRECHECK_FAILED` + `untouched: true` 拒绝，进入 `error` 并保留退避重试与 `SIGHUP` 恢复能力 |
| 运行中重载 | `aether-proxy/src/lib/reload.uc` `run_candidate()` → `validate()` → `check.precheck()` | 按候选配置重新发现引擎并校验；不兼容时在 `publish_stage()` 和 `execute_action()` 之前丢弃 staging 并返回 `PRECHECK_FAILED`，旧子进程不停止、新进程不启动、`current/` 与 `state.components`/`render_hash` 不替换、不发 `RELOAD_APPLIED`，`last_reload` 记录失败诊断，纠正配置后可正常重载 |

### 修正要点

- 不在 `config.uc` / `schema.uc` 全局禁用 `tls://`，不做协议降级，不新建能力注册表。
- `dns_upstream_issues(snapshot, path)` 仅在 `component_id.engine(path) == 'aether-dns'` 时检查实际会交给 DNS 引擎的上游集合：始终检查 `dns.china_dns`，仅当 `dns.direct_dns_enabled == true` 时检查 `dns.direct_dns`；对每个含 `tls://` 的字段产出：
  - `item`: `dns_upstream:aether-dns:<field>`（如 `dns_upstream:aether-dns:dns.china_dns`、`dns_upstream:aether-dns:dns.direct_dns`）
  - `detail`: `aether-dns does not support tls:// upstream in <field>: <upstreams>`

## 修前 / 修后证据（同夹具旧红新绿）

使用同一本地夹具 `python3 tests/daemon/engine-upstream-compat.py` 在修复前（基线 `53d8efd8`）与修复后分别实跑：

### 修前（基线 `53d8efd8`）

- 汇总：`T16.82 engine upstream compat: 12 passed, 17 failed`（退出码 `1`）。
- 典型失败证据：
  - **`aether-dns + china_dns TLS`**：`check` 误返回 `rc=0, ok=true`；冷启动通过 `precheck` 后继续启动 Xray、加载 `nft` 与 `ip rule`/`ip route`、再拉起 `aether-dns`，随后 `aether-dns` 因不支持 `tls://` 退出（`CHILD_CRASHED {name: "aether-dns", code: 1}`），最终以 `failed_step=chinadns_listen` 回滚失败。
  - **运行中 `chinadns-ng + TLS` 切换引擎到 `aether-dns`（真实 `SIGHUP` 重载）**：`reload` 放行并停止了正在运行的 `chinadns-ng`、将 `current/` 与 `state.components` 替换为 `aether-dns`、发出了 `RELOAD_APPLIED {actions: ["restart_chinadns"]}`，随后新起的 `aether-dns` 崩溃（`CHILD_CRASHED {name: "aether-dns", code: 1}`）。
