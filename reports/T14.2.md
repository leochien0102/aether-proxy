## 测试实现与替身边界

新增 `tests/luci/config-load.test.js`（7 个测试）。UCI 替身按任务卡描述的 uci.js 行为建模：

1. `loaded[config]` 缓存 package Promise，失败后仍保留；load 通过 Promise.all 等待并返回配置名数组。
2. 底层读取失败是普通 Error rejection，不转换成 ap.call 的 RPC_FAILED 对象。
3. `unload()` 同步返回 undefined，并删除缓存和已载入状态。
4. 分别记录 load API 调用、实际 package 请求和 unload，区分缓存命中与新请求；有专门的“失败缓存跨调用仍在”断言。

`tests/luci/loader.js` 为既有页面的 common 替身接入**生产代码的** load_config，使用各页面原有的 UCI 替身，不添加“永远成功”的 helper，也不修改这些 UCI 替身的 load/unload 行为。仅测试 RPC/UI 的旧 common 模块测试可注入空的未使用 UCI 依赖。`overview.test.js` 的真实 common 队列用例显式提供成功的 UCI load，保持只测试队列这一职责；失败与缓存语义由上述专门用例覆盖。

本测试不完整模拟 LuCI 的修改暂存、表单、批量 HTTP 和 uhttpd；只建模本卡涉及的 Promise 缓存/reject/unload 行为，不能代替真机验收。

## 变异验证

可复现命令：

```sh
node tests/luci/config-load.mutations.js
```

脚本先运行基线，再在 `tests/luci/.config-mutations-*` 中生成临时 common.js，运行同一份测试和同一缓存 Promise 替身；不修改生产源文件，不调整替身来适配变异，finally 删除临时目录。命令总退出码 0 表示基线通过且三个变异均被杀死。

| 变异 | 实际输出 | 结论与杀死依据 |
|---|---|---|
| baseline | `PASS (exit 0)`；7 tests、7 pass、0 fail | 基线通过 |
| 去掉 unload | `KILLED (exit 1)`；1 pass、6 fail | 非等价；重试命中原 rejected Promise，瞬时恢复/跨页缓存恢复失败，请求序列不符 |
| 去掉重试（直接返回首次 load） | `KILLED (exit 1)`；1 pass、6 fail | 非等价；第一次错误直接上抛，瞬时故障不能恢复 |
| 改成重试两次（第二次失败后再次 unload/load） | `KILLED (exit 1)`；5 pass、2 fail | 非等价；连续失败用例发生第三次请求并错误成功；并发用例超出每调用两次 load 的上限 |

第三个变异由“第二次错误对象身份保持/仅一次重试”和“并发持续失败有界”两项杀死。没有幸存或等价变异。

## 场景对照

| 卡片场景 | 自动化对应 | 结果 / 边界 |
|---|---|---|
| 首次 reject、第二次成功 | transient transport rejection | 成功返回配置名；严格序列 load → request → unload → load → request |
| 已有失败缓存后再次切页 | existing rejected cache | 预先两次 load 只发一次请求并拒绝同一错误；helper 清缓存后恢复 |
| 连续两次 reject | persistent failure | 严格两次请求/一次 unload；最终错误 === 第二次错误，不吞错 |
| 首次成功 | first success | 只有一次 load/request，没有 unload 或额外请求 |
| 两页并发、持续失败 | concurrent views bounded retries | 真实 rules/logs 的 load 并发；两调用合计四次 load、两次 unload、三次底层请求；两者均 reject，无递归重试 |
| 两页并发、瞬时失败 | concurrent views recover | 两页均成功；初次共享失败后各自最多重试一次 |
| 六页入口覆盖 | all six view loads | 每页各调用一次 helper；access 主机提示保留；nodes 补建 sub；成功重试后不额外发请求 |
| LuCI 全量回归 | bash tests/luci/run.sh | 1058 passed, 0 failed；原始 node 3 个 SDK 条件 skip 如上 |
| ≥3 变异 | config-load.mutations.js | 三个均 KILLED，无等价或幸存 |
| H28K 单次 Block 后不出红横幅 | 未进行设备窗口 | 仅 Promise/视图层自动化验证成功；未宣称实机 UI 已验收 |
| H28K 持续失败仍显示红横幅 | 未进行设备窗口 | 自动化确认 rejection 原样上抛；LuCI 框架实际横幅尚待实机确认 |

## 偏差与未覆盖项

- nodes 的读取原来藏在 subscriptions.load 中，按卡片要求在 nodes.load 接入 helper，并保留原初始化代码；不更改卡外共享订阅模块。既有订阅初始化/加载次数测试全绿。
- 不引入额外的并发去重锁。两个视图同时看到缓存失败时可能各自 unload/retry（该调度下共三次底层请求），但每次 helper 调用最多重试一次；本卡要求是有界恢复，不是修改 UCI/RPC 的并发语义。
- 应用层恢复不能阻止 uhttpd SIGSEGV，也不保证重启尚未完成时一次重试足够；第二次失败照常交给 LuCI 显示错误。
- 未连接 H28K/x86、未进行 DevTools Block、打包安装或浏览器截图；SDK 条件测试跳过如上。未改 poll，不解决旧页面 poll 残留问题。
