### 先复现，再修复：原因与证据

完整阅读任务卡要求的 SDK 24.10.8 `form.js` 方法及 `ui.js` DynamicList 实现后，先只修改访问控制测试替身和场景，再运行：

```text
node --test tests/luci/access-page.test.js
exit 1
19 passed, 4 failed
```

修复前的新测试失败：

- 反向范围添加框 `isValid()` 实际为 true，预期 false。
- 重复 IP 编辑框保存实际调用一次会话保存，预期零次。
- 合法重叠的编辑框保存没有 warning（通知数实际 0，预期 1）。
- IP 选项没有 `validate` 方法；尚无空添加框校验契约。

修复后又用临时、只读的 preload 将视图和模型加载内容替换为 `git show main:<路径>`，同一套 SDK 替身重放前三个场景（不修改产品文件、不另建 Git 元数据）：

```text
node --require ./tests/luci/t10.53-reproduce.cjs --test --test-reporter=tap \
  --test-name-pattern='T10.53 scenario [123]:' tests/luci/access-page.test.js
exit 1
scenario 1: closed 实际 1，预期 0（反向范围仍关闭编辑框）
scenario 2: save 实际 1，预期 0（重复项被暂存）
scenario 3: notifications 实际 0，预期 1（重叠不提示）
```

临时 preload 和日志已移除，不交入分支。

根因：SDK `renderMoreOptionsModal` 新建子 Map / NamedSection，克隆选项（包括自定义处理器，替换 map/section），保存按钮直接调用 GridSection/TableSection 的 `handleModalSave`。它执行子 Map 的 `save(null, true)`，再重载/刷新父 Map，成功后执行 `handleModalCancel(..., true)`；不会调用页面的 `handleSave`/`handleSaveApply`。原视图仅在底部两个按钮进行 `model.validate`，IP 列表也没有单项格式校验，所以编辑框路径漏过了这些检查。

另外，`AbstractValue.parse` 在校验通过后就可以写字段；Map 并不对前面字段的写入做事务回滚。故本实现先只读检查，不能先 parse 再整体检查。DynamicList 的无效待添加文本不会进入 `getValue()`，必须同时检查选项 `isValid()`，不能仅靠读回来的列表判断输入是否合法。
