# T16.112 — 简化 LAN 显式代理配置

工作树：`/workspace/openwrt/aether-proxy-wt/T16.112`；分支：`feat/t16.112-shared-proxy`；基线：`ac0c3f65`。

## 实现与接口边界

- `aether-proxy/src/lib/schema.uc`、`config.uc`：两协议独立开关、独立端口（默认 1080 / 8080），只配置一份 `proxy_username` / `proxy_password`。双开检查端口互异，保留内部端口冲突检查。关闭一项不清空共用凭据；双关无需地址或凭据。
- `pipeline.uc`：复用既有 `ubus call network.interface dump` 的后端查询，只精确匹配在线逻辑 `lan` 的当前可用本地 IPv4；排除 WAN、无效/通配/回环/IPv6/失效地址，不硬编码 `br-lan`，不从默认路由、主机提示或浏览器猜地址。一个候选自动使用，多个候选通过 `proxy_address` 只选一次；`proxy_listen` 仅是运行态，绝不持久化自动地址。
- 按本次用户补充授权，已有 `status` 增加 `explicit_lan: { interface: "lan", addresses: [...] }`，不返回完整接口列表、不增加方法、不扩大 ACL。查询失败为空候选，不影响其他状态字段。LuCI 直接消费这些候选，不另建一套过滤逻辑；启动、应用及节点选择预检重新查询，precheck 再确认 resolved 地址仍有效，不能信任浏览器缓存。其他配置出错的 status 仍可携带候选供管理员修复。
- `render/xray.uc`：两个入站强制使用同一地址、同一认证对、不同端口；未解析出具体 LAN 地址即拒绝渲染，不回退 `0.0.0.0`。就绪判定继续从发布产物检查本代 Xray 的精确地址/端口与 socket 所有权，不以其他进程占用冒充成功。
- `view/aether-proxy/advanced.js`、`model/advanced.js`、中文翻译：共用认证输入，单候选只读展示，多个候选一次选择；独立开关和端口。保留原生保存、保存并应用、撤销，以及 T16.111 保存前凭据可见性提示。未改系统 LuCI、全局摘要、RPC 权限、防火墙、透明代理或通用应用事务。

## 旧配置与防丢失

旧两套凭据按整组比较：相同或只有一组非空时无歧义沿用，不拼接两个不完整来源；不同则要求显式选旧 SOCKS5 / HTTP 来源或重新填写完整共用凭据。冲突时不展示旧密码。读取、打开页面、撤销和失败校验不迁移；只有整个表单有效保存后，才写一份共用凭据并删除旧认证及旧 listen 字段。双关可暂保留旧冲突，不强迫当场迁移。完整新共用字段是管理员显式决议，旧 listen 不再决定绑定。

独立审查发现并修复两处连接路径：

1. `status` 返回 CONFIG_INVALID 但附有实时候选时，表单不能丢弃候选，否则修复其他字段会被错误的“无地址”阻挡。已补模型及真实 SDK 回归。
2. `sub.prepare_config()` 原有启动备份恢复可能把旧凭据冲突误当损坏并覆盖当前配置。现在 `migration_conflict` 在读取备份及写回前直接失败；`tests/sub/config-recovery.py` 用有效旧同值备份 + 当前旧异值配置，覆盖重复 helper 调用和实际 daemon 启动，证明 live/backup 字节均不变、不发 CONFIG_RECOVERED、不发布 current。一般非迁移冲突的既有损坏恢复政策不变。
