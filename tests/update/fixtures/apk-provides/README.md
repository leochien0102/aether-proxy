# Real apk installed-query evidence

Generated by `tests/update/apk-evidence.sh` with real apk-tools 3.0.5
(compiled for x86_64), not a stub. Run from the worktree:

```sh
APK_BIN=/tmp/t1654-evidence/apk-3.0.5/build/src/apk \
  tests/update/apk-evidence.sh --capture
APK_BIN=/tmp/t1654-evidence/apk-3.0.5/build/src/apk \
  tests/update/apk-evidence.sh
```

`--capture` writes these fixtures; the default compares them byte-for-byte.
Both modes first assert the returned JSON semantics and exit codes. Bash,
Python 3, realpath, and standard Unix tools are required. No download, build,
host installation, package script, or network repository is involved.
`mktemp` provides a fresh root for each scenario; `apk mkpkg` creates empty,
unsigned local packages. Each installation explicitly uses `--root`,
`--usermode`, `--initdb`, `--no-network`, `--allow-untrusted`, and
`--force-non-repository`; all database queries use `--no-network`. The original
five scenarios use an empty repositories file. The repository-only scenario
uses a separate file pointing directly to a local unsigned `Packages.adb`
index created by `apk mkndx --allow-untrusted`; its queries also explicitly
allow the unsigned local index.

The installed query in the original five scenarios is:

```text
apk --root ROOT --no-network --repositories-file EMPTY_FILE query --from installed --format json --fields name,version,provides NAME
```

| Fixture prefix | Installed state / query | rc |
| --- | --- | --- |
| `aether-dns` | aether-dns 1.0.0-r1; provides dns-engine=1.0.0 | 0 |
| `chinadns-ng` | chinadns-ng 2025.08.09-r1; provides dns-engine | 0 |
| `aether-dns-list` | Same installed aether-dns root; original `list -I aether-dns` interface | 0 |
| `chinadns-ng-list` | Same installed chinadns-ng root; original `list -I chinadns-ng` interface | 0 |
| `no-provides` | aether-dns 1.0.0-r1; no provides metadata | 0 |
| `absent` | Initialized empty database; query aether-dns | 0 |
| `failure` | Nonexistent root; query aether-dns | 99 |
| `repository-candidate` | Empty installed database; local repository query returns aether-dns 1.0.0-r1 with dns-engine=1.0.0 | 0 |
| `repository-only` | Same root and repository; installed query returns an empty array | 0 |

The two `*-list` fixtures preserve the real, unmodified legacy text output for
old replay comparisons. Their commands use the same isolated installed roots,
empty repositories file and `--no-network`, but run `list -I NAME` rather than
JSON query. Both are included in capture, byte-for-byte compare and transcript.

The aether-dns runtime version used by consuming tests is 1.0.0; this script
only establishes package metadata and does not simulate a runtime executable.
`absent` has no repository candidate: it proves the empty-installed case,
not repository-vs-installed filtering in a populated repository. The separate
repository-only scenario proves that distinction: initialize an empty root,
index the provider package locally, then query `--from repositories` before
`--from installed` with the same root, repositories file and JSON fields.
The first result must contain the provider; the second must be empty.

Each prefix has literal `.stdout`, `.stderr`, and `.rc` files. No JSON
reformatting or stderr normalization is performed. In this version the
nonexistent-root diagnostic is `ERROR: Unable to open root: No such file or
directory`, with no absolute root path. An absent `provides` key is distinct
from a missing package; a database error has nonzero rc and no JSON stdout.

Every apk command (including version, help, package creation, installation,
and query) prints its shell-quoted argv, stdout, stderr, and rc. Set
`KEEP_EVIDENCE=1` to retain the temporary directory with separate
`logs/LABEL.command`, `.stdout`, `.stderr`, and `.rc` files, as well as the
isolated databases and locally built packages. `logs/version.stdout` records
the tool version for that complete transcript; `version.*` pins it here too.
Without that option the temporary directory is deleted on exit.

`--capture` also saves the complete successful run as `transcript.txt`, including
version, help, package/index creation, installations, both repository-only
queries and both legacy list calls, with every command's stdout, stderr and rc. Absolute temporary paths
are preserved for audit. The final PASS confirms semantic assertions and
fixture capture completed. Default compare mode regenerates its own transcript
but does not byte-compare or overwrite this path-dependent audit artifact;
it compares all named `.stdout`, `.stderr` and `.rc` fixtures instead.
Help commands return rc 1 in this real tool; the deliberately failed root
query returns rc 99. These expected outcomes do not mean the run failed.
