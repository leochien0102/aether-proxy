# aether-proxy 使用说明

aether-proxy 是 OpenWrt 上的透明代理：用 Xray 连接代理节点，用 ChinaDNS-NG 分流 DNS，局域网里的设备不需要做任何设置。
它只支持 firewall4（nftables）的固件，只处理 IPv4。

本文面向使用者。设计细节在同目录的 01–12 号文档中。

## 1. 准备

| 项目 | 要求 |
|---|---|
| 固件 | OpenWrt 24.10（opkg，ipk 包）或 25.12（apk 包），以及基于它们的 ImmortalWrt 等；必须是 firewall4 |
| 架构 | 本身与架构无关；发布通道里的 `xray-core` 目前只编译了 `aarch64_generic` 与 `x86_64` |
| Xray | `xray-core` 26.3.27 或更新。可以从发布通道安装（见下文），也可以用软件源里的 |
| ChinaDNS-NG | 2025.08.09 或更新。可以用软件源里的；官方 OpenWrt 的软件源里没有它，可以从发布页下载 `chinadns-ng` 包手工安装（见下文） |

**不要和 ssr-plus、passwall、OpenClash 同时启用。** 它们都会接管 dnsmasq 和透明代理规则。aether-proxy 启动前会检查，
发现其中任何一个在运行就拒绝启动（事件 `PRECHECK_FAILED`，缺失项写着 `conflict:<名称>`）。可以同时安装，但同一时间只启用一个。

## 2. 安装

软件包发布在 [aether-proxy-channel](https://github.com/leochien0102/aether-proxy-channel/releases/tag/channel-stable) 的 `channel-stable`。
首次安装需要手工下载三个包：`aether-proxy`、`luci-app-aether-proxy`、`luci-i18n-aether-proxy-zh-cn`（文件名中的版本以发布页为准），上传到路由器的 `/tmp` 后：

OpenWrt 24.10（opkg）：

```sh
opkg update
opkg install /tmp/aether-proxy_*.ipk /tmp/luci-app-aether-proxy_*.ipk /tmp/luci-i18n-aether-proxy-zh-cn_*.ipk
```

OpenWrt 25.12（apk）：

```sh
apk update
apk add --allow-untrusted /tmp/aether-proxy-*.apk /tmp/luci-app-aether-proxy-*.apk /tmp/luci-i18n-aether-proxy-zh-cn-*.apk
```

依赖（nftables 的 TPROXY 模块、`ip-full`、`curl`、ucode 模块等）由包管理器从软件源自动安装。

固件里没有 ChinaDNS-NG 时（官方 OpenWrt 就没有），从同一个发布页下载对应架构的 `chinadns-ng` 包（`aarch64_generic` 或 `x86_64`，
本机架构见 `/etc/openwrt_release` 的 `DISTRIB_ARCH`），一起安装即可。它是上游发布的静态二进制，aether-proxy **不会**自动更新它：
DNS 出问题会影响整个网络，所以只在你手工安装新版本时才变化。
安装后刷新 LuCI，菜单出现在「服务 → aether-proxy」。装好时服务**没有启用**，不会影响现有网络。

如果概览页提示缺少 Xray：可以在更新页从发布通道安装 `xray-core`（下载经过签名校验），或者从软件源安装。
缺少 ChinaDNS-NG 时概览页会显示本机的包架构，按上一段手工安装。

以后的更新都在 LuCI 的更新页完成，不需要再手工下载（见第 6 节）。

## 3. 首次配置

1. **添加节点**，二选一：
   - 节点页「导入」：粘贴一条节点链接（`vless://`、`vmess://`、`trojan://`、`ss://`）。
   - 订阅页「添加」：填订阅地址，保存后点「立即更新」。订阅地址里通常含有令牌，列表里只显示主机名。
2. 节点页里选一个节点「设为当前节点」。可以先点「检测全部」看看哪些节点能连通。
3. 规则与 DNS 页选择**模式**（默认「绕过大陆」，见第 4 节）。
4. 回到概览页，勾选顶部的「启用」，保存并应用。几秒后状态从「启动中」变为「运行中」。

「启用」开关决定服务是否运行、开机是否自动启动。概览页的「停止」只是**暂时**停止，重启路由器后会再次启动；要长期停用，请关掉「启用」。

## 4. 模式与主机策略

**模式**（规则与 DNS 页）：

| 模式 | 走代理的流量 | 说明 |
|---|---|---|
| 绕过大陆 `bypass_cn`（默认） | 目的地址不在中国大陆 IP 段中的 | 最省心，境外站点都经节点 |
| GFW 列表 `gfw` | 访问 gfwlist 中域名（以及少量固定网段）的 | 只代理被墙站点，其余直连 |
| 全局 `global` | 全部 | 内网、保留地址和节点本身仍然直连 |

另有四个自定义名单：代理域名、直连域名、代理 IP、直连 IP。**直连名单优先于一切**，包括被设为「强制代理」的主机。
修改名单后点「保存名单」，服务在运行时会自动重新加载。

**访问控制**（访问控制页）：每台设备可以单独设置策略，按 IP（可以是网段）或 MAC 匹配。

| 策略 | 效果 |
|---|---|
| 跟随模式 | 按上面的模式判断 |
| 不走代理 | 这台设备的流量全部直连 |
| 强制代理 | 这台设备的流量全部经节点（直连名单除外） |

- **游戏模式**：让这台设备的 UDP 也经节点（默认只代理 TCP）。「不走代理」的设备不能开游戏模式。
- **未列出的设备**：默认「跟随模式」；改成「不走代理」就变成「只有列出的设备才走代理」。
- 同一个 IP 或 MAC 不能出现在两台设备里，保存时会被拒绝并列出冲突。
- MAC 匹配只对直接连在这台路由器上的设备有效；经过另一台路由器的设备，这里看到的是那台路由器的 MAC。

修改策略或模式后，**已经建立的连接沿用原来的路径**，新连接才按新规则走。验证时请打开新的网页或重新连接，不要只刷新已打开的页面。

## 5. DNS

局域网设备照常把路由器当作 DNS。路由器上的 dnsmasq 把查询交给 ChinaDNS-NG：国内域名用国内 DNS，其余按「DNS 级别」解析：

| 级别 | 上游 | 什么时候用 |
|---|---|---|
| T1 经代理 | `trust_dns`（默认 `8.8.8.8`、`1.1.1.1`），经节点查询 | 代理健康时（正常状态） |
| T2 直连境外 | `direct_dns`（默认 `tcp://9.9.9.9`、`tcp://8.8.8.8`） | 刚启动还没确认代理可用，或代理不健康 |
| T3 国内 | `china_dns`（默认 `223.5.5.5`、`114.114.114.114`） | T2 也不通（可在设置中关闭这一级） |

服务自动在三级之间切换，概览页显示当前级别。需要知道的几点：

- **刚启动的几秒里，被墙的域名可能解析失败**：这时处于 T2，直连境外 DNS 查询被墙域名会受到干扰。首次健康检测通过后（通常几秒）升到 T1 就正常了。
- 默认的 `direct_dns` 是在一处国内网络实测后选的（`9.9.9.9` 成功率最高，DoT 全部不通）。网络环境不同时可以在规则与 DNS 页修改。
- 默认过滤 IPv6 解析（AAAA）和 HTTPS 记录，避免设备绕过代理走 IPv6。如果局域网接口有全局 IPv6 地址，概览页会提示：设备仍可能通过 IPv6 直连，建议关闭局域网的 IPv6 分配。
- 默认开启 **DNS 劫持**：设备手动把 DNS 设为 8.8.8.8 等，53 端口的查询也会被送回路由器（「不走代理」的设备除外）。

## 6. 更新与回滚

更新页显示每个软件包的已安装版本、最新版本和上一版。

- **规则数据**（gfwlist、国内域名、大陆 IP 段等）：默认每天凌晨 4 点多自动更新（每台设备的具体分钟随机，错开请求），下载的数据经过签名校验，有变化才写入并自动生效。
- **xray-core**：默认发现新版本只提示，点「安装」后安装；可以在更新策略中改为自动安装。
- **aether-proxy 与界面**：只提示，不自动安装。

每次安装后会自动检查：服务原本在运行，就重启并确认它回到运行状态；原本没运行，就检查配置能否通过。检查失败会**自动装回原来的版本**并重新生效，更新页和日志里会记录 `UPDATE_ROLLED_BACK`。
也可以手动点「回滚」装回上一版。

更新 aether-proxy 或界面包之后，请刷新浏览器（必要时清缓存），旧页面可能还在用缓存里的脚本。

## 7. 运行状态与故障时的行为

概览页的状态：

| 状态 | 含义 | 流量 |
|---|---|---|
| 运行中 | 一切正常 | 按规则代理 |
| 降级 | Xray 在运行但健康检测失败，或节点地址解析失败 | 健康检测失败时仍按规则代理（多半连不通）；节点地址解析失败时全部直连。DNS 退到 T2/T3 |
| 故障放行 | Xray 进程不可用 | **拦截规则已摘除，全部直连**，国内站点和未被墙的境外站点照常可用 |
| 启动失败 | 启动过程中出错 | 概览页显示错误码，详情见日志页 |

如果 ChinaDNS-NG 不可用，dnsmasq 会退回原来的配置，保证整个网络还能解析域名，概览页显示「DNS 已回退到原配置」。

「故障放行」可以在高级页关闭（`fail_open`）。关闭后 Xray 不可用时，本应走代理的流量会直接失败，而不是改走直连。

## 8. 排查问题

1. **日志页的「事件」**：每条带中文说明，等级分颜色，鼠标悬停能看到原始参数。可以按等级、事件码过滤。
2. **日志页的「原始日志」**：可按来源（aether-proxy / Xray / DNS）查看系统日志。需要更多细节时，在高级页把日志等级调到「调试」，查完再改回来。
3. 命令行（SSH 到路由器）：

   ```sh
   aether-proxy status          # 当前状态
   aether-proxy check           # 不改系统，只检查配置和环境能否启动
   aether-proxy events --level warn   # 最近的警告和错误事件
   aether-proxy log --source xray     # Xray 的日志
   ```

4. 网络异常、想立刻恢复原状：关掉「启用」并保存，或在命令行执行：

   ```sh
   uci set aetherproxy.main.enabled=0 && uci commit aetherproxy
   /etc/init.d/aether-proxy stop
   aether-proxy cleanup
   ```

   `cleanup` 会删掉 aether-proxy 的规则表、路由规则和 dnsmasq 片段，可以重复执行。所有运行时文件都在内存中，重启路由器也会回到干净状态。

## 9. 已知限制

- **只支持 IPv4。** IPv6 流量不经过代理（见第 5 节的 IPv6 提示）。
- **路由器自己的流量不走代理**（opkg、ntp 等都是直连）。aether-proxy 自己的订阅与更新下载会在需要时经节点。
- **GFW 列表模式依赖设备使用路由器的 DNS**：浏览器内置的 DoH、Android 的「私人 DNS」严格模式会绕过路由器，这些域名就不会被代理。
  DNS 劫持只能覆盖普通的 53 端口；853 端口不封锁（封锁会让 Android 严格模式直接断网）。
- **GFW 列表模式刚开机时**：设备里缓存的旧解析结果过期之前，这部分访问会走直连。服务重启有保存与恢复机制，整机重启没有。
- 订阅只支持节点链接列表（明文或 Base64），不支持 Clash 的 YAML 订阅。不支持的节点（例如带 SS 插件、IPv6 地址的）会被跳过，订阅页显示按原因统计的跳过数。
- 开启流量卸载（flow offloading）不影响代理；它只加速直连的转发流量。

## 10. 卸载

先关掉「启用」并保存，然后：

```sh
opkg remove luci-i18n-aether-proxy-zh-cn luci-app-aether-proxy aether-proxy   # 24.10
apk del luci-i18n-aether-proxy-zh-cn luci-app-aether-proxy aether-proxy       # 25.12
```

卸载会自动重新加载防火墙。配置文件 `/etc/config/aetherproxy` 按惯例保留，不需要可以手动删除；
`/etc/aether-proxy/`（自定义名单、下载的数据）也可以一并删除。
