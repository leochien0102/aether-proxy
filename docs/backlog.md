### 现有设计中要保持开放的地方

改动以下设计时，要确认不会妨碍将来的分流：

- **单个 Xray 进程多出站**：`xray.json` 中已有 `routing` 段和一个暂未使用的 `direct` 出站（[06](06-nodes-subscription.md)）。
  分流应当表达为「多个出站 + 路由规则」，而不是 helloworld2 那样每条规则一套进程。
- **nft 判定链**：`by_mode` / `proxy` 链是分开的（[02](02-dataplane.md)），可以在「代理」动作之前插入按集合打不同 mark、
  或 TPROXY 到不同入站端口的规则。
- **chinadns-ng 最多 6 个自定义组**，首版已占用 3 个（`uproxy`、`udirect`、`boot`）。按服务分流如果需要按域名填充集合，
  组数会成为限制，届时要评估把域名分流交给 Xray 的 sniffing + routing，而不是 DNS 层。
- **节点引用**：订阅更新时「被引用的节点保留为 stale」的逻辑（[06](06-nodes-subscription.md)）目前只检查 `main.node`。
  分流规则引用节点后，引用检查要扩展到规则，而不是另写一套。
- **节点身份稳定**：节点 ID 一旦生成就不变，正是为了让分流规则能长期引用节点。

### 已做的成本评估（流量与连接数）

- 推荐**按需读取、不在后台采样**：首页打开时随状态一起读计数器，速率由前端用相邻两次读数相减得到，不保存历史。
  - 代理流量：nft 中统计「路由器发往节点 IP」与「节点 IP 返回」的两条计数规则（内核维护，几乎零开销）。
  - 总流量：WAN 接口在 `/proc/net/dev` 中的计数；直连 ≈ 总量 − 代理。
  - 连接数：`/proc/net/tcp(6)` 中远端为节点地址的连接数（不开多路复用时即代理连接数）；总连接数读 `nf_conntrack_count`。
- 不推荐 Xray 的 stats API：每次查询都要另起一个 `xray api` 进程，在 ARM 设备上按 2 秒轮询开销过大，还要改 Xray 配置。
- 历史曲线如果要做：daemon 每分钟记一个点，存 tmpfs 环形缓冲（24 小时 1440 个点，几十 KB）。现有设计不妨碍以后加。

### 操作的现有实现路径

- 切换节点：改 `main.node` 后 reload（增量，只重启 Xray），之后**自动做一次健康检测**并在首页显示结果（仓库所有者确认）。reload 完成后发一次 USR1 即可，不需要新机制。
- 重启：重启整个服务（`/etc/init.d/aether-proxy restart`），不只重启 Xray（仓库所有者确认）。
- 测当前节点延迟：向 daemon 发 USR1，monitor 立即跑一轮代理健康检测，`last_probe` 几秒内更新（与首页显示的是同一个指标：经节点请求 `generate_204` 的耗时）。
- 更新订阅：`job start sub update`。
- 停用/启用：建议写 `main.enabled=0/1` 后触发 reload（`reload_service` 遇到 `enabled=0` 会停止服务，见 04「重载」），即**持久**停用，重启路由器后仍保持停用；
  按钮随状态显示「停用」或「启用」。是否还需要「临时停止、重启后恢复」的语义，设计时再定。
- 自动刷新的成本：每次刷新是一次 rpcd `status` 调用（读几个状态文件，加上流量计数的一次 `nft -j list`），开销很小。
  前端经 `/ubus` 调 rpcd，**不受** uhttpd `max_requests 3` 的限制（源码核实：该上限只作用于 cgi/ucode/lua 这类脚本处理器，超出的排队而不是拒绝；ubus 处理器不计入）。
  要注意的是 rpcd 串行处理调用：每次调用必须很快，间隔下限建议 2 秒，同一时刻只允许一个刷新请求在途，上一次没回来就跳过本次；页面不可见（`document.hidden`）时暂停刷新。

### 现有设计中要保持开放的地方

- 首页需要的数据应当都能从现有只读接口取得：`status`（`state.json`、`probe.json` 摘要、`updates_available`）、`events`、`sub.json`；
  新增接口时优先扩展这些输出，而不是让前端直接读文件（[10](10-cli-luci.md) rpcd 插件）。
- 长任务（节点检测、订阅更新）只能经作业机制发起与轮询（[10](10-cli-luci.md)「作业机制」），首页上的按钮也不例外。

## B12 T7.7 真机验收（2026-10-20，H28K，官方 channel-stable）

第一轮（服务不启用，0.2.0-r4 起步）：升到 r5 后安装后检查的 restart 超时（35 秒）→ 判失败并**自动回滚**到 0.1.0-r2（自动回滚路径在真机上实际走通）。

- 服务运行（停 ssr-plus，LAN 流量全程经 aether-proxy）：每次安装后 restart 都回到 running；结束时 DNS T1、检测正常（196 ms）。

## B13 M10 回归窗口发现的后端问题（2026-10-20，H28K，本地 main a60a48f 的 0.2.0-r7 测试包）

回归结论：新入口（T10.8）在 procd 启停、作业、rpcd、更新与回滚、reload 各路径上都正常；`components` 装包后无需重启 rpcd；

1. **已修（T9.5，2026-10-20）**。**切换节点偶尔失败，页面看不出来**（仓库所有者手动切换时遇到：选了另一个节点、应用后仍显示原节点，重复几次才切过去）。

   概览页已改为调 `components` 子命令（T10.5），影响变小，但 `status` 的输出在 reload 前后不一致。
3. 观察（仍待查）：stop 恰好赶上 monitor 正在跑一轮（`BUSY {holder: monitor}`）时，Xray 与 chinadns-ng 先收到终止信号、退出码 0，daemon 记了 `CHILD_CRASHED`（`restart_in: 5`），5 秒后正常停止，无残留。

## B20 分流判定交给 Xray（GeoSite / GeoIP + 多出口），合并 B1、B18 与「补漏」（2026-10-27，待调研）

- 状态：**待调研**，不设计、不出卡；[B1](#b1-自定义分流固定节点按服务分流) 与 [B18](#b18-chinadns-ng-停更与-dns-组件的替代2026-10-27观察项) 的调研并入这里一起做。
- 来源（2026-10-27 仓库所有者）：想要「GFW + 绕过大陆」的组合——默认只代理被墙目标以省流量，gfwlist 漏掉的再由绕过大陆的思路补上。
- 分析：两种模式只在「境外但不在 gfwlist」这一类目标上不同（绕过大陆→代理，仅被墙→直连）；静态组合等于二选一，要两全只能**自动发现漏网的被墙目标**。候选思路：
  1. 按连接失败学习：直连境外 IP 时握手无响应或 TLS 后被重置 → 放进带过期的「学来的代理集合」；缺点是每个漏网站点第一次会失败一次，需要 daemon 读 conntrack/日志。
  2. 按 DNS 污染判断：chinadns-ng 同时查国内与可信上游，能否识别「国内结果不可信」的域名；取决于 chinadns-ng（已停更，B18）。
  3. 把判定挪进 Xray：嗅探出域名后按 geosite（如 `geolocation-!cn`，远比 gfwlist 全）/ geoip 路由到直连、代理或指定节点。这同时覆盖 B1（Netflix、AI 固定节点 = 多出口 + geosite 规则）并减轻对 chinadns-ng 的依赖（B18）。
- 现状：分流全在 nft 层（chnroute 集合 + chinadns-ng 写的 gfw/自定义集合），只有判为代理的流量进 Xray；`xray.json` 有 `routing` 段和未用的 `direct` 出站。这样直连流量不经 Xray（省 CPU，Xray 挂了国内照常，`fail_open` 由此而来）。
- 代价（方案 3）：较合理的混合是 nft 继续直放国内地址，境外全部进 Xray 由它判定——境外直连也经过 Xray，CPU 与「Xray 故障的影响面」变大；geosite.dat / geoip.dat 数 MB 到十几 MB，要占空间并经发布通道更新。
- 参考（2026-10-27 查）：ssr-plus 的 Xray **不用** geo 数据分流——`gen_config.lua` 不引用 geosite/geoip；它的「Geo 数据库更新」页（2026-05-02）与 v2ray-geosite/geoip 包（2026-04-30）随 Mihomo 内核加入，供 Clash 配置使用；分流仍是 nft/ipset 的 chnroute + gfwlist。要借鉴「代理内核里按 geosite 分流」得看 passwall / passwall2 / homeproxy（sing-box）/ OpenClash（Mihomo）。
- 暂时的手动补漏：漏网网站加进「代理域名」名单（`proxy_domain.txt`，保存后自动重载生效）。
