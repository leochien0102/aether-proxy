# T16.107 显式代理服务第一步：可选的本机 SOCKS5 / HTTP 入站

目标：在实际 schema→快照→Xray 渲染路径实现两个独立、默认关闭的 TCP 入站；不是只在测试里手拼 JSON。只监听 127.0.0.1。此卡完成不等于 LAN 服务已上线。不复用 31081 内部诊断口、不改变透明代理策略或既有出站协议。两种入站独立标签、端口，显式路由到当前 proxy 出站，不回退 direct。仅 HTTP CONNECT 到 HTTPS 目标，不宣称支持 TLS 到代理。

配置跟随现有 schema 约定：默认双关兼容原配置；开启项必须有合法端口及成对非空的独立入站账号/密码（不借用上游账号）；两个启用端口不能互撞或占用内部监听。无节点沿用现有拒绝启动路径。不引入通配监听、UDP、WAN/LAN 暴露、LuCI、额外进程、周期任务、落盘日志中的凭据；核对配置导出/诊断脱敏及渲染文件权限。不能安全满足时列出阻塞，不降级为免认证。

验收：双关时既有配置/监听不变；仅 SOCKS、仅 HTTP、双开均通过现有 Xray 的配置检查，真实监听只在 loopback。使用离线本地测试上游与目标，正确认证后分别经 SOCKS5、HTTP 转发、HTTP CONNECT 到 TLS 站成功；无凭据或错误凭据目标零命中；停掉上游后不得直连。覆盖冲突端口/内部端口、凭据缺失、报告和诊断不回显秘密。优先复用现有真实 Xray 夹具；复跑受影响套件、diff --check，报告附版本、命令与结果。范围仅配置/渲染/必要校验脱敏、对应测试、配置文档与 reports/T16.107.md。不得改防火墙、发版、设备或 B29 草稿；若发现必须扩范围先说明。只本地提交交回 SHA。

后继卡另验可信 LAN 的入接口与目的地址限制（包含来自 WAN/访客访问 LAN 地址的反例）、运行时启停与 fw4 reload 不暴露、再接 LuCI。TLS 到代理及证书策略等用户定案，不阻塞 loopback 部分。
