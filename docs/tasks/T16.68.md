# T16.68 · SIGHUP 重载与外部 cleanup 使用同一操作锁（审计 M2）

**目标**：独立进程执行 cleanup 与 daemon 的外部 HUP 事务不能同时修改活动数据面。进程内 busy 不替代跨进程锁；不改变 daemon.lock 或账本锁。

**入口**：从 `daemon.uc` 的 `pending.reload`、`cleanup_run()` 及 `monitor.uc` 中持操作锁调用 reload 的路径梳理所有权。保护外部 HUP 的实际变更、失败回滚，以及 reload 触发 stop 的破坏性清理，至事务完成；已持锁的监控调用不得自锁。锁不可用不能发布成功或留下半套改动；遵守已有失败/完成反馈与停止优先语义。说明锁忙后如何再请求；不要求新增排队机制、重试循环、事件码或公共 API。

**验收**：用隔离 sysroot 和真实 flock/HUP/cleanup、确定性屏障，不依靠 sleep 猜时序。覆盖两方向竞争（HUP 在途拒绝并发 cleanup；外部持锁时 HUP 无副作用且释放后新请求可成功）；在回滚尚未完成时仍互斥，完成后能重取；覆盖 HUP 停用和已持锁监控 reload 正控。以状态/子进程/数据面 stub 调用证明，不只测是否调用 lock。先留一份基线红证据；沿用已有 fixture，不复制一套不必要的 daemon 框架。

**范围**：仅 `aether-proxy/src/lib/{daemon,reload,monitor}.uc` 中必要入口、`tests/{daemon,reload,monitor}/` 对应测试、必要的 `docs/04-lifecycle.md` 和 `reports/T16.68.md`。不顺带修 H4、T16.55，不碰版本、设备或远端。跑 daemon/reload/monitor、既有 instance-owner 与 startup-state-lock、`tests/review.sh ac2353ea` 和 `git diff --check`。报告记录锁的所有者、释放点与实测证据，仅本地提交后交回 SHA。
