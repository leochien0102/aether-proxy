## T0.4 `sys.run` 不再依赖 `timeout(1)`（H28K 实测后追加）

- **分支**：`m0/sys-run-timeout`
- **背景**：2026-10-14 在 H28K（lede，busybox）上实测：`timeout 5 ip rule help` 输出 `ip: invalid argument 'help' to 'ip'`，而直接执行 `ip rule help`
  正常（打印用法到 stderr，退出码 255）。也就是说经过 busybox 的 `timeout` 之后，被执行命令收到的参数不可靠；同一台机器上带 timeout 的
  `nft -c -f <file>` 却是正常的。`sys.run` 是所有外部命令的唯一入口（[12](../12-ucode.md) 规则 2），所以必须去掉这个依赖。
  这次的直接后果是 `check` 的前置检查把 ip-full 误判为不支持 fwmark，后续的 `nft -c` 与 `xray run -test` 都被跳过。
- **必读**：[12](../12-ucode.md)「编码规则」第 2 条、「ucode 2025.07.18 的语法限制」；现有 `aether-proxy/src/lib/sys.uc`（读懂 `WRAPPER` 的工作方式）
- **要求**
  - 只改 `aether-proxy/src/lib/sys.uc` 和新增测试，**不改 `run()` 的签名和返回结构**，只在结果中新增布尔字段 `timed_out`（未设置 `opts.timeout` 时恒为 `false`）。
  - 超时用 POSIX sh 在包装脚本里实现：把命令放到后台执行，另起一个计时子进程，到时 `kill` 它（先 TERM，1 秒后仍在则 KILL），然后 `wait` 取退出码；
    被计时器杀掉时退出码统一为 `124`、`timed_out` 为 `true`；命令在时限内结束时，必须**立即**结束计时子进程（不能留下 sleep 进程，也不能让调用方多等）。
  - 不准使用 `timeout`、`setsid`、`bash` 特性；只用 busybox ash 也支持的 POSIX sh 语法。参数仍然只能经 `"$@"` 传递，不准拼接进脚本文本。
  - 命令自己以 124 退出（而不是被杀）时，`timed_out` 必须为 `false`——用计时器留下的标记文件区分，不要靠退出码猜。
  - `CMD_FAILED` 日志在超时时附带 `timed_out=true`。
- **测试**：新增 `tests/unit/sys_run.uc`（表驱动，在宿主机上运行），至少覆盖：
  1. `['printf', '%s|', 'rule', 'help']` 在设置与不设置 `timeout` 时输出都是 `rule|help|`（参数原样到达）
  2. 带空格、单引号、`$()`、换行的参数原样到达
  3. `['sh', '-c', 'echo out; echo err >&2; exit 3']`：code 3、stdout/stderr 正确、`timed_out` false
  4. `['sleep', '5']` 加 `timeout: 1`：code 124、`timed_out` true，且整个调用耗时小于 3 秒
  5. `['sh', '-c', 'exit 124']` 加 `timeout: 5`：code 124、`timed_out` false
  6. 快速结束的命令加 `timeout: 30`：调用耗时小于 1 秒，且调用返回后没有残留的 sleep 子进程
- **验收**：`tests/review.sh` 的 FAIL 为 0；上述单元测试全部通过；报告中贴出 `tests/unit/sys_run.uc` 的运行结果。
  真机复测（H28K 上重跑阶段 1 脚本）由设计负责人在合并后安排。

## S1 子进程日志转发（探针）

- **问题**：`uloop.process` 不能重定向子进程的 stdio。要在 daemon 中监督 Xray 和 chinadns-ng，并把它们的输出分别以
  `aether-proxy-xray`、`aether-proxy-dns` 标签写入 logd（[09](../09-logging.md)「子进程日志」中的三个候选方案）。
- **做法**：在 24.10.8 虚拟机上为每个方案写一个原型脚本（`spikes/S1/`），子进程用一个会持续输出、并能被信号终止的 shell 脚本模拟。
- **必须回答**
  1. 每个方案能否得到正确的 pid；SIGTERM 能否结束子进程且不留下孤儿进程
  2. 子进程退出时能否拿到退出码，延迟多久
  3. 子进程高速输出（每秒 1000 行）时 daemon 是否阻塞或丢行
  4. daemon 被 `kill -9` 后，子进程是否残留（预期会残留，由 cleanup 处理；记录实际情况）
  5. ~~busybox `timeout` 的退出码~~：已由 T0.4 解决，`sys.run` 不再使用 `timeout(1)`
- **产出**：修改 [09](../09-logging.md)「子进程日志」，写明选定的方案和理由；如果影响 [04](../04-lifecycle.md) 的进程模型，一并修改。
