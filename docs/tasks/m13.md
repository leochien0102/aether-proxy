# M13 任务卡：游戏模式 UDP 并发下的 xray FD 上限

> **项目与范围**：本文件的任务卡全部属于 **aether-proxy** 仓库（主检出 `/workspace/openwrt/aether-proxy`，GitHub `leochien0102/aether-proxy`）。
> 执行时只在 `tests/start-task.sh <卡号>` 创建的 worktree（`/workspace/openwrt/aether-proxy-wt/<卡号>`）中读写；
> **不准修改主检出，也不准碰 `/workspace/openwrt` 下的任何其他仓库**（helloworld、luci-extras、openwrt-actions 等，含其构建目录）。
> 任务卡要求「参考」其他仓库的文件时，只读不写。执行约定见 [README.md](README.md)「执行约定」。

背景：开启游戏模式（UDP 转发）后，xray 进程的 `Max open files` 只有 **4095/4096**；高 UDP 并发时 `accept4: too many open files`，所有 inbound 一起失败。**这不是 x86 独有**，任何运行游戏模式或高 UDP 并发流量的设备都可能撞上；x86 只是目前先复现的环境。helloworld 的 ssr-plus 在 `ln_start_bin()` 里对子进程执行 `ulimit -n 1000000`，所以不撞这个上限；aether-proxy 由 procd 直接启动，缺这一设置。

---

## T13.1 为 aether-proxy 设置 procd nofile（全平台）

- **分支**：`fix/t13.1-xray-nofile`，从 main 建；不要基于 `experiment/b25-heatmap`。
- **允许改动**：`aether-proxy/files/aether-proxy.init`、`tests/ci/`（静态断言）、`docs/04-lifecycle.md` 或 `docs/11`（如需要）、`reports/T13.1.md`。不改后端/UI/B25/版本。
- **实现**：
  1. 在 `aether-proxy.init` 的 `procd_open_instance aether-proxy` 之后、`procd_close_instance` 之前加入：
     ```sh
     procd_set_param limits nofile="1000000 1000000"
     ```
     让 aether-proxy 及其启动的 xray、chinadns-ng 继承同一上限；该设置对所有 target 生效，不做 x86 条件分支。
  2. 不改变 start/stop/reload 语义；不引入 shell `ulimit`（procd 启动，shell 里的 ulimit 不作用于子进程）。
- **测试**：
  - `sh -n aether-proxy/files/aether-proxy.init`。
  - 在 `tests/ci/smoke.sh` 或 `smoke-host.py` 加静态断言：安装后的 `/etc/init.d/aether-proxy` 包含
    `procd_set_param limits nofile="1000000 1000000"`。
  - 现有 CI 冒烟/打包回归全过。
- **真机验收**（x86 是可复现环境；实现者若够不到就写清未做）：
  1. 安装新包，重启服务；
  2. `cat /proc/$(pidof aether-xray | awk '{print $1}')/limits | grep 'open files'` 应为 `1000000 1000000`；
  3. 开启游戏模式 UDP，观察 `aether-proxy` 日志不再出现 `accept4: too many open files`；其他 target 若做同样高 UDP 并发，行为应一致。
  4. 记录 xray FD 峰值，确认不是单调泄漏。
- **验收**：init 语法通过、静态断言存在、CI 通过；任意 target 上 xray 上限为 1000000；x86 作为复现环境验证不再报 FD 错；不 bump、不 push。

## T13.2 应用自有原始日志（后端）

- **目标**：系统 logd 继续保留；aether-proxy 另写一份 tmpfs 原始日志，`log` 命令改为读这份文件，不再从 `logread` 取原始日志。
- **分支**：`feat/app-raw-logs`，worktree `/workspace/openwrt/aether-proxy-wt/logs-app`。
- **允许改动**：`aether-proxy/src/lib/daemon.uc`、`supervise.uc`、`cmd/log.uc`、`const.uc`、`files/`（如需 collector 脚本）、`tests/`、`docs/09`、`docs/10`、报告。不改 UI 清理按钮、不改 config。
- **存储**：
  - 路径 `/var/run/aether-proxy/raw.log`（tmpfs，0600）；同目录 `raw.log.1` 为上一段。
  - 上限约 **1 MiB 或 2000 行**，达到后轮转：旧 `raw.log` → `raw.log.1`，只保留一份旧段（不写 flash）。
  - 只保存 `aether-proxy[...]` 标签的行（含 xray/chinadns-ng 子进程行），保持原始整行，供现有 source 分类。
- **采集**：
  - daemon 启动时启动一个受 supervise 管理的 raw-log collector；停止时停止。
  - collector 从启动后 `logread -f -e 'aether-proxy'` 取新行，追加到 `raw.log`；不做历史回填（重启前/清空前的旧行不需要）。
  - 采集不得清空或修改系统 logd；系统日志仍完整保留。
  - 关闭/重启服务时 collector 不得成为僵尸；失败只记录一次 warn，不影响主服务。
- **读取**：
  - `aether-proxy log` 读 `raw.log` + `raw.log.1`，保持 `--source` / `--lines` / `--json` 契约；行按文件时间顺序，取最后 N 行。
  - 文件不存在/为空返回空 lines；不再调用 `logread` 获取原始日志。
  - 事件页仍读 `events.jsonl`，不变。
- **测试**：collector 启停、追加/轮转、1 MiB/2000 行上限、log 读新旧段、source 过滤、空文件、系统 logd 未被调用/清空；现有 logs/cli/rpcd 回归。
- **验收**：原始日志来自应用文件；系统日志完整；不写 flash；不 bump、不 push。

- **目标**：原始日志页最新行在最上面；同时修日志页标签按钮/筛选行/操作行挤在一起的老问题，事件页不受影响。

- **布局（参照 docs/10「日志页」与既有 UI 规则）**：

- **测试**：3+ 行断言 DOM 文本为最新在前；标签按钮/筛选行/操作行的 flex/gap/wrap/宽度 class 或样式断言；窄屏不重叠；CLI/模型兼容；不引入 HTML。

## T13.4 清空应用日志按钮 + API

- **依赖**：T13.2、T13.3。
- **目标**：日志页提供「清空日志」按钮；只清 aether-proxy 的 `raw.log`/`raw.log.1`/`events.jsonl`，绝不清系统 logd。
- **允许改动**：`cmd/log.uc`、rpcd 插件、ACL、`common.js`、`view/logs.js`、`model/logs.js`、po、tests、docs/10、报告。
- **后端**：
  - CLI `aether-proxy log clear`（或等价子命令）：截断/清空 raw.log、raw.log.1、events.jsonl；不执行 `logread -c`，不删/改 `/var/log` 或系统日志；返回 `{ok:true}`，失败明确错误码。
  - rpcd `log_clear` 归 **write** ACL；`common.js` 白名单。
- **UI**：
  - **工具栏位置**：原始日志面板顶部放一行工具栏，左侧是「来源 / 行数」，右侧是「刷新 / 清空日志」；日志正文在工具栏下方，不能让用户滚动到底部才能刷新或清空。
  - 工具栏用 flex + `justify-content:space-between` + gap + wrap；窄屏自然换行，右侧按钮仍保持在日志正文上方。
  - 清空错误提示放在工具栏与日志正文之间，不挤占按钮行；成功/失败后仍停留在顶部。
  - 原始日志面板右侧加 `清空日志`，`cbi-button cbi-button-remove`；点击先 `ap.confirm`，文案明确「只清空 aether-proxy 日志，系统日志不受影响，不能撤销」。
  - 进行中禁用按钮；成功后清空 raw 区域并刷新事件页；失败内联错误，不弹全局横幅。
  - 按现有 UI 规则：破坏性按钮 `remove`、确认框 `destructive:true`、文本节点安全。
- **测试**：CLI 清理三个文件、不调用 logread -c、无文件/部分文件、失败；rpcd 参数/ACL；UI 按钮 class/确认/成功失败/禁用；现有 logs/rpcd/luci 回归。
- **验收**：只清应用日志；系统日志不变；按钮符合规范；不 bump、不 push。
