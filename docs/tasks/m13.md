# M13 任务卡：游戏模式 UDP 并发下的 xray FD 上限

> **项目与范围**：本文件的任务卡全部属于 **aether-proxy** 仓库（主检出 `/workspace/openwrt/aether-proxy`，GitHub `leochien0102/aether-proxy`）。
> 执行时只在 `tests/start-task.sh <卡号>` 创建的 worktree（`/workspace/openwrt/aether-proxy-wt/<卡号>`）中读写；
> **不准修改主检出，也不准碰 `/workspace/openwrt` 下的任何其他仓库**（helloworld、luci-extras、openwrt-actions 等，含其构建目录）。
> 任务卡要求「参考」其他仓库的文件时，只读不写。执行约定见 [README.md](README.md)「执行约定」。

背景：开启游戏模式（UDP 转发）后，xray 进程的 `Max open files` 只有 **4095/4096**；高 UDP 并发时 `accept4: too many open files`，所有 inbound 一起失败。**这不是 x86 独有**，任何运行游戏模式或高 UDP 并发流量的设备都可能撞上；x86 只是目前先复现的环境。helloworld 的 ssr-plus 在 `ln_start_bin()` 里对子进程执行 `ulimit -n 1000000`，所以不撞这个上限；aether-proxy 由 procd 直接启动，缺这一设置。

---

## T13.1 为 aether-proxy 设置 procd nofile（全平台）

- **分支**：`fix/t13.1-xray-nofile`，从 main 建；不要基于 `experiment/b25-heatmap`。
- **允许改动**：`aether-proxy/files/aether-proxy.init`、`tests/ci/`（静态断言）、`docs/04-lifecycle.md` 或 `docs/11`（如需要）、`reports/T13.1.md`。不改后端/UI/B25/版本。
- **实现**：
  1. 在 `aether-proxy.init` 的 `procd_open_instance aether-proxy` 之后、`procd_close_instance` 之前加入：
     ```sh
     procd_set_param limits nofile="1000000 1000000"
     ```
     让 aether-proxy 及其启动的 xray、chinadns-ng 继承同一上限；该设置对所有 target 生效，不做 x86 条件分支。
  2. 不改变 start/stop/reload 语义；不引入 shell `ulimit`（procd 启动，shell 里的 ulimit 不作用于子进程）。
- **测试**：
  - `sh -n aether-proxy/files/aether-proxy.init`。
  - 在 `tests/ci/smoke.sh` 或 `smoke-host.py` 加静态断言：安装后的 `/etc/init.d/aether-proxy` 包含
    `procd_set_param limits nofile="1000000 1000000"`。
  - 现有 CI 冒烟/打包回归全过。
- **真机验收**（x86 是可复现环境；实现者若够不到就写清未做）：
  1. 安装新包，重启服务；
  2. `cat /proc/$(pidof aether-xray | awk '{print $1}')/limits | grep 'open files'` 应为 `1000000 1000000`；
  3. 开启游戏模式 UDP，观察 `aether-proxy` 日志不再出现 `accept4: too many open files`；其他 target 若做同样高 UDP 并发，行为应一致。
  4. 记录 xray FD 峰值，确认不是单调泄漏。
- **验收**：init 语法通过、静态断言存在、CI 通过；任意 target 上 xray 上限为 1000000；x86 作为复现环境验证不再报 FD 错；不 bump、不 push。
