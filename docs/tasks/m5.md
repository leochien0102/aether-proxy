## T5.1 URI 解析与订阅解码

- **分支**：`m5/uri-parse`
- **必读**：[06](../06-nodes-subscription.md)「订阅解析」「URI 格式」（含跳过原因的固定枚举）；[05](../05-config.md) node 字段表与「校验规则」第 6、7 条；
  现有 `lib/config.uc`、`lib/schema.uc`、`lib/net.uc`
- **允许改动**：新增 `lib/uri.uc` 与测试；`lib/config.uc` 只允许**新增导出**一个纯函数 `validate_node(node) → errors[]`，复用现有的节点校验逻辑（规则 6、7），
  不准改变任何现有行为——T1.1/T1.9 的全部夹具与单元测试必须不经 `--update` 照样通过
- **要求**
  - `lib/uri.uc` 导出（全部为纯函数）：
    - `parse_line(line) → { node } | { skip: <原因> }`：按 06 解析 vless / vmess / trojan / ss（SIP002 与旧格式），`#` 后的名称写进 `label`
    - `parse_body(text) → { ok, nodes: [...], skipped: { <原因>: <数量> }, error: <代码>|null }`：实现 06「订阅解析」第 1–4 步
      （明文/Base64 判断、标准与 URL-safe 字母表、可选填充、Clash YAML 识别、`\r?\n` 切行、0 个有效节点即整体失败）
  - 解析出的节点再经 `config.validate_node` 检查；违反规则 7 的映射为跳过原因 `insecure_transport` 或 `invalid_value`，违反必填项的为 `missing_field`
  - 同一次订阅内 strong 键（06「节点身份」，T5.2 实现）重复的处理不在本卡，留给 T5.3
  - URL 解码、Base64 解码不准引入外部命令（纯 ucode，`b64dec` 等内置函数可用）
- **测试**：`tests/unit/uri.uc` 表驱动，至少覆盖：每种协议的典型 URI（vless reality vision、vless ws tls、vmess v2rayN JSON、trojan grpc、ss SIP002 base64 userinfo、
  ss 2022 的 URL 编码 userinfo、ss 旧格式）；每个跳过原因至少一例；`allowInsecure=1` 照常导入（报告中说明如何体现 `NODE_INSECURE_IGNORED`，06 要求记 WARN——
  纯函数里返回一个 `warnings` 字段即可）；名称含中文与 emoji 的 URL 编码；`parse_body` 的明文、标准 Base64、URL-safe 无填充、Clash YAML、全部无效 五种情况。
- **验收**：`tests/review.sh` 的 FAIL 为 0；T1.1/T1.9 期望文件无改动（`git diff --stat main...HEAD -- tests/fixtures` 为空）。

## T5.2 节点身份匹配

- **分支**：`m5/identity`
- **必读**：[06](../06-nodes-subscription.md)「节点身份」（匹配键**直接存拼接字符串、不做哈希**，2026-10-15 更新）与匹配算法 1–6 步；[05](../05-config.md) node 字段表
- **允许改动**：新增 `lib/identity.uc` 与测试
- **要求**
  - `keys(node) → { strong, weak }`：按 06 的公式拼接，`address` 小写，缺失字段按空串参与拼接
  - `match(old_nodes, new_nodes, opts) → { assign: [ { id, node, from: "strong"|"weak"|"label"|"new" } ], stale: [id…], removed: [id…], revived: [id…] }`
    - `old_nodes`：`{ <段名>: node }`，只包含同一订阅的旧节点；`opts.referenced(id) → bool` 决定消失的节点进入 `stale` 还是 `removed`；
      `opts.new_id() → string` 生成新 ID（测试中注入确定性的生成器，正式环境以后由调用方提供 `n_<32位十六进制>`）
    - 每个旧节点最多被匹配一次；严格按 06 的步骤顺序（strong → 唯一 weak → 唯一同协议同 label → 新建）
  - 纯函数，不读 UCI、不生成随机数
- **测试**：`tests/unit/identity.uc` 表驱动，至少覆盖 06 中列出的情况：凭据轮换（weak 命中）、换 IP 但 label 不变（label 命中）、同一 `IP:443` 下多个节点仅 path/SNI/UUID 不同、
  weak 键在旧节点中不唯一时不得用 weak 匹配、消失且被引用（stale）、消失且未被引用（removed）、stale 节点重新出现（revived）、全部新增。
- **验收**：`tests/review.sh` 的 FAIL 为 0。
