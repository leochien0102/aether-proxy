> **项目与范围**：本文件的任务卡全部属于 **aether-proxy** 仓库（主检出 `/workspace/openwrt/aether-proxy`，GitHub `leochien0102/aether-proxy`）。
> 执行时只在 `tests/start-task.sh <卡号>` 创建的 worktree（`/workspace/openwrt/aether-proxy-wt/<卡号>`）中读写；
> **不准修改主检出，也不准碰 `/workspace/openwrt` 下的任何其他仓库**（helloworld、luci-extras、openwrt-actions 等，含其构建目录）。

## T5.1 URI 解析与订阅解码

- **分支**：`m5/uri-parse`
- **必读**：[06](../06-nodes-subscription.md)「订阅解析」「URI 格式」（含跳过原因的固定枚举）；[05](../05-config.md) node 字段表与「校验规则」第 6、7 条；
  现有 `lib/config.uc`、`lib/schema.uc`、`lib/net.uc`
- **允许改动**：新增 `lib/uri.uc` 与测试；`lib/config.uc` 只允许**新增导出**一个纯函数 `validate_node(node) → errors[]`，复用现有的节点校验逻辑（规则 6、7），
  不准改变任何现有行为——T1.1/T1.9 的全部夹具与单元测试必须不经 `--update` 照样通过
- **要求**
  - `lib/uri.uc` 导出（全部为纯函数）：
    - `parse_line(line) → { node } | { skip: <原因> }`：按 06 解析 vless / vmess / trojan / ss（SIP002 与旧格式），`#` 后的名称写进 `label`
    - `parse_body(text) → { ok, nodes: [...], skipped: { <原因>: <数量> }, error: <代码>|null }`：实现 06「订阅解析」第 1–4 步
      （明文/Base64 判断、标准与 URL-safe 字母表、可选填充、Clash YAML 识别、`\r?\n` 切行、0 个有效节点即整体失败）
  - 解析出的节点再经 `config.validate_node` 检查；违反规则 7 的映射为跳过原因 `insecure_transport` 或 `invalid_value`，违反必填项的为 `missing_field`
  - 同一次订阅内 strong 键（06「节点身份」，T5.2 实现）重复的处理不在本卡，留给 T5.3
  - URL 解码、Base64 解码不准引入外部命令（纯 ucode，`b64dec` 等内置函数可用）
- **测试**：`tests/unit/uri.uc` 表驱动，至少覆盖：每种协议的典型 URI（vless reality vision、vless ws tls、vmess v2rayN JSON、trojan grpc、ss SIP002 base64 userinfo、
  ss 2022 的 URL 编码 userinfo、ss 旧格式）；每个跳过原因至少一例；`allowInsecure=1` 照常导入（报告中说明如何体现 `NODE_INSECURE_IGNORED`，06 要求记 WARN——
  纯函数里返回一个 `warnings` 字段即可）；名称含中文与 emoji 的 URL 编码；`parse_body` 的明文、标准 Base64、URL-safe 无填充、Clash YAML、全部无效 五种情况。
- **验收**：`tests/review.sh` 的 FAIL 为 0；T1.1/T1.9 期望文件无改动（`git diff --stat main...HEAD -- tests/fixtures` 为空）。

## T5.2 节点身份匹配

- **分支**：`m5/identity`
- **必读**：[06](../06-nodes-subscription.md)「节点身份」（匹配键**直接存拼接字符串、不做哈希**，2026-10-15 更新）与匹配算法 1–6 步；[05](../05-config.md) node 字段表
- **允许改动**：新增 `lib/identity.uc` 与测试
- **要求**
  - `keys(node) → { strong, weak }`：按 06 的公式拼接，`address` 小写，缺失字段按空串参与拼接
  - `match(old_nodes, new_nodes, opts) → { assign: [ { id, node, from: "strong"|"weak"|"label"|"new" } ], stale: [id…], removed: [id…], revived: [id…] }`
    - `old_nodes`：`{ <段名>: node }`，只包含同一订阅的旧节点；`opts.referenced(id) → bool` 决定消失的节点进入 `stale` 还是 `removed`；
      `opts.new_id() → string` 生成新 ID（测试中注入确定性的生成器，正式环境以后由调用方提供 `n_<32位十六进制>`）
    - 每个旧节点最多被匹配一次；严格按 06 的步骤顺序（strong → 唯一 weak → 唯一同协议同 label → 新建）
  - 纯函数，不读 UCI、不生成随机数
- **测试**：`tests/unit/identity.uc` 表驱动，至少覆盖 06 中列出的情况：凭据轮换（weak 命中）、换 IP 但 label 不变（label 命中）、同一 `IP:443` 下多个节点仅 path/SNI/UUID 不同、
  weak 键在旧节点中不唯一时不得用 weak 匹配、消失且被引用（stale）、消失且未被引用（removed）、stale 节点重新出现（revived）、全部新增。
- **验收**：`tests/review.sh` 的 FAIL 为 0。

## T5.3 `sub update`：下载、匹配、原子应用

- **分支**：`m5/sub-update`
- **必读**：[06](../06-nodes-subscription.md)「订阅获取」「订阅解析」「节点身份」「原子应用」（2026-10-15 补充了逐订阅处理、`duplicate`、新 ID 格式、删除缺失字段、临时副本校验、换包名生成新文件再整文件替换、订阅锁、命令约定）；
  [05](../05-config.md) `subscription` 与 `node` 段；[09](../09-logging.md) `SUB_*`、`NODE_STALE` 事件；[10](../10-cli-luci.md)「`aether-proxy` 约定」与「仅供测试的选项」；
  现有 `lib/uri.uc`（`parse_body`）、`lib/identity.uc`（`keys`、`match`）、`lib/pipeline.uc`、`lib/sys.uc`（`run`、`lock`、`write_atomic`）、`lib/net.uc`（`tcp_listening`）、`lib/cmd/probe.uc`（子命令的写法参考）
- **允许改动**：新增 `lib/sub.uc`、`lib/cmd/sub.uc`，在入口 `aether-proxy` 中分发 `sub` 并补充用法说明；`lib/const.uc` 末尾追加 T5.3 区块；
  新增 `tests/unit/sub.uc`、`tests/sub/run.sh`（集成测试）、`tests/sub/` 下的夹具、`tests/stubs/sub-bin/`（`curl`、`xray`、init 脚本替身）。不准改 `uri.uc`、`identity.uc` 的行为
- **结构**
  - **纯函数** `plan(old_nodes, parsed, opts) → { changes, counts, current_changed }`（`lib/sub.uc` 导出）：
    `old_nodes` 为 `{ <段名>: node }`（只含该订阅的旧节点），`parsed` 为 `uri.parse_body` 的 `nodes`；先按 strong 键去重（`duplicate` 计入 `counts.skipped`），
    再调用 `identity.match`；`opts.current`（`main.node`）、`opts.new_id()`（测试注入确定性生成器）；
    `changes` 是有序的 `[ { op: "add"|"set"|"delete_option"|"delete_section", section, option?, value? } ]`，覆盖 06 第 2 步的全部规则（含删除新节点没有的协议字段、`stale` 设置与清除）；
    `current_changed` 为当前节点的协议字段是否变化
  - **执行器** `update(ctx, sub_name|null) → { ok, subs }`：拿订阅锁 → 逐订阅 下载 → 解析 → 读旧节点 → `plan` → 当前节点受影响时在临时 confdir 副本上应用 `changes` 并渲染加 `xray run -test`
    → 按 06 第 3–5 步：在 `<run-dir>/sub-work/` 中以包名 `aetherproxy_sub` 生成新文件 → 当前节点受影响时渲染校验 → 比较原文件未被并发修改后 `sys.write_atomic` 替换
    → 释放锁 → 需要时执行 init 脚本的 `reload` → 写 `sub.json` 与事件。**不准**直接对包 `aetherproxy` 用 cursor 提交（06 第 3 步解释了原因）
  - 新 ID 用 ucode 读 `/dev/urandom` 生成（06 的格式），不调用外部命令
  - `fetch_via=proxy|auto` 判断「Xray 在运行」：`state.json` 的 `state` 为 `starting`/`running`/`degraded`，且 `HTTP_PORT` 在 `/proc/net/tcp`/`tcp6` 中处于监听（`net.tcp_listening`）
  - curl 经 `sys.run` 调用（超时 35 秒，大于 `--max-time 30`），参数按 06「订阅获取」；下载目录 `/tmp/aether-proxy-dl/`（受 `--sys-root` 前缀影响），用完删除
- **测试**
  - `tests/unit/sub.uc`（表驱动，覆盖 `plan`）：首次导入全部新增；凭据轮换沿用 ID；同 strong 键重复只保留第一条并计 `duplicate`；沿用 ID 时删除缺失字段（旧有 `flow`、新无）；
    当前节点消失 → `stale`；未被引用的消失节点 → 删除；stale 节点重新出现 → 清除 `stale`；当前节点字段变化与不变两种 `current_changed`
  - `tests/sub/run.sh`（替身 + 临时 sysroot，不访问外网）：`curl` 替身按 URL 返回夹具文件内容，可按环境变量模拟 HTTP 错误、空内容、记录参数；`xray` 替身可按环境变量让 `run -test` 失败；
    init 脚本替身记录 `reload` 调用。场景至少包括：
    1. 首次更新：节点写入 UCI，`source`、`match_strong`、`match_weak` 正确，段名符合 `^n_[0-9a-f]{12}4[0-9a-f]{3}[89ab][0-9a-f]{15}$`
    2. 再次更新同一内容：UCI 文件内容不变（md5 相同），不调用 reload
    3. 当前节点字段变化且 `state.json` 为 `running` → 调用一次 `reload`；服务未运行 → 不调用
    4. 当前节点变化但 `xray run -test` 失败 → `SUB_APPLY_INVALID`，UCI 文件不变
    5. 下载失败、内容为空 → `SUB_FETCH_FAILED`，UCI 文件不变；全部无效 → `SUB_NO_VALID_NODES`
    6. `fetch_via=proxy` 而 Xray 未运行 → `SUB_PROXY_UNAVAILABLE`；`auto` 直连失败且 Xray 在运行 → 第二次 curl 带 `-x http://127.0.0.1:31081`
    7. 节点数缩水到一半以下（旧 ≥ 4）→ 照常应用并记 `SUB_SHRANK`
    8. 两个订阅一个成功一个失败 → 成功的照常写入，退出码 1；指定不存在的段名 → 退出码 2；订阅锁被占用 → 退出码 3
    9. LuCI 未保存的修改不被提交：测试开始前在**真实的** `/tmp/.uci/aetherproxy` 写入一条 delta（例如 `aetherproxy.main.mode='global'`；文件已存在则跳过本场景并在输出中说明），
       更新后断言配置文件里 `mode` 未变，测试结束时删除该文件（`trap` 保证删除）。另加一个场景：更新过程中原文件被修改（`curl` 替身在返回内容前改动配置文件）→ `SUB_APPLY_INVALID`，文件保留替身改动后的内容
    10. `sub.json` 内容与 06 第 6 步一致
- **验收**：`tests/review.sh` 的 FAIL 为 0；`tests/sub/run.sh` 全过；`tests/daemon/run.sh`、`tests/reload/run.sh` 仍全过。
