# T16.104 提交与用户版发布说明约定（从 1.3.0-r1 起）

目标：让维护者从 git log 一行读懂行为变化，让设备用户从一个版本条目看懂「改了什么、升级前要做什么」。本卡只做规范与首份草稿；不重写旧提交或旧 Release。

在既有维护者提交约定和发布清单上增补、交叉引用，不另造平行规范：保留 emoji、类型和小写模块 scope，新提交优先用中文写具体行为；任务号放正文，复杂变更交代原因/兼容边界；保留仓库已有的正式版本提交格式。给出一个真实的前后对照，不新增 CI。

以 docs/releases/1.3.0-r1.md 作为第一份新格式说明，清楚标记未发布，不填写发布日期。固定二级标题「主要变化」和可选「升级须知」，各用单层纯文本列表；这两段是将来 LuCI 与正式 Release 共用的唯一摘要来源。维护者的技术细节可放后面。基于 v1.2.2-r10..HEAD 最终净变化，按用户效果归并并核对依据，不逐条翻译提交；不要把测试数量、临时返工或独立 DNS 仓尚未进入应用包的行为写成已交付。变更日志界面另卡实现，未完成前不列为既成变化。

验收：读者只看示例标题能说出行为差异；只看版本摘要能判断升级影响。报告列摘要到最终代码/卡的对应关系，并说明本次为何不改历史。仅改既有约定/清单、上述版本草稿和 reports/T16.104.md；不实现 LuCI，不 bump 已安装包、不改兼容窗口/状态页为已发布，不碰 B29 草稿。git diff --check。仅本地提交交回 SHA，不合 main、不推送、不发版、不动设备。
