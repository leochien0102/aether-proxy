# T16.63 · 更新页的文本与通道链接（审计 M8）

目标：更新状态行中的外部数据只能作为文本显示；通道地址只有在确为有效的绝对 HTTP(S) URL 时才可点击。不改数据来源、更新策略或安装流程。

入口：LuCI `view/aether-proxy/updates.js` 的状态行；核对实际 SDK 的 E()/DOM 对字符串子项的处理，不把简化的测试 loader 当作浏览器证据。范围限该视图、`tests/luci/` 的针对性回归、`reports/T16.63.md`。不改后端、依赖、全局渲染器、版本或设备。

验收：用含尖括号和 & 的普通错误文案，断言显示原文且无由该文案生成的元素。沿现有更新状态行检查同源值的其他渲染点。用平台 URL 解析并明确限定 http:/https:；有效 HTTP 与 HTTPS 均保留通道地址链接及原有新窗口隔离属性；缺值、占位符、相对地址、格式错误和非 HTTP(S) 均不产生该链接，也不留下孤立分隔符。无须构造攻击载荷。覆盖状态刷新从有链接到无链接；不要仅断言源代码包含某字面量。

报告记录基线与修后对照、实际 SDK 语义依据与验证边界。跑定向回归、完整 LuCI、`CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh <派卡基线>`、`git diff --check`。仅本地提交。
