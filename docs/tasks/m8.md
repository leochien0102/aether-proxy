# M8 LuCI 与 rpcd

## 拆卡计划

依据：[10](../10-cli-luci.md)「分层」「rpcd 插件」「LuCI 页面」「作业机制」；Dashboard 的需求见 [backlog](../backlog.md) B2（未设计）。

原则：**业务逻辑全部在 `aether-proxy` 命令行**，rpcd 插件只做参数校验与转发，LuCI 只做展示与调用。
所以凡是页面需要、命令行还没有的功能，先补命令行（可以写宿主机测试），再加 rpcd 方法，最后写页面。

## T8.1 rpcd 插件（已有子命令）

- **分支**：`m8/rpcd`
- **必读**：[10](../10-cli-luci.md)「分层」「`aether-proxy` 约定」「作业机制」「rpcd 插件」（含 2026-10-16 的「实现约定」，本卡的依据）；
  现有 `luci-app-aether-proxy/root/usr/share/rpcd/ucode/aetherproxy.uc`、`…/acl.d/luci-app-aether-proxy.json`、`…/view/aether-proxy/overview.js`；
  `lib/sys.uc`（`run` 的参数与返回值，含超时）、`lib/schema.uc`（`NODE_NAME_RE`、`SUBSCRIPTION_NAME_RE`）、`lib/const.uc`（`UPDATE_PACKAGES`）
- **允许改动**：上面三个 LuCI 文件；新增 `tests/rpcd/run.sh` 与它用的替身；`.github/workflows/test.yml` 增加运行 `tests/rpcd/run.sh` 的步骤。
  **不改** `aether-proxy/` 下的任何文件（插件需要的校验常量从 `aetherproxy.schema`、`aetherproxy.const` 导入，不要在插件里另写一份）
- **要求**
  - 实现 10「rpcd 插件」表中的 `version`、`status`、`service`、`check`、`job_start`、`job_status`、`events`，行为按「实现约定」逐条实现：转发方式、原样返回、`CMD_FAILED` 与 `USAGE` 的格式、超时、`service` 后台执行、`job_start` 参数表、`events` 参数、测试用环境变量
  - 每个方法声明 `args`（无参数的方法声明为空对象）
  - ACL：read 为 `version`、`status`、`events`、`job_status`；write 为 `service`、`check`、`job_start`；UCI `aetherproxy` 读写保持不变
  - `overview.js`：现在的 `status` 方法不再返回版本号，改为调用 `version` 方法显示版本，其余不变（页面在后面的卡重写）
- **测试**（`tests/rpcd/run.sh`：用 `tests/host/ucode` 加载插件文件取得方法表，直接调用 `methods.<名>.call({ args: {...} })`；
  命令行与 init 脚本用替身——记录收到的参数，输出、退出码、stderr、耗时可控）。场景至少包括：
  1. `version`、`status`：替身收到的参数恰好是 `version --json` / `status --json`；返回值与替身输出的对象完全相同（深比较）
  2. 退出码非 0 但 stdout 是 JSON 对象（`job start` 忙：退出码 3，`{"ok":false,"code":"BUSY","job":"j_1_2"}`）→ 原样返回
  3. stdout 不是 JSON（或是 JSON 数组）、退出码 1、stderr 2000 字节 → `CMD_FAILED`，`detail` 以 `exit 1: ` 开头，stderr 部分恰好 512 字节
  4. 替身睡眠超过 10 秒 → `CMD_FAILED`，`detail` 为 `timeout after 10s`；调用总耗时小于 15 秒
  5. `service` 的 `start`/`stop`/`restart`：init 替身睡眠 5 秒，调用在 1 秒内返回 `{"ok":true,"action":…}`，之后替身记录到对应动作；`action` 非法或缺省 → `USAGE`，替身没有被调用
  6. `job_start` 每个 `kind` 的正确参数 → 替身收到的参数逐项等于参数表中的命令（`probe_nodes` 带 0 个与 2 个节点、`sub_update` 带 0 个与 1 个、`update_package` 带与不带 `--previous`）
  7. `job_start` 的非法参数逐个 → `USAGE` 且替身没有被调用：未知 `kind`；`args` 不是数组；元素不是字符串；节点段名格式不对（含 `n_…;reboot` 这类注入尝试）；257 个节点；重复节点；`sub_update` 2 个参数；`update_check`/`update_data` 带参数；`update_package` 未知包名、缺包名、`--previous` 在包名前、多余参数
  8. `job_status`：合法 ID 转发为 `job status <id> --json`；`j_1`、`j_1_2;x`、缺省 → `USAGE`
  9. `events`：省略参数 → `events --json`；`since`、`level` 转为 `--since`、`--level`；`since` 为负数、小数、字符串，`level` 不在枚举中 → `USAGE`
  10. ACL 与插件一致：解析 ACL JSON，read 与 write 的方法集合恰好如「要求」所列；插件方法表中的每个方法在 ACL 中恰好出现一次，ACL 中的方法在插件中都存在
  11. `node --check` 通过 `overview.js`；`overview.js` 调用的是 `version` 方法（检查源码中的 rpc 声明）
- **验收**：`tests/review.sh` 的 FAIL 为 0；`tests/rpcd/run.sh`、`tests/cli/run.sh` 全过；报告含「场景对照」（[README](README.md)「报告」）。
