# M8 LuCI 与 rpcd

## 拆卡计划

依据：[10](../10-cli-luci.md)「分层」「rpcd 插件」「LuCI 页面」「作业机制」；Dashboard 的需求见 [backlog](../backlog.md) B2（未设计）。

原则：**业务逻辑全部在 `aether-proxy` 命令行**，rpcd 插件只做参数校验与转发，LuCI 只做展示与调用。
所以凡是页面需要、命令行还没有的功能，先补命令行（可以写宿主机测试），再加 rpcd 方法，最后写页面。

| 卡 | 内容 | 执行 | 依赖 |
|---|---|---|---|
| T8.1 | rpcd 插件：已有子命令的方法（`version`、`status`、`service`、`check`、`job_start`、`job_status`、`events`）、ACL、宿主机测试 | 实现 agent | — |
| T8.2 | 命令行补齐 `log`、`node import`、自定义列表读写，并加对应的 rpcd 方法（`log`、`node_import`、`list_file`、`save_file`）；先补设计细节 | 设计负责人写细节 → 实现 agent | T8.1 |
| T8.3 | LuCI 公共部分：rpc 声明、settle-once 轮询、作业轮询助手（同时在途请求 ≤ 2）、全部页面的菜单项与空页面 | 实现 agent | T8.1 |
| T8.4–T8.11 | 页面：概览、节点、订阅、访问控制、规则与 DNS、更新、日志、高级（各一张卡，可并行） | 实现 agent | T8.2、T8.3 |
| T8.12 | Dashboard（B2）：先设计（状态输出增加流量/连接数计数等），再拆卡；完成后取代概览作为首页 | 设计负责人 → 实现 agent | T8.4 |
| T8.14 | 旧模块只补注释（模块开头的职责与设计出处、不显然决定的理由），**一行代码都不改**；验收时自动检查 diff 只有注释行（「3a. 代码风格」，2026-10-16 定）。放在页面卡之后 | 实现 agent | T8.11 |

待办（T8.4 复审时发现）：`state.json` 的 `components` 只有 `path`、没有 04 说的 `version`（概览页对缺失做了容错，显示「–」）。
daemon 在启动时用 `xray version` / `chinadns-ng -V` 取版本写进去，放进 T8.9（更新页同样要显示组件版本）。

页面卡（JS）无法像命令行那样写宿主机测试：验收为 `node --check` 语法检查、[10](../10-cli-luci.md)「UI 规则」逐条自查，以及真机截图。

  命令行与 init 脚本用替身——记录收到的参数，输出、退出码、stderr、耗时可控）。场景至少包括：
  1. `version`、`status`：替身收到的参数恰好是 `version --json` / `status --json`；返回值与替身输出的对象完全相同（深比较）

  4. 替身睡眠超过 10 秒 → `CMD_FAILED`，`detail` 为 `timeout after 10s`；调用总耗时小于 15 秒
  5. `service` 的 `start`/`stop`/`restart`：init 替身睡眠 5 秒，调用在 1 秒内返回 `{"ok":true,"action":…}`，之后替身记录到对应动作；`action` 非法或缺省 → `USAGE`，替身没有被调用
  6. `job_start` 每个 `kind` 的正确参数 → 替身收到的参数逐项等于参数表中的命令（`probe_nodes` 带 0 个与 2 个节点、`sub_update` 带 0 个与 1 个、`update_package` 带与不带 `--previous`）
  7. `job_start` 的非法参数逐个 → `USAGE` 且替身没有被调用：未知 `kind`；`args` 不是数组；元素不是字符串；节点段名格式不对（含 `n_…;reboot` 这类注入尝试）；257 个节点；重复节点；`sub_update` 2 个参数；`update_check`/`update_data` 带参数；`update_package` 未知包名、缺包名、`--previous` 在包名前、多余参数
  8. `job_status`：合法 ID 转发为 `job status <id> --json`；`j_1`、`j_1_2;x`、缺省 → `USAGE`
  9. `events`：省略参数 → `events --json`；`since`、`level` 转为 `--since`、`--level`；`since` 为负数、小数、字符串，`level` 不在枚举中 → `USAGE`
  10. ACL 与插件一致：解析 ACL JSON，read 与 write 的方法集合恰好如「要求」所列；插件方法表中的每个方法在 ACL 中恰好出现一次，ACL 中的方法在插件中都存在
  11. `node --check` 通过 `overview.js`；`overview.js` 调用的是 `version` 方法（检查源码中的 rpc 声明）
