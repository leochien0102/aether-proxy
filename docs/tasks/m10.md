## T10.1 翻译带上下文 `aether-proxy`

- **分支**：`m10/i18n-context`
- **必读**：[10](../10-cli-luci.md)「UI 规则」中的「翻译一律带上下文」（2026-10-20，本卡的依据）、「公共模块与菜单」最后一条；
  [m9.md](m9.md) T9.1（翻译闸门的原始要求）；`tests/luci/i18n.test.js` 全文；[README](README.md)「3a. 代码风格」。其他页面的设计不需要读
- **允许改动**：
  - `luci-app-aether-proxy/htdocs/` 下全部 JS：**只**给每个 `_()` 调用加第二个参数 `'aether-proxy'`，别的一个字符都不改（包括文字本身、格式、注释）；
  - `po/zh_Hans/aether-proxy.po`：给菜单标题以外的条目加 `msgctxt "aether-proxy"`；菜单标题在页面里也用到时，两种条目都要有；
    删除没人用的「This page has not been implemented yet.」（T8.3 占位页遗留）；译文不改；
  - `tests/luci/i18n.test.js`；其他 `tests/luci/*.test.js` 中自己解析 po 的辅助函数与 `_` 替身，只在需要认识 `msgctxt`、接受第二个参数时改，断言不改。
  - **不改** `menu.d`、命令行、rpcd、ACL，不改任何页面行为
- **要求**：按 10「翻译一律带上下文」。闸门升级为：
  1. 每个 `_()` 调用必须正好两个参数：第一个是字面量（允许 `+` 拼接，同 T9.1），第二个是**单个**字符串字面量且等于 `'aether-proxy'`；
     缺上下文、上下文不对、上下文不是字面量 → 失败，报「文件:行」与原因；`NON_LITERAL_ALLOWLIST` 机制保留（目前仍为空）；
  2. po 解析认识 `msgctxt`，目录的键是「上下文 + 原文」：同一原文带与不带上下文是两条，不算重复；同一键出现两次算重复；
  3. JS 中的文字按上下文 `aether-proxy` 查找，菜单标题按无上下文查找；找不到或译文为空 → 失败（报告格式同 T9.1）；
  4. po 中 `msgctxt` 不是 `aether-proxy` 的条目 → 失败；不带上下文、又不是菜单标题的条目 → 失败；没有被引用的条目（PO 元数据除外）→ 失败（T9.1 时只报告，现在只剩 1 条且本卡删除）
- **测试**。场景至少包括：
  1. **真实代码**：全部 JS 与菜单标题都通过新闸门；未引用条目为 0；诊断信息照旧打印扫描到的文件数与引用数（引用数与改动前相同，改动前为 450）
  2. **缺上下文与错误上下文**：内存中的样例 `_('X')`、`_('X', 'other')`、`_('X', ctx)`（变量）、`_('X', 'aether' + '-proxy')` 各报一条错误，带正确的文件与行
  3. **键含上下文**：po 只有不带上下文的「X」时，JS 的 `_('X', 'aether-proxy')` 报缺译文；po 只有带上下文的菜单标题时，菜单报缺译文
  4. **po 规则**：其他上下文的条目、无上下文的非菜单条目、未引用条目各报一条错误；同一原文带与不带上下文并存不报重复，同一键两次报重复
  5. **T9.1 的既有场景**全部保留（按需改成带上下文的写法），断言的含义不变
  6. 其他页面测试全部照旧通过（它们的 `_` 替身接受并忽略第二个参数、po 解析跳过或认识 `msgctxt`）
- **验收**：
  1. `tests/review.sh` 的 FAIL 为 0；`tests/luci/run.sh` 全过；报告含「场景对照」。
  2. **JS 只加了上下文**：对 `luci-app-aether-proxy/htdocs` 下每个 JS 文件，把本卡版本中的 `, 'aether-proxy')` 去掉后与 `main` 上的版本逐字节相同。
     报告中给出所用的命令与输出（例如对每个文件 `diff <(git show main:<文件>) <(sed "s/, 'aether-proxy')/)/g" <文件>)`，输出为空）。
  3. **po 只加了上下文**：去掉 `msgctxt` 行、去掉菜单标题的重复条目后，与 `main` 上的 po 相比只少了被删除的那一条。报告中给出命令与输出。
  4. 页面上的实际效果（「切换」「刷新」「跟随」等不再显示成别的应用的译文）由设计负责人在复审后上真机看。

  3. 概览页既有测试中停止确认、dnsmasq 提示的断言改为新原文后照旧通过（只改原文，断言的含义不变）
