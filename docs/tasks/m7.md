## T7.1 `tools/channel/`：生成发布目录

- **分支**：`m7/channel-builder`
- **必读**：[08](../08-updates.md)「发布通道」「数据格式与来源」「`manifest.json`」「签名」「发布仓库」「S7 探针结论」；现有 `tools/data/build.py`（数据由它生成，本卡只调用）与 `tools/data/test_build.py`（测试写法参考）；`tests/ci/xray.sh`（下载 Xray 并按 `.dgst` 校验的现成做法）
- **允许改动**：新增 `tools/channel/`（Python 3，只用标准库）及其测试 `tools/channel/test_*.py` 与夹具 `tools/channel/fixtures/`；`.github/workflows/test.yml` 增加一步运行这些测试。不准改 `tools/data/` 的行为
- **要求**
  - `tools/channel/arch.json`：`{ "arch_map": { "<DISTRIB_ARCH>": "<资产键>" }, "upstream": { "xray": { "<资产键>": "<Xray 的 linux 键，如 arm64-v8a>" }, "chinadns-ng": { "<资产键>": "<三元组@cpu，如 aarch64-linux-musl@generic+v8a>" } } }`。
    首版至少覆盖 `aarch64_generic`、`aarch64_cortex-a53`、`x86_64`、`mipsel_24kc`、`arm_cortex-a7_neon-vfpv4`；资产键用中性名（`arm64`、`amd64`、`mipsle-softfloat`、`armv7`），`manifest.json` 的 `arch_map` 直接取自这里
  - `tools/channel/build.py --out <目录> [--previous <旧 manifest.json 路径或 URL>] [--sha-record <chinadns sha 记录 json>] [--offline <夹具目录>]`：
    1. 数据：调用 `tools/data/build.py` 生成五个文件，逐个 gzip 为 `<名称>-<内容 sha256 前 12 位>.txt.gz`，清单中记 `version`（同前缀）、`sha256`（解压后内容）、`size`（gz 大小）、`lines`
    2. 组件：取上游**最新版本（含 prerelease）**（GitHub API `releases?per_page=…` 取第一个非 draft）；Xray 下载 zip 与 `.dgst`，按 `SHA2-256=` 校验，解出 `xray` 后 gzip 为 `xray-<版本>-<资产键>.gz`；
       chinadns-ng 下载单个二进制，按 `--sha-record` 校验：该版本已有记录则必须一致（不一致 → 失败退出），没有记录则写入；gzip 为 `chinadns-ng-<版本>-<资产键>.gz`。清单中记 `version`、各资产的 `url`（相对路径）、`sha256`（gz 文件）、`size`、`unpacked_size`
    3. 收录前校验：用新 Xray 的 `amd64` 资产对本仓库 `tests/fixtures/*/expected/xray.json` 逐个执行 `run -test`，任一失败 → 退出码非 0、不生成清单
    4. 生成 `manifest.json`（`schema: 1`，键排序、两空格缩进，`generated` 用 UTC ISO 8601）；与 `--previous` 相比，除 `generated` 外内容全同 → 在输出目录写 `unchanged` 标记文件（发布 workflow 据此跳过发布）
  - `tools/channel/sign.sh <manifest.json> <私钥文件>`：调用 `usign -S`，生成 `manifest.json.sig`；随后用同目录的公钥（参数可选）`usign -V` 自检。**私钥只从文件读取，不打印、不写日志**
  - 访问网络的部分集中在一个模块，`--offline <夹具目录>` 时从夹具读取（伪造的 release 列表 JSON、伪造的 zip/dgst/二进制），测试全部离线
- **测试**（`python3 -m unittest discover tools/channel`，离线）：夹具生成完整发布目录且清单字段齐全；Xray `.dgst` 不匹配 → 失败；chinadns sha 记录不一致 → 失败、新版本 → 写入记录；与上一份清单相同 → 写出 `unchanged`；
  收录前校验失败（夹具里放一个对 `run -test` 返回 1 的假 xray）→ 不生成清单；签名往返：测试中用宿主机的 `tests/host/prefix/bin/usign -G` 临时生成密钥对，`sign.sh` 签名后验签通过、改一个字节后验签失败
- **验收**：`tests/review.sh` 的 FAIL 为 0；`python3 -m unittest discover tools/channel` 全过；`tools/data/test_build.py` 仍全过。

## T7.3 设备端下载、验签与 `update check`

- **分支**：`m7/update-check`
- **必读**：[08](../08-updates.md)「签名」「设备端流程 · 下载」「检查」「S7 探针结论」；[09](../09-logging.md) `UPDATE_AVAILABLE`、`MANIFEST_BAD_SIGNATURE`、`NO_SPACE`、`ARCH_UNSUPPORTED`；
  [10](../10-cli-luci.md)「`aether-proxy` 约定」「仅供测试的选项」「作业机制」；现有 `lib/sys.uc`、`lib/net.uc`（`tcp_listening`）、`lib/sub.uc` 中经代理/直连下载的写法、`lib/cmd/status.uc`、`lib/job.uc`
- **允许改动**：新增 `lib/update.uc`、`lib/cmd/update.uc`，在入口分发 `update`（本卡只实现 `update check`；`update component`/`upload`/`data` 返回 `USAGE`「尚未实现」）；`lib/cmd/status.uc` 让 `updates_available` 读 `updates.json`；
  `lib/job.uc` 增加作业种类 `update_check`（`update check`）；`lib/const.uc` 末尾追加 T7.3 区块；新增 `tests/update/run.sh` 与夹具；`aether-proxy/Makefile` 安装 `files/keys/`（目录可以为空，公钥由 T7.2 加入）
- **要求**
  - 下载：按 `channel_urls` 顺序；Xray 在运行（`state.json` 为 running/degraded 且 HTTP 端口监听）时先经 `-x http://127.0.0.1:31081` 再直连；`curl --fail --silent --show-error --max-time 30 --max-filesize <清单 1MB / 资产按清单 size>`，经 `sys.run`（超时 35 秒）；
    下载目录 `/tmp/aether-proxy-dl/`（受 `--sys-root` 前缀影响），用完删除
  - 验签：`usign -V -q -m manifest.json -P <keys 目录>`（`/etc/aether-proxy/keys/`，受 `--sys-root` 影响；`usign` 经 `--bin-dir` 可替换）；失败 → 记 `MANIFEST_BAD_SIGNATURE` 并换下一个地址；全部失败 → 退出码 4（10：校验或验签失败）
  - 清单 JSON 解析失败或 `schema != 1` → 视同验签失败，换下一个地址
  - 资产下载函数（本卡只实现与测试，T7.4/T7.5 使用）：空间预检（`/tmp` 与目标目录，按 08 的公式；不足 → `NO_SPACE` 不下载）、下载后校验 `size` 与 `sha256`，不符 → 删除并换下一个地址
  - 架构：读 `/etc/openwrt_release` 的 `DISTRIB_ARCH`（受 `--sys-root` 影响），查清单 `arch_map`
  - 已安装版本：按 01 的组件查找顺序找到二进制并试运行，取输出第二个字段；找不到为 `null`
  - 写 `updates.json`（08「检查」的格式，`sys.write_atomic`），`--json` 时输出同样内容
- **测试**（`tests/update/run.sh`，不访问外网）：测试中用 `python3 -m http.server` 在随机端口起两个本地「通道」目录；用宿主机 usign 临时生成密钥对签名；`curl`、`xray`、`chinadns-ng` 用真实 curl 与替身二进制。场景至少包括：
  1. 正常：验签通过，`updates.json` 中版本、`newer`、`arch`、`asset_key` 正确；`status --json` 的 `updates_available` 等于它
  2. 第一个地址的清单被篡改（签名不符）→ 记 `MANIFEST_BAD_SIGNATURE`，从第二个地址取到
  3. 所有地址都篡改 → 退出码 4，不写 `updates.json`
  4. 签名密钥不在 keys 目录（换了一把私钥签名）→ 视同验签失败
  5. 清单不是 JSON / `schema` 为 2 → 换下一个地址
  6. `DISTRIB_ARCH` 不在 `arch_map` → `asset_key: null`、`ARCH_UNSUPPORTED`
  7. 组件不存在 → `installed: null`；版本比较 `26.10.10 > 26.9.30`
  8. 资产下载函数：sha256 不符 → 删除并失败；空间不足（用测试钩子让可用空间读数变小，做法自选，不准新增命令行选项）→ `NO_SPACE`
  9. `job start update check` 能跑完并得到同样的结果
- **验收**：`tests/review.sh` 的 FAIL 为 0；`tests/update/run.sh` 全过；`tests/job/run.sh`、`tests/cli/run.sh` 仍全过。
