## T11.3 WireGuard 出站（0.6.1 版本）

- **目标**：新增 `protocol=wireguard` 的手工节点；端点复用现有 `address`/`port`，支持本机隧道地址、Peer 公钥、私钥、可选预共享密钥和 keepalive；不做 URI/订阅导入。
- **分支**：`m11/t11.3-wireguard`；从 **`main`**（含 T11.2，`2944b51` 之后）建 worktree。
- **必读**：T11.1/T11.2 的实现与测试、[05](../05-config.md)、[06](../06-nodes-subscription.md) 出站映射、[10](../10-cli-luci.md)、[12](../12-ucode.md)；Xray `infra/conf/wireguard.go` 或同版本的官方配置说明（只读）。
- **允许改动**：`docs/05-config.md`；`lib/schema.uc`、`lib/config.uc`、`lib/render/outbound.uc`；`model/nodes.js`、`view/aether-proxy/nodes.js`、`po/zh_Hans/aether-proxy.po`；`tests/unit`、`tests/luci`、`tests/ci`、fixtures。**不改** `lib/uri.uc`、订阅、后端更新/通道、其他页面。
- **实现要求**：
  1. 协议枚举加 `wireguard`；新增字段：
     - `secret_key`（私钥，必填，Base64 32 字节）；
     - `peer_public_key`（必填，Base64 32 字节）；
     - `local_address`（本机隧道地址列表，IPv4/CIDR，必填至少 1 项）；
     - `preshared_key`（可选，Base64 32 字节）；
     - `keepalive`（可选，整数秒，0–65535，不设则不渲染）。
     `address`/`port` 继续表示 Peer endpoint；不新增 `node_order` 等配置。
  2. 私钥/PSK/任何凭据不得进入日志、事件或错误 detail。
  3. 出站：
     ```
     settings.secretKey = secret_key
     settings.address = local_address
     settings.peers = [{
       publicKey: peer_public_key,
       endpoint: <resolved node address>:port,
       allowedIPs: ['0.0.0.0/0'],
       ...(presharedKey/keepAlive when set)
     }]
     ```
     允许 `allowedIPs` 先固定 `0.0.0.0/0`（不做分流）。
  4. 若 Xray 对 WireGuard 的通用 `streamSettings` 有约束，按真实 `xray run -test` 结果处理；不得凭猜测加字段。
  5. LuCI 协议列显示 `WireGuard`；添加/编辑节点按协议显示 endpoint、secret key、peer public key、local address、PSK、keepalive；旧值保留策略不变。
- **先复现**：先加协议/字段/出站/UI/密钥格式测试，在 T11.2 基线上应失败；再实现。
- **测试**：`bash tests/host/bootstrap.sh`；`tests/host/ucode tests/run.uc`；`tests/cli/run.sh`；`tests/luci/run.sh`；真实 Xray `26.3.27` 与 `26.10.21` 的 WireGuard golden/`run -test`；`git diff --check`。报告 `reports/T11.3.md`。
- **验收**：SOCKS/HTTP/旧协议全回归；手工 WireGuard 节点形成有效配置并通过真实预检；缺字段/密钥格式错误被拒且不泄露密钥；不扩展 URI/订阅。不要 push、不改 release/tag。

**复核结论（2026-10-31，已合并 main）**：unit **1135/0**、CLI **215/0**、LuCI **1003/0**；Xray 26.3.27/26.10.21 各 **24/0**；WireGuard basic/PSK/PSK-zero 三条 golden 均 `Configuration OK`，7 条错误夹具 CONFIG_INVALID 且无凭据。实现按上游真实字段 **`preSharedKey`**（非卡内示例的 `presharedKey`）；`/24` 在 26.3.27 被拒、golden 使用 `/32`。`tests/review.sh` **0 FAIL**（仅授权 docs WARN）。0.6.1 小版本，不升 0.7.0。

  1. workflow 触发：`push` tag `v*`；手动重跑用 `workflow_dispatch` 选择已有 tag/ref，不再输入 version。tag 是唯一版本源。
  2. 解析版本：`github.ref_name` 如 `v0.6.2-r1` → `0.6.2-r1`；轮询 `channel-stable/manifest.json`，直到 `packages['aether-proxy'].current.version == 版本`（60 秒间隔，最长 90 分钟）。
  3. 从 manifest 选择资产：aether-proxy/LuCI/i18n 的 ipk+apk，aether-xray 的 aarch64_generic/x86_64 ipk+apk；下载后按 manifest `sha256` 校验。
  4. `permissions: contents: write`；如果 Release 不存在则创建，存在则复用；上传用 `--clobber` 幂等。Release notes 优先用 `docs/releases/<version>.md`，否则用通用安装说明（先装 aether-xray，再装应用/LuCI/i18n）；包含架构对应关系。
  5. 只使用仓库自带 `GITHUB_TOKEN`，不引入 PAT/跨仓库 secret；下载 channel 公开资产。
  6. tag 早于 channel 完成时等待；超时失败并保留日志。PR/普通 push 不触发发布。
- **要求**：
  - 不重复编译，不把 channel 的 manifest/signature 当资产上传（只上传包）。
  - 不发布 patched `xray-core`；只发布 aether-xray 核心。

- **测试**：YAML 解析、`bash -n` 所有 run 块、本地 fake `gh`/manifest 的脚本测试（版本等待、资产选择、hash 校验、幂等）；`git diff --check`。报告 `reports/T11.7.md`。
