# T16.93 M16：按本次客户端查询的 UDP 上限返回 DNS 应答

实现仓 aether-dns，基线 565855eb15b1821c654ec1d28814e3ae0022a035，分支 fix/t16.93-udp-response-limit，工作树 /workspace/openwrt/aether-dns-wt/T16.93。与 proxy 的 T16.92 无代码依赖，不等其合入。

## 范围与契约

src/server.rs 的 UDP 入口在 handle_query 返回后直接 send；src/dns/mod.rs 已解析 EDNS。先追踪实时/缓存/本地回答与 TCP 写回，尽量复用现有 DNS 库与统一 UDP 出口。上限由本次客户端请求决定，不取上游响应或首个填充缓存的客户端：无 OPT 为 512 字节，有合法 OPT 按通告值（小于 512 按 512；若有本端既定上限再取小）。以最终 DNS wire 字节数判断，不含 IP/UDP 头。不要另设 512 为所有客户端上限。

能容纳的响应不人为置 TC、不清掉已有 TC；仅省略可选附加信息（如可省略的 OPT 内容）不等于必设 TC。无法容纳必需数据时给出长度合规、可正常解析且 TC=1 的回复，不直接切割字节串或生成残缺 RR；保留本次客户端 ID、Question 与响应语义，不因删 OPT 把扩展错误码误报成成功。只在交付本次 UDP 响应时限长，不能以截断副本污染缓存；TCP 不套 UDP 上限。无需追求塞满每个剩余字节。不改路由、缓存键、上游竞速、并发或 Netlink 策略；不改 proxy、版本、工作流、依赖或设备。

## 验收

- 隔离本机 UDP/TCP 与固定回答，无外网、无设备。基线与修后使用同一超长应答，记录实收字节、可解析性、ID、Question、TC、RR 计数；基线先证实实际越限。
- 覆盖无 EDNS 的恰好 512 与 513、EDNS 小于 512、较大 EDNS 可完整返回、已有 TC；仅可选附加信息导致越限与必需答案越限分别断言。边界构造可用纯函数，至少一次真实 UDP 超限→同题 TCP 重查拿到完整答案。
- 证明实时与真实缓存命中均受本次请求限制（记录上游调用次数）；小预算查询之后，允许更大预算的查询或 TCP 仍能取得完整答案。若代码原本隔离了缓存键，不为构造测试改变其策略。
