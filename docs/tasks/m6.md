## T6.1 节点 TCP 可达性检测（同步版）

- **分支**：`m6/node-probe`
- **必读**：[07](../07-probe.md)「节点可达性检测」（`probe.json` 格式、`error` 枚举、实现要求：ucode `socket` 模块非阻塞 connect + poll、单调时钟计时）；
  [10](../10-cli-luci.md)「`aether-proxy` 约定」、子命令表中的 `probe nodes`、「仅供测试的选项」；现有 `lib/pipeline.uc`（读配置的方式）
- **允许改动**：新增 `lib/probe.uc`、`lib/cmd/probe.uc`，在入口中分发 `probe`；扩展 `tests/cli/run.sh`
- **要求**
  - `aether-proxy probe nodes [<节点ID>...] [--json] [--confdir …] [--run-dir …]`：同步执行（作业机制以后由 T6.2 包装，本卡不做），结果写入 `<run-dir>/probe.json`（经 `sys.write_atomic`）并输出
  - 地址解析：IPv4 字面量直接用；域名用 `resolveip -4 -t <超时>`（经 `sys.run`），失败记 `resolve_failed`
  - 每个节点 3 次 TCP connect，超时 `probe.node_timeout`，记录每次耗时；连接建立后立即关闭、不发数据；并发上限 `probe.node_concurrency`
    （ucode 单线程：用多个非阻塞 socket 加 poll 实现并发，不准 fork 子进程）
  - 结果字段与 07 一致：`ok`、`fail`、`min_ms`、`median_ms`、`error`（取最后一次失败的类别）
  - 拿不准 ucode `socket` 模块用法时，查 24.10 版本源码 `lib/socket.c`（提交 `3f64c808`）中的函数表与文档注释，不准使用该版本之后才有的函数
- **测试**（宿主机，`tests/cli/run.sh` 或独立脚本，不访问外网）：
  - 在测试中用 ucode 起一个监听 `127.0.0.1:<随机端口>` 的服务端，节点指向它 → `ok=3`
  - 节点指向 `127.0.0.1` 上一个未监听的端口 → `refused`
  - 节点指向 `192.0.2.1`（TEST-NET，不可达） → `timeout` 或 `unreachable`（两者都接受），且整个命令在 `3 × 超时 + 2 秒` 内结束
  - 节点地址是无法解析的域名（如 `nonexistent.invalid`） → `resolve_failed`
  - 并发：10 个指向不可达地址的节点、并发 8、超时 1 秒时，总耗时明显小于串行（小于 6 秒）
- **验收**：`tests/review.sh` 的 FAIL 为 0；上述场景全部通过。
