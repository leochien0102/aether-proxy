## T6.1 节点 TCP 可达性检测（同步版）

- **分支**：`m6/node-probe`
- **必读**：[07](../07-probe.md)「节点可达性检测」（`probe.json` 格式、`error` 枚举、实现要求：ucode `socket` 模块非阻塞 connect + poll、单调时钟计时）；
  [10](../10-cli-luci.md)「`aether-proxy` 约定」、子命令表中的 `probe nodes`、「仅供测试的选项」；现有 `lib/pipeline.uc`（读配置的方式）
- **允许改动**：新增 `lib/probe.uc`、`lib/cmd/probe.uc`，在入口中分发 `probe`；扩展 `tests/cli/run.sh`
- **要求**
  - `aether-proxy probe nodes [<节点ID>...] [--json] [--confdir …] [--run-dir …]`：同步执行（作业机制以后由 T6.2 包装，本卡不做），结果写入 `<run-dir>/probe.json`（经 `sys.write_atomic`）并输出
  - 地址解析：IPv4 字面量直接用；域名用 `resolveip -4 -t <超时>`（经 `sys.run`），失败记 `resolve_failed`
  - 每个节点 3 次 TCP connect，超时 `probe.node_timeout`，记录每次耗时；连接建立后立即关闭、不发数据；并发上限 `probe.node_concurrency`
    （ucode 单线程：用多个非阻塞 socket 加 poll 实现并发，不准 fork 子进程）
  - 结果字段与 07 一致：`ok`、`fail`、`min_ms`、`median_ms`、`error`（取最后一次失败的类别）
  - 拿不准 ucode `socket` 模块用法时，查 24.10 版本源码 `lib/socket.c`（提交 `3f64c808`）中的函数表与文档注释，不准使用该版本之后才有的函数
- **测试**（宿主机，`tests/cli/run.sh` 或独立脚本，不访问外网）：
  - 在测试中用 ucode 起一个监听 `127.0.0.1:<随机端口>` 的服务端，节点指向它 → `ok=3`
  - 节点指向 `127.0.0.1` 上一个未监听的端口 → `refused`
  - 节点指向 `192.0.2.1`（TEST-NET，不可达） → `timeout` 或 `unreachable`（两者都接受），且整个命令在 `3 × 超时 + 2 秒` 内结束
  - 节点地址是无法解析的域名（如 `nonexistent.invalid`） → `resolve_failed`
  - 并发：10 个指向不可达地址的节点、并发 8、超时 1 秒时，总耗时明显小于串行（小于 6 秒）
- **验收**：`tests/review.sh` 的 FAIL 为 0；上述场景全部通过。

## T6.2 作业机制：`job start` / `job status`

- **分支**：`m6/jobs`
- **必读**：[10](../10-cli-luci.md)「作业机制」（含 2026-10-15 补充的「实现约定」，按它实现）、「`aether-proxy` 约定」与「仅供测试的选项」；[09](../09-logging.md) `JOB_LOST`；
  现有 `lib/sys.uc`（`run`、`lock`、`write_atomic`）、`lib/cmd/probe.uc`、`lib/cmd/sub.uc`（两个可作业化的子命令，它们的 `--json` 输出就是作业的 `result`）
- **允许改动**：新增 `lib/job.uc`、`lib/cmd/job.uc`，在入口 `aether-proxy` 中分发 `job`（用法说明只列 `job start`、`job status`，不列内部的 `job run`）；
  `lib/const.uc` 末尾追加 T6.2 区块；`lib/log.uc` 只增加 `JOB_LOST`；新增 `tests/job/run.sh` 与 `tests/stubs/job-bin/`。不准改 `probe`、`sub` 子命令的行为
- **要求**
  - 严格按 10「实现约定」：种类识别、ID 格式、作业文件字段、BUSY 判定（同种类 running 且 pid 存活、命令行含 `job run`）、后台启动方式（`sh -c '"$@" … &'`，不准用 `nohup`/`start-stop-daemon`/`setsid` 等不一定存在的命令）、
    工作进程取种类锁、600 秒超时、`JOB_LOST` 判定、1 小时清理、退出码与 JSON 形状
  - 作业文件的读写集中在 `lib/job.uc`；`cmd/job.uc` 只做参数解析与输出
  - 子命令的 stdout 不是合法 JSON 时：`state: failed`、`error: CMD_FAILED`，`result` 为 `null`，原始输出的前 200 字节放进 `detail` 字段
- **测试**（`tests/job/run.sh`，临时 run-dir，不访问外网）：`tests/stubs/job-bin/aether-proxy` 是一个替身，按环境变量决定：输出给定 JSON 并以给定退出码结束、睡眠若干秒、输出非 JSON。场景至少包括：
  1. `job start probe nodes` 立即返回（< 1 秒）且输出 `{"job": "j_…"}`；轮询 `job status` 直到 `ok`，`result` 等于替身输出的对象，`exit` 为 0
  2. 子命令以退出码 1 输出 `{"ok": false, "code": "SUB_FETCH_FAILED"}` → `failed`、`error: SUB_FETCH_FAILED`
  3. 子命令输出非 JSON → `failed`、`error: CMD_FAILED`、`detail` 有内容
  4. 同种类作业运行中再次 `job start` → 退出码 3，JSON 中 `job` 为正在运行的 ID；不同种类可以同时运行
  5. 工作进程被 `kill -9` → 下一次 `job status` 返回 `failed`、`error: JOB_LOST`，并记了 `JOB_LOST` 事件
  6. `job start daemon`、`job start check` → 退出码 2；`job status abc` → 退出码 2（`USAGE`）；`job status j_1_1` 不存在 → 退出码 2（`JOB_NOT_FOUND`）
  7. 发起者退出后作业仍完成：`job start` 返回后立即结束发起它的 shell，作业照样变成 `ok`
  8. 清理：手工放一个 `finished` 为两小时前的作业文件，`job start` 后它被删除；`finished` 为 10 分钟前的保留
  9. 测试选项透传：`job start sub update --confdir X --run-dir Y` 时替身记录到的参数包含这些选项和 `--json`
- **验收**：`tests/review.sh` 的 FAIL 为 0；`tests/job/run.sh` 全过；`tests/sub/run.sh`、`tests/cli/run.sh` 仍全过。

## T6.3 daemon 内的订阅定时更新（依赖 T6.2）

- **分支**：`m6/sub-schedule`
- **必读**：[06](../06-nodes-subscription.md)「调度」（含 2026-10-15 补充的细节）；[10](../10-cli-luci.md)「作业机制」；`lib/daemon.uc`（`run_monitor` 与信号处理）、`lib/job.uc`
- **允许改动**：新增 `lib/schedule.uc`（纯函数部分）与测试；`lib/daemon.uc` 只增加定时器的创建、取消与调用；`lib/const.uc` 末尾追加 T6.3 区块；扩展 `tests/daemon/run.sh` 或新增 `tests/schedule/run.sh`
- **要求**
  - **纯函数** `due(subs, status, jitter, now, started_at) → <段名>|null`：`subs` 为配置中的订阅，`status` 为 `sub.json` 内容，`jitter` 为 `{ <段名>: 0–0.1 }`；
    按 06 的规则（启用、`interval_hours > 0`、以 `last_attempt` 计、没有则以 daemon 启动时刻计、按段名排序取第一个到期的）返回要更新的订阅
  - daemon 进入 monitor 阶段后创建 60 秒定时器，离开时（停止、重载为停止、启动失败）取消；每次触发：状态不是 `running`/`degraded` 就跳过；
    否则读配置快照与 `sub.json`，调用 `due`，有结果就执行 `job start sub update <段名>`（经 `sys.run`，超时 10 秒），退出码 3 跳过；
    reload 后订阅配置变化（新增、删除、改 `interval_hours`）以新快照为准，新增订阅的抖动在第一次见到时生成
- **测试**：`due` 的表驱动测试（未到期、恰好到期、`interval_hours=0`、禁用、从未更新过、多个同时到期取段名最小者、抖动影响到期时间）；
  daemon 集成测试用替身 `aether-proxy`（记录被调用的参数）验证：到期时发起 `job start sub update <段名>`；状态为 `failsafe` 时不发起；停止后定时器不再触发
  （测试中 60 秒的间隔与小时级的周期需要缩短，做法自选，不准为此新增命令行选项，在报告里说明）
- **验收**：`tests/review.sh` 的 FAIL 为 0；新增测试全过；`tests/daemon/run.sh`、`tests/reload/run.sh` 仍全过。
