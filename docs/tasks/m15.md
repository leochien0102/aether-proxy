## T15.1 restart 期间保留 DNS handoff

状态（2026-11-07）：复审和真机验收通过，已合并 `0e0aac4`。记录见 [真机验收](../validation/t15.1-h28k-20261107.md)。

- **单一目标**：`/etc/init.d/aether-proxy restart` 全程保留 dnsmasq 到本地 DNS 引擎的 handoff，杜绝 restart 窗口回落到直连解析器。
- **分支**：`fix/t15.1-restart-dns-handoff`
- **必读**：[04-lifecycle.md](../04-lifecycle.md)「启动」「停止」「进程模型」、[03-dns.md](../03-dns.md)「dnsmasq 对接」、
  `aether-proxy/files/aether-proxy.init`、`aether-proxy/src/lib/daemon.uc` 的 `apply_cleanup()` / `shutdown()` / 启动流程、
  `aether-proxy/src/lib/apply.uc` 的 `dnsmasq_install()` / `dnsmasq_remove()`、`tests/stubs/procd/run.sh`。
- **现场证据（2026-11-06 H28K，授权受控 restart）**：
  1. 21:12:00 `SERVICE_STOPPED`，21:12:07 新 DNS child 才监听，21:12:14 `SERVICE_STARTED`。
  2. 客户端持续查询随机 `x*.google.com`：21:12:01.5–21:12:07.7 返回 NXDOMAIN、约 300 ms；此时 31053 与 Xray 均未监听，结果只能来自 dnsmasq 的直连 resolver。
  3. `/tmp/dnsmasq.d/aether-proxy.conf` 正常内容为 `no-resolv` + `server=127.0.0.1#31053`；停止流程删除它并重启 dnsmasq 后，dnsmasq 回落到 `resolv-file` 中的 223.5.5.5。
  4. 根因链已由源码确认：OpenWrt `rc.common` 的 `restart()` 是 `stop` 后 `start`；daemon `shutdown()`、兜底 `cleanup --wait`、新 daemon 的启动残留清理都会调用 `dnsmasq_remove()`。

### 允许改动

- `aether-proxy/files/aether-proxy.init`；
- `aether-proxy/src/lib/const.uc`、`daemon.uc`、`apply.uc`（仅实现 restart handoff 所需部分）；
- `tests/stubs/procd/run.sh`、daemon/apply/生命周期相关测试与测试 stub；
- [04-lifecycle.md](../04-lifecycle.md)、[03-dns.md](../03-dns.md) 与 `reports/T15.1.md`。

不改 LuCI、RPC/状态 JSON、日志文案、组件命名/版本判断、DNS 级别与渲染内容。

### 要求

1. **restart 与 stop 明确区分**：restart 在旧 daemon 收到停止信号之前持久化一个仅位于 `/var/run/aether-proxy/` 的 restart intent；手动 `stop`、`enabled=0` 和普通 `cleanup` 不得继承该意图。
2. **restart 全程保留 handoff**：restart intent 存在时，旧 daemon 的有序 shutdown、`service_stopped` 的 `cleanup --wait`、新 daemon 的启动残留清理都不得删除 `aether-proxy.conf`，也不得执行“删除片段所需的 dnsmasq restart”。片段内容在 stop/start 交接期间保持原样。
3. **成功后才清 intent**：新 daemon 成功执行 `dnsmasq_install()`、确认 handoff 已安装后再清 restart intent；不能由异步的 `start_service()` 提前清除。正常启动/开机没有 intent 时保持现有清理语义。
4. **失败时 fail closed**：restart 在新 handoff 安装前失败或进入退避时，保留 intent 和旧片段，使查询失败/超时而不是回落直连；后续启动重试仍可完成安装并清 intent。
5. **显式 stop 可收口失败 restart**：restart 失败后，用户执行手动 `stop` 或关闭 `enabled` 必须清 restart intent，删除 handoff、重启 dnsmasq，并保留既有 `stopped-by-user` / reload-trigger 语义。
6. **兜底路径一致**：daemon 正常处理 SIGTERM与被 SIGKILL 后由 `cleanup --wait` 兜底，两条路径的 handoff 决策一致；重复执行仍幂等。restart intent 文件写入/删除失败必须明确失败或记录现有 `FS_FAILED` 类错误，不能悄悄切成直连。
7. **不扩大成无中断 restart**：允许本地 31053 尚未监听时出现 timeout/SERVFAIL；本卡只保证“不直连泄漏”。不调整 Xray/DNS child 启动顺序，不等待 31082/31083，不改 dnsmasq 安装阶段剩余的一次 restart，不宣称完成后续启动窗口或重启次数优化。
8. **兼容包升级**：opkg/服务管理触发的标准 `restart` 使用同一保护；单独 `stop` 后安装/卸载仍按 stop 语义恢复系统 DNS。

### 测试场景

| ID | 场景 | 必须证明 |
|---|---|---|
| R1 | running → init `restart` | restart intent 在 stop 前存在；整个 stop / cleanup / start-cleanup 期间 fragment 不被删除；新 handoff 安装成功后 intent 消失 |
| R2 | restart 中旧 daemon 正常退出 | shutdown 不调用 handoff remove；子进程、nft、route 等其他清理仍执行 |
| R3 | restart 中旧 daemon 被强制结束 | `cleanup --wait` 兜底也保留 fragment；重复 cleanup 不删除、不重复重启 dnsmasq |
| R4 | 普通手动 `stop` | fragment 被删除、dnsmasq 恢复系统 resolver；`stopped-by-user` 与 reload trigger 行为不回归 |
| R5 | `enabled=1 → 0` | fragment 被删除且 manual-stop marker 按既有规则清掉；再次启用仍能启动 |
| R6 | restart 后新 daemon 在 handoff 前失败/退避 | fragment 与 intent 保留，不出现直连回落；随后重试成功会清 intent |
| R7 | 失败 restart 后手动 `stop` | intent 被清除、fragment 被删除、状态最终 stopped |
| R8 | 无 intent 的普通 start / crash residue cleanup | 保持原有清理行为，不把陈旧 handoff 永久保留 |
| R9 | dnsmasq 安装失败并回滚 | intent 不提前删除；旧 fragment 保留；错误仍按原路径返回 |
| R10 | init 脚本完整流程 | restart、stop、reload(enabled=0)、start 的标记与 procd 注册顺序均有可判定断言 |

测试必须核对 fragment 文件内容/存在性及 dnsmasq restart 调用次数，而不只核对返回码或 marker。

| E7 | 私有端口冲突及重试 | 占用首选端点，真实引擎明确启动失败，不误判占位者为己方；下一候选端点成功，失败child被wait回收，最多10次，不无限循环；明确端口选择建议及对并行实例的约束 |

| E9 | child被SIGKILL后的残留 | 只杀本卡启动的私有child，真实wait回收；候选清理根据PID/命令行/所属目录核对身份；不能误杀同名其他实例；明确交给生产supervise的责任 |
| E10 | 不接管正式DNS | 全程只操作本卡临时目录与分配的端点；模拟handoff/intent字节不变，未改真实dnsmasq、nft、路由或系统resolver；普通gfw请求不由探针调用方送入bootstrap |

端口隔离不等于引擎提供域名访问控制。只证明调用方仅发送节点域名、私有端点不发布到handoff，不得宣称“其他本机进程无法查询此端口”。

### 冻结接口和选择语义

1. `render.chinadns.boot_upstreams(snapshot, ctx)`：纯函数，direct_dns_enabled=0返回原有展开后的china_dns，1返回原有direct_dns；保持顺序、语法和默认回退，不新增DNS地址。正式renderer的boot组改调用它，输出与所有现有fixture逐字节一致，不修改golden来迁就实现。
2. `bootstrap_dns.lookup(domain, endpoint, on_signal, timeout_ms)`：一次有界A/IN解析；返回`{ok:true, ip}`或`{ok:false, detail, cancelled?:true}`。默认3000ms，显式测试参数只允许1–3000ms；deadline包含UDP、TCP回退、CNAME追问与报文解析，不随活动续期。
3. 域名输入须经过现有域名语法校验（空标签、超长label/全名等明确拒绝，不调用系统resolver）；endpoint仅接受`{address:'127.0.0.1', port:<整数1..65535>}`，拒绝53、正式DNS端口及Xray DNS tunnel端口；不接受域名、通配地址、远程IP、协议URL，不调用getaddrinfo/resolveip。端点真实child归属检查由后续B3负责，本接口校验不冒称证明归属。域名/端点等参数错误直接失败，不进入三轮重试或LKG回退；字面量节点按第4项允许不提供端点。
4. `apply.resolve_node_explicit(ctx, address, endpoint, on_signal)`：IPv4字面量直接返回`source:'literal'`，不发DNS、不要求endpoint；域名最多三次lookup（每次默认3秒），DNS成功取首个合法关联IPv4、调用现有update_lkg，返回`source:'dns'`；保存失败仍算失败，不能谎报成功。三次均失败后才查现有按域名LKG，保留已有fallback/failed事件及source语义。
5. 取消返回`cancelled:true`，立即结束，不做下一轮、LKG回退或LKG写入，不记NODE_RESOLVE_FAILED来冒充普通DNS失败。普通传输/解析失败与取消区分；预置成功LKG不能抢在DNS前使用。

### 冻结协议语义

- 私有端点先UDP；**合法匹配事务的TC=1应答改用同端点TCP查询**，共享本轮剩余deadline；TCP仍TC则失败，不截取其中的A，不降级或改问其他resolver。无TLS实现，上游协议由私有真实引擎负责。
- 每个查询事务使用随机16位ID；UDP采用已连接的socket约束来源，并核对ID、QR、opcode、单一question的大小写不敏感qname、A/IN。错误ID可在原deadline内忽略；匹配ID但坏包、负RCODE/NODATA等返回明确失败，不能误用尾部四字节。
- TC回退前仍核对可用的header/question，不把无法匹配问题的坏包当TC。TCP长度前缀、分段读写、EOF、长度不一致和最大65535字节均须处理。
- 校验全部section边界，RR长度与压缩名字不得越界/循环；压缩指针跳数最多128，展开名长度按DNS界限。只采用ANSWER中与原qname或其CNAME链关联的A/IN，不从无关ANSWER/authority/additional捡A。
- 支持同包CNAME链及仅CNAME应答的同端点追问：一个lookup累计最多16个CNAME跳转、最多16次question（含首次，不含同question的TCP TC重试）；循环或超限失败。追问不经系统DNS、不刷新deadline；多个关联A按wire顺序取首个。无关联A且无可继续CNAME则NODATA失败。
- 只做IPv4节点A/IN，不做通用递归resolver、缓存、AAAA或DNSSEC；不复制S15.3的简化解码器。可以参考现有dns_test的边界策略，但不改其boolean诊断接口、不顺手重构它。

### 超时、信号和资源

- 所有socket使用有界非阻塞等待；一次poll最长100ms，并在循环/报文处理处检查deadline与取消。允许通过uloop派发既有信号回调，使on_signal真的能观察到SIGTERM；不能只用一个测试callback证明真实信号可中断。
- TCP/UDP、成功/超时/坏包/取消各路径都关闭本轮socket；不创建child、handoff、intent或新的持久文件。LKG只由现有helper写入，不建立第二套缓存。
- `resolve_node_explicit`总网络等待最多约9秒（三轮），取消不等待剩余轮次；文件I/O失败明确返回。禁止改ctx的已应用状态、初始tier或fail_open。

### 所有权与等待契约

- `xray_ready.wait(ctx, child, required, on_signal)`返回`{ok:true}`或`{ok:false,detail,cancelled?:true}`；child为本次supervise句柄，依据其`pid()`定位。进入时固定本次PID及进程启动标识，退出/换PID/重用或不可验证时不能报ready，不能把自动respawn的新PID冒当原计划启动成功。
- 读取对应网络命名空间的tcp/tcp6/udp/udp6 socket表，匹配地址、端口、协议及`/proc/<pid>/fd` socket inode。TCP只认LISTEN；UDP只认绑定socket而非TCP LISTEN。不能用同号端口、SYN_SENT/ESTABLISHED、其他进程占位或只看PID文件冒充就绪。
- 生产读真实/proc；现有ctx.root测试约定必须一致地作用于socket表与进程归属fixture，禁止一半读宿主、一半读fixture后凑出PASS。不可读/坏行/进程退出属于not-ready或明确失败，不能降级为全局端口扫描。
- 地址比较必须处理IPv4、IPv6和实际Xray的dual-stack TPROXY，不把`::1`当作127.0.0.1。对IPv4要求，不能只因tcp6存在同号端口就声称可达；如需判定通配IPv6是否真能服务IPv4，可采用预算内的本地无payload TCP连通校验并结合inode归属。UDP不得因有同号TCP或未证实的IPv6-only绑定而通过。
- 一次wait共享现有5秒总deadline（所有端口共用，不是每端口5秒），每轮/成功返回前/超时尾部均检查停止意图，派发真实信号；取消不在尾部补一次无条件成功检查。不要新增外网健康/DNS答复要求，健康检测仍由monitor负责。
- socket表轮询使用有界等待、避免busy loop；如做本地TCP连通校验，socket必须非阻塞、包含于同一deadline并关闭。不得运行ss/netstat/lsof或引入新二进制依赖。

### 冻结资源接口

1. 在bootstrap模块提供内部`start(ctx, snapshot, engine, on_signal)`、`stop(handle)`和负责节点解析/收口的薄封装（沿用begin/end命名亦可，报告须说明对应关系，不新增init服务）。handle保存本次受监督child句柄、端点、独占目录/文件清单、生命周期标识；在任何可能派发信号或失败返回前登记到启动清理上下文，不靠局部变量存活掩盖遗漏回滚。停止流程明确为：请求stop→在限定预算内等本次直属child真实退出回调→确认后才删本代运行文件。
2. 只使用前置检查已选定的DNS引擎，不擅自换引擎。最小私有配置沿S15.3真实契约：仅loopback动态端口，china/trust显式为共享boot_upstreams的完整列表，default-tag gfw、ipset-name4/6 null、cache 0；无普通列表/自定义组/nft写入/正式handoff。能力不支持（如aether-dns TLS）不能静默降级协议。
3. 配置和状态只在`run_dir`下独占bootstrap代目录，目录0700、文件0600；临时child逻辑名使用`aether-bootstrap-dns`，与正式DNS pid/FIFO/目录隔离。端口排除53、31053、31080/81/82/83及正式配置占用的端点。
4. 内核取候选再启动有TOCTOU，候选最多10个，就绪等待共享最多5秒预算；只对有证据的端口竞争换候选，其他配置/能力/权限错误明确返回。每轮失败child必须确认退出才能选新端口，不以占位者有响应证明己方就绪。预算耗尽不再派生下一child；stop收尾是独立的最多5秒停止判定预算，内部可复用既有监督者的TERM/升级行为，但不承诺信号必然使进程退出，也不因此获得新一轮begin预算。
5. 私有实例必须确认本child拥有本端点未连接UDP及TCP LISTEN（B1的TC回退需要TCP），之后才能查询。优先复用B2验证过的所有权/ELF/取消能力；允许给`xray_ready.wait`加可选第5参数`{timeout_ms,label}`，timeout_ms为1–5000、默认仍5000，旧调用语义不变。私有实例不额外要求TPROXY，不借用published的正式产物，也不放宽归属规则。
6. 私有child意外退出只报告本次失败、不自动respawn。允许为supervise.create增加可选`respawn:false`，默认保持正式Xray/DNS既有退避；不能拿raw_log选项代替。正常stop复用当前监督者持有的child生命周期；其真实退出回调已到才算停止成功，再回收timer、FIFO/reader、pid与本代文件。重复stop幂等；不得仅按kill返回0、kill -0、PID文件缺失或已发送KILL推断退出。
7. 成功、上游失败、无LKG、取消、引擎拒绝配置、端口冲突、写文件失败等路径均必须stop。最多5秒仍不能确认退出，返回明确的stop/cleanup失败并保留handle（父存活时）与代记录，不进入Xray、正式DNS、handoff或下一候选/下一代。可以在后续重试只检查是否已退出，不能用自动再fork掩盖残留。停止/清理错误须进入现有错误返回/事件，不能以状态stopped掩盖未回收资源；不新增RPC字段或事件码。不得递归删除整个run_dir或他代文件。
8. daemon遭SIGKILL后，没有直属child句柄的残留处理只做身份/存活检查：旧生命周期已消失或PID已换身份时，不向新PID发信号，按owned清单清理旧文件；原私有进程仍执行、PID记录缺失/损坏或无法确认时，保留代目录和诊断并返回清理失败，阻止继续启动。**不向孤儿/历史数字PID自动发TERM或KILL**，不广泛pkill；无需实现原子信号绑定、gate/token授权、额外管家或pidfd模块。
9. fork前准备并回读本代目录/配置及prepared记录，记录本代范围、引擎完整argv、父身份等；fork后尽早登记PID/starttime及完整所属信息。明确承认fork到登记之间父SIGKILL可能留下不能自动辨识的私有进程：缺失PID不是无人执行的证明。该窗口只要求“保留prepared代、报告不确定、拒绝误杀和继续启动”，不要求证明任意SIGKILL窗口都能自动恢复或有界回收。直属child仍以uloop退出回调确认回收；孤儿不宣称能直接wait，文件只删已证明属于本代且已不再使用的项目，handoff/intent及外部文件不属本代资源。

**本次安全边界**：有界的是停止判定与错误返回，不是保证内核态/D-state、SIGSTOP或无调度进程在期限内消失。复用现有直属child stop机制，不要求本卡重新证明全局监督器信号实现具有pidfd式原子性；事后检查也不能宣称消除了发信号前的竞态。明确接受异常残留可能需要管理员处理、服务暂时拒绝重启的可用性取舍，不以放宽身份校验换取自动恢复。

### 冻结启动顺序与失败分支

- 保留原有配置校验、组件闸门、boot等待、同一applied_context的读取/冻结、staging渲染/校验与失败不改系统的边界。bootstrap只在原本允许清理/启动的位置之后创建，不能为做解析提前绕过前置校验。
- 对节点IPv4字面量，不创建bootstrap、不发DNS，沿B1 literal语义。
- 对节点域名，用同一已展开且冻结的snapshot创建私有实例，再调用B1显式端点解析；不调用系统resolveip，不查询正式31053，不重新读WAN/UCI导致跨代。只发当前节点名及其关联CNAME追问，不承载普通客户端查询。
- 保持DNS优先、三轮/每轮3秒（含TCP/CNAME）的B1语义，失败才按地址LKG。引导child无法建立的runtime失败，只有已确认本次资源停止并清理成功后才可复用同一LKG失败收口；stop/cleanup不确定或失败优先阻断，不能用LKG继续启动掩盖残留。不得复制另一套缓存优先逻辑。前置能力/配置校验错误仍按原阶段失败，不靠LKG绕过；LKG写失败不当成成功，取消不fallback、不写缓存、不再重试。
- 取得IPv4（DNS/literal/LKG）后必须先end私有child，再用该IPv4补全Xray并-test，启动Xray并通过B2正式published门。**在此之前不启动正式DNS**。
- 正常路径：完成应有nft/route加载后，启动正式DNS，核对本child的正式UDP/TCP socket就绪，才dnsmasq_install；成功才清T15.1 intent、发布最终状态/健康检测。不得把fork/PID或日志listening当成正式DNS归属就绪。
- 域名失败且无LKG：这是既有degraded分支，不是永远等待Xray。end私有实例，不启动Xray、不等其socket；仍按原初始tier启动正式DNS，fail_open=1跳过拦截、0保留原拦截策略，之后交monitor按原规则恢复。默认T1在此分支可以失败，不能临时开T2/T3或把gfw送bootstrap来凑NOERROR。
- restart安装前失败/退避继续保留旧fragment和intent；新handoff安装成功后按T15.1边界清intent。首次start没有旧handoff的既有未接管窗口不宣称已保护；显式stop/禁用仍释放。原安装成功后的后续回滚语义不擅自扩大成永久保留。
- 每个等待/解析后、每个新child fork前、安装handoff前重新检查停止意图；TERM期间取消当前工作，只清已有资源，不再启动Xray/正式DNS、不发布迟到成功、不执行新健康探针。旧正式子进程的正常监督退避不改。
- 原生产步骤名保持可读性；允许在现有steps字典增加bootstrap_start/bootstrap_resolve/bootstrap_stop等内部计时，不新增事件码或RPC字段，不将本卡扩成日志命名统一。

- **依赖/必读**：T15.5全部归属/UDP/ELF契约、T15.6及修订；`docs/validation/t15.6-followup-20261108.md`；`xray_ready.uc`、`net.uc`、B2真实listener/最小模块/变异测试；B3复用wait的方式及最小模块边界。H28K已证实readiness和单独31080握手各新增1条loopback日志；诊断原型可取得本Xray inode及v6only=0，但原型不是可直接复制的生产parser。

### 冻结行为

1. 对原先需要`tcp4_reachable`的分支（IPv4需求命中本child的IPv6通配TCP LISTEN），先用现有socket能力只读查询Linux NETLINK_SOCK_DIAG/INET_DIAG。不连接TPROXY、不发送探测payload；已有fs/socket和核心chr/ord足够，不引入struct、外部ss/tcpdump、原生helper、pidfd或内核模块依赖。
2. 内核记录必须与当前候选的family、TCP LISTEN、地址/端口、inode一致；继续核对本次child PID/starttime及FD inode。匹配的v6only=0才能作为双栈证据；v6only=1明确不满足IPv4需求，不能再用另一个进程的IPv4 listener把它凑成ready。该证据证明socket地址族能力，不冒称防火墙/透明代理端到端健康，后者仍由既有monitor负责。
3. IPv4/mapped地址、仅IPv6需求、明确IPv4 DNS socket、UDP未连接绑定、未引用端口等继续沿B2规则；本卡不改引用集合和原普通端口健康检测。不将全局bindv6only默认值或“同号端口存在”当作per-socket证据。
4. 只用当前readiness进程所在的原生Linux network namespace，延续原项目环境前提；不可用另一个namespace或宿主的数据为ctx.root夹具作证。ctx.root非空时不向真实宿主发diag/握手来补齐fixture；正向真实双栈测试用真实监听器+真实proc，纯错误/字节序场景使用明确的受控边界。
5. 保持wait/published原签名、默认5秒共享deadline、B3的可选短预算/label与取消优先。diag读写、解析、必要兼容探测均包含在同一剩余预算内；无忙等，不因重试重置deadline；非阻塞等待每次最长100ms并派发/检查停止意图，成功返回前仍复核child生命周期。
6. 使用本请求专用socket和明确seq，验证NL消息长度/对齐、请求关联、family/protocol/tuple/inode、NLMSG_ERROR、multipart终止/中断及属性长度。未知扩展属性可安全跳过；冲突/坏格式不能当成缺属性。不要错误要求响应header的nlmsg_pid必须为0，须按真实netlink语义处理。只实现TCPv6就绪所需最小协议，不写通用netlink框架。
7. 所有成功/不支持/错误/超时/取消路径关闭本次diag/兼容probe FD，不加常驻worker、持久缓存或新的运行文件。复用已验证的显式ELF字节序，不复制另一套默认小端检测。

### 兼容回退策略（不新增隐含内核依赖）

- **允许沿旧规则作有界本地TCP兼容验证**：接口明确不支持（如EAFNOSUPPORT/EPROTONOSUPPORT/EOPNOTSUPP），该只读接口被权限拒绝（EPERM/EACCES），或完整可信且匹配的内核记录确实没有v6only属性。这些环境原本可通过主动探测启动，不能为一个日志修复直接变成永久不可启动。
- 兼容验证仍使用原本的本child候选、地址约束和competing_tcp4排除，不降低归属/IPv4要求，不访问远程端点；ctx.root仍禁止回读宿主。该回退可能保留旧loopback副作用，文档与报告须明确支持范围，不能说所有平台都完全被动。
- **禁止用回退掩盖已明确不满足/坏数据**：v6only=1、inode/tuple不匹配、child已退出/换代、消息畸形、取消或总预算耗尽不能转为另一次握手凑成功。未知错误/收取超时不冒充“不支持”；可以在剩余预算内重试或明确失败。
- 不为回退改RPC字段/新增事件码/刷屏，也不改Xray日志等级或过滤其Error。测试通过受控listener计数与故障边界证明所走路径，不能只靠日志静默或成功返回值自证。
