# T16.114 DNS 层级切换失败后恢复原服务

基线 a15c84ea。唯一目标：monitor 的 `action_set_tier()` 失败时，不能只留下旧 tier 标签却运行候选配置。当前 `aether-proxy/src/lib/monitor.uc:234–272` 先覆盖 current、重启 DNS、等目标子进程 UDP/TCP ready，再通知 dnsmasq；后两步失败没有补偿。不是外部 HUP reload 的诊断修复，也不是 DNS 协议修改。

- 首先复用现有 tier readiness 测试，记录基线反例。替换前保全实际正在使用的配置字节；无法取得时不破坏现状。区分未产生副作用和已经发布候选。不要从可能变化的配置重新推导旧字节。
- 已产生副作用后，候选启动、就绪或通知 dnsmasq 失败：在原操作锁内撤下候选、恢复旧配置，按原引擎恢复服务，验证恢复代子进程拥有正式 UDP/TCP 监听，按需要重新通知 dnsmasq。原错误仍返回、不发成功切层事件；恢复也失败时保留两段错误，不宣称恢复成功。不得无限重试或二次获取同一把锁。
- TERM 优先：正向和恢复路径的异步边界都不得在停止请求后再拉进程、发成功通知；完成回调恰一次，释放 busy/锁。保持正常切换、失败后再次切换及 T3 回试 T2 原语义。
- 验收：本地隔离目录和 loopback，覆盖候选启动/就绪失败、首次 dnsmasq HUP 失败、恢复自身失败、TERM 及正常切换。用确定性屏障，不靠 sleep 猜顺序。关键断言是失败后旧配置逐字一致、候选未占正式端口、旧配置的恢复代可经 UDP/TCP 回答可区分的新查询（不能只看 PID、端口可连或状态标签）。通知失败路径核验调用顺序和结果；stub 与实际进程证据分别标注。用同一反例证明基线失败、修后通过。
- 白名单：`aether-proxy/src/lib/monitor.uc`、`tests/monitor/`、`reports/T16.114.md`；若确需扩围先说明。不要改通用 HUP 回滚、nft、DNS 引擎仓、LuCI、版本、CI 或 B29 草稿。复跑 monitor、reload、`git diff --check` 和 `CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh <卡提交>`。只本地提交，报告记录基线/修后证据、命令及限制，不提交临时产物。
