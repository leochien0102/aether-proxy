# T16.82 选用 aether-dns 时提前拒绝不支持的 TLS 上游（H15）

单一目标：配置语法允许 chinadns-ng 的 TLS 上游，而当前 aether-dns 引擎拒绝它。按实际解析出的候选引擎和将交给它的上游判断，不按已运行的旧引擎猜，不在通用 schema 中禁用 tls://；不实现 DoT、不静默降级成 UDP/TCP。

先追踪已有 component_id、check/precheck、启动、HUP 与 DNS 渲染的实际路径。复用现有检查/错误返回，让检查、冷启动、重载在不可兼容时给出可定位引擎与配置项的诊断；在任何停止旧子进程或替换活动配置之前拒绝，失败后保留可重试能力。不要为了统一而另造能力注册表。只验证实际会交给 DNS 引擎的配置，避免误拒绝其它组件处理的地址。

用本地夹具覆盖：aether-dns + TLS 提前失败、aether-dns + 普通受支持上游成功、chinadns-ng + 合法 TLS 不误拒；运行中的可用服务通过真实 reload 提交不兼容候选（含切换引擎情形），断言无旧子进程 stop/新进程 start、活动配置不变、无成功事件，纠正后可成功。报告给出修前/后证据、涉及的实际入口。仅改 proxy 侧所需检查与针对性测试、相应契约文档和 reports/T16.82.md；不改 DNS 仓、版本、更新器、设备或远端。运行受影响套件、git diff --check 及 review.sh main，只交本地 SHA。
