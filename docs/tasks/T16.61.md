# T16.61 · LuCI 安装后刷新框架缓存（M14）

项目与范围：仅在本卡 aether-proxy 工作树内实现。产品基线 `114d9795`。目标是安装或升级界面包后，LuCI 不再沿用旧菜单索引和模块缓存；不是清浏览器缓存，也不重开已撤回的 H9。

## 契约与验收

1. 对照目标 LuCI SDK 的 `luci.mk` 默认 postinst 与本包自定义钩子，补回被覆盖的服务端缓存清理。只动框架指定的缓存；缺缓存也成功。保持在线 rpcd reload（非 restart）一次、原失败处理不变，不重复执行 default_postinst。不扩展到卸载、后端包或业务服务。
2. 在隔离临时根或等价沙箱里运行实际钩子内容：在线升级清掉旧索引及模块缓存，保留旁边的无关文件；缓存不存在仍成功；有 IPKG_INSTROOT 时不清宿主缓存也不 reload。记录调用次数；不得在宿主真实 /tmp 或 /etc 上执行清理。给出同一用例基线失败、修改后通过的证据。
3. 白名单：`luci-app-aether-proxy/Makefile`、已有安装钩子测试或 `tests/luci/` 下最小回归、`reports/T16.61.md`。查清测试位置再改，不改 SDK、CI、版本号、后端、UI 或生产设备。能离线核对打包脚本则注明格式与证据，不把源码测试写成 ipk/apk 真机验收。
4. 跑专项回归、`bash tests/luci/run.sh`、`CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh <派卡基线>`、`git diff --check`。只本地提交，交回 SHA、报告和未验证边界，不合 main、不推送。
