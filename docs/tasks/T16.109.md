# T16.109 显式代理：只允许指定可信 LAN 访问 IPv4 TCP 入口

目标：让可信局域网客户端实际使用已有 SOCKS5 / HTTP（含 CONNECT）服务，而来自其他接口的客户端即使访问同一个 LAN 地址也不能用。只做后端；沿用认证和当前 proxy 出站。旧配置、默认双关和既有 loopback 模式保持不变，无需迁移。先读 T16.107/108、生产 nft input_guard 及真实启动、reload/rollback、停止、fw4 reload 和降级路径，不把单纯绑定 LAN 地址当成访问控制。

用显式配置指定一对可信接口、属于该接口的本地单播 IPv4 地址；两个入口沿用各自开关和端口。无显式选择不扩大监听；错误/缺失/地址漂移/端口冲突时拒绝或撤销 LAN 服务，绝不回退到通配绑定。权限和透明代理名单独立：被标为直连的可信客户端可主动使用，普通流量策略不变。不加通配/多 LAN/IPv6/UDP/TLS 到代理、LuCI、自动开 fw4 区域、设备操作或新依赖。不提升既有防火墙权限：来自可信接口仍受原有 fw4 input 策略约束；只收窄新监听的入口，不误封同端口其他本地地址或不相关服务。凭据和日志沿用前卡边界。

验收核心：在独立 Linux netns 拓扑中，用真实监听与内核规则证明：可信接口正确认证能经所选上游访问目标；另一接口（访客/WAN 模拟）即使访问可信 LAN IP 且凭据正确仍不可用；其他接口地址没有代理监听。分别验证 HTTP/CONNECT 与 SOCKS；双关不改变既有规则。就绪判定须校验本代 Xray 持有精确地址/端口，不接受通配或旁进程。用确定性故障/同步点验证先设保护再放监听、先关监听再撤保护，至少覆盖启动、改绑/回滚、fw4 reload 和停止/降级风险；不能证明的过渡路径须写明并交回阻塞，不以最终状态替代全过程证明。区分真实内核、真实 Xray 与夹具结果，不在宿主网络空间或路由器测试。
