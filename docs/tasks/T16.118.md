# T16.118 命令包装器：计时器收尾不得把已完成的命令报成失败

基线 `ed573fcd`。唯一目标：修 `aether-proxy/src/lib/sys.uc` 的命令包装器，使「runner 已经运行结束、计时器最后一条 `kill` 因目标已退出而返回 1」不再被当作握手失败，从而不再产出 `CMD_FAILED rc=-1 / timer exited early (status 1)` 和上层的 `START_FAILED step=render: … generation cleanup failed`。不是调大 `remove_generation` 的超时数值，也不是重做 HUP reload 的诊断。

## 现场证据（2026-11-27，H28K 1.3.1-r3 实测）

- 三次复现，形态完全一致：`SERVICE_STOPPED` 之后约 16 s 出现
  `CMD_FAILED {cmd: "rm -rf /var/run/aether-proxy/applied/<gen>", rc: -1, stderr: "timer exited early (status 1)"}` →
  `START_FAILED {step: "render", detail: "cannot publish …: generation cleanup failed"}` →
  `START_RETRY {attempt: 1, in_secs: 30}` → 30 s 后启动成功。x86 在 10:39 与 16:59 也是同一对事件。
- 同一个 generation 目录（8 个文件、1.4 MB、tmpfs）单独 `rm -rf` 实测 **0.00 s**；成功重启自身的 `SERVICE_STARTED` 里 `steps.publish: 17`（毫秒）。所以那 16 s 不是命令本身在干活。
- 代码路径：`aether-proxy/src/lib/pipeline.uc` 的 `remove_generation()` 是 `sys.run(['rm','-rf',path], {timeout: 10})`；`sys.uc` 的计时器子 shell 最后一条命令是 `kill -KILL "$runner"`，它的退出状态直接成为 `D` 事件的值；controller 的 `D` 分支先判 `trc -ne 0` 就置 `handshake_err`，**不看是否已经收到成功的 `R`**。
- 触发条件观察：**改写配置文件后的第一次重启**会复现（`uci commit` 与直接覆盖 `/etc/config/aetherproxy` 都算）；不改配置的普通重启不复现；「装引擎后不重启、再重启」也不复现（引擎切换不是原因）。

## 要求

1. 计时器收尾的 `kill` 失败不得成为计时器退出状态：`kill -TERM`/`kill -KILL` 目标已消失时不得让子 shell 以 1 退出，收尾后显式 `exit 0`。
2. controller 的 `D` 分支：若已收到成功的 `R`（`runner_done=1 && rc=0`），忽略非 0 的 `trc` 并返回成功；若 `R` 未到且有 `timed_file`，仍按超时 `124` 报；不得把「命令已正常完成」报成 `-1`。
3. `remove_generation()`：目标已经不存在时视为清理成功（先 `fs.stat` 判断），不要让它把 publish 拖进 10 秒等待；目标存在而 `rm` 真失败时仍必须报错。
4. 真失败必须仍然失败：真超时 = `124`、命令自身非 0 = 它自己的码、握手记录真的损坏 = `-1`。三条各要一个反例用例。
5. 白名单：`aether-proxy/src/lib/sys.uc`、`aether-proxy/src/lib/pipeline.uc`（仅第 3 点）、`tests/unit/`、`tests/reload/` 或 `tests/daemon/`（新增确定性 fixture）、`reports/T16.118.md`。不改事件名与字段、不改 CLI、不改 LuCI、不改版本与两个 Makefile、不动 `docs/backlog.md` 里的 B29 草稿。

## 验收

- 新增确定性单测，至少四组输入：快命令 + 收尾 kill 竞态 → 0；真超时 → 124；命令返回 7 → 7；握手记录被截断 → -1。用注入式 fixture 控制收尾竞态，不靠 `sleep` 猜顺序。
- 复跑 `bash tests/host/ucode tests/run.uc`、`tests/reload/run.sh`、`tests/daemon/run.sh`、`git diff --check`，以及
  `CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh <卡提交>`。
- 真机（H28K，由维护者执行）：10 次「改一项配置 → `/etc/init.d/aether-proxy restart`」，0 次出现 `timer exited early` 与 `generation cleanup failed`；事件里不再出现该 `rc=-1`。
- 报告写清基线反例、修后证据、命令与限制；只本地提交，不 push、不合 main、不动设备。
