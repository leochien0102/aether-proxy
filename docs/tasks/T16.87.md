# T16.87 单条分享链接的字节上限（M13 第三部分）

目标：给单条节点 URI 的解析工作设定固定预算：16 KiB（16384 字节，含 scheme、参数、标签），恰等允许，超过则拒绝整条，不截断。是新的产品边界，不是协议本身的限制，也不声称旧实现必为二次复杂度。

在现有公共解析路径用唯一常量，按字节而非字符计数。以去掉订阅行分隔符后的原始条目为准（空行不计；非空行两端空格仍算长度）；在逐字节扫描、协议字段百分号/Base64 解码和 URI 正规化之前检查，不得先 trim 订阅条目导致绕过。整包 Base64 订阅先按既有下载预算解包，再按每条节点行检查，不能把 16 KiB 当整包上限。原有 LF/CRLF、裸 CR、C0/DEL 以及 1024 有效候选数契约不变。手动 parse/import 与订阅共用规则；订阅超长行沿用无效行跳过语义（不消耗有效节点数）；全坏不发布，不泄露输入或凭据。不新增 UCI 开关、事件、下载限制或依赖。

验收：用合法合成 URI 构造 16383/16384/16385 字节（包括 UTF-8 多字节以及带填充空格的非空行），给出修前/修后对照。手动导入超限不写 UCI；明文与整包 Base64 均验证超长行夹在合法行之间不影响邻居、全超限不发布；多个合规短行组成的 >16 KiB 订阅不误拒。跑 URI、node、sub、干净检出的 review.sh main 与 git diff --check。仅改 const.uc、uri.uc、必要的直接调用处、对应测试、docs/06-nodes-subscription.md 与 reports/T16.87.md。只本地提交后交回 SHA，不合 main、不推送、不发版、不动设备。
