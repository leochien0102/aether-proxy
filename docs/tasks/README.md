# 任务卡

派给实现 agent 的任务卡。每张卡对应一个分支、一个 PR（[12-ucode.md](../12-ucode.md)「协作流程」）。

| 文件 | 里程碑 | 状态 |
|---|---|---|
| [m0.md](m0.md) | M0 骨架、打包、测试环境、探针 | 可开工 |
| [m1.md](m1.md) | M1 配置读取、校验、渲染器 | 依赖 M0 的 T0.1、T0.2 |

M2 及以后的任务卡在前一个里程碑完成、探针结论写回设计之后再拆。原因是这些任务依赖真机行为，提前拆卡容易写错。

已知要放进 M2 的事项：

- **初始数据基线**：`aether-proxy/files/data/` 目前为空，M2 上真机之前需要一份手工生成的基线快照（5 个文件，格式见 05），否则 `data.load` 会因缺少规则数据而失败。M7 的发布通道建好之后改由 CI 生成。

## 派卡方式

把下面这段连同任务卡全文一起交给 agent：

```
你在 aether-proxy 仓库中工作。开始前完整阅读 docs/README.md（尤其是「给实现者的规则」）和 docs/12-ucode.md，
然后阅读任务卡「必读」中列出的章节。只做任务卡范围内的事。设计文档没覆盖的情况不要自行决定：
在 PR 描述中列出问题，按最保守的方式实现，并在代码中标注 TODO(design)。
```

## 卡片类型

- **实现卡（T）**：产出代码与测试，验收标准是命令及其预期输出。
- **探针卡（S）**：在真机或虚拟机上验证某个假设，产出是写回设计文档的结论（PR 只改 `docs/`，附带实测记录）。
  探针不写正式代码，原型脚本放进 `spikes/<编号>/`，合并后保留作为证据。

## 测试机

探针 S1–S4、S6 需要 OpenWrt 虚拟机：官方 24.10.8 与 25.12.5 的 x86-64 镜像各一台，**不要用承担实际出口的设备**。
虚拟机需要能访问一个测试用的 Xray 节点（自建一个即可，不要用生产节点的凭据）。
