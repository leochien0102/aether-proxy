# T16.60 · 日志洪峰下有界、完整地发布子进程统计（H2）

产品基线 `a3dd4bf0`，与 T16.55 更新器独立。目标：丢弃日志时统计仍可观察，但额外进程/文件写入开销不随同一秒丢弃行数线性增长；并发读者只能读到完整的一版统计。

## 契约
- 梳理所有统计发布入口，保留现有放行进度（5 秒或新增 50 条）、首次丢弃的即时摘要及可读统计、会话结束精确总数。持续丢弃时有新输入且达到 5 秒应更新，不设后台定时器；同一时刻的连续丢弃不能逐条启动 writer。摘要文本、顺序、5 秒启动豁免、20/120 限流、去重窗口及其计数语义不变。区分日志摘要的输出和统计文件的发布，不以吞摘要换性能。
- 快照仍为原路径、原 JSON 契约；同目录独占临时文件完整写好后原子替换，保持私有权限。保留对不安全目标类型的拒绝与路径引用处理。写失败不破坏已有可读统计，不影响日志 FIFO 的消费、后续放行及 EOF 收尾；正常和可处理的失败路径清掉自己的临时文件。不增加常驻进程、依赖或 flash 写入。

## 验收
1. 复用现有测试时钟和夹具。在同一秒送足量**不同**消息以真正进入丢弃分支，量化统计写入/子进程调用，提供同一输入基线旧红、新版新绿，不能只报耗时。分别验证首次丢弃在 EOF 前可见、持续丢弃跨 5 秒可见、EOF 最终计数精确；静默时不新增写入。
2. 给原子发布留下可重复验证：已打开旧快照的读者仍见完整旧内容，新打开的读者见完整新 JSON。覆盖至少一条发布失败路径及 FIFO 后续正常输出，保留原有负向用例。不靠高频读取一次没撞到半行来证明原子性。
3. 允许 `aether-proxy/files/aether-proxy-logfilter.awk`、`tests/daemon/logfilter.py`、`tests/daemon/supervise-log.py`，必要时 `tests/daemon/run.sh`、`docs/09-logging.md`、`reports/T16.60.md`。不改 raw.log 收集器、daemon 生命周期、更新器、CLI 输出、CI、版本或 Makefile；超范围先问。
4. 宿主 awk 与 BusyBox awk 均实跑，明确列出解释器，不静默跳过；跑 daemon 套件、既有打包 smoke-host、`CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh <派卡基线>` 和 `git diff --check`。报告给出可复跑命令、实际计数、错误路径和未覆盖边界。仅本地提交，不合 main、不 push、不发版、不操作设备。
