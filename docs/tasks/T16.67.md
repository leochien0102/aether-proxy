# T16.67 · 启动状态写入失败时释放操作锁（审计 M1）

目标：start_sequence() 在组件就绪后写 initial_state 失败，须在把错误交回调用者前显式结束本次 C.LOCK_FILE 的持有。当前成功路径显式解锁并关闭，而 state_result.ok 为假直接返回。不要假定基线一定永久自锁；区别隐式析构、继承文件描述符与显式解锁的证据。

只修这条失败出口。不动 H1 的 daemon.lock（须继续保护实例直到清理结束），不提前放开成功路径，不改失败 step/code/detail、children 的移交或清理顺序，不做 HUP 事务锁（M2），不重构整段启动流程。核对当前 sys.lock 的打开/继承模式以及已有释放路径，采用最小有效修改。

验收：用隔离夹具让启动确实到最后一次 initial_state 写入才失败，验证错误为 state、未发 SERVICE_STARTED、已启动子进程仍按原路径清理。证明该失败出口显式释放操作锁且可被独立持有者再次取得；不得只在整个 daemon 退出后测一次锁就宣称覆盖，也不得用 sleep 猜时序。记录基线红/修后绿；若基线能因隐式关闭恢复，照实记录，区分显式释放的观测点和真实锁的行为。覆盖正常启动、实例锁仍有效的对照。
