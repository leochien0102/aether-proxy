### 契约（照此实现，不要自创）

1. `usage.json` 顶层新增：`"quota": { "bytes": <整数>|null, "set_at": <epoch 秒>|null }`。
   字段缺失或 `bytes:null` 均表示「未设置」；读取时缺失不算错误。
2. `stats history` 回复顶层新增 `"quota": { "bytes": <整数>|null, "set_at": <epoch 秒>|null }`，
   其余字段与语义不变（`ok`/`enabled`/`days`/`updated_at`）。
3. CLI（唯一实现处）：
   - `aether-proxy stats quota` → 显示当前额度；
   - `aether-proxy stats quota set <值>`，值接受整数字节或带单位：`<n>G`、`<n>GB`、`<n>T`、`<n>TB`
     （**十进制**：1 GB = 10^9，1 TB = 10^12；只接受整数，`1.5G` 视为 `USAGE`）；
     允许范围 1 GB – 100000 GB（含端点）；
   - `aether-proxy stats quota clear`；
   - 三者都支持 `--json`、`--sys-root`、`--run-dir`；成功 `{ "ok": true, "quota": {…} }` 退出 0；
     参数错误 `USAGE` 退出 2；写失败 `FS_FAILED` 退出 1（错误码按 `docs/10` 现有惯例）。
4. **本卡不做 rpcd**：`stats_quota`、ACL 与 `common.js` 的 `rpc.declare` 由 T16.3 与前端调用方一起加。
   原因：`tests/luci/static.test.js` 断言「ACL 方法 == 前端声明方法」，先加后端方法会让 16 套测试
   立刻失败，而加白名单只会留一个暂时没人调用的 rpcd 方法（2026-11-16 决定）。
5. 落盘互不覆盖（本卡关键点）：
   - monitor 的每日 flush 写 `usage.json` 前必须**重新读取文件**，只替换 `days` 与 `updated_at`，
     保留 `quota` 等其余字段；
   - quota 的写入读→改→写，保留 `days`；
   - 两条路径都用现有 `sys.write_atomic` 与 0600 权限。
6. 文件损坏/权限错误：按现有「空历史 + 一次 warn」处理，`quota` 读不到按「未设置」返回，不新增事件码。

### 背景（2026-11-17 真机实测）

安装含新方法 `log_truncate` 的 `luci-app-aether-proxy` 后，`ubus -v list aetherproxy` 里**没有**该
方法，必须手动 `/etc/init.d/rpcd restart` 才出现——rpcd 只在启动时扫描插件，安装不会触发。
H28K 实测：`/etc/init.d/rpcd reload`（实现是 `procd_send_signal`，即 SIGHUP）**能**让新方法立即
注册（临时加 `dummy_probe` → reload 后可见），因此修法用 `reload` 而不是 `restart`
（restart 会打断正在通过 rpcd 执行的更新事务）。

### 允许改动

- `luci-app-aether-proxy/Makefile`（新增 `Package/luci-app-aether-proxy/postinst` 与 `postrm`）
- `docs/10-cli-luci.md` 或 `docs/08-updates.md`（一句升级行为说明）
- `tests/`（见测试要求；不改共享基础设施）
- `reports/T16.11.md`

**不改**：任何 `aether-proxy/src/**`、LuCI JS/po、rpcd 插件本身、ACL、版本号。

### 要求

1. `postinst`：

   ```sh
   #!/bin/sh
   [ -n "$${IPKG_INSTROOT}" ] && exit 0
   [ -x /etc/init.d/rpcd ] && /etc/init.d/rpcd reload || echo "luci-app-aether-proxy: rpcd reload failed (rc=$$?)" >&2
   exit 0
   ```

   - 镜像构建（`IPKG_INSTROOT` 非空）时**不做任何事**并成功退出；
   - rpcd 未安装时静默跳过；
   - reload 失败只打印一行到 stderr，**不能让安装失败**。
2. `postrm` 同样 `reload`（卸载后方法要及时消失），同样守卫 `IPKG_INSTROOT` 与失败不致命。
3. 不得使用 `restart`、不得 `kill` rpcd、不得改 `/etc/config/rpcd`。

### 现象与证据（H28K 真机，2026-11-18）

|---|---|---|---|

**背景（2026-11-19 用户定案）**：RC 是"发出来给人短期验证"的独立站点；发 RC 就停在 RC，
不通过不出 Release；通过后由「RC Promote」把**已存在的 RC** 推进通道并成正式 Release；
不要求 RC 时走「发 Release」直接出。三条路各自是一个入口，互不隐式串联。

**三个入口（都在 app 仓 `tools/release/`，用 `gh` 驱动 CI）**

1. `rc.sh <version>` —— 发 RC：
   前置检查（工作区干净、HEAD 与门禁绿 run 同 commit、契约/发布说明已就位）→ 推 tag
   `v<ver>-r<n>-rc<N>`（N 从 1 递增，已存在则拒绝）→ 等 `release-candidate` 完成 →
   打印预发布 URL 与资产清单。**到此为止**：不打正式 tag、不 promote、不写通道。
2. `promote-rc.sh <rc-tag>` —— RC Promote：
   校验该 tag 是已发布的 prerelease 且与门禁 commit 绑定 → 派发 channel 仓 `promote.yml`
   （`release_tag=<rc-tag>`）→ 等成功 → 推正式 tag `v<ver>-r<n>` → 等 `release-assets`
   走清单路径建 Release → 打印 Release URL、并把 Release 资产与 RC 资产逐一比对 sha256。
   **不重新编译**；RC 试用不通过时不得执行本入口。
3. `release.sh <version>` —— 发 Release（默认，不经过 RC）：
   前置检查同上 → 推正式 tag `v<ver>-r<n>` → 等 `release-assets` 走**直发**路径
   （通道里没有本版本清单时，用门禁产物自行组 18 件资产并建 Release）→ 派发 channel
   `promote.yml`（`release_tag=<正式 tag>`）把同一批字节写进通道 → 等清单 → 打印
   Release URL、通道 `current/previous`、以及两边 24 个包的 sha256 对照。**不建 RC**。

三条路共用一条不变量：**产物只能来自同一 commit 的门禁构建**，任何入口都不重新编译；
RC 路径在 promote 之前不得出现正式 tag / Release / 通道条目。

**通道隔离与版本比较规则（2026-11-19 补充，必须落到测试里）**

- RC 包**沿用最终版本号**（`1.2.1-r1`），不造 `-rc1` 版本串：实测

  `channel-stable` **禁止**出现任何 prerelease 条目——由 `promote.yml` 在写入前校验，

## T16.36 子进程日志限流：启动突发、立即摘要与自检

**来源**：2026-11-19 真机对比（x86 vs H28K）。x86 跑 `chinadns-ng`（Zig），启动瞬间超过日志过滤器的

摘要会说错名字。

**目标**：让"启动瞬间的突发"不再被丢；丢弃一旦发生立刻可见；名字跟着实际引擎走；并提供自检，

1. **启动豁免（只豁免秒级）**：每个子进程拉起后的前 5 秒不参与秒级上限（当前 20 行/秒）；
   分钟上限（120 行/分）与去重窗口（10 秒、同消息重复折叠）照旧生效，防止真刷屏。
   豁免窗口按"该子进程的本次会话"计算，与现有 `REPEAT_SECONDS` 无关。
2. **摘要立即落盘**：一旦 `dropped` 从 0 变正，立刻输出摘要，不再等到下一条被接受的行或会话结束
   （本次现象：92 秒的时差）。摘要格式保持现有 `aether-proxy: %s output rate limited, dropped %d lines between %s and %s`，

3. **监督名跟随引擎**：`aether-proxy/src/lib/reload.uc` 的 `start_child(daemon, 'dns', …)` 与

   事件文字保持一致；`daemon.children` 的 key 仍是 `dns`，不改内部键。

1. **收集器丢启动 burst**：`rawlog.sh` 的 `logread -f` 与子进程启动之间没有同步，窗口期内打出的
   行不会进 `raw.log`；现象是"每会话只留第一行"，因为那一行是 `chinadns-ng` 在加载 dnl 列表之前
   立刻打的，之后的十几行落在同一个窗口里。
2. **`.logstats` 不刷新**：过滤器只在"第一条被接受"、"写摘要"、"退出"三个时刻写文件，
   长会话里计数永远停在启动时的值，`log stats` 的"自检"名不副实。

### 详细要求

1. **可复现的收集器测试（先做这个）**：在 `tests/` 下写一个用假 `logread` 脚本的测试——脚本被调用后
   立刻输出 N 行 `… daemon.info aether-proxy[1]: …`，随后每秒再输出一行；断言 `raw.log` 收到全部 N 行
   且顺序正确。若当前实现就是红的，说明缺陷在收集器自身；若绿，说明是真实 `logread -f` 的挂载时序，
   按第 2 条修。
2. **收集器与子进程握手**：`rawlog.sh` 在 `logread` 挂上之后写 `<run-dir>/raw-log.ready`；`daemon.uc`
   的 `start_collector()` 之后等待该标记（上限 2 秒，超时记一条 warn 事件后继续放行），再启动
   `xray`/`dns` 子进程；每次重试循环开始前删除旧标记，避免旧文件骗过等待。若测试证明仅靠握手不足以
   覆盖 `logread -f` 的历史窗口，则改为启动时先 `logread -l <N>` 回放最近 N 行、再切 `-f`，
   并按 `(时间,pid,消息)` 三元组去重，保证重启不会写重复行。
3. **`.logstats` 节流刷新**：过滤器的 `ACCEPTED` 计数改为"距上次写入 ≥5 秒，或累计 ≥50 行"时刷新一次
   （`dropped` 变化与摘要路径仍立即写）；写失败仍自禁用。`aether-proxy log stats` 输出格式不变。
4. **文档**：`docs/09-logging.md` 补一段「收集器握手与 `.logstats` 刷新」；若加了回放，写清去重规则。

## T16.38 原始日志：chinadns-ng 启动噪音收敛

**状态：已合并（`ea2c1d2`，2026-11-20）。** 收集器写盘时去掉 ANSI 与 chinadns-ng 自带时间戳，抑制
`I [main.zig|dnl.c|groups.zig:…]` 明细（保留 `local listen addr`、`W [`/`E [`/`[Warning]`/`[Error]`/含 `failed`、
`dnl_init tag:` 汇总行），并在后续可写记录之前或 EOF 时补一行 `chinadns-ng startup: N info lines suppressed`。
审查：daemon **330**、cli 222、luci 1171、其余套件 exit 0；`review.sh main` **0 FAIL / 0 WARN**。
真机验收由维护者在 x86 执行（见 `reports/T16.38.md`）；注意 `local listen addr` 本身以 `I [main.zig` 开头，
判据要用「排除保留例外后的 main.zig 明细为 0」。
**背景**：T16.37 修好 burst 丢失之后，x86 上 `raw.log` 里一次启动会出现约 30 行 `chinadns-ng` 的
`I [main.zig:…]` / `I [dnl.c:…]` / `I [groups.zig:…]` 配置明细（且同一个消息会以「纯文本」和
「带 ANSI 颜色 + 自带时间戳」两种形态各出现一次，合计翻倍），真正有用的只有启动完成与加载规模。
目标：一次启动的 chinadns-ng 段落压到 **≤6 行**，警告与错误一条都不丢。

### 详细要求

只在收集器 `aether-proxy/files/aether-proxy-rawlog.sh` 的写盘 awk 里做，不碰 `logfilter.awk`：

1. **归一化**（只用于判断与写入）：先删 `\033\[[0-9;]*m`（ANSI 颜色），再删行首
   `YYYY-MM-DD HH:MM:SS `（chinadns-ng 自带的时间戳）与紧随其后的空白，得到 `msg`。
   写盘时优先写归一化后的整行（保留 `daemon.info aether-proxy[pid]: ` 前缀），让 `raw.log` 不再出现颜色码。
2. **抑制**：`msg` 匹配 `^I \[(main|dnl|groups)\.(zig|c):[0-9]+ ` 且不属于下面的例外 → 不写，`suppressed++`。
3. **例外保留**（任何一条命中就写）：
   - 含 `local listen addr`（启动完成）；
   - 以 `W [` / `E [` 开头，或含 `[Warning]` / `[Error]`；
   - 含 `failed`（连接失败类，排查最常用）；
   - 匹配 `^I \[dnl\.c:[0-9]+ dnl_init\] tag:`（每个 tag 一行加载规模）。
4. **汇总行**：`suppressed > 0` 时，在**下一条要写盘的行之前**先写一行
   `aether-proxy: chinadns-ng startup: <N> info lines suppressed`；若抑制后一直无新行，则在
   `logread` EOF（会话结束、重连前）补写这一行，保证「压掉了多少」始终可查。
5. **非 chinadns-ng 的行一律不动**（xray 的 `[Warning] core:`、`[Info] infra/conf/serial:`、
   `A unified platform…` 等照旧入库）。
