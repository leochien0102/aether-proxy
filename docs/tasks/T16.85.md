# T16.85 单份订阅的有效节点数上限（M13 第一部分）

目标：限制单次订阅解析交给规划器的有效候选数。现有下载字节限制不等于节点数限制。`uri.parse_body()` 在强键去重前收集候选；`sub.update_one()` 通过 `error_for_parse()` 决定是否继续规划，不能只在解析器返回一个无人识别的错误。

契约：每份订阅最多接受 1024 个解析成功的候选（含重复候选，按去重前计数，不是 64 项自动切换名单限制）。恰好 1024 个仍可用；遇到第 1025 个即停止解析本份，明确报节点数超限，不把前 1024 个当成成功结果，不发布部分配置。空行和既有可跳过行不占额度。明文与整体 Base64 经同一判定。失败详情不回显原始链接、凭据。既有订阅内容、当前节点及其名单不因这次失败而被替换或清空；正常的失败状态记录可以更新。

验收：边界 1024/1025、重复候选、无效行、明文/Base64 的离线解析测试；真实 sub update 入口用临时配置、假下载验证超限失败且原 UCI 字节一致，邻近合法更新仍能发布。实现保持一处生产上限、不给用户新增配置项。跑 unit、sub 及干净检出 review.sh main、git diff --check。报告说明对大订阅的兼容影响与计数口径。允许改 uri/sub/const 与必要的错误映射、订阅文档、相关测试和 reports/T16.85.md；不改下载上限、分享链接方言、UI 布局、版本号、设备，不顺带做单行字节上限或控制字符策略。本地提交后交回 SHA，不合 main、不推送。
