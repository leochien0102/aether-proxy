# T16.113 快速命令取消计时器时，握手记录不得互相拼接

单一目标：修复 sys.run 共享控制管道的帧边界竞态。不改访问控制策略、sha256sum 调用方或 LuCI。现场 H28K（1.3.0-r2，BusyBox ash，daemon 有 LD_PRELOAD=/lib/libsetlbf.so）：对同一文件计算哈希，stdout 正确，两次捕获的控制流均为 `P pid\nT pid\nS pid\nR 0\nSG -\nD 0\n`；包装器返回 -1、`timer exited without publishing grace pid`，reload:hash_current 中止。两组分别第 20/121 次出现；不要把随机命中次数当验收条件。

先核对所有共用这条管道的发布者、两阶段 PID 所有权、取消与清理的先后关系。即使某个可取消的发布者在写记录时被杀，也不能把另一发布者的有效记录吞掉。不要假设 shell 内建 printf 一定只做一次 write；不限定实现。不得靠特判 `SG`、忽略缺 G/D、重试哈希、去掉超时保护或全局改 daemon 的缓冲环境掩盖问题。

验收：
1. 在隔离宿主用可控同步点复现同一时序（runner 已返回、发布者被取消、随后发布 no-grace）；旧版稳定红、新版稳定绿。不能只伪造终端错误字符串或只测试解析器。快速成功和自然非零都须精确保留退出码、stdout/stderr，不等满超时。
2. 复跑 T16.83/84 专项：真缺 PID/发布者异常退出仍有界失败；真实超时与自然 124 可区分，TERM→KILL 和忽略 TERM 的旧约束不退化；返回时无本次进程或私有目录残留，不伤旁边哨兵。兼顾首阶段及 grace 阶段。不新增运行时依赖，不用固定 sleep 赌调度。
3. 宿主复跑 reload 套件；附一次禁用单设备规则、未列出策略 direct 的真实 reload 路径证据：成功事件和生成/应用规则不再包含该设备。不要以仅保存了 UCI 或旧连接的结果代替运行规则。H28K 的真实客户端新连接验证由维护者安排，不是实现者的设备权限。
4. 范围：aether-proxy/src/lib/sys.uc、必要的定向宿主测试与 reports/T16.113.md。报告记录修前/修后控制流、命令与结果；干净检出跑 tests/review.sh 对卡基线、git diff --check。只本地提交，交回 SHA。不要改 B29、主仓、版本、发布或设备。
