# T16.78 限制更新规则解压后的字节数（M11）

目标：只处理 `update data` 的单项规则数据。下载大小、超时和签名不能代替明文上限；不得先经 `sys.run` 完整捕获 gunzip stdout 再检查长度。先核对现有规则资产明文规模与现有约束，选一个有余量的固定上限，在报告记下依据。无需新增配置、依赖或通用执行框架。

验收：在解压过程中限制输出（可读至多上限+1以区分边界）；超限即中止并回收解压进程，不留下无界临时文件或内存副本。通过限制后仍执行原有明文哈希、行数和内容解析检查；恰好上限的有效规则可更新，超过一字节须报该项失败，原规则和哈希文件逐字节不变。失败/超时清理本项临时资源。覆盖真实本地 gzip 正常、边界、超一字节及无效 gzip；只用无害文本夹具，不依赖网络、设备或宿主特权。不能只测一个脱离更新路径的长度函数。

范围：`aether-proxy/src/lib/update.uc`、必要的 `const.uc`、`tests/update/`、`reports/T16.78.md`。若需改共用进程工具先说明原因，不顺手调整软件包安装、通道、下载协议或公网 CI。报告列阈值依据、资源界限、真实入口的断言和退出码。跑 `bash tests/update/run.sh`、`CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh main`、`git diff --check main...HEAD`。只本地提交，不合 main、不推送、不发版、不碰设备。
