# T16.69 · 同节点 IP 刷新的失败回滚（H4）

**目标**：监控把当前节点从旧 IP 刷新到新 IP 是一次变更。可恢复失败退回旧的有效配置与转发；只有新 Xray 就绪才公布切换。不是节点间 failover，不承诺进程崩溃时跨资源原子性。

**证据入口**：`aether-proxy/src/lib/monitor.uc` 的 `update_node_ip` 当前在校验前依次改 current 的 nft/Xray 文件，加载 nft 后重启 Xray。单文件 rename 不是整笔事务；不要把可能暂时失步写成永久损坏。先核对现有 reload/apply、nft 动态集合保存/恢复及 Xray readiness、停止优先的语义，复用能复用的步骤；不在已持操作锁的 monitor 回调二次取锁。

**验收**：用已有隔离夹具，先在基线上证明至少一种失败留下不一致，再覆盖候选写入（含第二份失败）、Xray 配置校验、nft 加载、子进程启动/就绪失败；逐项区分哪些资源真正改变、哪些才需要恢复。核旧 current 两份文件字节、实际生效的 nft/模拟转发与子进程使用的配置、运行态 IP、最后可用 IP（LKG）及事件，不只数命令。恢复成功后新请求可成功；正控只发布一次 NODE_IP_CHANGED。主动注入一次回滚失败，须能区分原错与恢复错，不报切换成功或假称已恢复。TERM 在途不复活退出中的子进程，busy/操作锁与完成回调在所有出口正确收尾。假命令只写临时 sysroot，不操作宿主网络或真机。

**范围**：`aether-proxy/src/lib/monitor.uc`、已有 apply/reload 辅助（仅确有必要）、`tests/monitor/`、`tests/xray-ready/`、必要的生命周期说明和 `reports/T16.69.md`。不改其他节点选择策略、更新器、配置/API、版本、发布或 B29。若需扩白名单先说明。跑 monitor、reload、xray-ready、daemon，`CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh e4e52dbb` 与 `git diff --check`；报告保留注入点、前后证据及未验证边界。仅本地提交，交回 SHA。
