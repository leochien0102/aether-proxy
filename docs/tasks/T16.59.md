# T16.59 · daemon 实例独占（H1）

产品基线 `7fe443fd`。同一运行实例域内，从首次发布启动状态到停机清理结束，只允许一个 daemon 当所有者。与 H6 更新器无关，不把 M1/M2 的 cleanup/reload 操作锁改造并进来。

## 边界
- 先沿真实 daemon 入口确认首次共享写入、现有短期操作锁释放时点、退出清理及独立进程继承 fd 的情况。用稳定、独立的实例锁覆盖完整生命周期，包括启动失败但仍等待恢复、运行、重载与退出清理。不要把操作锁持有到进程结束；不要用 PID 存活检查或文件是否存在代替原子互斥。清理不能删除正在使用的锁对象从而允许另建同名锁。尊重隔离的 sys-root / 运行目录，不在宿主真实系统路径落锁。
- 竞争者快速以忙（退出码 3）退出，不写/删首实例的 state 或 PID，不启动/停止组件、不触碰数据面；无法建立锁时拒绝启动并保留可诊断错误，不冒充已知竞争。不能依赖错误文案猜 errno。若绑定不支持精细区分，请先说明能观察的事实，再定错误映射。
- 所有者正常退出后允许立即接管；所有者异常死亡不应被遗留锁文件或幸存子进程无限阻挡。保持单实例时原有启动、HUP、TERM 和已有操作锁的外部行为。不引入常驻辅助进程。

## 证据与门禁
1. 用隔离 sys-root、真实 daemon 和现有 stub 复现旧红。至少检查已运行实例遭遇第二次启动，以及两个首次启动交错。用屏障选定时序，断言只有一方取得所有权；检查整个竞争窗口的快照/PID 发布与组件调用（不能只看最终状态或只数存活 daemon）。排除正常 monitor 自己更新快照造成的误判。
2. 同域竞争失败后，所有者仍能完成正常控制请求和停机。验证正常退出后可再次启动、所有者被强制结束后能重新取得锁，区分“锁可取”和“数据面全部恢复”；夹具有界等待，回收自己的进程。验证至少一个建锁失败路径。复用现有 daemon 测试设施，不改生产代码只为调度测试。
3. 允许：`aether-proxy/src/lib/daemon.uc`、`const.uc`，必要的最小 `sys.uc` 锁操作（不改变现有调用者契约）；`tests/daemon/` 对应夹具及默认入口；`docs/04-lifecycle.md` 实例锁的准确说明、`reports/T16.59.md`。其他路径先问。不改更新器、监控策略、T16.58 信号语义、版本、CI。
4. 独立跑新增测试、`bash tests/daemon/run.sh`、`bash tests/reload/run.sh`、`bash tests/host/ucode tests/run.uc`、`CI_TOOLS_DIR=/workspace/openwrt/ci-spike/tools bash tests/review.sh <派卡基线>`、`git diff --check`。报告列基线旧红、修复后同夹具新绿、单实例正对照、实际退出码、未覆盖边界。只本地提交，不合 main、不推送、不派 CI、不发版、不操作设备。
