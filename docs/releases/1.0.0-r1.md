# aether-proxy 1.0.0-r1

## DNS 引擎依赖

- 后端硬依赖从 `chinadns-ng` 切换为虚拟包 `dns-engine`，默认提供者为 `aether-dns`。
- `chinadns-ng` 仍声明 `PROVIDES:=dns-engine`，不设默认变体；设备只需满足其中一个提供者。
- 引擎选择与升级前置事务已在 0.7.0 实现，本次不改变产品运行逻辑。
  升级到 1.0.0 时事务先检查运行能力与包 Provides；不满足时先安装签名清单中的 `aether-dns`，再装后端与页面。

后端与 LuCI 同步为 **1.0.0-r1**；LuCI 侧包含更新日志页的开始/完成事件文案（M4-04）。

## 迁移要求

0.x 不能跳过迁移步骤直升 1.0.0：先按 [更新文档](../08-updates.md) 满足手工前置，
升级到 0.7.0，再通过其前置事务升级到 1.0.0。支持窗口为 1.0.0 与 0.7.0；
0.6.3 及更早版本为 manual-only。0.7.0 的已知包快照不变。

若事务需要替换已装日期版 `aether-dns`（如 `2026.11.04-1`），目标为 `1.0.0-r1`：
这在包管理器看来是降级。opkg 安装与精确恢复使用 `--force-downgrade`；
apk-tools 3.0.5 对本地资产使用精确 checksum 依赖，保持 `apk add --allow-untrusted <资产>`，
不使用不存在的 `--allow-downgrade` 选项。两条路径均须先验签及校验 hash/size。
替换前必须有与已装版本精确匹配的恢复资产，否则事务拒绝并要求人工迁移。
已满足运行能力及 Provides 的引擎可以跳过，不无条件替换；后端失败时恢复精确原版。

## 发布边界

正式 proxy 资产由现有 CI 构建，不手工上传临时包；`aether-dns` 资产由 DNS 仓库 CI 唯一构建，
channel 按 pin 校验、签名并分发。发布前须确认 channel 清单已包含 `aether-dns 1.0.0-r1`；
管道合并本身不等于下一次 REF 变更已发生。本次任务不发布、不打 tag。
发布后再更新兼容测试冻结快照；当前仍使用已发布的 0.7.0-r1 页面/RPC。
