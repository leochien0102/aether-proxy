# aether-proxy 0.7.0

本版把 DNS 引擎的选择与版本下限改为按引擎处理，并把升级到 1.0.0 的前置事务做成两阶段：

- `dns` 成为权威逻辑键，`chinadns-ng` 作为兼容别名双写，组件 JSON 新增 `engine` 字段。
- 概览与更新页按逻辑组件显示「DNS 引擎」，更新页的说明按提供组件的包区分。
- 事件与通知中的组件 id 改为 `dns`；历史记录里的 `chinadns-ng` 仍显示为「DNS 引擎」。
- 引擎按显式 `chinadns_bin` → `/usr/bin/aether-dns` → PATH 中的 `chinadns-ng` 顺序选择，没有失败回退。版本下限按引擎区分：`aether-dns` 为 `1.0.0`，`chinadns-ng` 为 `2025.08.09`；自定义路径引擎不设下限。
- DNS 的路径或版本变化会在重载时重启 DNS 子进程，Xray 的路径变化同样重启；未变更的 reload 不额外查询版本。
- 升级前置事务只在目标 backend ≥ 1.0.0 时触发：先确认运行时下限与包依赖都满足，再安装 backend；任一步失败回到可启动的旧组合，结果带 `prerequisite` 字段。
- 更新页新增「已是最新」以及「前置已安装／已回滚／需人工迁移」两类结果文案。

本版不提供引擎自动故障切换，也不回退到另一个引擎；不提供 aether-proxy 回退入口，手动降级不受支持。

后端与 LuCI 同步为 0.7.0-r1，本版仍依赖 `chinadns-ng`，不打包、不发布 aether-dns。0.7.0 是升级到 1.0.0 的桥接版本，0.x 不能直接跳到 1.0.0，须先经过本桥接版本。

正式资产由 CI 构建与检查，本机验证结果见任务卡报告 `reports/M4-03d.md`，不把本地包当作发布资产。
