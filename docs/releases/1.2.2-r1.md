# aether-proxy 1.2.2-r1

正式版：**1.2.2-r1**。核心版本升到 1.2.2：把「组件更新」块的状态行收成一行、给通道地址一个
可点的链接，日志页标签条与表格左对齐；同时**取消候选（RC）更新通道**，发版流程简化为
「发布正式 Release → 写通道」两步入式。支持窗口为 **1.2.2 + 1.2.1**。

## 组件更新

- 「组件更新」标题、手动安装说明、状态行、表格回到正常层级：说明跟在标题右侧（窄屏换到标题下方），
  状态行自己占一行，表格紧随其后并有固定间距，不再出现按钮贴着表头的情况。
- 状态行内容：`上次检查: <时间或「尚未检查」>` + 一条「通道地址」链接（新标签页打开，
  悬停可看完整 URL），右侧是「检查更新」按钮；检查中/失败/无法检查的反馈也显示在同一行，
  不再单独占一行、也不再撑开一大片空白。
- 通道地址为空时退回内建默认地址，不显示占位符 `–` 的链接。

## 取消候选通道

- 移除「检查 RC 更新」开关、预发布徽标与预发布按钮文案、`main.update_channel` 配置项、
  rpcd `set_update_channel` 以及 CLI 的 `--channel`；客户端只读正式通道 `channel-stable`。
- 原因见 `docs/design/rc-channel-drop-20261119.md`：版本号在包字节里，因此「RC 与正式版
  逐字节相同」和「RC 版本号低于正式版」不可兼得；设备实测 opkg 把 `-rc1` 一类版本判为**高于**
  正式版（只有 `~` 能压序，而 git 标签不允许 `~`），装上 RC 后就无法正常升回正式版。
- 服务端同步收紧：`channel-stable` 清单在写通道时拒绝任何层级的 `prerelease` 条目，
  正式 Release 的 18 件资产必须与通道登记的哈希逐件一致。

## 发版流程（维护者）

- 只保留两个入口：**发 Release**（门禁产物 → 正式 tag → 直接组 18 件资产 → 写通道）与
  **写通道**（已发布的正式 Release → 只下载重发，不重新构建）。
- `tools/release/release.sh` 支持 `--dry-run`；`release-assets.yml` 的 push 触发只匹配正式版本
  tag，候选 tag 不会触发任何发布。

## 日志页

- 「事件 / 原始日志」标签条与下方表格左边缘对齐，右侧按钮贴齐块右边缘；
  窄屏下两组控件允许并排，但都不越出块边界。

## 修复

- 更新页：状态行与表格之间补回间距（合并反馈行时丢掉的 `margin`）。
- 日志页：工具栏的 `padding-inline` 是内联样式，改用作用域规则覆盖后标签条才真正对齐。

## 升级说明

- 从 1.2.1-r1 直升；1.2.0 及更早版本滑出支持窗口，为 **manual-only**。
- 若设备上装过候选包（`1.2.1-r2` 之类的本地试用包同号不算候选，但 `-rc` 版本算），
  必须用 `opkg install --force-downgrade` 装回正式版：opkg 认为 `-rc` 更高，不会正常升级。
