# aether-proxy 1.2.0-r3

修订版：**1.2.0-r3**。本版收口日志页改造与节点地址解析的两组问题；核心版本仍 1.2.0，
支持窗口仍为 **1.2.0 + 1.1.3**。

## 日志页（T16.9 / T16.10 / T16.11 / T16.13）

- **截断到上次启动**：新增 `aether-proxy log truncate` 与 rpcd `log_truncate`——只保留最近一次
  服务启动之后的事件与原始日志（`events.jsonl`、`raw.log`、`raw.log.1`），原地重写、不换 inode，
  采集器继续写；无启动标记时返回 `NOT_RUNNING`，需要显式 `--since`。
- **页面外层工具栏**：「清空日志」「截断到上次启动」移到 tab 行右侧，事件页与原始日志页都可见；
  确认框、互斥禁用、按当前 tab 刷新、失败提示都沿用原有语义。
- **升级后 rpcd 自动生效**：`luci-app-aether-proxy` 安装/升级后执行 `rpcd reload`（SIGHUP），
  新 rpcd 方法无需重启设备即可使用；不再需要手动重启 rpcd。

## 节点地址（T16.12 / T16.14 / T16.15）

- **切换前可达性校验**：10 分钟一次的节点域名刷新，在切换前对新 IP 的节点端口做 3 秒 TCP 探测；
  不可达则**保留当前 IP**、不写切换产物、不重启 Xray，并记 `NODE_IP_UNREACHABLE`。
- **不健康立即重解析**：转入 `PROXY_UNHEALTHY` 时立即触发一次重解析（60 秒防抖），不再干等 10 分钟。
- **解析取证**：每次刷新把原始 `resolveip` 输出、尝试次数、耗时、来源、dns tier 写进
  `/var/run/aether-proxy/node-probe.log`（JSONL、64 KiB 轮转、tmpfs），事件参数也带 `source`/`raw`；
  便于事后定位"为什么解析拿到旧地址"。
- **坏候选快速重试**：被探测拒绝后 60/120/240/600 秒退避重试。
- **LKG 只存可用地址**：解析成功不再写 LKG；只有启动应用成功、reload 生效、monitor 切换探测通过后
  才写入"最后可用地址"，坏 IP 不会进入回退路径。

## 背景

2026-11-17 两次实测：节点域名已切到新 IP，但 10 分钟刷新拿到了**不可达的旧地址**并直接切换，
导致 10 分钟降级后自愈。根因仍在观察（上游/缓存侧），本版先把"坏地址不会造成断线"与
"现场取证"两件事做实。

## 迁移要求

- 支持窗口不变：**1.2.0 + 1.1.3**；`1.1.2` 及更早仍为 manual-only。
- 从 1.2.0-r2 直升即可，无配置迁移；热力图开关、额度与 `usage.json` 均保留。

## 发布边界

资产由门禁 CI 构建，正式发布复用同一批产物（RC 不重建）。`aether-xray` / `aether-dns` /
`chinadns-ng` 版本未变，按通道规则复用已发布字节。
