# aether-proxy 1.2.0-r4

修订版：**1.2.0-r4**。只修一个缺陷：日志页「截断到上次启动」在服务期间发生过状态迁移时会误清空。
核心版本仍 1.2.0，支持窗口仍为 **1.2.0 + 1.1.3**。

## 截断基准改为服务启动时刻（T16.16）

- 现象：`state.json` 的 `since` 是**最后一次状态变化**的时间（monitor 在每次状态迁移时更新它），
  而 `log truncate` 默认拿它当"上次启动"。于是服务启动后只要发生过一次降级/恢复，
  启动那一段的日志就全部早于 `since`，点「截断到上次启动」会把它们全删掉——用户看到的就是"被清空"。
- 修法：`state.json` 新增 **`started_at`**，daemon 启动时写入、整个运行期不再变动（状态迁移只更新
  `since`）。`log truncate` 的默认参照改为 `started_at` → 旧状态文件退回 `since` → 都没有才 `NOT_RUNNING`。
- 兼容：旧状态文件（无 `started_at`）行为与旧版一致；`--since` 显式覆盖、`log clear` 均不变。
- 真机验证（H28K）：同一份日志，新状态文件（`started_at` 早于全部日志、`since` 晚于全部日志）
  截断后 `kept=3 / dropped=0`；旧状态文件（只有 `since`）`kept=0 / dropped=3`，复现原 bug 并证明修法有效。

## 迁移要求

- 支持窗口不变：**1.2.0 + 1.1.3**；`1.1.2` 及更早仍为 manual-only。
- 从 1.2.0-r3 直升即可，无配置迁移；热力图开关、额度、`usage.json` 与日志都不受影响。
