# aether-proxy 1.2.2-r2

补丁版：**1.2.2-r2**。修复子进程日志的两处采集缺陷——启动瞬间的日志被限流丢弃、丢弃摘要要等到
会话结束才出现；并把「子进程到底打没打日志、丢了多少」变成可自检。核心版本仍为 1.2.2，
支持窗口为 **1.2.2 + 1.2.1**。

## 子进程日志：启动突发不再被丢

- 每个子进程拉起后的**前 5 秒只豁免秒级上限**（原为 20 行/秒）。分钟上限（120 行/分）与
  10 秒去重窗口照旧生效，真刷屏仍会被压住。
- 现象来源：x86 上跑 `chinadns-ng` 时，启动瞬间超过 20 行/秒被丢 14 行，`raw.log` 里只剩一行
  `local listen addr`；H28K 跑 `aether-dns` 启动只打两三行，看不出异常。

## 丢弃摘要立即出现

- `dropped` 由 0 变正的那一刻立即输出摘要，不再等下一个被接受的行或会话结束
  （此前 16:38:49 的丢弃要到 16:40:21 才报，容易被误读成"采集不全"）。
- 摘要末尾追加 `, first: <消息>`：第一条被丢弃的消息（去掉 ANSI 与时间戳后截断 160 字符），
  便于直接看出丢的是哪一类日志。

## 自检：`aether-proxy log stats`

- 过滤器在每次写摘要时把计数落到 `<run-dir>/<name>.logstats`（单行 JSON：name / accepted /
  dropped / first_drop / last_drop / second_limit / minute_limit）。
- 新命令 `aether-proxy log stats [--json]` 汇总打印 run-dir 下所有计数；没有文件时输出空表并成功退出。
  这样"没打日志 / 被限流 / 没启动"三种情况可以直接区分。

## 子进程名跟随实际引擎

- DNS 子进程的监督名改为按实际二进制取（`aether-dns` 或 `chinadns-ng`），限流摘要、`ps`
  与事件文字不再把 `aether-dns` 说成 `chinadns-ng`；`daemon.children` 的内部键仍是 `dns`，
  升级后首次启动会顺带清理旧的 `chinadns-ng.pid`。

## 升级说明

- 同版本核心的补丁版，配置无需迁移；`uci export aetherproxy` 升级前后保持一致。
- 若从 1.2.2-r1 升级：`aether-proxy` 与 `luci-app-aether-proxy` 都会被替换为 r2；i18n 包无新增词条，不随版。
