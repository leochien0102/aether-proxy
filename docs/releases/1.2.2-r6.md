# 1.2.2-r6

**发布日期**：2026-11-20
**组件版本**：`aether-proxy 1.2.2-r6`、`luci-app-aether-proxy 1.2.2-r6`

## 本版内容

### 修复：`main.log_level` 真正生效（backlog B27）

配置里的日志级别以前**从未**应用到运行时：生产代码从不调用 `log.set_level`，阈值永远停在
`notice`，`main.log_level=debug` 一行 `debug` 都看不到。

现在守护进程在启动读到已校验配置后立即应用该级别（早于任何子进程与服务启动日志），重载成功后
若级别发生变化再同步一次；非法值回落 `notice`，不新增事件、不改任何既有日志文案。

CLI 子进程（`check`/`render`/`log`/`update` 等）不加载这份配置，仍用默认 `notice`——这条边界已写进
`docs/09-logging.md` 与 `docs/05-config.md`。

### 修复：reload 集成测试的计数抖动

1.2.2-r1 的门禁首轮出现过一对互斥失败：

```
M4-03a live-set path change emits success event: expected '10', got '9'
T9.8 invalid-config has no success event: expected '9', got '10'
```

根因是测试的采样窗口：`RELOAD_APPLIED` 在状态落盘之后才追加，而 M4-03a 只等版本字段；
`reload_checkpoint()` 也不保证上一次 HUP 的提交已经结束。

现在新增 `await_quiet()`（事件文件与调用日志连续 300 ms 无增长，5 s 超时记失败），
`reload_checkpoint()` 先等静默再采基线，M4-03a 先等本轮事件计数、再做严格相等比较，负向断言
改为等该路径的终态标记与 stderr 之后比较。**断言没有放宽、没有删除、没有加全局重试**，
生产代码零改动；反向验证（把等待目标改成 `+2`）时 20 次全部按预期变红。

## 升级说明

- 同核心版本内的补丁版本，直接在线更新即可；兼容窗口仍为**当前正式版 + 上一个正式版**
  （`1.2.2` + `1.2.1`），`1.2.0` 及更早为 manual-only。
- `1.2.2` 之前安装的用户请先按 [08-updates](../08-updates.md) 的迁移表升级。
- 本次没有新增配置项，`/etc/config/aetherproxy` 不需要调整。

## 发布边界

- 组件字节：`aether-proxy`、`luci-app-aether-proxy` 为本版新构建；`aether-xray`、`aether-dns`、
  `chinadns-ng` 版本未变，复用通道里已发布的同名字节（M4-17）。
- 通道：正式发布后写入 `channel-stable`，`previous` 为 `1.2.2-r5`。
- 固件 feed：`openwrt-actions/configs/feeds.conf` 同步钉到本版发布提交。
