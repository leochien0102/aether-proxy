# aether-proxy 1.1.0-r1

后端与 LuCI 同步为 **1.1.0-r1**；本次整理更新日志、自动更新链与端口范围选项。

## 更新日志（M4-04）

- 日志页显示「开始更新」（`UPDATE_STARTED`）与「已完成更新」（`UPDATE_INSTALLED`），便于区分安装开始与校验完成。
  开始事件在下载、验签和资产校验通过后、实际安装前记录；完成事件在安装与检查通过后记录。
- 更新链另有「更新链步骤已安装」（`BRIDGE_INSTALLED`）与「更新链未完成」（`BRIDGE_INCOMPLETE`）文案，
  不把某个中间步骤已完成误报为整条链已完成。开始/完成文案已随 1.0.0 发布，本版继续保留。

## 自动走完更新链（M4-07）

- 按签名清单声明的有序步骤自动继续更新，不跳过必经版本；每步重新拉取清单并验签，再计算下一步。
- 中间步安装后端并重启检查，随后由新安装的后端继续；到最终目标后再处理页面配套包，保持先后端、后页面的顺序。
- 整条链共享一个作业时间预算，不因换步重新计时。每步写入前及交接下一步前，剩余预算须 **≥180 秒**，
  恰好 180 秒可准入；不足时停止调度，返回 `BRIDGE_INCOMPLETE`，保留已完成步骤，可重试继续。
- 自动续步不改变更新链格式，也不赋予旧版更新器新能力；测试中的合成桥接链不是已发布迁移路径。

## 端口范围（M4-09）

- 概览页新增端口范围下拉：`all`（默认，全部端口）、`common`（常用端口）、
  `common_extra`（常用端口加补充端口）。常用端口集合与 ssr-plus 一致。
- 范围限制**仅作用于 TCP**，UDP 仍走原有主机策略；它不是对所有协议的统一端口过滤器。
- 高级页可填写 `extra_ports`，仅在 `common_extra` 生效，支持逗号分隔的端口及 `a-b` 区间。
  端口须在 1–65535，区间起点不大于终点；最多 **64 个输入项**，按输入项计而非区间展开后的端口数，
  输入项先去重再检查限额，非法输入报字段错误。

## 迁移要求

支持窗口滚动为 **1.1.0-r1 + 1.0.0-r1**，两者路径均为 `direct`，契约已知包相同：
四个 `UPDATE_PACKAGES` 加 `aether-dns`（引擎前置事务管理，不加入更新页主列表）。
0.7.0 移出窗口，和 0.6.3 及更早版本一样为 **manual-only**。
0.6.3 存量设备必须按 [更新文档](../08-updates.md) 手工迁移、满足依赖，不能据此承诺直升 1.1.0。

固件包版本后缀 `-1` 与通道版本后缀 `-r1` 在更新器的版本比较中等价；
这不改变资产完整性校验或引擎替换前必须准备精确恢复资产的要求。

## 发布边界

正式 proxy 资产由现有 CI 构建；`aether-dns` 资产由 **DNS 仓库 CI 唯一构建**，
channel 按 pin 校验、签名并分发，不在 proxy 仓库重新构建 DNS 包。
发布说明按 tag 去掉 `v` 后命名为 `1.1.0-r1.md`，供 `release-assets` 按 tag 查找。

本卡仅做升版与发布准备，**不构建、不打 tag、不推送、不发布**，没有进行 1.1.0 真机验证。
兼容测试的冻结页面/RPC 仍为已发布的 **1.0.0-r1**；发布后再另行更换快照。
