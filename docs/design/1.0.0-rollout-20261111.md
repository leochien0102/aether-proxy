# 1.0.0 发布方案：aether-dns 由 DNS 仓库构建（A 方案）

状态：**已定**（2026-11-11，仓库所有者批准 A 方案与三条建议）。本文是可执行规格；实现拆成
`docs/tasks/m4.md` 的 M4-05（proxy 侧）与 M4-06（channel 管道），DNS 侧要求见第 3 节。

## 1. 职责边界

| 仓库 | 职责 | 产物 |
|---|---|---|
| `aether-dns` | **唯一**的 aether-dns 包构建者：编译、打 ipk/apk、发 Release | 2 架构 × 2 格式 = 4 个资产 + `SHA256SUMS` |
| `aether-proxy-channel` | 下载、按 pin 校验 sha256、签名清单、发布；**不再构建** aether-dns | 清单含 aether-dns，资产原样进 `channel-stable` |
| `aether-proxy` | 依赖 `+dns-engine`；升级事务负责先装引擎；契约登记 provides | 1.0.0 包 |

理由：DNS 仓库拥有自己的构建与版本节奏；channel 只做"校验 + 签名 + 分发"，保持单一签名面。

## 2. 资产契约（channel 侧按此解析，不可变）

- 版本：`1.0.0-r1`（`PKG_VERSION:=1.0.0`、`PKG_RELEASE:=1`）。
- 文件名（必须逐字一致）：
  - `aether-dns_1.0.0-r1_aarch64_generic.ipk`
  - `aether-dns_1.0.0-r1_x86_64.ipk`
  - `aether-dns-1.0.0-r1_aarch64_generic.apk`
  - `aether-dns-1.0.0-r1_x86_64.apk`
- 包元数据：`Provides: dns-engine`、`Default-Variant: 1`、`Architecture: aarch64_generic|x86_64`、
  `Version: 1.0.0-r1`，静态 musl 二进制装到 `/usr/bin/aether-dns`，`aether-dns -V` 输出 `1.0.0`。
- 发布为 annotated tag `v1.0.0` 的 Release；**资产一旦发布不得重传**（pin 固定 sha256）。

## 3. DNS 仓库要求（可整段转发给 DNS 对话）

1. 打包：新增 `openwrt/Makefile`，采用"CI 交叉编译静态二进制 + Makefile 只打包"的模式
   （与 `aether-proxy/chinadns-ng/Makefile` 相同），不在 SDK 内编 Rust。
2. CI：tag `v*` 触发，矩阵 2 架构（aarch64_generic、x86_64）× 2 SDK（24.10 ipk、25.12 apk），
   校验 `aether-dns -V`，产出第 2 节的四个资产与 `SHA256SUMS`，创建 Release。
3. 包名与安装路径固定为 `aether-dns` / `/usr/bin/aether-dns`；`PROVIDES:=dns-engine`、`DEFAULT_VARIANT:=1`。
4. 不依赖 libc（静态），不装 systemd/init 单元；不写 `/etc`。
5. 交付前自检：`opkg`（或 `apk`）安装后 `aether-dns -V`、`/usr/bin/aether-dns` 存在、
   `opkg info aether-dns` 能看到 `Provides: dns-engine`。

## 4. channel 仓库改动

1. 新增 `AETHER_DNS_RELEASE`（JSON）：DNS 仓库、tag、版本、四个资产的文件名与 sha256。
   改 DNS 版本必须改这里并留痕。
2. `packages.yml`：SDK 构建之后加一步——按 pin 下载四个资产、逐个校验 sha256、放到
   `<packages_dir>/<arch>/channel/`（apk 放同目录，arch 由目录名给出）。
3. `tools/channel/build.py`（在 aether-proxy 仓库）：`PACKAGE_NAMES` 加 `"aether-dns"`；
   `ARCH_ALL` **不加**（架构相关）。收集逻辑不改，按目录扫描即可。
4. smoke 增加：安装 `aether-dns` 并执行 `-V`，确认版本与 `Provides` 可查。

## 5. aether-proxy 仓库改动（M4-05）

1. `aether-proxy/Makefile`：`PKG_VERSION:=1.0.0`、`PKG_RELEASE:=1`；
   `DEPENDS` 中 `+chinadns-ng` → `+dns-engine`。
2. `chinadns-ng/Makefile`：加 `PROVIDES:=dns-engine`（不设 `DEFAULT_VARIANT`，默认给 aether-dns）。
3. 兼容契约：`dns-engine` 是虚拟包，`update-contract.py` 的 `check_closure()` 只看 `deps ∩ managed`，
   虚拟名不进交集会**静默失去引擎依赖保护**。需在契约中登记 provides 映射
   （`dns-engine → aether-dns`），并要求支持窗口内的客户端认识 `aether-dns` 或将其登记为手工前置。
4. 迁移：已装日期版本（如 `2026.11.04-1`）的设备，opkg 视 `1.0.0-r1` 为降级，必须走
   `--force-downgrade`（`install_package(..., previous=true)` 已实现）；apk 路径要确认
   25.12 SDK 是否需要 `--allow-downgrade`，需要就补上并加测试。
5. 版本契约滚动：`support_window` → `["1.0.0", "0.7.0"]`；`docs/08` 窗口与迁移表同步；
   `tests/compat/fixtures/` 仍冻结 `0.7.0-r1`（发布后再换）。
6. 发布说明 `docs/releases/1.0.0.md`：依赖切换、引擎默认变 aether-dns、0.x 不能直升、日期版引擎迁移。

## 6. 顺序

1. DNS 仓库完成第 3 节并发 `v1.0.0`。
2. channel 管道（第 4 节）用该 Release 跑通，`channel-stable` 清单出现 `aether-dns 1.0.0-r1`。
3. proxy M4-05 合并，`main` 升到 1.0.0。
4. 发布 1.0.0（复用 0.7.0 流程：tag → release-assets 从清单复制）。
5. 发布后 `tests/compat/fixtures/` 换 1.0.0。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| DNS Release 资产重传 | channel pin 固定 sha256；`publish.sh` 同名不同字节即失败 |
| 命名/版本不一致 | 第 2 节冻结文件名；channel 侧校验失败即中止 |
| apk 架构识别 | 资产按 `<arch>/channel/` 摆放 |
| 日期版 → 1.0.0 降级 | opkg 强制降级；apk 参数待确认；M4-05 必须有对应测试 |
| 两套 CI 重复构建 | DNS 只在 tag 构建；channel 不编 aether-dns |

## 8. 测试矩阵

- DNS：两种格式安装、`-V`、`Provides`、四个架构组合。
- channel：pin 校验失败即中止；清单含 aether-dns 且 sha256 与资产一致；smoke 安装。
- proxy：契约 provides 校验（缺 aether-dns 时必须失败）；事务先装引擎（日期版强制降级）；
  1.0.0 目标触发事务、0.7.0 目标不触发；`components.dns.version == 1.0.0`。
- 设备（发布后）：0.7.0-r1 → 1.0.0 升级，引擎由 2026.11.04 换成 1.0.0，`dns_tier` 保持 T1。
