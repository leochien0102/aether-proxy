实现卡见 [tasks/m16.md](../tasks/m16.md)。

§2–§6（开关、数据模型、采样、持久化、`stats history` 契约）与 §9 的失败边界沿用实验实现，不再重写。

## 1. 目标与非目标

目标：在概览页**「流量与连接」块内**左右分栏放热力图（左侧 90 天日历网格，右侧保留原有实时流量
与连接信息），并按**月流量额度**给格子上色——越接近日均额度越红。

非目标：
- 不做域名/节点/目的地记录，不做历史回填，不改 `stats` 口径；
- 不改采样与持久化的数据字段（除新增 `quota`），不引入图表库；
- 不做「本月已用 / 剩余」汇总卡，不做超额告警（后续可另开卡）。

## 2. 数据口径

沿用实验实现：`config stats 'stats'` 的 `heatmap_enabled`（默认 0）、`/etc/aether-proxy/usage.json`
的 `days{日期:{tx,rx,observed,healthy}}`（保留 90 个本地日期）、`stats history` 与 rpcd
`stats_history`。

新增（T16.2）：`usage.json` 顶层 `quota`。

```json
{
  "schema": 1,
  "updated_at": 1790000000,
  "quota": { "bytes": 100000000000, "set_at": 1790000000 },
  "days": { "2026-11-15": { "tx": 123456, "rx": 987654, "observed": 86400, "healthy": 82000 } }
}
```

- `quota.bytes` 为**十进制**字节（1 GB = 10^9，1 TB = 10^12）；`null` 或字段缺失 = 未设置。
- 日平均额度按**该格日期所在月**的实际天数计算：`daily = quota.bytes / daysInMonth(日期)`。
  2026-02 用 28 天、2026-11 用 30 天、2026-12 用 31 天；跨月不重置、不累积。

### 2.1 当天数据的读路径（实时快照，2026-11-17）

问题：当天数据只在内存，`usage.json` 仅跨天/干净停止才写，页面只读文件 → 当天那格一直不更新，
用户必须重启才看得见。修法**不是多写闪存**，而是复用已有的内存快照通道：

- monitor 每个 tick 把当天累计写进 **`state.json`**（`/var/run/aether-proxy/`，tmpfs，本来每 tick 就写）：
  `usage_today: { date: "YYYY-MM-DD", tx, rx, observed, healthy, at: <epoch 秒> }`；
  热力图关闭时**不写**该字段。
- `stats history` 读完 `usage.json` 后合并快照：`date` 等于本地今天、且 `at` 距今 **≤ 600 秒**时，
  用快照值覆盖该日条目；过期或日期不符则忽略（daemon 未运行时自然只用文件）。
- 概览页热力图的 history TTL 由 600 秒降到 **60 秒**；仍是"最多一个请求在飞"，不新增 5 秒轮询。

效果：新鲜度 ≈ monitor tick（30 秒）+ 页面 60 秒 → 通常 30–60 秒可见；闪存写入次数**不变**；
掉电仍最多丢当天（与现状一致）。不做定时 checkpoint（2026-11-17 决定）。

## 3. 额度设置

- 存放：`usage.json` 的 `quota`。**不放 UCI**：`aether-proxy.init` 注册了 `aetherproxy` 的
  reload 触发器，任何 UCI 保存都会重载服务，而额度只是展示参数，不该动数据面。
- CLI（逻辑唯一实现处）：`aether-proxy stats quota`、`stats quota set <值>`、`stats quota clear`。
- rpcd：`stats_quota`（`{action:'show'|'set'|'clear', bytes?}`），ACL 归 **write**，转发 CLI。
- `stats history` 回复顶层加 `quota`，前端据此着色；未设置时前端退回相对算法（§4.3）。
- 写入互不覆盖：monitor 的每日落盘必须**先重读**文件再写，保留 `quota`；quota 写入保留 `days`。

## 4. 颜色（2026-11-16 试用以告警语义重定）

### 4.1 额度档（quota 已设置）

`r = 当日(tx+rx) / (quota.bytes / 该日期所在月天数)`，冷→暖 5 档 + 2 个中性档：

| 档 | 条件 | 浅色主题 | 深色主题 | 含义 |
|---|---|---|---|---|
| 空 | 该日无记录 | `#eef1f4` | `#1c2228` | 无数据、无 tooltip |
| 0 | 有记录但 tx+rx = 0 | `#dbe7f3` | `#1f2a33` | 当天没走代理 |
| 1 | r < 0.25 | `#9ec9e8` | `#2c4a63` | 低 |
| 2 | 0.25 ≤ r < 0.5 | `#74b3d8` | `#4b8ab5` | 中 |
| 3 | 0.5 ≤ r < 0.75 | `#f2c14e` | `#b08a2e` | 偏高 |
| 4 | 0.75 ≤ r < 1 | `#ef8c3c` | `#c66a25` | 接近日均额度 |
| 5 | r ≥ 1 | `#d9463f` | `#d0453b` | 达/超日均额度（**全图唯一红色**） |

阈值边界按「左闭右开」：`0.25 → 档 2`，`1.0 → 档 5`。颜色语义务必是「越多越该警告」，
不许再出现「流量越多越绿」的读数（2026-11-16 试用反馈 #4）。

### 4.2 深色主题

用 CSS 变量 + `@media (prefers-color-scheme: dark)` 覆盖，不检测 LuCI 主题类。上表两列都必须是
八进制色调一致的色板，不许只反转亮度。

### 4.3 未设额度（相对模式：分位数分档）

窗口内**有记录且流量 > 0** 的日期取总流量排序。对某一天，令 `r` = 窗口内严格小于它的天数、
`n` = 有流量的天数，则：

`level = min(4, 1 + floor(4 × r / n))`

- 四档大致均分天数（GitHub 贡献图的思路），不受极值和分布形状影响；
- **只用 1–4 档，不出现红色**（红色只给额度模式的 ≥100%）；
- 有记录但流量为 0 → 档 0；无记录 → 空档；
- `n = 0` 时全部档 0；`n = 1` 时唯一一天为档 1。

2026-11-16 反馈 #7：原来的 `log1p(当日)/log1p(窗口最大值)` 比例法会把 9.6 MB 以上的日子全部
压进最高档，90 天里几乎全橙，颜色失去区分度，已废弃。

### 4.4 健康度与读图

格子仍只编码流量热度：健康占比、观测时长、额度占比只在 tooltip。**图例删除**（2026-11-16
试用反馈 #3），改由 caption 行一句「越红 = 用量越大」+ tooltip 承担读图说明。

## 5. 布局

### 5.1 分栏

「流量与连接」块（`trafficSection`）在 `h3` 之后两列：

```text
[ 月额度 ▾ ]                        [ 近 90 天 · 越红 = 用量越大 ]
[ ▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢ ]                                  |  （表头）上传  下载
[ ▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢ ]                                  |   代理   …     …
[ ▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢ ]   5 行 × 18 列                    |   直连   …     …
[ ▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢ ]                                  |   合计（WAN）…
[ ▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢▢ ]                                  |   代理连接 n  总连接 m
```

- 容器：`display:flex; gap:1.5em; align-items:flex-start; flex-wrap:nowrap`（**顶部对齐**，2026-11-16
  第二轮反馈 #6：原来 `center` 会把左列压在中间、上方留空）。
- 左列 `flex:0 0 auto`：**宽度由网格决定**（≈519px），不再写死百分比；右列 `flex:1 1 auto` 吃掉剩余宽度，
  这样两列之间不会出现大片空档。
- 左列自上而下：caption 行、网格。caption 行 `justify-content:space-between`：
  **左「月额度」控件、右说明「近 90 天 · 越红 = 用量越大」**；说明右端与网格右端自然对齐
  （同一列、同宽）。
- 两块整体高度一致：5 行 ≈142px 与右侧「4 行表格 + 连接行」≈150px 对齐；右列更高时只让左列停在顶部，
  **不拉伸格子**。
- `heatmap_enabled` 关闭时整块与主线完全一致：不渲染 caption/网格、不调 `stats_history`。
- 宽度 < 720px 时 `flex-direction: column`：热力图在上、实时信息在下，两列都占满宽度。

### 5.2 网格尺寸

- 90 天 = **5 行 × 18 列**，row-major 连续日期，无前导空格，今天恒为第 90 格（index 89）。
- `grid-template-columns: repeat(18, minmax(0, 1fr)); gap:3px; width:519px; max-width:100%`；
  每格 `aspect-ratio:1; border-radius:20%`；**格子 ≈26px**（不再用 `1fr` 撑满整列，也不随视口放大，
  宽度由 519px 封顶；窄屏由 `max-width:100%` 让格子等比缩小）。
- 推导：`18×26 + 17×3 = 519px`，`5×26 + 4×3 = 142px`，与右列 ≈150px 基本等高。

## 6. 交互

### 6.1 额度控件（可编辑的自定义项）

- 一个控件占 caption 行右侧**一个槽位**，永远不新增行（2026-11-16 试用反馈 #1）。
- 下拉列表：`不限` / `50 GB` / `100 GB` / `200 GB` / `500 GB` / `1 TB` / `自定义…`。
- 选中「自定义…」后**同一个控件变为可编辑**：直接在当前自定义项里填数值（单位 GB，
  1–100000 整数），单位和输入在同一行内；回车或失焦用 `stats_quota {action:'set', bytes}` 提交，
  Esc 或空值/非法值回退到上一个选择并显示一行错误（复用现有错误行）。
- 其余选项选中即生效：`不限` → `{action:'clear'}`；预设 → `{action:'set', bytes}`。
- 成功后**只重着色**：不刷新页面、不重载服务、不重建控件 DOM；失败保留输入与上次配色，
  只显示一行错误文字。
- 初始值：`quota.bytes` 等于预设则选中它；否则视为自定义并在控件里显示 GB 数；`null` → `不限`。
- 5 秒轮询**不得重建** caption 行与额度控件（只更新格子 class 与 `title`），否则正在输入的
  自定义值会丢焦点（T16.3 已有约束，本卡继续遵守）。

### 6.2 tooltip（原生 `title`）

按行：
1. 日期 `YYYY-MM-DD`；
2. 代理流量（自动单位，沿用现有 `ap` 格式化）；
3. 健康占比 `82%（70800/86400 秒）`；`observed = 0` 显示「—」；
4. 观测时长；
5. 占日均额度百分比（仅设了额度时显示）：`r × 100` 取整，`≥100%` 原样显示。

无记录的格子没有 `title`。

### 6.3 刷新与错误

沿用概览页现有节奏：热力图数据来自 `stats_history`，在开启状态下随概览刷新读取；读取失败保留
上一次网格并在图例下方显示一行错误（沿用实验实现的「保留最后网格」语义）。

## 7. 边界

| 场景 | 行为 |
|---|---|
| 关闭开关 | 不采样、无历史 API、块内无热力图、布局与今天一致 |
| 首次开启 | 只有开启后的日期有记录，之前全部「无记录」 |
| 未设额度 | 相对绿阶回退，图例标「少…多」 |
| 额度 < 当日流量 | 档 5（红），不裁剪、不封顶显示 |
| observed = 0 | 健康占比显示「—」，仍按流量着色 |
| 跨月 | 每格按自己那个月的天数算日均额度 |
| 时钟/时区 | 日期取自 `usage.json` 的本地日期字符串，不在前端重新推算时区 |
| 历史文件损坏 | `stats_history` 返回 `enabled:true, days:[]`，显示空网格 + 一行错误 |
| 额度写入失败 | 下拉恢复原值附近显示错误，不改变现有配色 |
