# S15.2 启动期 DNS 依赖解环设计证据

## 结论与适用边界

复审状态（2026-11-07）：已合并`38ef822`。独立临时副本复跑正常/恢复各54项断言通过，三项反向验证命中预期失败，review退出0（0 FAIL、1个允许的docs WARN），原worktree干净。接受拓扑证据，不将B的Python中继视为真实引擎验证；下一步为S15.3契约探针。

基线：`633d74b`，分支 `spike/s15.2-startup-dns-order`。任务卡和执行约定相对 main 无差异。

**建议采用 B：独立隔离 bootstrap DNS 路径 → 显式取得节点 IPv4 → 渲染/测试并启动 Xray → 等待配置实际引用的 DNS socket → 启动正式 DNS → 安装 handoff → 按 T15.1 清 intent。**

A（节点专用一次性显式直查）在受控 UDP/TCP 上也能解环，但不作为覆盖现有配置语法的首选：它需要新增完整上游 resolver，承担 TLS、host@IP、多上游并发等职责。
B 可复用现有 chinadns-ng 的上游实现，仅新增面向私有 loopback 端点的取 IPv4 查询器，代价是一个短命 child 和相应清理接口。
本结论是建议，不冻结新产品行为；不改生产代码，不代表设备已修复。B 的真实组件最小配置/端口可分配性还须实现前契约测试确认。

实验实际证明了本机 socket/报文/信号顺序，足以否决“直接把正式 DNS 后移但仍用系统解析”和“只等 TPROXY”。
没有运行设备、真实 Xray/chinadns/dnsmasq/procd，不声称证明真实组件内部的启动顺序。
如果后续真实 B 配置无法不依赖 nft 或系统 resolver 工作，须停下交设计负责人，不改级别或保护边界补洞。

## 可重复实验及观测

入口：`bash spikes/S15.2/run.sh`。脚本与原始记录在 `spikes/S15.2/`，字段说明见其 README。

- 全部真实 loopback socket，内核分配端口，`listen` 事件把角色映射到实际目标；无固定公共 DNS。
- 假上游 china/direct/tunnel 分别返回 `192.0.2.11/.22/.82`；每条收发记录 qname、协议、目标、单调时间和 P 编号。
- P4 只读执行真实纯 renderer，注入 wan_dns 验证展开与 boot 选择；P5 也保存真实一项/两项 trust 配置。
- 延迟 180 ms 才 bind DNS TCP，上游“TPROXY”提前监听；正确 gate 到延迟端口出现后才开。缺失引用端口阻止 gate，未引用的第二端口不阻止。
- P6 对独立 worker 真正发 SIGTERM；A/B 的引导/端口等待各一次，退出 <1 秒，wait 回收，socket 可重新 bind，临时 owned 文件消失，handoff 不变。
- P7 是文件状态模型：首次没有旧片段，失败后仍没有；restart 保留旧片段/intent；重试新安装后清 intent。不是对 dnsmasq restart 的真实验收。

| 场景 | 本地结果与证据 |
|---|---|
| P1 IPv4 字面量 | A/B 均不发 bootstrap；仍走引用 DNS gate，`*-P1 literal skips bootstrap and waits referenced DNS` |
| P2 域名无 LKG，旧 handoff 保留、31053 无监听 | 先向关闭端点查询确定失败，再 A 直查/B 私有中继解析成功；普通 gfw 仅在正式 tunnel 有 `.82` 应答。`*-P2` 真实 receive 记录不含 bootstrap 接收普通域名 |
| P3 bootstrap 失败，有/无 LKG | 黑洞实际收到三次节点查询；有缓存才回退，无缓存明确 degraded；有缓存但 DNS 成功仍取 DNS。fail_open=0/1 为显式策略模型，不冒充 nft 测试 |
| P4 direct_dns_enabled=0/1 | 真实 renderer 的 boot-upstream 分别为 wan 展开 UDP 本地 china/配置 TCP direct，真实目标返回 `.11/.22` |
| P5 TPROXY 提前，DNS 延迟/缺失 | A/B 均延后 gate；一项不等第二端口，混合 TCP/UDP 均满足才过；TCP 存在不等于 UDP 可用 |
| P6 停止 | A/B × 两个等待阶段，SIGTERM 有界回收；B 的私有端口也验证可重用 |
| P7 首次与 restart 重试 | 失败不创建/移除不属于本次的 handoff；成功重试安装后清 intent；首次 start 早期仍没有 privacy handoff，不能称零泄漏/零中断 |

反向验证均退出非零且命中指定断言（不是启动报错碰巧非零）：

| 变异参数 | 实际杀死它的断言 | 否决依据 |
|---|---|---|
| tproxy-only | `A-P5 gate cannot pass before delayed DNS tunnel` | gate 在 DNS bind 前开放，恢复旧门禁不够 |
| closed-handoff | `A-P2 explicit bootstrap independent of closed handoff` | bootstrap 指向关闭的 31053 后无法得到节点 IPv4，不能只把 DNS 后移 |
| client-leak | `A-P2 ordinary gfw never reaches bootstrap or system` | 普通 gfw 真正送达 china bootstrap，来源断言失败，不能临时切客户端上游 |

变异参数只在 spike 进程生效，没有修改生产源码；全部结束后自动无参数恢复复跑。`normal/restored.jsonl` 是两次正常证据。

## 候选比较与否决

| 方案 | 实验 | 优点 | 代价/决定 |
|---|---|---|---|
| A 一次性节点显式 bootstrap | UDP/TCP、本地直查不经 31053 可行；P2/P4 通过 | 无额外常驻/短命 DNS 服务，清理简单 | 当前配置允许 tls://、host@IP、并发多上游；不能用 dns_test 的有限语法无声缩窄。要完整自写上游 resolver 的审计面太大，**不推荐作为第一实现**，不是否定其解环正确性 |
| B 私有隔离 bootstrap | 相同目标和协议经过私有中继仍通过 P1–P7 | 将上游语法/并发/TLS 留给现有 DNS 引擎；正式链路尚未存在也可取 IPv4 | 新增短命 child/配置/私有端口与显式查询器；**推荐**，须后续真实引擎配置契约探针/测试 |
| 只后移 DNS、保留 resolveip 系统路径 | closed-handoff 变异失败 | 表面改动小 | 域名无 LKG restart 依赖环，不接受 |
| DNS 先接客、只看 TPROXY | tproxy-only 变异失败 | 保持现状 | T1 报文仍可能送到缺失 tunnel，不接受 |
| 先摘 handoff、临时 T2/T3/把客户端切 bootstrap | client-leak 变异失败 | 能掩盖表面超时 | 泄漏或改变开关/级别/T15.1 边界，不接受 |
| 优先用 LKG 跳过 DNS | P3 要求 DNS 优先 | 更快 | 改现有优先级、缓存可能陈旧，不接受 |

## 推荐 B 的明确启动分支

1. 保持校验、冻结快照、残留清理的无副作用失败边界；restart 残留清理继续尊重 intent。
2. IPv4 节点直接返回；域名节点派生私有 bootstrap child（独立 loopback 端口，绝不 31053，绝不写 dnsmasq handoff），上游由同一已展开快照选择。
   私有实例不挂 nft 集合，不加载普通 gfw/自定义列表、不服务客户端；请求发起者只接受本次选定节点域名。
   不假定 chinadns 的 boot group 是访问控制；隔离靠端口不接入 handoff和调用方限制，不新增所谓生产 allowlist 能力。
3. 显式查询私有端点，最多三轮/每轮 3 秒（需并发上游仍由引擎处理），DNS 成功取首合法 IPv4并沿用 update_lkg；失败才读按地址 LKG。
   停止信号可中断，不因异常/不支持语法改走系统 resolver。
4. 取得 IP 后先终止/回收 bootstrap，再重渲染并测试 Xray，拉起 Xray。等待 TPROXY 以及 **当前 chinadns 配置实际引用的本地 DNS 端口及协议**。
   默认 T1：一项等 31082 的所选 TCP 或 UDP；两项两端口各等自己的协议。虽 Xray 同时开放 tcp,udp，不额外等待未引用协议/31083。
   当前 tier 为 T2/T3 时不为未引用的 T1 DNS 设置额外门槛；TPROXY 仍按既有规则等。
5. 在成功路径 gate 通过之后才启动正式 DNS，确认本地监听，再 dnsmasq_install；成功后清 intent。失败/取消先清本次 child/私有资源，再沿既有 rollback。
   **不将 DNS 上游能成功回答当成 gate**：监听 ≠ 健康，但上游不可达应由 monitor 判断，不能因此永远不能启动。
   生产 gate 可检查 tcp/tcp6 的 LISTEN、udp/udp6 的绑定地址/端口，注意 UDP 没有 LISTEN 标志；避免仅检查任意进程占同号端口。
6. **无 LKG 的解析失败是既有 degraded 分支，不是永远等待 Xray**：回收 bootstrap，不启动 Xray、不等其端口；仍启动正式 DNS，沿现有初始 T1/T2、monitor 降级与 fail_open 策略。
   默认 T1 下普通 gfw 可以失败，不被送到 bootstrap；T2（用户本来启用）/T3（既有策略降级允许）可能按既有产品规则直连，不能称它们是新的临时隐私保证。
   fail_open=1 跳过 nft/route，0 保持代理拦截；这不等于让 bootstrap 服务普通查询。
7. restart 安装前错误/退避仍保持旧片段与 intent；新 handoff 安装后按 T15.1 原边界清 intent，后续失败不能私自扩大为永久保留。
   手动 stop/禁用照旧释放。首次 start 在新安装之前系统 DNS 未接管，是既有非保护窗口；本卡不以重排顺序宣称修复它。

## 最小新增接口与 resolver 合约

建议由负责人冻结命名，不新增用户配置/RPC/事件码：

- `boot_upstreams(snapshot)`：纯函数返回开关选择的已展开列表，供正式 boot renderer 与私有 renderer 共同使用，避免语义漂移。
- `bootstrap_begin(ctx, snapshot)` → `{child, endpoint, owned_paths}`；`bootstrap_end(handle)` 幂等、终止并回收，错误返回不吞掉。
- `resolve_node_explicit(ctx, address, endpoint, on_signal)` → `{ok, ip, source}`，保留 resolve_node 的重试/LKG/缓存写失败语义；端点只能是新实例的 literal loopback。
- `required_dns_sockets(chinadns_artifact, xray_artifact)`/共享纯映射 → `[{address, port, protocol}]`；校验引用关系，不能维护第二套散落常量。
- `wait_xray_ready(ctx, requirements, on_signal)`：同一 5 秒总 deadline，取消检查在每轮之前及到时返回之前，不能尾部再次绕过停止判定。

B 需要的新查询器只是 **IPv4 loopback UDP A/IN 取地址**（可用 TCP 处理显式 TC 重试，但不是本卡已实现能力）；其对外上游由 chinadns-ng 处理，必须继续接受 `[udp|tcp|tls://][host@]IPv4[#port]`、默认协议/端口及多上游并发先有效答复行为。
不在查询器里再解析 host、不静默丢掉 TLS 名、不固定公共 DNS。不支持/无法建立私有配置要明确失败，按现有 LKG 路径收口。

正式 resolver 需另测：随机事务 ID；匹配来源 socket、ID、QR/opcode、单一问题名/类型/类；NOERROR、非 TC、完整长度；压缩指针循环/越界/跳数限制；只取本次 qname 或有限 CNAME 链关联的 A/IN，不能取无关附加记录。
负 RCODE、NODATA、坏报文均失败；CNAME 追问若需额外包必须共用该轮 deadline/取消信号，禁止经系统 DNS 补查。TCP 分片读写和长度前缀、UDP 截断处理必须有契约测试。
三轮最多约 9 秒，解析报文时间也在轮内；poll 建议不超过 100 ms 重新派发信号，取消后关 socket、回收 child，不能重复刷新 deadline。
`dns_test.valid_answer` 的布尔语义只适于诊断，可参考规则但不能当 IPv4 结果；修改/抽公共解析器需独立回归诊断接口。

## 建议拆卡与待决策

1. **B0 真实引擎契约小探针**：确认无 nft 的最小私有 chinadns 配置、可选 loopback 端口分配/冲突、现有 TLS/host@ 语法、child 生命周期；原端口不占用，不装设备。失败就停，不偷偷缩窄 schema。
