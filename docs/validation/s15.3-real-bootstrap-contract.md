# S15.3 真实引擎私有 bootstrap 契约

## 结论与证据范围

卡片基线 `cca4cab`，分支 `spike/s15.3-real-bootstrap-contract`。任务卡与执行约定相对 main 无差异。

**B 在两个真实引擎的可支持 UDP/TCP 配置下可行；wolfssl 回退引擎的 TLS 也已用受控服务真实验证。**
无列表、无集合的独立 loopback child 能直接解析节点 A/IN，不依赖正式 DNS、系统 resolver、Xray 或 nft。
成功、无应答、启动冲突、SIGTERM 取消及 SIGKILL 残留均有真实 child/wait/资源回收证据。
这不是生产修复或设备验收，不能宣称两引擎全语法等价或所有配置都可实施：

- aether-dns **不支持 TLS**，实测拒绝启动，不改引擎、不改用 UDP/TCP。
- chinadns-ng 拒绝非 TLS `host@IP`，不应静默删 host；TLS `host@IP` 真实握手发送 `boot.test` SNI。
- aether-dns 接受非 TLS `host@IP`，当前 `src/upstream.rs::exchange` 只使用 literal IP/port，host 不参与 UDP/TCP。
- TLS 测的是回退引擎默认的“不校验证书”模式；未验证 `cert-verify`/CA/主机名错误拒绝等 PKI 合约。
- 裸 IP 无 `#port` 测到启动接受；有实际报文的裸地址形式为 `127.0.0.1#动态端口`。
  无端口默认 53 的网络行为未测试，避免触碰宿主真实 DNS。不能写作“默认 53 实查通过”。

统一入口 `bash spikes/S15.3/run.sh` 退出 **0**：正常/恢复各 268 条断言，四次反向运行各退出 **1**
并命中指定断言。主矩阵 19 PASS、1 UNSUPPORTED，无 FAIL/BLOCKED。E4 的回退引擎非 TLS host 子项
明确为 UNSUPPORTED。所有原始证据在 `spikes/S15.3/evidence/`，字段和运行要求见该目录的上级 README。

## 最小私有配置

两个引擎使用相同配置（每次完整实际值在 `child.text` 中）：

```text
bind-addr 127.0.0.1
bind-port <动态私有端口>
china-dns <真实renderer所选boot上游列表>
trust-dns <同一列表>
default-tag gfw
ipset-name4 null
ipset-name6 null
cache 0
```

启动：`<真实引擎> -C <本代独占目录>/bootstrap.conf`，cwd 也为本代目录。
不声明任何 gfw/chn/custom/boot 列表，不写 group-ipset/add-tag*，不启用 hosts、cache-db、verdict-cache-db。
`default-tag gfw` 将所有送入本私有端点的问题交给指定 trust 上游，不使用 tag:none 的中国 IP 集合判定。
china/trust 均显式指定，防止引擎默认公共上游参与；实测每个单上游查询只产生一个 exchange。
这不是复制生产 renderer 作为修复：E3 调用真实 renderer，取 `group boot` 的 `group-upstream`，
将**完整原值**应用到本配置的两行；`wan` 展开及 direct 开关均由生产代码决定。

## 反向验证与恢复

只改变 spike 运行参数，不编辑引擎或生产代码。每种变异按两个引擎独立执行：

| 变异 | 指定失败断言（前缀为引擎名） | 退出/证据 |
|---|---|---|
| `closed-formal`：显式取地址目标错接已关闭的正式替身 | `E2 node IPv4 from explicit private endpoint` | 各退出1，`.jsonl` 有对应唯一 FAIL；清理断言仍通过 |
| `impostor`：在端口占用后跳过归属门，把占位端点用于 ready 查询 | `E7 readiness requires owned child and expected source` | 各退出1，authority `occupier` 真实返回 `.99`，而本次 child 不拥有该 socket；清理仍通过 |

`entry.log` 记录四次指定失败被 suite 确认；随后恢复无参数实验，双引擎 E1–E10 再跑，核心全部通过。
不能把“进程启动失败”或任意异常当成成功的反向验证：suite 要求失败断言名称**唯一且精确匹配**。

## 端口、生命周期及残留契约建议

1. 私有端点只绑定 loopback，与正式 31053/53/31082/31083 分离，绝不写入 handoff。
   先向内核取动态候选，再启动引擎有 TOCTOU；不能假定选到就占到。本实验最多两次尝试，
   建议生产最多10个候选且共享总 deadline，失败 child 必须 wait 后再试。不要开启 reuse-port。
2. 每次 begin 拥有独立目录、配置、PID/child handle、选定 endpoint；不要用同名进程扫描充当所有权。
   readiness 必须结合 child 活着、退出错误、监听 socket 归属（本探针用 fd inode），
   查询还须核对来源/事务与预期 A。占位者有响应不是引擎就绪。
3. 成功取得节点 IP 也必须 end；DNS无应答、配置拒绝、端口冲突、取消都经过相同回收。
   本探针 query deadline 900ms；取消真实发送 SIGTERM 给 supervisor，停止等待、关闭 query socket，
   child TERM 最多1秒再 KILL/wait，取消收口断言小于1.5秒。此数值是探针测试界限，不擅自替换生产三轮/3秒语义。
4. child 被 SIGKILL 后 socket 随进程释放，但本代文件不会自动删。本探针父进程真正 wait(-9)，
   按句柄收口文件；同名另一实例通过错误PID/配置校验被排除，不会误杀/误删。
   生产必须由 supervise 负责 child 退出回调/reaping、取消收口和超时升级；daemon 崩溃后只能验证
   PID/真实可执行文件/完整配置路径/本代目录再发信号，考虑 PID 重用。非父进程不能直接 wait，
   不把本探针父子 wait 证明扩大为任意孤儿回收能力。
5. 文件只删本代已知 owned_paths；不会删除父目录、外部预置文件、另一个实例、旧 handoff/intent。
   清理失败要报错，不能依赖吞异常。统一入口共享 evidence/runtime fixture，不允许并行运行；
   生产多实例必须各自命名空间/锁，不能共享本代目录或端口。

## 后续三张实现卡接口边界

| 卡 | 可复用契约/接口建议 | 不应越界 |
|---|---|---|
| 查询器 B1 | `boot_upstreams(snapshot)` 共享已展开选择；`resolve_node_explicit(address, endpoint, on_signal)` 用 literal 私有端点取首合法 IPv4，保留 DNS优先/LKG/缓存写失败语义 | 不能直接复制本探针简化解码器；需事务ID、来源、qname/qtype/class、长度/RCODE、CNAME与压缩指针/坏报文测试；不经系统DNS补查 |
| readiness B2 | 从真实配置引用关系导出 socket/protocol；同一5秒 deadline，验证 TPROXY 与实际引用 DNS socket，取消可中断 | 不把端口存在当成归属，不把上游答得出问题当 readiness，不等未引用31083或额外协议 |
| 编排 B3（含supervise） | `bootstrap_begin(snapshot)` → `{child,endpoint,owned_paths}`；`bootstrap_end(handle)` 幂等 TERM/KILL/wait/本代清理；取IP后先结束私有child，再启动/等待Xray，后启动正式DNS并安装handoff | 不改初始DNS tier、fail_open、LKG顺序或T15.1安装成功才清intent；不顺带修改probe/reload解析语义 |

**TC/TCP 决策仍需查询器卡冻结**：本卡证明上游 TCP可用、引擎拥有私有TCP监听，未发送 TC，未验证私有查询器 TCP重试。
若支持通用 DNS 上游结果，建议 B1 对 TC 做有界 TCP重试；在该能力完成前 TC应明确失败并沿既有LKG路径，不能误取截断A。
CNAME追问、额外关联A与坏报文完整 resolver 都未实现、未宣称已覆盖。本卡只提供简化 A 应答契约。

## 隔离不是访问控制；未覆盖与停点

没有将普通 gfw 查询送到 bootstrap，证据的 qname 全为节点；没有真正 dnsmasq/handoff/nft/route 操作。
模拟 handoff/intent 证明探针所有权不越界，不证明生产T15.1编排已接入。
Python audit hook 限制调用方系统resolver和端点，**不是引擎 syscall 沙箱**；未做全量系统调用/包捕获。
引擎以 literal 地址配置，受控 authority 收到查询并返回不同地址，足以证明显式路径成功而非系统resolver兜底。
不声称“其他本机进程无法访问私有端口”，端口隔离与调用方仅发送节点名不提供域名ACL。

TLS默认端口853、DNS默认53网络访问、证书校验、TC/CNAME/坏报文、真实procd/设备/生产编排未测；
不能据此冻结“两个引擎所有配置等价”的实现卡。回退TLS传输已验证，不再属于S15.2的待验证项；
aether TLS仍是既有能力限制，负责人须在实现卡保留明确失败/LKG边界，不能要求此卡补功能。
本次未出现最小配置必须依赖nft、正式DNS、系统resolver或改变boot/tier/LKG/T15.1的停点。
